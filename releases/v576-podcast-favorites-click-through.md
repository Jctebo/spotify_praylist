## 2 · Plan

- **Data model — everything rides the standing starred store** (server `starred_tracks` whole-JSON entries in the private shape; `S.favorites.starred` in the v568 on-device file in the public shape; the device mirror `opn-starred-v546` between them):
  - **D1 — two new entry kinds in the same store:** `series` — a favorited podcast, a door: `{k:'series', id:<series key>, title, imageUrl, sub, date}`; `folder` — a custom folder definition: `{k:'folder', id:<folder id>, title:<name>}`. Star keys: `series:<id>` · `folder:<id>`. Both stores' PUT validation (index.ts + the client.ts local layer) learns the two kinds; entries remain whole-JSON, so no migration and no shape change for standing entries.
  - **D2 — folder assignment:** a track or door entry may carry `folder:<folder id>`; absent, its folder is derived: podcast episode → Catechesis (Q4 C) · episode with block `Novenas` → Catechesis · any other episode → Praylist · series → Podcasts. Default folder ids: `praylist` · `catechesis` · `prayers` · `podcasts`; custom ids are minted at creation. The Prayers folder's content is NOT starred entries — it is the book favorites list itself (Q3 A).
  - **D3 — the reset rule (Q6 B form):** an entry whose EFFECTIVE folder is Praylist and whose `date` is a day earlier than the current day is removed from the store (persisted through the standing whole-list write). An entry moved out of Praylist — to any other folder — never resets, whatever its kind or date. Entries with no date never reset.
- **Client build (app/worker/src/client.ts):**
  - **C1 — star machinery:** `starKeyOf`/`starKeyOfEntry` (client + server + layer key builds) gain the series/folder kinds; `starEntryForKey` resolves a `series:` key from the standing series payloads (`state.podcasts`, `state.podcastsIndex`); the one delegated `[data-trackstar]` handler toggles series entries through the standing `toggleStar`; `starredDescFor` returns null for series/folder entries (never playable — Play all and Add all to queue pass them by); `favoritesList()` narrows to track entries (episode|podcast) so every standing flat-list consumer (Play all, reorder, the home folder row's count) reads exactly what it read before.
  - **C2 — the grouped Favorites page:** `paintFavoritesPage` paints FOLDER SECTIONS in order — the four defaults, then custom folders in store order. Each section: a header row (folder name · item count · collapse chevron) and its rows. All folders stand EXPANDED on visit; collapse state is device-local UI state (`opn-favcollapse-v576`, the played-marks precedent — not personal data, not synced). Rows: tracks through the standing `starredRowHtml` (full controls, Intention line, marks — v550/v553 unchanged) · series doors through a new door row (art · title · "Podcast" meta; tap opens the podcast through the standing `goSeries`) · prayers in the Prayers folder through a new prayer row (title · group · play disc that plays the prayer's audio through the standing `prayerAudioDesc` + `playTrack`; the star on the row is the book star, `prayer:` key — the delegated handler already routes it to `toggleBookFav`). A default folder with nothing in it stands with a quiet empty line (the default folders exist, per John's word); a custom folder stands while it exists. Reorder mode stands as built (the flat track order; folder paints read store order within each folder).
  - **C3 — move + add + folder management:** the Favorites row's ⋮ menu (`openFavRowMenu`, and the door row's own menu) gains **Move to folder** — one item per other folder (defaults + customs; the Prayers folder is not a move target — its content is definitional under Q3 A; prayer rows carry no Move for the same reason). The act writes/clears the entry's `folder` through `starredSet` + `starredSync`. The header menu's Favorites group gains **New folder** (the page's overflow seat, beside Add all to queue / Reorder) — a name sheet in the intention-editor form mints the folder entry and syncs. A custom folder's header carries a ⋮ menu: Rename (the same sheet) · Delete (its items return to their derived folders — the assignment clears — and the definition entry is removed).
  - **C4 — the Praylist reset sweep:** `favPraylistSweep()` runs at the Favorites paints and at the starred load's settle: it computes the current day (the day payload's date, else the presented day, else `todayChicago()`), drops the D3-expired entries, and persists through the standing write when anything dropped. It never runs in web mode (the layer's list stands empty there and its writes are refused by design).
  - **C5 — the series star seats (Q2 A):** `paintPodcastsIndex` puts the star on each series card (the titlerow form; the card's own click handler exempts `[data-trackstar]` taps, the v546 Novenas-card precedent); `paintPodSeriesPage` seats the star in the row-2 bar's right slot at the head of the podcast's own page, for every series painter (audio · RSS · own · video), cleared when no series stands.
  - **C6 — web mode stands as built:** the Favorites page keeps the v568 app-pointer card; the layer answers the favorites reads empty, so the folders paint empty under the card; no web write is attempted by the new acts (the sweep is web-exempt; star seats on web carry the layer's standing refusal shape, as the standing stars already do).
- **Server build (app/worker/src/index.ts):** the `/api/prayer/starred` PUT validation accepts `k:'series'` and `k:'folder'` beside the standing kinds, and `starKeyOfEntry` gains both key forms. Nothing else server-side; no migration.
- **Local layer (client.ts, the v568 span):** the starred PUT validation + key build learn the same two kinds (a series entry's id is its series key; a folder entry's id is its folder id). The export/import census counts the store as it stands (doors and folder definitions count with the starred entries — the file carries them home, which is the point of the copy).
- **Harness (harness-v576.mjs, the v570 mold — worlds run the RENDERED client):** L1 folder derivation partitions a production-shaped store (a day episode → Praylist · a Novenas episode → Catechesis · a podcast episode → Catechesis, never Podcasts · a series door → Podcasts · an explicit `folder` wins over derivation) · L2 the series star toggles a door entry on the index-card key and the series-page key, and the door opens the series · L3 the Prayers folder renders the book favorites and a row's play builds the prayer audio descriptor (`/api/prayer/book/audio/<slug>/en`) · L4 the reset sweep: a Praylist entry dated yesterday drops and persists · the same entry moved to a custom folder survives (Q6 B) · a Catechesis entry dated yesterday survives · a dateless entry survives · L5 folder acts: New folder mints the definition · Move writes the assignment and the sync body carries it · Delete returns items to their derived folders · L6 collapse: expanded by default, the toggle persists to the device key and the next paint honors it · L7 validation: the layer's starred PUT accepts series/folder kinds and still refuses a bad kind; the server PUT's validation is read against the same cases in the served-leg proof · L8 the RENDERED client parses whole (the v568 lesson) · L9 both shapes: the device shape round-trips the store through the layer; web mode reads empty and the pointer card stands · L10 Play all / Add all carry no door or folder entry.
- **Fixtures (Improvement D):** entry snapshots are built by the client's own `starEntryForDesc` from live-shaped descriptors; the series list fixture carries the live `/api/player/podcasts` index fields (`series · title · showImageUrl · kind · category`); book favorites use live book slugs (our-father · memorare).
