## 2 · Plan

- **P1 · The microphone finding (the named unknown, resolved from the shell code):** the Android shell is Capacitor 7.6.10 — `MainActivity extends BridgeActivity` (com.thibeaux.orapronobis), loading the live app origin; it registers the one local plugin (OraDayBridgePlugin) and installs NO custom WebChromeClient. Capacitor's stock `BridgeWebChromeClient.onPermissionRequest` answers a WebView AUDIO_CAPTURE request by launching a runtime permission request for `MODIFY_AUDIO_SETTINGS` + `RECORD_AUDIO` and grants the WebView request only when every requested entry comes back granted. The shell's `AndroidManifest.xml` declares NEITHER permission (verified in the standing shell copies — v466 · v469 · v472 · v479: RECORD_AUDIO count 0), so the runtime request returns denied with no dialog and the WebView request is denied: **in the current APK (1.0.45), `getUserMedia({audio})` fails.** Verdict: a small shell change + a new APK stand between here and Ship — declare both permissions in the manifest (RECORD_AUDIO is the runtime one; MODIFY_AUDIO_SETTINGS is normal-level but Capacitor's callback requires every entry granted, so it must be declared too). No MainActivity or plugin change is needed — Capacitor's stock client does the rest. The web build works in a browser (the browser's own prompt) the moment it ships; in the shell it works once the new APK is installed. This release builds the web side only; the shell step is a Ship prerequisite, restated at Review.

- **P3 · On-device store:** one module (`homilyStore`) over two stores kept in step, the app's standing mirror discipline (the starred and day-additions mirrors): IndexedDB database `opn-homilies` v1, object store `recordings` (keyPath `id`) holding `{id, blob, mimeType}` — the audio truth; localStorage index `opn-homilies-v551` holding metadata only — `{id, name, dateKey, dayName, createdAt, durationS, sizeBytes, mimeType, starred, played, state}` — the paint-time truth for the list and for the Catechesis pill (read synchronously). - **P4 · Capture flow (the Mass-scroll seat):** `paintMassScroll` gains the record card immediately after the `#mass-readings` block — after the Gospel, ahead of the Creed where the Creed stands, in all cases before the Universal Prayer section: the homily's own place in the order of the Mass (mockup M1). Card states: idle (ring disc · "Record the homily" · the standing line) → recording (solid disc · elapsed timer · Stop — mockup M2) → a transient saved note, then idle. Capture: `navigator.mediaDevices.getUserMedia({audio: true})` → `MediaRecorder`, mimeType the first supported of `audio/webm;codecs=opus` · `audio/webm` · `audio/mp4` · `audio/ogg;codecs=opus`; `ondataavailable` on a 5000 ms timeslice — chunks flush to the IndexedDB record (state `recording`, the index entry written at record start under its auto-name) as they arrive, so the take on disk is never more than ~5 s behind the microphone. Stop: `recorder.stop()` → final flush → state `ready`, durationS from the take's elapsed clock, sizeBytes from the assembled blob. Interruption (page killed, recorder error, stream ended): the standing `recording` entry finalizes at next boot as a partial take (state `ready`, `partial: true`, duration from its chunks) — Q6 A's partial-take rule. A screen wake lock is requested at start and released at stop, best-effort (`navigator.wakeLock` where it stands): the chunk flush is the guarantee, the lock a help, never a dependency. A denied microphone (the pre-APK shell case, or a refused browser prompt) paints "Microphone not available on this device" on the card and writes no entry.
