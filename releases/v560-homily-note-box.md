- **Verified facts** (fresh clone of GitHub main, Jctebo/spotify_praylist, HEAD d370639; app/worker/src/client.ts, the v551 homily module):
  - A homily lives in two device-local stores kept in step: IndexedDB `opn-homilies` (object stores `takes` + `chunks` — audio only) and a localStorage index `opn-homilies-v551` holding one metadata entry per homily (id · name · dateKey · dayName · mimeType · state · chunkCount · durationS · sizeBytes · played · starred · partial · createdAt).
  - Index entries are written by `homilyEntrySave(entry)` — the same save step the played mark (`homilySetPlayed`) and the star (`homilySetStarred`) already use. A note is one more text field on that entry: a non-audio entry in the same store, saved the same way. No server row, no fetch, no upload — the module holds no network call (v551 Local-only rule stands).
  - The record card (`massHomilyCardInner`) stands in the Mass scroll at the homily's place. On finish (`homilyFinishRecord`) the entry goes `ready`, and the card repaints at rest showing the saved line ("Saved — <name> (<duration>). On this device only.") plus the v557 microphone row. The recording state shows the timer only — no box can stand during capture without new dress.
  - The Homilies list (`homilyRowHtml` + `paintCatechesisHomilies`, Catechesis fourth side) renders one card row per ready entry: play disc · name · meta (duration · long date · day name · partial) · played/star cluster · ⋮ menu (`openHomilyMenu`: Play · Add to queue · Add to Praylist · Mark played/unplayed · Rename · Delete). Rename (`openHomilyRename`) is the standing edit-sheet pattern — a sheet with a text field and Save — which a note edit rides.
  - Deleting a homily removes its index entry and its IndexedDB take (`homilyDelete`) — a note field on the entry goes with it, under the same "only copy" warning.
  - There is no opened/detail view for a homily today; the list row and the record card are the only two surfaces. The descriptor (`homilyDescFor`) carries no note field.
- **The design as scoped:** one brief free-text note per homily, stored as a text field on the homily's device-local index entry; the box stands under the take on the record card after recording stops and under the homily's entry in the Homilies list; editing rides the rename-sheet pattern (an "Edit note" menu act in the list; the box itself at the record card).
