## §2 Plan (passed) — diagnosis from production fixtures

Fixture: the live production payloads for today, 2026-11-21 (Memorial of the Presentation of the Blessed Virgin Mary), fetched from app.orapronobis.media at Plan time: `/api/prayer/mass?date=2026-11-21` and `/api/prayer/mass-readings?date=2026-11-21` (the readings payload carries the memorial with 4 parts — the day carries two reading sets, as the screenshot shows).

**Defect 1 — the pill shows no active segment: a class-name mismatch.**
- `massReadingsChipsHtml()` (client.ts) builds the readings-set pill (`Weekday` / one chip per memorial) and marks the standing set's button with `class="on"`. The per-part option chips in `massFeedPartHtml()` do the same.
- The segtoggle dress (ui.ts) defines the selected state ONLY for `.active`: `.segtoggle button.active` (ui.ts:384) and `.segtoggle.pill button.active` — cream background, navy text (ui.ts:393). That is the dress the Worship pill wears (`paintSideToggle`, and `massPenToggleHtml` emits `class="active"` likewise).
- No `.segtoggle … .on` rule exists anywhere in ui.ts (the `.on` rules that exist belong to other controls: podmark, settoggle, pindot, homily-mic-item). So the chips' state is present in the markup and invisible on screen — both segments stand grey, exactly as the screenshot shows.
- Fix (Q1 A): the two chip builders emit `class="active"` instead of `class="on"` — the standing set stands in the Worship pill's selected dress; the tap handler already repaints the readings host from the standing set key, so switching swaps the readings. No CSS change; no state change. The per-part option chips carry the identical defect on the same surface and take the identical one-word fix.

**Defect 2 — the COLLECT heading stands with no text: the text is ABSENT, at the source.**
- The client renders `massPrayerHtml('Collect', f.collect)`; `massPrayerHtml` prints the heading always and the body only when text stands. Today's production mass payload: the standing version `saint-presentationofblessedvirginmary` carries an EMPTY formulary (no keys at all); the ferial version's formulary carries its collect. So the heading-alone render is the client faithfully showing an absent collect — the whole saint formulary is absent; the Collect is the absence the screenshot catches.
- Why absent: `resolveFormulary` (mass.ts, kind "saint") reads the feast's propers from liturgies.net saint pages (`/saints/<slug>/readings.htm`). Every candidate slug for this feast (presentationofblessedvirginmary · presentationofblessedvirgin · presentationofblessed · presentationof · presentation) returns 404 (verified at Plan). The one Presentation page the source carries (`/saints/mary/presentation/presentation.htm`, 5,257 bytes) is a readings page with no Missal items and stands under the 8,000-byte stub guard. The source carries no Missal propers page for this memorial in the read shape — the gap is systemic to the source's Marian set (all `/saints/mary/<feast>/<feast>.htm` pages are readings pages, not propers pages).
- Fix: in the saint branch, when no candidate page yields a formulary and the feast is a memorial of the Blessed Virgin Mary, return the Common of the Blessed Virgin Mary formulary extracted from the proven Commons page (the same source, verbatim extraction — `commonsFormulary(lines, "Common of the Blessed Virgin Mary")`, Ordinary Time formulary 1 as extracted). Precedent in the same function: the "Dedication of" fallback returns its Common whole when the saint page is absent. The Commons page itself prints the warrant: "These Masses are also used for celebrating the Memorial of the Blessed Virgin Mary." Marian test: label contains "Blessed Virgin Mary", or starts with "Our Lady of", or is "Mary, the Holy Mother of God" — and never a label starting with "Saint" (excludes St Joseph, Spouse of the Blessed Virgin Mary, and Ss Joachim and Anne, whose own pages stand first in the loop anyway; the fallback fires only when no page yields a formulary). Known limit, stated: the Common's seasonal variants are not selected — the extracted first (Ordinary Time) formulary stands; it is a verbatim Missal text, never a paraphrase, and the memorial's own proper, where the source carries it, always stands ahead of the Common.
- Cache consequence: `mass_cache` holds today's EMPTY saint formulary (an empty result is served for 24 hours), so the fix would not show on the live leg today without invalidation. The saint cache key is versioned in this release (`form:saint:` → `form:saint:2:`) so stale saint empties retire at deploy and every saint formulary re-derives once under the fixed code. No production D1 write is made by hand.
