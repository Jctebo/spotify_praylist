## 2 · Plan

- **Zone (connector, read-back verified):** Smart Tiered Cache ON for orapronobis.media (one fill per region rides the upper tier). Cache Rule spec for the token edit (recorded, not applied — rulesets scope missing): on host audio.orapronobis.media, paths matching the date-stamped episode assets → cache eligible, edge TTL 31 days, browser TTL respect existing headers; the rule exists to pin the lifetime the R2 public host's defaults otherwise leave short.
- **Worker (index.ts):** (a) `GET /api/prayer/day-manifest?date=` — ONE call carrying the day's whole shape: the standing day payload, the day's Mass payload, the day's readings payload, and the day-set asset list (every own-feed enclosure whose stem carries the date, feed order, deduped, with byte sizes). Each fold keeps its own failure posture — a failed fold reads as its empty shape, never as a failed manifest. Same session gate as the day route. (b) Immutable day builds at the app layer: a settled day (before Chicago today) answers its day + manifest with `Cache-Control: private, max-age=31536000, immutable`; today keeps the standing uncached shape (settledJson). (c) Nothing else: PRAYER_AUDIO byte-identical, playback routes untouched, the agent day-read untouched.
- **Client (client.ts):** `daySetPrefetch(date)` — one manifest call per day (a per-date local stamp stops repeats), then the day set downloads in ONE pass, sequentially, through the standing feed-audio pass-through (the enclosure host sends no CORS header), into the standing device audio cache (`opn-ext-audio-v1`) under each asset's own URL — the key the cache-restore playback paths already read. Already-cached entries skip; a failed asset never blocks the pass or the day. Purely additive: no playback route changes; the pass warms the cache so the day replays locally, offline included. Called once behind the boot.
- **Cost watch (jobs/ora_cost_watch.py):** a monthly read through the connector's registered API — R2 storage + 30-day operations for bucket ora-pro-nobis-audio (account analytics, which the token CAN read), priced at named list-rate constants, plus the audio-host request volume for cost per prayer when the zone-analytics scope exists; a refused volume read records null + the refusal, never a fabricated number. First run stands in §3.
- **Cache warmer (runner/warm_day_cache.py):** at publish time, walk the published day's dated assets and request each once through the edge (then a ranged re-check reporting cf-cache-status) so the first listener per region reads the tiered cache, not the origin. Ships as a repo tool for the publish flow to call; the nightly runner wiring is a named follow-up (§5), deliberately not landed tonight beside the Nov 23 publish repair.
- **Harness (harness-v569.mjs):** S1 manifest machinery present · S2 day + manifest routes answer through settledJson, agent read untouched · S3 manifest folds the four parts with their failure postures · S4 settledJson immutable only for settled dates · S5 asset scan date-keyed, deduped, failure-empty · S6 client prefetch stands, boot calls it, the client diff adds exactly one function · S7 pin = ora-pro-nobis-v569-1 and the ui.ts diff is the pin line only · S8 PRAYER_AUDIO byte-equal to base · S9 cost watch + warmer present and python-clean · S10 diff confined to the v569 surface.
