## Objective
Remove the noisy legacy OneDrive prefetch error from the daily novena workflow. The workflow should continue prefetching the current `Praylist Audio` libraries, but it should only attempt the legacy `Novena Audio Library` backfill when a legacy root is explicitly configured.

## Problem statement
The remote daily novena workflow currently logs repeated `rclone copy` errors for a missing legacy source root such as `Pictures/Samsung Gallery/DCIM/Novena Audio Library`. The workflow continues, but the log noise makes the run harder to read and suggests the legacy backfill path is still being attempted even when no legacy root is configured.

## Desired outcome
When the legacy root is not configured, the workflow should skip that backfill path entirely and complete the prefetch step without missing-root errors. When a legacy root is explicitly configured, the workflow should still be able to prefetch that legacy novena library for backfill or migration purposes.

## In scope
- Make the legacy novena prefetch optional instead of always attempting the fallback path.
- Keep the current primary `Praylist Audio` prefetch behavior unchanged.
- Update documentation so the workflow’s legacy-prefetch behavior is clear.
- Verify that the workflow still runs successfully when the legacy root is absent.

## Out of scope
- Changing novena audio generation behavior.
- Changing the OneDrive upload or sync destinations.
- Removing the current primary `Praylist Audio` prefetch path.
- Refactoring unrelated workflow steps.

## Users / systems affected
- The GitHub Actions daily novena workflow.
- Anyone reading workflow logs or maintaining the OneDrive sync configuration.

## Functional requirements
- FR1: The workflow must not attempt the legacy novena prefetch when no legacy root is configured.
- FR2: The workflow must continue to prefetch the primary `Praylist Audio` libraries as before.
- FR3: If a legacy root is configured, the workflow must still support copying from it.

## Non-functional requirements
- Performance: The prefetch step should stay fast and avoid redundant failed copy attempts.
- Reliability: Missing legacy sources should not produce failure noise in an otherwise successful run.
- Security: No new secrets or permissions should be required.
- Cost: No material change in storage or compute usage.
- Maintainability: The legacy path should be easy to understand and clearly opt-in.
- Observability: The logs should make it obvious when the legacy prefetch is skipped versus used.

## Existing assumptions
- A1: The primary `Praylist Audio` path is the authoritative source for daily novena prefetching.
- A2: The legacy novena source root is optional and only needed for explicit backfill or migration use.

## Open questions

- AC2: The primary `Praylist Audio` prefetch and later sync steps still complete successfully.
- AC3: The workflow still supports the legacy backfill path when a legacy root is explicitly configured.
