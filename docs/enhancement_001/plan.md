Snapshot date: March 18, 2026

Status: Ready for implementation and verification.

Reference:
- https://deepwiki.com/humanlayer/advanced-context-engineering-for-coding-agents/3.2-planning-phase

## Goal

Implement Enhancement 001 as a docs-first, code-second delivery:

- update the enhancement scope, research, and plan artifacts first
- add ordered OneDrive `Playlist Audio` export naming and managed daily truncation
- preserve Morning Prayer's current page-body behavior
- expand reliable-text page-content coverage without inventing text for unsupported prayers

## Chosen Approach

Use the existing page-audio workflow as the execution path. The new work belongs in the current `jobs/notion/generate_page_audio.py` pipeline and its scheduled workflow, not in a new export job.

Use a mixed text-sync strategy:

- preserve Morning Prayer and other established full-page writers that already behave correctly
- add a managed autogenerated-section path only for prayers whose reliable text is being promoted into page content from a more generic source

## Dependency And Sequencing Notes

- Phase 1 must happen before code changes so the written contract is stable.
- Phase 2 should land before Phases 3 and 4 so export naming and queue ordering share the same order semantics.
- Phase 5 depends on the current text-plan normalization flow and should preserve existing page-content writers rather than replacing them wholesale.
- Runtime docs should be updated only after the code behavior is settled.

## Test Strategy

### Unit

- `python -m unittest tests.test_page_audio_job`
- `python -m unittest tests.test_refresh_job`

Coverage focus:
- order normalization
- ordered filename generation
- duplicate stem validation
- managed truncation
- managed-section page-content sync
- Morning Prayer non-regression

### Integration

- one local page-audio export path against a temporary `PAGE_AUDIO_LIBRARY_DIR` if the local environment has the required env vars and fixtures

### Manual Verification

- inspect generated ordered files in a temp library root
- confirm the scheduled workflow env now enables truncation
- if a live environment is available, inspect representative Notion pages and OneDrive folders after a manual run

## Edge Cases To Validate

- rows with missing or invalid top-level `Order`
- duplicate sanitized stems inside one folder
- title, folder, or order changes between daily runs
- prayers configured for `page_content` that resolve audio but no reliable text
- Morning Prayer rows with existing novena placeholders and generated novena sections

## Non-Goals During Implementation

- new shortcut or manifest artifact types
- wholesale redesign of page-content sync across every prayer family
- migration away from the existing daily page-audio workflow
