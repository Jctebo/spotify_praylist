## Objective
Define the scope for diagnosing and fixing the daily novena audio regeneration bug. The system should regenerate daily novena audio in a way that fully replaces the previous managed output for the same novena run, without leaving stale audio artifacts behind. The fix should preserve the current intended ordering behavior and avoid introducing unrelated changes to the novena generation pipeline.

## Problem statement
The daily novena audio is regenerating new audio, but some old audio appears to remain in the output. This may be happening because the ordering changed, but the exact cause is not yet confirmed. The result is a confusing mixed output state where regenerated audio and older audio can coexist when they should not.

## Desired outcome
After the bug is fixed, a daily novena run should produce a clean, current set of audio artifacts only. Any previous managed novena audio that is no longer part of the latest generated set should be removed or overwritten as part of the normal workflow. The fix should make stale audio disappearance deterministic and verifiable.

## In scope
- Investigate why stale novena audio remains after regeneration.
- Confirm whether the issue is caused by ordering changes, filename changes, folder changes, truncation gaps, or sync behavior.
- Fix the daily novena audio generation or cleanup flow so regenerated output replaces the prior managed output cleanly by fully truncating the managed novena audio subtree before regeneration.
- Add regression coverage for stale-audio persistence after a rerun.
- Document the behavior if the code change affects operational expectations.

## Out of scope
- Reworking unrelated playlist or enhancement workflows.
- Changing the content of the novena audio itself beyond what is needed to fix the stale-output bug.
- Broad refactors of the full audio generation architecture.
- Creating new output types unrelated to the existing daily novena artifacts.

## Users / systems affected
- End users who consume the daily novena audio.
- The scheduled daily novena generation job.
- Any downstream sync or storage location that receives the generated audio artifacts.

## Functional requirements
- FR1: The daily novena workflow must not leave behind stale managed audio artifacts after regeneration.
- FR2: The regenerated output must reflect the current source ordering and naming rules consistently.
- FR3: If cleanup is required, it must happen automatically as part of the normal daily job flow.

## Non-functional requirements
- Performance: Cleanup should not add noticeable delay to the daily run.
- Reliability: Re-running the job on the same day should not produce mixed old/new audio sets.
- Security: No new secrets or permissions should be required.
- Cost: No meaningful increase in storage or compute usage.
- Maintainability: The fix should be easy to reason about and limited to the smallest necessary scope.
- Observability: The job should make it clear when stale output is removed or when a cleanup-related failure occurs.

## Inputs
- Input 1: Current daily novena source data and ordering.
- Input 2: Existing novena output directory or sync target contents.

## Outputs
- Output 1: Fresh daily novena audio artifacts.
- Output 2: Regression tests and/or logs that prove stale audio is not retained.

## Constraints
- Technical constraints: Must fit the existing novena generation pipeline and its current output layout.
- Organizational constraints: Keep the fix narrow and avoid unrelated workflow churn.
- Deployment constraints: Must work in the scheduled daily execution path.
- Time constraints: Diagnose and scope the fix without needing a full rewrite.

## Existing assumptions
- A1: The bug is caused by stale artifacts, not by the audio generation itself being incorrect.
- A2: The managed novena audio subtree can be safely rebuilt from scratch on each rerun.

## Open questions
- Q1: Resolved: the cleanup boundary is the managed novena audio subtree rooted at `NOVENA_AUDIO_LIBRARY_DIR`.
- Q2: Resolved: cleanup will remove the full managed subtree before regeneration so prior filenames cannot linger.
- Q3: Resolved: the authoritative managed output is the novena audio library tree that the daily job prefetches and syncs back to OneDrive.

## Acceptance criteria
- AC1: The bug cause is identified and documented clearly enough to explain why old audio remained.
- AC2: The fix ensures a rerun of the daily novena workflow does not leave stale audio artifacts behind.
- AC3: Tests or verification steps demonstrate that regenerated output replaces prior managed output cleanly.

## Risk notes
- Risk 1: Cleanup could remove files that are still intended to be kept if the managed-output boundary is defined too broadly.
- Risk 2: Ordering changes could mask a deeper naming or sync bug if investigation stops too early.
