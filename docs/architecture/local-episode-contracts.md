# Local Episode Contracts

## Contract format

`config/publish/contracts/<contract-id>.json` remains the source for contract metadata, entries, blocks, and audio configuration. Each entry gains an optional `episode_state` object populated from the former Notion row:

```json
{
  "entry_id": "morning-prayer-elevenlabs",
  "date": "daily",
  "title": "Morning Prayer",
  "status": "approved",
  "text": "Morning Prayer",
  "text_config": { "enabled": true },
  "audio_config": { "enabled": true },
  "blocks": [],
  "episode_state": {
    "entry_id": "morning-prayer-elevenlabs",
    "date": "2026-10-16",
    "status": "approved",
    "text": "...",
    "text_hash": "...",
    "audio_enabled": true,
    "audio_url": "...",
    "audio_path": "...",
    "content_hash": "..."
  }
}
```

The contract's authored `entry_id`, `date`, `title`, `blocks`, and `audio_config` continue to drive generation. `episode_state` records the last persisted/current episode values and is updated by the later pipeline migration. Hashes are preserved verbatim and recalculated only by the pipeline when content changes. `episode_state.entry_id` retains the Notion Entry ID even if it differs from the authored entry key.

## File layout

- Contract definitions and per-entry state: `config/publish/contracts/*.json`.
- Generated text/audio and episode sidecars: existing `docs/` paths and sidecar formats.
- Podcast feed: existing `docs/podcast.xml`, generated by the shared RSS path.
- Daily completion state: `docs/state/publish-completions.json`, keyed by local date and contract/entry ID. Each record contains `date`, `contract_id`, `entry_id`, `text_completed`, and `audio_completed`; the pipeline prunes dates older than the current local date when it writes state. A `schema_version` integer permits later format changes.
- One-time exporter: `scripts/migrate_notion_episodes.py`; it reads all pages in the `Opus Dei` database and atomically writes validated contract JSON.

## Reuse boundary

Use novena contract validation primitives and the novena resolver/artifact/RSS helpers where their inputs match. Publish entries retain `jobs/publish/contracts.py` block normalization and generation because these include daily intros, Rosary, and reflection-specific blocks. Shared RSS and audio artifact writers remain the source of output behavior; no parallel publishing implementation is introduced.

## Migration and compatibility

The one-time migration is read-only against Notion and repeatable. It maps every row by stable Entry ID, copies Date, Status, Text, Text Hash, Audio Enabled, Audio URL, Audio Path, and Content Hash, validates all rows and target contracts before writing, and uses staged files plus atomic replacement. Unknown or duplicate IDs, malformed required properties, or ambiguous mappings abort without changing contracts. After local pipelines pass output parity review, the Notion client, reset job/workflow, and setup scripts can be removed in a separate phase.

The current credentials' `Opus Dei` database does not expose the episode schema: its visible properties are `Intention`, `Completed`, `Order`, `Enabled`, `Output Folder`, and `Name`. The exporter detects this mismatch and stops before writing. The episode export must be run against the database containing `Entry ID`, `Date`, `Status`, `Text`, and the remaining episode properties.
