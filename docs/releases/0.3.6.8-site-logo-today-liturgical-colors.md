# Release 0.3.6.8 - Site Logo, Today Focus, And Liturgical Colors

## Scope

### Problem
- The generated Ora Pro Nobis prayer website works as a directory, but it does not yet look or feel consistent with the current Ora Pro Nobis logo.
- The site still communicates "latest" audio behavior, which can surface the newest archived episode rather than clearly orienting the listener around today's prayer.
- Generated devotional images exist in the broader publishing system, but the prayer website does not yet use them as visual material for cards, prayer pages, or daily focus.
- The site misses an opportunity to gently reflect the Church year through liturgical colors without turning the interface into a heavy seasonal theme.
- Why now: the site has just become a real listener-facing directory and audio hub, so brand polish, date clarity, and devotional imagery are now part of the core experience rather than decoration.

### Audience
- Primary user: a Catholic listener opening the Ora Pro Nobis site to pray today, usually from a phone.
- Secondary stakeholders:
  - The site/podcast maintainer who needs the generated pages to stay contract-driven and low-maintenance.
  - Podcast and Spotify listeners who arrive from feeds, playlist links, or shared prayer pages.
  - Future maintainers who need images and colors to be generated from metadata, not hand-edited into published HTML.

### Current Status Quo
- `jobs/publish/site.py` generates `docs/index.html`, `docs/prayers/index.json`, and one `docs/prayers/<slug>/index.html` page per active praylist entry.
- The site CSS is embedded in `jobs/publish/site.py` and currently uses a warm green/wine/paper palette that is not aligned with the navy/gold/cream logo.
- The logo file already exists at:
  - `config/publish/images/logo_ora_pro_nobis.png`
  - `docs/images/logo_ora_pro_nobis.png`
  - `C:/Users/jcteb/Downloads/logo_ora_pro_nobis.png`
- The logo image is 1254x1254 and about 1.47 MB, which is reasonable for podcast cover art but oversized for repeated website UI use.
- Prayer cards currently show source, availability, and a `Latest: <date>` pill when sidecar audio exists.
- Prayer pages render a "Latest episode" label, audio player, latest audio link, podcast feed link, audio archive link, and readable prayer text where available.
- `_attach_latest_audio()` attaches the first matching sidecar job from `load_published_audio_jobs()`; that behavior is "latest archive match" rather than an explicit "today first" contract.
- Daily novena pages can list individual novena episodes but still use the same archive-first ordering.
- The devotional image pipeline lives under `jobs/novena/generate_devotional_image.py` and can write manifests/images for current and archived devotional outputs, but the site generator does not consume those images.
- Liturgical context helpers already exist in the publish system, especially `jobs/publish/daily_liturgical_context.py`, `jobs/publish/rosary_reflections.py`, and liturgical metadata in generated audio sidecars.

### Goal
- Redesign the generated static site so the first impression is clearly Ora Pro Nobis: navy, gold, warm ivory, sacred restraint, and prominent but not overwhelming logo usage.
- Replace user-facing "latest" language with "today" language wherever the site is presenting the prayer for the current local date.
- Prefer today's matching sidecar audio and prayer text for each generated prayer page; fall back to the most recent available episode only with clear fallback wording.
- Incorporate generated devotional images into the site in a maintainable way:
  - Use optimized web variants instead of raw large originals.
  - Expose image metadata in the site manifest.
  - Render images on the home page and/or prayer detail pages when there is a relevant image.
- Subtly integrate liturgical colors:
  - Purple for Lent and Advent.
  - White/gold for Easter and Christmas.
  - Green for Ordinary Time.
  - Red for martyrs and Pentecost.
- Keep the site fast, static, and fully generated by code.
- Preserve existing audio publishing, RSS, R2 audio hosting, and playlist contracts.

### Constraints
- Follow the existing generated-site boundary: update `jobs/publish/site.py` and tests rather than hand-editing generated files as the source of truth.
- Keep the site static and GitHub Pages compatible; do not add a client-side framework for this release.
- Optimize images locally during publishing or site generation using dependencies already present if possible; Pillow is already available through the devotional image pipeline.
- Do not break podcast cover art usage; the 1254x1254 logo can remain as the feed image while smaller web derivatives serve the site.
- Do not make the palette one-note. Liturgical colors should appear as accents, states, rules, borders, or small visual fields over the navy/gold/ivory brand base.
- The date focus must use the publish/site runtime timezone intentionally, not whatever order archive files happen to sort in.
- If today's episode has not been published yet, the page should degrade gracefully and tell the truth.
- Generated images may be missing locally or in CI; missing images must not fail site generation unless the implementation intentionally requires a known logo derivative.
- Preserve accessibility:
  - Meaningful alt text for logo and devotional images.
  - Good contrast for liturgical accent colors.
  - No text baked into devotional images as the only source of meaning.

### Narrow Wedge
- Build a brand-and-today pass for the existing generated static site:
  - Add optimized web logo derivatives for header/hero/card contexts.
  - Update the home and prayer-page templates to use Ora Pro Nobis visual identity.
  - Change "Latest" labels and matching logic to prefer today's local-date sidecar.
  - Add explicit fallback wording when only an older episode is available.
  - Attach a liturgical color token to the manifest/pages from today's liturgical context or sidecar metadata.
  - Add a small image asset pipeline that copies/optimizes available generated devotional images into `docs/images/` and exposes them to site rendering.
- This release should improve the existing site in place, not create a new app or a parallel design system.

### Non-Goals
- Do not rebuild the site with React, Next.js, Astro, or another frontend framework.
- Do not redesign the podcast RSS feed.
- Do not change Spotify playlist membership, resolver logic, or queue ordering.
- Do not regenerate devotional images in this release unless needed for a local smoke test; consume and optimize existing/generated image outputs.
- Do not bulk migrate images to R2 or a CDN in this release.
- Do not add user-selectable themes or settings.
- Do not make liturgical color override the whole page background for every season.
- Do not remove historical archive access.
- Do not change the theology/content of the prayers themselves except for wording around today's availability.

### Risks And Unknowns
- The exact shape and location of generated devotional image manifests needs verification; the repo has image generation code, but local `artifacts/` currently shows only logo copies.
- "Today" needs a single canonical timezone. The site should likely use the same local Catholic/publishing date behavior as the audio pipeline, not UTC archive timestamps.
- Some entries are external Spotify prayers and may not have Ora Pro Nobis sidecars; they still need a useful page without pretending there is today's generated audio.
- Daily novenas can have multiple active episodes on the same date; the design needs to show today's relevant novena episodes without burying prayer text.
- Liturgical colors from sidecar metadata may not be complete for every episode type, so the implementation may need a deterministic fallback from the shared liturgical helper.
- The current logo is square and detailed; it needs smaller derivatives so mobile pages do not load 1.47 MB just to show a header mark.
- Generated devotional images may have different aspect ratios; the site needs stable aspect-ratio containers and cropping rules.

  - Decide the exact today-selection algorithm and fallback text.
  - Specify logo/image optimization outputs.
  - Define the HTML/CSS changes and focused tests for `jobs/publish/site.py`.

### Current System Map
- Site generation flow:
  - `write_prayer_site()` resolves `docs_root`, site base URL, and audio base URL.
  - `load_prayer_site_entries()` loads enabled publish-contract website metadata and Spotify-contract website metadata.
  - `_build_active_praylist_index()` maps playlist definitions to Morning/Daily/Night praylist groups.
  - `_apply_active_praylists()` filters entries to active playlist-backed items.
  - `load_published_audio_jobs()` loads local `docs/audio/*.json` sidecars, requires matching MP3s, and returns jobs sorted newest-first.
  - `_attach_latest_audio()` walks the sorted jobs and attaches the first matching job to each entry; daily novenas receive all novena sidecars in the same newest-first order.
  - `build_site_manifest()` writes `docs/prayers/index.json`.
  - `_site_index_html()` and `_prayer_page_html()` render the embedded-CSS static pages.
- Audio sidecar shape:
  - `render_audio_job()` writes `published_date`, `entry_id`, `episode_id`, `contract_id`, `contract_type`, `title`, `description`, `audio_url`, `audio_branding`, `fragments`, `render_context`, `rosary_reflections`, and `daily_reflection`.
  - `load_published_audio_jobs()` currently drops `audio_branding`, `render_context`, `rosary_reflections`, and `daily_reflection`; site work that needs liturgical or generated context must either preserve more fields there or read full sidecars separately.
- Date behavior:
  - `run_audio_pipeline._target_dates_for_mode("daily")` publishes tomorrow only.
  - Bootstrap/reset modes publish today and tomorrow.
  - `jobs.novena.liturgical_helpers.local_today()` is the existing local-date helper and defaults to CST offset when `JOB_UTC_OFFSET` is unset.
  - Therefore "today" UI must handle the common case where today's sidecar may be absent from a fresh normal audio publish.
- Logo behavior:
  - `ensure_podcast_cover_art()` copies the full 1254x1254 logo from `config/publish/images/logo_ora_pro_nobis.png` to `docs/images/logo_ora_pro_nobis.png`.
  - RSS/feed tests expect the podcast cover URL to remain `/images/logo_ora_pro_nobis.png`.
  - Smaller web-specific derivatives should be additive, not replacements for the podcast cover art.
- Devotional image behavior:
  - Source tree convention is a DCIM root with `devotional_image_library.json` and folders `Current Devotion`, `Current Devotion Wide`, `Non Current Devotion`, and `Non Current Devotion Wide`.
  - Folder manifests are named `images_manifest.json` and contain items with `state`, `variant`, `start_mmdd`, `end_mmdd`, `source`, `subject_slug`, `style_id`, and `files.image.relative_path`.
  - Local OneDrive currently has a live manifest with 129 total images; current portrait and current wide each have 4 items.
  - `sync/build_devotional_public_tree.py` currently publishes only current portrait and wide folders to `devotional/DCIM`.
  - The public tree copies original PNGs at roughly 2-3 MB each; it does not optimize images.
- Workflow split:
  - `publish_audio.yml` builds the site from `docs/` and has no devotional image tree.
  - `daily_devotional_image_remote.yml` builds a staged `pages/` tree, adds `pages/devotional/DCIM`, then generates the site against that staged root.
  - Site image support must gracefully no-op when `devotional/DCIM/devotional_image_library.json` is absent.

### Constraints
- Do not replace `docs/images/logo_ora_pro_nobis.png` as the podcast cover path; RSS tests depend on it.
- Generated pages must remain static, framework-free, and GitHub Pages-compatible.
- Site generation must succeed when `docs/audio/` is empty, when `devotional/DCIM/` is absent, and when no matching image exists.
- The main publish workflow stages Pages without `docs/audio/`; site pages must continue to use R2/public audio URLs rather than local `audio/` paths when configured.
- Image filenames can contain spaces and folder names contain spaces; generated HTML and manifest references must URL-escape correctly.
- The home page and cards need stable dimensions for images so missing/slow images do not shift layout.
- Liturgical color should be represented as a token/class/data attribute plus CSS accents; it should not require client-side date logic.
- Today selection needs to distinguish:
  - today's generated episode,
  - a future/tomorrow episode created by the normal publish workflow,
  - an older fallback episode from the archive,
  - external Spotify-only entries with no Ora Pro Nobis sidecar.

### Risks
- Biggest behavior risk: simply renaming "Latest" to "Today" would be wrong when the normal audio workflow has only tomorrow's generated sidecar or an older archive item.
- Image availability is workflow-dependent. The audio workflow may publish a non-image site after the image workflow previously published an image-enhanced site unless image restoration/building is added there.
- `load_published_audio_jobs()` currently omits rich sidecar metadata, so liturgical color extraction from sidecars is not available without changing that boundary.
- Public devotional images are currently large PNG originals. Rendering them directly on the home page would hurt mobile performance.
- Daily novenas can legitimately have multiple current/today episodes; the site should not collapse those into one misleading "today" card.
- Sidecar metadata is not uniform across episode families; Daily Reflection has `daily_reflection`, Rosary has `rosary_reflections` and `render_context`, and other prayers may only have `audio_branding` or fragments.

### Assumptions To Validate
- The intended "today" date should use `local_today()`/`JOB_UTC_OFFSET`, matching the repo's existing Central-time default.
- When today's sidecar is missing, the site should show a clear fallback such as "Most recent available episode" rather than showing tomorrow as today's prayer.
- The first implementation can use current devotional images as site-level visuals rather than attempting exact prayer-to-image matching for every card.
- Wide images are best for the home hero/daily visual, while portrait images are best for detail-page or card-level artwork.
- The `daily_devotional_image_remote.yml` workflow is an acceptable source of image-enhanced Pages output, but `publish_audio.yml` may need follow-up workflow work if image availability should survive every audio publish.

### Unknowns
- Whether the main audio publish workflow should also restore/copy the devotional image tree before `python -m jobs.publish.site`.
- Whether generated images should be matched by `subject_slug` to liturgical context, by active date window, or simply by current/wide priority in this release.
- Whether web image derivatives should be checked into `docs/images/` during generation or generated only in staged Pages output.
- Whether the desired site visual direction should make the square logo a header mark only, or use it as a larger hero/brand element on the home page.

### Recommended Direction
- Plan around three small implementation tracks:

  - Brand/theme system: add web logo derivatives, navy/gold/ivory CSS, and a server-generated liturgical color token from `build_daily_liturgical_context()` with safe fallbacks.
  - Image ingestion: read `devotional/DCIM/devotional_image_library.json` when present, optimize selected current images into web derivatives, expose them in the site manifest, and render them only when available.
- `/plan-astack` should decide whether image-tree restoration belongs in `publish_audio.yml` now or remains limited to `daily_devotional_image_remote.yml` for this release.

### Architecture

```text
publish_audio.yml / daily_devotional_image_remote.yml
  -> build or restore docs/pages root
  -> optionally create devotional/DCIM from OneDrive image manifests
  -> python -m jobs.publish.site

jobs.publish.site
  -> load active prayer entries
  -> load audio sidecars
  -> choose today audio, fallback audio, or no audio per entry
  -> resolve today liturgical context + color token
  -> prepare web logo + selected devotional image derivatives
  -> write docs/index.html, docs/prayers/index.json, docs/prayers/*/index.html
```

- Site manifest will gain generated context fields:
  - `today`: ISO local date used for the page.
  - `liturgical_context`: compact season/feast/rank/color token metadata.
  - `brand_assets`: web logo derivative paths.
  - `devotional_images`: selected optimized current image records when available.
- Entry records will replace implicit `latest_audio` behavior with explicit audio status:
  - `today_audio`: matching audio for `today`.
  - `fallback_audio`: most recent non-future older audio when today's audio is absent.
  - `upcoming_audio`: future/tomorrow audio when present but not presented as today's prayer.
  - `audio_status`: `today`, `fallback`, `upcoming`, or `none`.
- Existing `latest_audio` can remain temporarily as an internal/backward-compatible alias if needed, but user-facing templates should use the explicit status fields.
- Liturgical color token derivation:
  - Use `build_daily_liturgical_context(local_today())`.
  - Map Advent/Lent to `purple`, Easter/Christmas to `gold`, Ordinary Time to `green`, Pentecost or martyr/cross/passion feasts to `red`.
  - Fall back to `green` when Romcal/context lookup fails.
- Image selection:
  - Prefer current wide devotional image for the home hero/daily visual.
  - Prefer current portrait devotional image for prayer detail visual accents.
  - Match by active date window when possible; otherwise use the first current image in manifest order.
  - Optimize selected images into `docs/images/site/` (or the active `docs_root/images/site/`) as web-friendly JPEG/WebP-compatible outputs. Use JPEG for broad GitHub Pages/browser compatibility unless implementation confirms WebP handling is straightforward.
- Logo asset strategy:
  - Keep `docs/images/logo_ora_pro_nobis.png` unchanged for podcast/RSS cover art.
  - Generate additive smaller site derivatives under `images/site/`, such as `ora-pro-nobis-mark-160.png` and `ora-pro-nobis-mark-320.png`.

### UX And States
- Home page:
  - Header shows a compact Ora Pro Nobis logo mark and navigation.
  - Hero presents `Ora Pro Nobis` / daily praylists with today's local date and the liturgical day/season.
  - If a current wide devotional image exists, show it as a restrained visual surface with stable aspect ratio and alt text derived from `subject_slug` or feast label.
  - If no image exists, show a logo/brand-led hero with no broken image or empty box.
- Prayer cards:
  - `Today: YYYY-MM-DD` when today's generated audio exists.
  - `Most recent: YYYY-MM-DD` when today's audio is absent and an older episode exists.
  - `Upcoming: YYYY-MM-DD` only when only future audio is available; never call it today's prayer.
  - No generated-audio pill for Spotify-only entries unless they have a valid external action.
- Prayer pages:
  - Today's audio section says `Today's episode` only for exact today matches.
  - Older fallback says `Most recent available episode`.
  - Future-only state says `Upcoming episode` and should not auto-frame it as today's prayer.
  - No-audio generated entries keep feed/archive actions and explanatory text.
  - External Spotify entries keep the Spotify action and do not show generated prayer text/audio promises.
- Liturgical color:
  - Appears as subtle accent borders, small labels, rules, and button/hover accents.
  - Does not dominate the page background.
- Accessibility/responsive:
  - All images get non-empty `alt`.
  - Image containers use fixed aspect ratios to avoid layout shift.
  - Button text must fit on mobile.
  - Color tokens must maintain contrast on ivory/paper backgrounds.

### Failure Modes
- Today's sidecar missing:
  - Detected by no sidecar with `published_date == today`.
  - User sees `Most recent available episode`, `Upcoming episode`, or no generated audio state.
- Future sidecar present from normal publish:
  - Detected by `published_date > today`.
  - User sees `Upcoming`, never `Today`.
- Romcal/context lookup failure:
  - Detected by exception in liturgical context helper.
  - User sees default Ordinary Time/green-style accents with no broken page.
- Missing logo source:
  - Existing podcast cover-art code fails where cover art is required.
  - Site asset helper should skip derivative generation only if the cover source truly is absent; tests should cover no crash in isolated fixtures where source is unavailable.
- Missing devotional image manifest:
  - Detected by absent `devotional/DCIM/devotional_image_library.json`.
  - User sees logo/brand-only site, no broken images.
- Malformed devotional manifest or missing referenced image:
  - Detected during manifest/image loading.
  - Skip bad image records and keep generation alive.
- Rclone missing or misconfigured in production workflow:
  - Workflow fails before publishing image-contracted Pages, or logs a deliberate skip only on non-production contexts.
- Oversized generated image derivatives:
  - Detected by tests/checks on max dimensions and file existence.
  - User impact would be slow mobile pages; optimize selected images before render.
