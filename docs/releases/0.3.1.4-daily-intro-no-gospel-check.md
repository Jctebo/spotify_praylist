# Release 0.3.1.4 - Daily Intro No Gospel Check

Date: 2026-05-02
Status: Shipped
Branch: fix/daily-intro-no-gospel-check
Depends On: 0.3.1.3

## Scope

### Problem
- The Gospel-free Morning Prayer daily intro fallback still had a residual guard that could reject an empty or longer-than-expected response.
- The user no longer wanted a sentence-count check on the Gospel-free path.

### Goal
- Remove the remaining Gospel-free validation guard.
- Let the Gospel-free intro return whatever the model produced, including an empty string.
- Keep the Gospel-present path strict at exactly three sentences.

### Constraints
- Do not change the Gospel-present validation path.
- Do not change the prompt wording unless necessary.
- Keep the change narrow to the Gospel-free validation path.

### Risks
- Removing the guard entirely could allow weak model output to pass through.
- The downstream pipeline must continue to tolerate empty intro text cleanly.

## Research

### Scope Baseline
- The previous release already relaxed the Gospel-free sentence-count gate, but it still preserved a minimal guard for empty output.
- The user explicitly wanted that remaining check removed.
- The downstream text/audio pipeline already prunes empty strings, so returning an empty Gospel-free intro is acceptable as long as it does not crash the resolver.

### Relevant Files
- `jobs/publish/daily_intro.py` - contains the Gospel-free validator.
- `tests/test_publish_daily_intro.py` - covers the fallback path and now needs a no-check regression.
- `tests/test_publish_text_pipeline.py` - proves empty text is already pruned downstream.

### Reuse Opportunities
- Reuse the existing Gospel-free prompt path.
- Reuse the downstream empty-text pruning.
- Reuse the current daily intro tests and extend them to cover the empty-output case.

### Risks
- If empty intro text is not handled downstream, this change could bubble up as a later publish failure.
- The Gospel-present path must stay strict so this change doesn’t leak into the normal intro behavior.

## Plan

### Summary
- Remove the last Gospel-free validation guard in `_validate_daily_intro(...)`.
- Add a regression test proving an empty Gospel-free response returns an empty string instead of raising.
- Keep the Gospel-present validation path unchanged.

### What Already Exists
- `build_daily_intro_text(...)` already routes into the Gospel-free path when `allow_missing_gospel` is true.
- The downstream text pipeline already prunes empty outputs.
- The Gospel-present validation remains intact.

### Architecture
- The validator should behave like this:
  - Gospel present: exactly three sentences.
  - Gospel omitted: no sentence-count gate and no empty-output exception.

### Concrete Changes
- `jobs/publish/daily_intro.py`
  - Remove the remaining empty-output guard from the Gospel-free branch.
- `tests/test_publish_daily_intro.py`
  - Add a regression test for an empty Gospel-free model response.
