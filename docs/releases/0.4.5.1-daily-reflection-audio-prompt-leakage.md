## Scope

### Problem
- Daily Reflection model output can still contain prompt instructions or serialized context labels that pass the current finite leakage blacklist and are then sent to TTS.
- Because the generated episode is reused to build readable text, audio fragments, and sidecars, one missed output-boundary pattern is spoken across the whole episode.

### Audience
- Primary user: listeners praying with the Daily Reflection audio.
- Secondary stakeholders: maintainers of the generated-text and publish-audio pipeline.

### Current Status Quo
- The reflection generator validates structure and several known prompt markers before caching the episode.
- The final fragment expansion and TTS path do not independently assert that Daily Reflection fragments are listener-facing prose.

### Goal
- Ensure prompt, schema, instruction, and model-commentary text cannot reach Daily Reflection TTS input.
- Success criteria: representative prompt echoes fall back deterministically; the contract-to-fragment-to-renderer test captures every TTS input; all relevant and full tests pass.

### Constraints
- Preserve the four-paragraph Daily Reflection contract, theology, pauses, fallback behavior, and unrelated audio families.
- Keep the change narrowly scoped to Daily Reflection generation and its audio handoff.

### Narrow Wedge
- Strengthen the reflection output boundary with explicit prompt-field detection and add an end-to-end regression through audio fragment expansion and TTS rendering.

### Non-Goals
- Reworking the shared TTS provider layer, other devotional generators, or existing generated audio files.

### Risks And Unknowns
- A finite detector cannot prove arbitrary model prose is safe; structural validation and deterministic fallback remain the defense for unknown leakage.
- Existing production artifacts require the normal publish workflow to be regenerated after release.

### Recommended Next Step
- Complete repository research, lock the implementation plan, then implement and verify the generator-to-TTS path.

## Research

## Plan

### Summary

- Make Daily Reflection output validation reject the full family of prompt-field echoes that can survive the current blacklist.
- Validate the already-expanded Daily Reflection fragments at the contract/audio boundary before any TTS provider or cache lookup receives them.
- Add focused unit and integration regressions, then run targeted and full repository verification.

### Root Cause

- `_reject_prompt_leakage()` checks selected phrases but omits prompt scaffolding such as `Rules:`, `Date:`, `Episode title:`, and several labeled context fields.
- `expand_audio_fragments()` trusts any cached/runtime episode object and forwards its paragraphs to `_fragment_payload()`; the renderer sanitizes print labels but does not detect prompt leakage.

### Concrete Changes

- Extend the Daily Reflection detector with case-insensitive line/field patterns for instruction headings, schema/commentary language, and serialized context labels while retaining valid prose safeguards.
- Add a reflection-specific fragment-boundary validation call in `jobs/publish/contracts.py` so invalid runtime/cached episode payloads fail before fragment creation/TTS.
- Add regression tests for omitted prompt fields and a full contract-to-TTS test that captures renderer inputs and asserts no prompt markers are spoken.
- Update this artifact’s progress and QA sections with fresh test evidence.

### Implementation Phases

#### Phase 1: Harden the generated-text boundary

- Modify `jobs/publish/ignatian_reflection.py` and its tests.
- Verify representative leaked model responses fall back to deterministic listener-facing prose.

#### Phase 2: Guard the audio handoff

- Modify `jobs/publish/contracts.py` and integration tests.
- Verify a leaked runtime episode is rejected before the renderer is called.

#### Phase 3: Full verification and review

- Run focused reflection, contract, and audio pipeline tests, then the complete test suite.
- Review the diff for trust-boundary, cache, and regression issues.

### Failure Modes

- A new prompt echo not covered by the detector is still constrained by structural validation and the final fragment-boundary guard.
- A false-positive marker would cause safe deterministic fallback; tests must preserve normal fallback and valid generated prose behavior.
- Cached audio may remain stale until the normal publish job reruns; no generated artifact is edited in this source patch.
