# Release 0.3.4.4 - All Podcast Loudness Normalization

## Scope

### Problem
- Final loudness normalization was configured manually for only part of the generated audio surface.
- Rosary, both Marian Antiphon contracts, and novena episodes could publish at different perceived volumes even though they share the same podcast feed.
- This matters now because the feed is becoming a multi-show prayer surface where users hear episodes back-to-back.

### Audience
- Primary user: the podcast listener using Ora Pro Nobis daily prayer audio.
- Secondary stakeholders: maintainers reviewing publish contracts and future voice/provider changes.

### Current Status Quo
- The publish pipeline can normalize final assembled MP3 episodes through ffmpeg `loudnorm`.
- The behavior is opt-in per contract through `audio_config.loudness_normalization`.
- Only two of five publish-audio contracts currently opt in.

- Enable the same final-episode loudness target by default across publish-audio podcast contracts and novena audio.
- Preserve all existing voices, providers, text generation, and episode structure.
- Allow contracts to override or disable loudness normalization when needed.
- Add regression coverage so new audio jobs are expected to carry loudness normalization unless explicitly disabled.

### Constraints
- Do not change TTS voices.
- Do not normalize individual cached fragments; normalize only the final assembled episode output.
- Keep the loudness target aligned with the existing podcast setting: `I=-16`, `TP=-1.5`, `LRA=11`.
- Keep the change scoped to audio configuration defaults, novena final rendering, tests, and release documentation.

### Narrow Wedge
- Centralize `loudness_normalization` as a default value for publish-audio and novena contracts.
- Add tests that every active publish-audio job has normalization enabled and uses the standard target by default.
- Add novena tests proving the default is applied and contract overrides are honored.

### Non-Goals
- No ElevenLabs voice changes.
- No RSS, Spotify playlist, Notion, or archive behavior changes.

### Risks And Unknowns
- Existing cached final MP3s with old content hashes may be skipped unless hashes change; adding the setting to the contract should update the manifest hash.
- ffmpeg loudnorm can slightly change output duration/size, but this already applies to Auxilium and Morning Prayer.
- Future non-contract audio paths may still need to opt into the shared standard separately.

### Recommended Next Step
- Research the publish-audio contract loader, hash behavior, and existing loudness tests before locking the implementation plan.

- Apply final-episode loudness normalization to all active publish-audio podcast contracts and document the astack workflow in this release artifact.

### Relevant Files

- `tests/test_publish_contracts.py`: already asserts Auxilium and Morning Prayer loudness settings.
- `tests/test_publish_audio_pipeline.py`: already proves configured final episodes are normalized and sidecars record settings.
- `README.md`: publish audio documentation should mention the all-contract standard.

### Current System Map
- Contract JSON defines per-entry `audio_config`.
- `jobs.publish.contracts.build_audio_jobs` turns enabled entries into renderable jobs and computes `content_hash` from normalized audio settings.
- `jobs.publish.audio.render_audio_job` renders or reuses fragments, assembles the final MP3, then runs `normalize_episode_loudness` before writing the episode file.
- Sidecars record `loudness_normalization`, so published artifacts expose whether final normalization ran.

### Reuse Opportunities
- Reuse the exact canonical block already present in Auxilium and Morning Prayer.
- Extend existing contract tests rather than adding new test infrastructure.
- Reuse current content-hash behavior to force re-rendering once the missing contracts gain the loudness setting.

### External References
- No new external references are needed; the repo already uses ffmpeg loudnorm through `imageio_ffmpeg`.

### Constraints
- JSON files must remain deterministic and readable.
- The standard target should stay identical across all podcast contracts.
- Tests should avoid live API calls and use existing offline stubs.

### Risks
- A future contract could omit the setting unless tests assert coverage over loaded jobs.
- If a contract disables audio, the test should not require normalization for that disabled entry.

### Assumptions To Validate
- All active publish-audio podcast contracts are in `config/publish/contracts/*.json`.
- Every active audio entry should use the same `-16 LUFS / -1.5 dBTP / 11 LRA` target.

### Unknowns
- Whether novena audio should eventually share this standard; it is outside this specific contract set.

### Recommended Direction
- Add default normalization in the publish-audio and novena contract loaders.
- Apply final normalization in the novena renderer.
- Add regressions that assert defaults and contract overrides.
- Update README publish-audio docs and the release artifact progress.

## Plan

### Summary
- Standardize final loudness normalization across publish-audio and novena audio.
- The chosen approach is default contract normalization with per-contract override support.

### What Already Exists
- Final episode loudness normalization in `jobs/publish/audio.py`.
- Hash inclusion in `jobs/publish/fragments.py`.
- Novena audio already uses shared fragment rendering and assembly helpers.

### Architecture
- Data flow:

```text
contract audio_config or default audio settings
  -> build_audio_jobs content_hash
  -> render fragments
  -> assemble final MP3
  -> ffmpeg loudnorm
  -> MP3 + sidecar + RSS
```

### Concrete Changes
- Edit `jobs/publish/contracts.py` to provide default `loudness_normalization` and contract override handling.
- Edit `jobs/novena_contracts/contracts.py` to provide default `loudness_normalization` and contract override handling.
- Edit `jobs/novena_contracts/audio.py` to normalize final novena MP3 output.
- Edit `tests/test_publish_contracts.py` to enforce the standard target for all active publish-audio jobs and override behavior.
- Edit `tests/test_novena_artifacts.py` to verify novena defaults, rendering, and override behavior.
- Edit `README.md` to document the default-plus-override model.
- Update this release artifact `Progress` section during implementation.

### UX And States
- No UI changes.
- Listener-facing success state: podcast episodes have a more consistent perceived volume across Morning Prayer, Auxilium, Rosary, Angelus, and Regina Caeli.
- Failure state: if ffmpeg loudnorm fails, the publish job fails visibly before writing the final episode output.

### Failure Modes
- Missing config in a contract: defaults apply.
- Bad loudness values: test fails on target mismatch.
- ffmpeg failure: publish audio fails and logs the ffmpeg stderr.
- Stale final MP3 reuse: content hash includes loudness settings, so changed contracts should force regeneration.
