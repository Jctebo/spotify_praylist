## Scope

### Problem
- The daily Spotify playlist workflow currently runs three times per day at fixed UTC times.
- The schedule does not express the requested Central Time deadline clearly and creates unnecessary repeated refreshes.

### Audience
- Primary user: the playlist owner who needs the daily queue ready by 2:00 AM Central.
- Secondary stakeholders: GitHub Actions and downstream listeners relying on the refreshed Spotify playlists.

### Current Status Quo
- `.github/workflows/daily.yml` schedules refreshes at 05:00, 13:00, and 21:00 UTC.
- The workflow is gated by `SPOTIFY_REFRESH_SCHEDULE_ENABLED` and uses the existing refresh job unchanged.

### Goal
- Run one automatic playlist refresh each day early enough that it is completed by 2:00 AM America/Chicago.
- Success criteria: the workflow has one scheduled trigger at 07:00 UTC, documentation matches the schedule, and automated tests verify the cron contract.

### Constraints
- GitHub Actions cron is expressed in UTC and does not adjust for daylight saving time.
- The existing Spotify, Notion, queue-resolution, and manual-dispatch behavior must remain unchanged.
- The schedule must retain the existing enablement gate.

### Narrow Wedge
- Replace the three scheduled cron entries with a single `07:00 UTC` entry and update the schedule documentation and contract test.

### Non-Goals
- No changes to playlist contents, refresh runtime, credentials, Notion membership, or manual dispatch inputs.
- No attempt to make the trigger occur at exactly 2:00 AM local time in both CST and CDT; the chosen time guarantees completion by the deadline.

### Risks And Unknowns
- GitHub Actions queue/start latency means the schedule is a start time, not a hard completion SLA.
- The repository variable `JOB_UTC_OFFSET` may affect date selection independently of the workflow trigger and should not be changed without separate validation.

### Recommended Next Step
- Validate the workflow contract and documentation references, then implement the schedule change and run the focused plus full test suites.
