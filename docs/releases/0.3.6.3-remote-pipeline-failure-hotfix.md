# Release 0.3.6.3: Remote Pipeline Failure Hotfix

## Scope

### Problem
- Some manually dispatched GitHub Actions workflows on `main` are failing after the website release.
- `Morning Prayer Page Audio Publish (Remote OneDrive via rclone)` fails before generation because the workflow reads `config/custom_tts/morning-prayer.json`, a legacy file that no longer exists in the repo.
- `Publish Prayer Text` is also failing, but logs show the same failure happened before the website merge and `NOTION_PUBLISH_DATABASE_ID` is blank in GitHub Actions.

### Audience
- Primary user: repo maintainer running remote pipelines after ship.
- Secondary stakeholders: future maintainers who need workflow failures to point at real runtime problems instead of stale repo paths.

### Current Status Quo
- The page-audio Python runtime can synthesize a default Morning Prayer custom-TTS contract when `config/custom_tts/` is absent.
- The remote workflow bypasses that runtime fallback by parsing the missing JSON file inline in shell.
- The text-publish workflow falls back to searching the `Opus Dei` Notion database when `NOTION_PUBLISH_DATABASE_ID` is unset, then fails with a Notion query 400.

### Goal
- Make the remote Morning Prayer page-audio workflow stop failing on the missing legacy config file.
- Add coverage so workflow validation catches direct references to the removed config path.
- Preserve the Notion publish-text failure as a documented external configuration issue until the correct database secret/schema is available.

### Constraints
- Keep the fix small and workflow-local unless root cause proves broader.
- Do not recreate removed legacy contract files unless the active runtime genuinely needs them.
- Do not change live Notion database shape or secrets from code.
- Keep generated website behavior unchanged.

### Narrow Wedge
- Replace inline workflow parsing of `config/custom_tts/morning-prayer.json` with a small Python helper that asks the existing page-audio runtime for the active contract output path.
- Add a unit test that validates the remote workflow no longer hard-codes the removed path.

### Non-Goals
- Fixing `Publish Prayer Text` Notion 400 without the correct `NOTION_PUBLISH_DATABASE_ID` value or schema access.
- Refactoring the page-audio runtime.
- Changing website generation or GitHub Pages output.

### Risks And Unknowns
- The page-audio workflow may reveal a later remote dependency failure after the missing-file failure is fixed.
- `Publish Prayer Text` likely requires a repository secret/configuration update or a Notion schema correction outside this code change.

### Recommended Next Step
- Implement the workflow helper and regression test, rerun focused tests, ship the hotfix, then remotely rerun the failing workflow.

## Research

- Remote run `27481611510` failed in `Validate rclone remote` with `FileNotFoundError: config/custom_tts/morning-prayer.json`.
- `jobs/notion/generate_page_audio.py` defines `default_morning_prayer_custom_tts_contract()` and falls back to it when `config/custom_tts/` is missing.
- Remote run `27481654218` failed in `Publish Prayer Text` with `NOTION_PUBLISH_DATABASE_ID:` blank and a Notion 400 against database `2d819eee-5051-8096-8cca-defcf97dd093`.
- Earlier pre-merge run `27480337993` shows the same blank `NOTION_PUBLISH_DATABASE_ID` and Notion 400, so that failure is not caused by the website release.

## Plan

### Summary
- Add a runtime helper in the remote workflow to resolve the active Morning Prayer output path through `jobs.notion.generate_page_audio` instead of reading a removed JSON file.
- Cover the workflow contract with a regression test.

### What Already Exists
- `load_morning_prayer_contract_from_file()` already returns the active normalized Morning Prayer page-audio contract.
- `default_morning_prayer_custom_tts_contract()` already owns the fallback output path.
- Existing workflow tests validate GitHub Actions wiring for publish and website jobs.

### Architecture

```text
GitHub Actions workflow
  -> python helper imports jobs.notion.generate_page_audio
  -> load_morning_prayer_contract_from_file()
  -> output_path
  -> rclone remote root/folder
```

- Rclone secret or remote path issue: workflow reaches rclone validation and fails there.
