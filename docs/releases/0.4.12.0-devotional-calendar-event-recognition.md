# Release 0.4.12.0 - devotional-calendar-event-recognition

- Status: shipped
- Created: 2026-10-01
- Source: failed Daily Devotional Wallpapers run 36831865834.

## Scope

### Problem
- The Oct. 1 daily wallpaper run failed during calendar resolution, before generating images, with `Unclassified devotional calendar event on 2026-10-10`.
- Unknown calendar entries previously stopped resolution for the entire date window.

### Audience
- The operator relying on daily phone and watch devotional wallpapers.

### Current Status Quo
- `resolve_calendar` failed the full resolution when it encountered a non-context event whose classification could not be determined.
- Generic weekday/week/season events continue to be ignored under the existing context rules.

### Goal
- Keep the wallpaper job running when it encounters an unclassified calendar event by skipping only that entry.
- Success means other valid entries on the same date still resolve and generate, and skipped entry summaries are recorded in the run artifact.

### Constraints
- Preserve explicit event classification and `[DEVOTIONAL-IMAGE]` validation.
- Do not fabricate a devotional subject; preserve every other valid entry on the affected date.
- Preserve existing recurrence, date-window, named-observance, and monthly-fallback behavior.

### Narrow Wedge
- Treat the existing unclassified-event detection as an entry-level exclusion signal; do not infer a title or classification.
- Record each skipped event's date and summary in `CalendarResolution` and run artifacts; keep absent dates distinct.

### Non-Goals
- Image rendering/provider changes, storage rotation, unrelated calendar expansion, and broad changes to observance rank policy.

### Risks And Unknowns
- The failed run summary artifact is not downloadable, and the private feed URL is not stored in the repository. The operator clarified that only the unclassified entry should be ignored, not other entries from the same date.

### Recommended Next Step
- Skip only unclassified entries, report their summaries, and cover mixed valid/unclassified event sets in resolver tests.

## Research

- GitHub Actions run 36831865834 failed during calendar resolution with `Unclassified devotional calendar event on 2026-10-10`, before image generation.
- The public repository calendar snapshot shows standard weekday context on Oct. 10; the wallpaper resolver already ignores titles beginning with a weekday, so that snapshot alone does not identify the failing event.
- `resolve_calendar` currently raises on an unclassified non-context event, aborting the whole ten-day window. Resolution and `--resolve-only` report construction are localized in `jobs/novena/devotional_calendar.py` and `jobs/novena/generate_devotional_wallpapers.py`.
- User direction: skip only unclassified entries; valid entries on the same date, including a Blessed Virgin Mary entry, should remain eligible for images.
- User additionally requested useful artifacts on every run. The workflow already uploads its artifact directory with `if: always()`, but standard generation previously wrote local diagnostics only after successful completion.

## Plan

### Summary
- Skip only each unclassified event while continuing to resolve other events on the same date and other dates in the window.

### What Already Exists
- `resolve_calendar` deduplicates and orders valid date subjects, and `CalendarResolution` reports absent dates.
- `generate_devotional_wallpapers.py` writes a private `resolve-report.json` only in local resolve-only mode; standard generation has no artifact until the end.
- `DailyImageSpec` and downstream inventory generation process each resolved subject independently.

### Architecture

```text
ICS occurrences -> classify each event -> unclassified event?
                                      yes -> record and skip that entry
                                      no  -> keep the resolved subject/context
All remaining entries by date -> existing deduplication/fallback -> generate
```

No UI changes; skipped entries appear in the uploaded private run artifact.

### Concrete Changes
- In `jobs/novena/devotional_calendar.py`, represent unclassified events distinctly from malformed metadata; record and skip only those events.
- Add skipped unclassified event details to `CalendarResolution` while keeping `missing_dates` semantics for dates absent from the feed.
- In `jobs/novena/generate_devotional_wallpapers.py`, write a resolution artifact before generation with skipped event summaries, and update it with terminal status/errors.
- In `tests/test_devotional_calendar.py`, cover unclassified-only dates, mixed recognized/unclassified events on one date, and valid neighboring dates.
- In `tests/test_devotional_wallpaper_pipeline.py`, assert uploaded artifact availability/content and that recognized same-date entries remain generation targets.

- Catching every `RuntimeError` would hide malformed metadata or broken ICS; only the dedicated unclassified-event condition should mark a date skipped.
- A broad catch could drop a valid subject or hide malformed metadata; only unclassified-title errors should be recorded and skipped.
