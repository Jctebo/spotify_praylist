## Scope

### Problem
- Daily wallpaper selection currently collapses a date to one event and one phone/watch pair. That drops additional saints/devotions in the same day and allows imagegen to place a face behind the locally overlaid title.
- The scheduled runner also skips the calendar request whenever its one-pair-per-date inventory appears full, so later calendar corrections and additional observances are invisible.

### Audience
- The operator using the four OneDrive current/queue folders for daily phone and watch backgrounds.

### Current Status Quo
- Outlook ICS Sept. 28 lists Saint Wenceslaus as the event title and Saint Lawrence Ruiz and Companions as an additional optional memorial in the same `Church observance` description. The resolver returns Wenceslaus only.
- Calendar resolution chooses a single ranked winner per date. Inventory keys only by date and device, while rotation requires exactly one image of each device per date.
- The complete-window fast path returned 20 existing slots without fetching the calendar, so it could not discover the missing Ruiz artwork.
- The phone renderer overlays text in the top band. Existing vision QA checks general composition but does not require faces to stay out of that text band; the supplied Wenceslaus image shows the resulting overlap.

### Goal
- Resolve every distinct saint, feast, named devotion, and private devotion explicitly represented by calendar event titles or the calendar's structured `Church observance` field for each of the next ten dates.
- Drop only generic weekday/week/season context titles when they contain no named observance. Use the month devotion only when a represented date has context but no named observance; skip dates absent from the calendar.
- Store one independently composed phone and watch image per resolved subject. Preserve all subjects in each dated queue and promote the complete same-date set into current folders.
- Read the calendar every daily run, even when existing images appear complete. Match assets by date, subject, and device; preserve accepted files and generate only absent subject/device assets.
- Keep faces and important iconography outside the phone title/subtitle region. Reject and retry art whose face overlaps the text; never publish a failed QA candidate.
- Success: every resolved subject has verified phone/watch assets; only generic context is omitted; a full existing inventory still detects feed changes/additional subjects; rotation promotes the complete date set; repeat runs are idempotent; phone/watch labels do not cover faces.

### Constraints
- Preserve the existing infographic, audio, site publication, and local rotation workflows. Reuse the existing public ICS secret, OpenAI credentials, rclone connection, four OneDrive folders, and private archive/manifests.
- Keep ISO date and readable subject slug in filenames. Multiple subjects for a date are expected; same subject/date/device ambiguity must still fail closed.
- Respect the current non-overwrite contract. Existing managed files remain unchanged except for the operator-approved Sept. 28 Wenceslaus correction, which must be archived and checksum-verified before replacement.
- Calendar titles/descriptions are untrusted input. Parse only the dedicated Church observance text and explicit subject/classification patterns; never infer subjects from prayer-focus prose, commands, or arbitrary description mentions.
- Keep the ten-day Chicago-local window, device sizes, exact locally rendered labels, and current/queue folder contract.

### Narrow Wedge
- Expand calendar resolution and asset identity to all daily subjects; reconcile the complete current/queue set safely; enforce and retry text/face separation in vision QA; repair today's two named observances.

### Non-Goals
- Changes to infographic generation/web publication, Outlook calendar content, local phone/watch rotation, device UI overlays, or unrelated image aesthetics.

### Risks And Unknowns
- Multiple images per day change the current-folder set contract. Rotation and crash recovery must journal and verify every member of both device sets before deleting managed prior-current files.
- Description parsing must capture the explicitly labeled Saint Lawrence Ruiz entry without turning prayer-focus prose into image subjects.
- The safe title band requires model compliance; vision QA must reject overlaps and bounded retries must fail visibly if acceptable art cannot be produced.

### Recommended Next Step
- Plan subject extraction, per-subject inventory/delivery, set-based rotation/recovery, image-quality retry, and OneDrive repair as one coherent release.

## Research

### Root Cause Evidence
- The live calendar feed lists `[m] Saint Wenceslaus, Martyr, Optional Memorial` on 2026-09-28. Its `Church observance` description explicitly adds `St. Lawrence Ruiz and Companions, Martyrs (optional)`.
- `jobs/novena/devotional_calendar.py::resolve_calendar` sorts candidates and stores only `candidates[0]` in `specs[date]`; it does not parse additional structured observances in DESCRIPTION.
- `jobs/novena/generate_devotional_wallpapers.py::run_pipeline` inventories solely by date/device and exits before fetching ICS when all twenty slots exist.
- `sync/devotional_onedrive.py::inventory_assets` rejects multiple files for one date/device and `rotate_current` requires exactly one phone and one watch file. Its journal, manifest, archive, and recovery paths all model singular files.
- `jobs/novena/devotional_image_contract.py::build_art_prompt` says to leave phone title space at the top but does not explicitly prohibit a face/silhouette in the overlaid band. `vision_qa` asks for generally suitable composition but does not explicitly reject a face beneath text. The supplied Sept. 28 phone render reproduces this defect.

### Relevant Existing Contracts
- `DailyImageSpec`, filename `subject-slug__YYYY-MM-DD.jpg`, Chicago date arithmetic, two phone/watch variants, monthly fallbacks, read-before-write delivery, SHA-256 verification, remote rotation journal, and local OCR/vision QA.
- Existing suite uses Python `unittest`, an in-memory OneDrive store, calendar fixtures, and mocked image provider responses.

### Decisions
- One resolved subject becomes one phone+watch pair. For a date with named events, retain all distinct subjects from event summaries and explicit additional observances in the dedicated `Church observance:` description field. Deduplicate repeated title/subject strings. Ignore prayer-focus prose. Only generic context titles with no named subject are dropped.
- Monthly fallback is one additional date subject only when the date is represented by generic liturgical context and has no named observance. Unrepresented dates stay absent.
- Reconcile the calendar and full asset set every run; per-subject existing phone/watch images suppress only their own slots.
- Current folders contain all managed assets for today's date. Rotation verifies equal subject sets across phone/watch, journals all copies, archives the complete previous set, and cleans up only files listed in managed state. Unknown files remain protected.
- Before delivering corrected Wenceslaus artwork, archive and verify the current/queue originals. Generate and verify Wenceslaus replacements plus Saint Lawrence Ruiz phone/watch images from the live ICS resolution, then rotate/reconcile Sept. 28's full set.

## Plan

### Summary
- Expand the additive wallpaper system from one winning subject per date to a complete set of explicitly named daily observances, while preserving its existing calendar, output folders, and no-overwrite safety.

### What Already Exists
- ICS parser/fetcher, `DailyImageSpec`, date-stamped slug filenames, rclone inventory/delivery, SHA-256 validation, journaled rotation/recovery, OCR validation, vision QA, and OneDrive live credentials.

### Architecture
```text
Outlook ICS (each daily run)
       -> all named subjects by date (ignore generic week/season only)
       -> expected keys: (date, subject slug, phone|watch)
       -> compare with current + queue + verified staging
       -> render absent keys; retry face/text overlap QA
       -> upload immutable, checksum-verified queue set
       -> journal + promote complete same-date phone/watch sets
       -> archive prior managed sets; preserve unknown files
```

### Concrete Changes

- `jobs/novena/devotional_wallpaper_render.py`: strengthen phone composition prompts, require vision QA to reject faces under title/subtitle, and run bounded new-art retries for that rejection without uploading failures.
- `tests/test_devotional_calendar.py`, `tests/test_devotional_wallpaper_contract.py`, `tests/test_devotional_onedrive.py`, `tests/test_devotional_rotation.py`, `tests/test_devotional_wallpaper_pipeline.py`, `tests/test_devotional_wallpaper_render.py`: regression coverage for every listed subject, structured additional observance extraction, generic-only omission, multi-subject idempotency, same-set rotation/recovery, calendar refresh on complete inventory, face/text QA and retries.

### Failure Modes
- Unsupported description text is ignored and surfaced in diagnostics instead of treated as a subject; calendar fetch/parse failure never means empty calendar.
- Same-subject duplicate paths, incomplete phone/watch subject sets, checksum mismatch, journal fault, or unmanaged current files stop promotion and retain the previous committed set.
- Face/text overlap fails vision QA; bounded attempts exhaust with an explicit missing-asset failure, and rejected pixels stay private.
