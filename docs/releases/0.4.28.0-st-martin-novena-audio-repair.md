# Release 0.4.28.0: St. Martin de Porres Novena Audio Repair

## Scope

### Problem
- The live Day 1 and Day 2 episodes both cut off the shared opening prayer after “your burning charity,” then continue with the day's meditation.
- The contract places a bell and five-second intention pause after the complete opening prayer, so the cutoff makes the bell arrive early and removes the rest of that petition.
- The same opening prayer is reused across all nine days; the available evidence points to a bad synthesized fragment being reused, though published fragment metadata is unavailable to confirm its provenance.

### Audience
- Primary user: listeners praying the active St. Martin de Porres novena.
- Secondary stakeholders: maintainers of the novena audio publisher and podcast feed.

### Current Status Quo
- The source contract contains the complete 441-character opening prayer and orders it before the bell and intention pause.
- The live Day 1 and Day 2 audio both stop that prayer at the same short prefix.
- Novena speech fragments are content-hash cached. The novena renderer honors episode force-rebuild for the episode file but currently disables force-rebuild when rendering cached speech fragments.
- The workflow's `bootstrap-no-cache` mode targets today and tomorrow; the pipeline has no exact-date repair mode, so it cannot directly rebuild Day 1 and Day 2 together without affecting unrelated publishing.

### Goal
- Publish repaired audio for the already-live Day 1 and Day 2 episodes, with the complete opening prayer, bell, five-second intention pause, and remaining prayer in the contract's intended order.
- Regenerate the affected shared speech fragment and the selected episode files while preserving all unrelated podcast feed entries and audio assets.
- Verify both live enclosure URLs after publication and confirm that the opening prayer is complete before the bell.

### Constraints
- Keep the correction specific to selected St. Martin episode dates; do not reset or rebuild the complete RSS feed or daily prayer audio.
- Preserve the novena's prayer wording, order, voice, and five-second pause.
- Publish episodes idempotently using the existing feed merge and R2 sync behavior.
- Telemetry release `0.4.27.0` has merged; this repair follows as `0.4.28.0`.

### Narrow Wedge
- Add a per-part cache revision to the shared St. Martin opening prayer so its TTS fragment hash changes and only that speech fragment is synthesized again.
- Add a manual, exact-date novena repair path that rebuilds selected episode files from the refreshed shared fragment and merges them into the existing feed without reset or unrelated daily audio publishing.
- Use it for the live St. Martin Day 1 and Day 2 dates, then verify the downloaded audio and feed entries.

### Non-Goals
- Rewrite or normalize all St. Martin prayer text or bulk-update other novena contracts.
- Change the bell sound, pause duration, voice, audio branding, or ordinary daily publishing schedule.
- Reset the feed, regenerate unrelated daily prayer episodes, or repair historical novenas beyond the two affected live episodes.

### Risks And Unknowns
- Public episode JSON sidecars are accessible at `https://audio.orapronobis.media/<episode-id>.json`; they record the complete 441-character source fragment and `audio.rendered=true`, but do not include TTS fragment hashes or speech-fragment render status.
- Forcing all speech fragments in two selected episodes could add synthesis cost; the implementation should scope force-rendering as narrowly as the existing renderer allows.
- The repair must update existing episode URLs/feed items without leaving a stale audio file in the R2 archive or an incorrect RSS GUID.

### Recommended Next Step
- Use the findings below to plan a part-level cache revision and exact-date repair mode; no further scope clarification is needed.

- The live feed identifies Day 1 as October 25, 2026 and Day 2 as October 26, 2026. Their audio is available at [Day 1](https://audio.orapronobis.media/2026-10-25-st_martin_de_porres-day-1.mp3) and [Day 2](https://audio.orapronobis.media/2026-10-26-st_martin_de_porres-day-2.mp3).

- `jobs/novena_contracts/engine.py` — converts the selected day's structured blocks into ordered speech, cue, and pause fragments.
- `jobs/publish/fragments.py` — computes shared speech-fragment cache hashes and honors `force_rebuild` when rendering cached TTS.

### Current System Map
- The St. Martin contract's `blocks` contain the complete 441-character opening prayer, followed by `sacred_bell`, a 5000 ms personal-intention pause, then the day's meditation. The parallel legacy `sections` omit cues; audio rendering uses `blocks`.
- The opening text repeats exactly in each day's block. `fragment_content_hash` hashes sanitized text, audio role, and TTS settings, but not the episode-specific fragment key, so identical opening speech shares one cache file.
- `render_novena_audio_job` reads `PUBLISH_AUDIO_FORCE_REBUILD` to decide whether to reuse the assembled episode, but passes `force_rebuild=False` for ordinary speech fragments. Therefore the existing `bootstrap-no-cache` flag can rebuild an episode while retaining a truncated cached opening fragment.
- `run_novena_pipeline` can render an explicit date sequence and merges current jobs with the existing feed by default. The workflow entry point currently selects only today/tomorrow, today, tomorrow, or reset dates.
- The workflow runs the general daily-audio publisher before the novena publisher. Its global force-rebuild flag also affects general audio, so a targeted repair needs to avoid rebuilding that unrelated pipeline.
- R2 sync uses size plus SHA-256 manifest comparison; changed MP3 and sidecar files at the existing episode paths are eligible for upload.

### Reuse Opportunities
- Reuse the existing content-addressed fragment cache by adding an optional part-level cache revision to the fragment hash; the changed hash naturally requests fresh TTS only for the St. Martin opening prayer.
- The revision changes the episode manifest hash and RSS GUID, causing selected episodes to be reassembled while other speech fragments remain cached.
- Reuse `run_novena_pipeline(publish_dates=...)` and its non-reset RSS merge rather than implementing another publisher.
- Reuse the workflow's cache restore/render/R2-sync sequence, with a manual repair mode that skips unrelated daily audio generation.
- Reuse the existing test fakes for renderers, podcast feed loading, sidecar freshness, and R2 delta uploads.

### External References
- No new external API or library is required. The existing audio and RSS publisher interfaces are sufficient.
- Live evidence: transcriptions of both published episodes end the opening invocation at the same short phrase before moving directly to the day heading. Their public JSON sidecars confirm the full source fragment is present and the episode was rendered, but omit the per-fragment cache identity needed to prove whether TTS generation or cache reuse truncated the audio.

- The same cached opening fragment is shared with future days, so successful refresh must populate the revisioned shared cache with complete audio for subsequent novena days.
- The repair path must skip unrelated daily prayer publishing and must not force regeneration of other novena fragments.
- Telemetry PR #149 has merged as `0.4.27.0`; this repair follows as `0.4.28.0`.

- A part-level cache revision must pass through contract loading and audio-fragment assembly and participate in both fragment and episode hashes; otherwise old speech or RSS identity could survive the repair.
- Feed merge and R2 overwrite behavior must both be verified so podcast clients receive updated bytes at the existing URLs and no unrelated items disappear.

## Plan

### Summary
- Add an optional per-part `cache_revision` to TTS fragment identity and set it to `1` on the shared St. Martin opening prayer in all nine day blocks. This creates a fresh cache entry for that prayer while leaving other novena speech cache keys unchanged.
- Add a manual targeted novena repair mode that accepts a contract ID and explicit dates, skips the general daily publisher, rebuilds only the selected episode files, and merges their updated RSS items without resetting the feed.
- Use the content hash change to revise each rebuilt episode's RSS GUID; use the existing R2 SHA-256 delta sync to replace the same public audio keys.

### What Already Exists
- `engine.py` copies template part dictionaries into audio fragments; `fragments.py` content-addresses speech from sanitized text, audio role, and TTS settings.
- `audio_manifest_hash` includes every fragment hash, and `compose_rss_guid` includes the episode content hash.
- `run_novena_pipeline` already accepts `publish_dates`, merges the feed unless `reset_feed=True`, and can reuse sidecar content for dates outside the requested set.
- The workflow restores the fragment and audio archives, runs the novena publisher, syncs changed audio to R2, and deploys the refreshed podcast feed through GitHub Pages.

### Architecture

```text
St. Martin block part + cache_revision=1
                 |
                 v
engine emits cache_revision on speech fragment
                 |
                 v
fragment hash changes -> synthesize shared opening prayer once
                 |
                 +--> episode manifest hash and RSS GUID change
                 |
exact-date repair mode filters contract + episode dates
                 |
                 v
reassemble selected episodes -> merge RSS without reset
                 |
                 v
R2 SHA-256 sync replaces selected MP3s -> Pages deploys feed
```

The episode-level rebuild switch bypasses existing assembled MP3s, including when their sidecars are missing, without forcing cached speech fragments. Existing episode sidecars predate the contract revision, so the targeted pipeline overlays the current part revision onto the matching stored fragment after verifying its block path and text; it preserves the stored intro and all other fragments. The changed fragment hash then triggers only the opening prayer's TTS cache miss. The existing global no-cache mode continues to force all fragments when explicitly selected.

### Concrete Changes
- `contracts/novenas/feast-days/st_martin_de_porres.json`: add `cache_revision: 1` to the first text part of each of the nine structured day blocks. Keep prayer text, cue, pause, and legacy `sections` text unchanged.
- `jobs/novena_contracts/validators.py`: validate optional `cache_revision` as a positive integer on text or fragment parts; reject booleans, strings, and nonpositive values.
- `jobs/novena_contracts/engine.py`, `_block_parts_to_fragments`: carry an explicitly provided part revision into the emitted speech fragment.
- `jobs/publish/fragments.py`, `fragment_content_hash`: include `cache_revision` only when present. Preserve every existing fragment hash when the field is absent.
- `jobs/novena_contracts/audio.py`, `render_novena_audio_job`: add an episode-only rebuild option that bypasses episode and missing-sidecar reuse checks while retaining normal speech-fragment cache reuse. Keep `PUBLISH_AUDIO_FORCE_REBUILD` as the all-fragment override and pass it through for ordinary speech fragments.
- `jobs/novena_contracts/pipeline.py`, `jobs/novena_contracts/rss_publisher.py`, `run_novena_pipeline` and `main`: add optional contract filtering, episode-only rebuild, and `_apply_contract_fragment_revisions` for selected sidecars. Match each revisioned part by normalized block path and exact source text; fail closed if the target part is absent or divergent. Parse `NOVENA_REPAIR_CONTRACT_ID` and comma-separated `NOVENA_REPAIR_DATES` for `targeted-novena-repair`; validate ISO dates, reject duplicates, require the contract to be active exactly once on each requested date, sort dates, and keep `reset_feed=False`. Update selected sidecar metadata and replace only matching existing RSS episode entries so their new content hashes produce current GUIDs while unrelated items remain.
- `.github/workflows/publish_audio.yml` and `README.md`: add a manual `targeted-novena-repair` mode plus contract ID/date inputs; pass them to the novena publisher; skip the general daily-audio publish step only in this mode. Keep R2 sync and the normal main-branch Pages deployment in the run, and document the operator inputs.
- Tests: extend `tests/test_novena_contracts.py`, `tests/test_novena_engine.py`, `tests/test_publish_audio_fragments.py`, `tests/test_novena_artifacts.py`, `tests/test_novena_pipeline.py`, `tests/test_publish_audio_pipeline.py`, and the existing R2 sync tests for revision validation/hash compatibility, one-time shared TTS regeneration, episode-only rebuilds, exact-date filtering, feed/GUID preservation, workflow isolation, and changed-object upload.

### UX And States
- This is an operator workflow, with no listener-facing UI change.
- In GitHub Actions workflow dispatch, the operator chooses `targeted-novena-repair`, enters `st_martin_de_porres` and `2026-10-25,2026-10-26`, then reviews the run summary for those two episode IDs.
- Invalid dates, duplicate dates, an unknown contract, or a date without exactly one active matching novena fail before feed publication.
- A successful run emits both refreshed audio files and updates the feed entries while retaining unrelated items. Provider or R2 failures fail the workflow and surface in its logs.

### Failure Modes
- Cache revision is dropped during template parsing or fragment conversion: hash regression tests fail before rollout; targeted sidecar reconciliation also verifies the exact block path and text and aborts on mismatch.
- Requested date is invalid or does not resolve to the chosen contract: abort before audio or feed changes.
- TTS generation, episode assembly, or workflow job fails: stop before RSS build/R2 sync where possible; surface the failing episode and provider error.
- RSS merge loses unrelated items: pipeline regression test compares preserved episode IDs before and after the two-item update.
- R2 does not replace a same-size MP3: existing SHA-256 delta test must prove content-hash mismatch still triggers upload.
- Legacy `sections` still omit control cues: this is a pre-existing representation mismatch; audio continues to use `blocks`, and this repair does not alter spoken text in either representation.
