# Release 0.3.10.1 — Exclude Year-Long Novenas

## Scope

### Problem
- The importer accepted a page titled as a year-long St. Bridget devotion and produced a normal nine-day publishing contract.
- That contract should not be available for audio/RSS publication, and future year-long devotions must not enter the contract set.

### Audience
- Primary user: Ora Pro Nobis listeners seeking normal, finite novenas.
- Secondary stakeholder: the repository maintainer running bulk novena imports.

### Current Status Quo
- The One Year St. Bridget of Sweden contract is enabled in `contracts/novenas/feast-days`.
- The URL importer extracts any numbered day headings without a maximum duration policy.

### Goal
- Remove the One Year St. Bridget contract.
- Refuse imports whose extracted prayer days span 364 days or longer.
- Prove the importer rejects the source before it writes a contract.

### Constraints
- Preserve supported shorter novenas and their existing output format.
- Make the policy deterministic and independent of a page's title.

### Narrow Wedge
- Delete the specific St. Bridget contract and enforce a 363-day maximum on imported distinct day headings.

### Non-Goals
- Removing historical published RSS/audio artifacts.
- Redesigning the novena contract schema or changing manual contract authoring.

### Risks And Unknowns
- A source page could label a long devotion with non-numeric headings; this release only guards the importer's numbered-day extraction path.

### Recommended Next Step
- Update the importer and its tests, then validate the complete novena test suite.

## Research

### Scope Baseline
- Remove the One Year St. Bridget contract and ensure URL imports reject sources reaching Day 364, the duration of that devotion.

### Relevant Files
- `jobs/novena_contracts/url_import.py`: shared parser and writer for both single and bulk Catholic Novena App imports; now enforces the source-day limit.
- `scripts/new_novena_url_contract.py`: CLI facade for single and bulk imports; delegates directly to `import_single_url` and `import_bulk_catalog`.
- `jobs/novena_contracts/traditional_import.py` and `scripts/run_traditional_novena_import_local.py`: batch import path; delegates to the same bulk importer.
- `jobs/novena_contracts/validators.py`: validates checked-in/manual contract payloads, but currently permits any positive `duration_days`.
- `contracts/novenas/feast-days/`: runtime-loaded contracts; the only St. Bridget year-long contract was removed.
- `tests/test_novena_url_import.py`: source parsing and no-write behavior coverage.

### Current System Map
- All supported URL-import entry points converge on `_extract_prayer_sections` in `url_import.py`.
- The parser discovers headings with ids in the form `day-N`; the new policy runs immediately after parsing and before normalization, contract construction, validation, or filesystem writes.
- The importer builds generated URL contracts with a fixed runtime `duration_days` of nine; the source-heading check therefore detects a long source that would otherwise be silently compacted into a normal contract.
- Existing contract loading and publication consume checked-in JSON contracts through `contracts.py` and `validators.py`, independent of the URL importer.
- One-time audit result: every checked-in contract was scanned for `duration_days >= 364` and inline template day references reaching Day 364; no remaining matches were found after removing the St. Bridget contract.

### Reuse Opportunities
- One shared parser guard covers the direct CLI, catalog bulk CLI, and traditional monthly batch workflow with no duplicated policy.
- Existing failed-import report behavior provides the correct user-visible outcome and nonzero CLI exit status without new report formats.

### External References
- No new external API, library, or standard is required; the source constraint is enforced entirely from parsed Catholic Novena App heading ids.

### Constraints
- A year-long devotion can be identified reliably only when its source uses the existing numeric `day-N` heading convention.
- Existing raw JSON contracts intentionally accept positive durations, so this release's URL-import policy does not prohibit an explicitly authored long contract.

### Risks
- A long source with unnumbered or nonconforming headings will not trigger this source-based guard.
- Broadening the policy into `validators.py` would change the accepted contract schema for all manually authored and future generated contracts, beyond the stated import-only requirement.

### Assumptions To Validate
- The requested exclusion applies to URL imports, not every manually authored long-duration contract. This matches the user’s wording and the current implementation boundary.
- Historical audio/RSS output does not need deletion; the release scope explicitly retains it.

### Unknowns
- None blocking the current scope.

### Recommended Direction
- Keep the implementation as-is: remove the existing St. Bridget contract and retain the shared URL-import guard at Day 364. Do not add a global contract-validator cap unless the policy is intended to ban manually authored long devotions too.

## Plan

### Summary
- Remove the known One Year St. Bridget of Sweden contract and reject any URL-import source reaching Day 364.
- Centralize the policy in the shared URL parser so the direct, bulk, and traditional batch import routes behave identically.

### What Already Exists
- `jobs/novena_contracts/url_import.py` owns parsing, report construction, and both single/bulk import functions.
- `scripts/new_novena_url_contract.py` and `jobs/novena_contracts/traditional_import.py` reuse those functions rather than maintaining independent parsers.
- `tests/test_novena_url_import.py` supplies synthetic source pages and asserts importer reports.

### Architecture

```text
single CLI / bulk CLI / traditional batch
                  -> shared URL parser -> source-day policy -> resolve/build -> validate/write
                                         | reject (Day 364+) -> failed report / no write
```

### Concrete Changes
- Delete `contracts/novenas/feast-days/one_year_st_bridget_of_sweden.json`.
- In `jobs/novena_contracts/url_import.py`, add a named maximum and validate extracted day numbers in `_extract_prayer_sections` before returning sections.
- In `tests/test_novena_url_import.py`, add source-page coverage for a 364-day import rejection and verify no output contract is written.
- Do not change `jobs/novena_contracts/validators.py`: manual contract validation remains intentionally outside the URL-import policy.

### UX And States
- No UI changes.
- A qualifying source is reported as `failed` with a clear policy error and nonzero CLI exit; supported short imports retain their existing behavior.

### Implementation Phases
#### Phase 1: Enforce source duration policy
- Goal: reject whole-year-or-longer source devotions before contract creation.
- Exact files: `jobs/novena_contracts/url_import.py`.
- Change: add a 363-day maximum and raise a descriptive error when parsed numbered days reach 364.
- Verification: targeted single-import test; shared routing covers both CLI and traditional batch callers.
- Rollback: revert the named guard; no data migration is involved.

#### Phase 2: Remove and prove the unwanted path
- Goal: eliminate the current St. Bridget contract and lock in the policy with regression coverage.
- Exact files: `contracts/novenas/feast-days/one_year_st_bridget_of_sweden.json`, `tests/test_novena_url_import.py`.
- Change: delete the contract; add a generated 364-day source test asserting a failed report and absent output.
- Verification: targeted importer tests followed by the novena test suite.
- Rollback: restore the deleted JSON from Git if policy changes.

### Failure Modes
- A source uses 364 numbered headings: import returns a failed report with the maximum-duration error and writes nothing.
- A normal nine-day source: existing parsing and contract construction continue unchanged.
- A manually authored 364-day JSON contract: remains valid by design; this is not a URL-import bypass because it is an out-of-scope authoring path.

### QA And Test Matrix
- 9-day fixed-feast source: succeeds (existing regression).
- 364-day source: fails with a clear duration-policy message and leaves the output directory empty.
- Direct and bulk URL flows: both remain covered by the shared importer functions; no duplicate parser needs separate policy coverage.
- URL importer test module: `python -m unittest tests.test_novena_url_import`.
- Broader contract/import regression: `python -m unittest tests.test_novena_url_import tests.test_novena_contracts tests.test_novena_pipeline`.

### Rollout Notes
- The policy applies to future URL imports, including the CLI and monthly traditional batch runner. Existing published feed/audio artifacts are intentionally retained.

### Not In Scope
- Reconciliation or deletion of historical episodes.
- Rejecting manually authored long-duration JSON contracts.
- Detecting unnumbered year-long devotions.

- None.
