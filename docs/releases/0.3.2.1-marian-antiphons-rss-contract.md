## Scope

### Problem
- Marian Antiphons do not yet have dedicated publish-audio contracts.
- We want two season-tied audio sources: Regina Caeli for Easter Season and Angelus for all other seasons.
- The current publish-audio contract set has no clean way to express those two Marian Antiphon sources as separate feed items.

### Audience
- Primary user: the repo owner maintaining the podcast feed.
- Secondary users: listeners who expect Marian Antiphons to match the church season.

### Current Status Quo
- Publish audio currently ships the existing prayer contracts, but not Marian Antiphons.
- The audio pipeline already knows how to render MP3s, write sidecars, and rebuild RSS from archived audio.
- What is missing is a season-aware Marian Antiphon pair that stays separate from the other prayer families.

### Goal
- Add two new publish-audio contracts for Marian Antiphons.
- One contract should publish Regina Caeli during Easter Season.
- One contract should publish Angelus outside Easter Season.
- Each contract should produce one date-scoped MP3 and RSS episode per day.

### Constraints
- The change should stay inside the existing publish-audio and RSS pipeline.
- Contract validation should remain strict and fail closed on bad shapes.
- The Marian Antiphon outputs should have stable date-scoped episode ids and filenames so reruns overwrite the same day’s feed item instead of duplicating it.
- The rest of the publish-audio catalog should continue to work unchanged.

### Narrow Wedge
- Add exactly two Marian Antiphon publish contracts.
- Tie each contract to the correct church season.
- Use the existing liturgical season helper for the season decision.
- Prepend a short daily intro that announces the day and any feast days, then start with the sign of the cross and the prayer body.
- Keep the change limited to Marian Antiphons only and reuse fragments for repeated portions.

### Non-Goals
- Do not touch Spotify contracts or playlist refresh logic.
- Do not add any new devotional families beyond Marian Antiphons.
- Do not redesign the audio or RSS pipeline.
- Do not add a daily repost loop.

### Risks And Unknowns
- The main risk is choosing a season-gating shape that is harder to maintain than the existing daily-prayer contracts.
- Another risk is choosing a daily intro shape that changes too much across reruns or makes the episode feel inconsistent.
- We need to keep the Marian Antiphon contract naming readable so future maintenance stays simple.

### Recommended Next Step
- Run `/research-astack` to confirm the cleanest publish-audio contract shape for the two Marian Antiphon season sources.

## Research

### Scope Baseline
- Add two Marian Antiphon publish-audio contracts: one Easter-season Regina Caeli source and one ordinary-time Angelus source.
- Keep the rest of the publish-audio pipeline unchanged, but keep the Marian Antiphon item identity date-scoped so reruns overwrite the same day’s feed item.
- The scope is audio/feed only; this is not a Spotify contract change.

### Relevant Files
- `config/publish/contracts/morning-prayer.json`, `config/publish/contracts/rosary.json`: the only checked-in publish-audio contracts today; they show the current `daily-prayer` shape, metadata templating, and fragment tree patterns.
- `jobs/publish/contracts.py`: contract loader, metadata templating, block expansion, and job assembly; this is the narrowest place to introduce seasonal gating and season-aware job metadata.
- `jobs/publish/formatting.py`: safe template rendering and episode-id derivation; it already supports date-driven templates, but not a Marian Antiphon-specific intro shape by itself.
- `jobs/publish/audio.py`: MP3 writing, sidecar writing, content-hash reuse, and per-episode audio path selection.
- `jobs/publish/rss.py`: archive merge and feed dedupe; it dedupes by `episode_id`, so a date-scoped id is what prevents duplicate feed items.
- `jobs/publish/run_audio_pipeline.py`: daily vs bootstrap date selection and archive merge orchestration.
- `jobs/novena/liturgical_helpers.py`: the existing Romcal-backed Easter-season helper boundary to reuse.
- `jobs/publish/daily_intro.py`: likely source for a short generated intro that can announce the day and feast context before the fixed prayer body.
- `jobs/publish/fragments.py`: fragment cache and assembly helpers; this is where repeated phrases and reused blocks keep rerenders cheap.
- `docs/releases/0.1.4.2-angelus-easter-exception.md`: the closest shipped precedent for Marian Antiphon season routing on the Spotify side.
- `docs/releases/0.1.5.5-daily-podcast-episode-metadata.md`: the precedent for contract-owned title/description/episode-id templates.
- `tests/test_publish_contracts.py`, `tests/test_publish_audio_pipeline.py`, `tests/test_publish_audio_fragments.py`: current contract, RSS, and cache regression coverage.

### Current System Map
- `load_publish_contracts(...)` reads every JSON file in `config/publish/contracts/` and normalizes only the fields the loader knows about; unknown top-level contract fields are not currently modeled.
- `build_text_jobs(...)` and `build_audio_jobs(...)` both flow through `_render_entry_metadata(...)`, which uses `build_publish_context(...)` plus `derive_episode_id(...)` for title, description, and `episode_id`.
- `build_publish_context(...)` currently exposes date fields only. There is no season label, liturgical-year key, or season group in the context yet.
- The daily intro and fragment code paths already support reusable blocks, which is a better fit for "announce the day, then pray" than inventing a one-off monolithic text blob.
- `render_audio_job(...)` writes one MP3 and one JSON sidecar per `episode_id`, and it short-circuits when the cached sidecar hash matches.
- `load_published_audio_jobs(...)` and `build_rss_feed(...)` both dedupe by `episode_id`, so the episode id, not just the file path, controls archive uniqueness.
- `is_easter_season_for_date(...)` already exists in `jobs/novena/liturgical_helpers.py` and fails closed if Romcal season data cannot be determined.
- The current publish-audio catalog has no seasonal contract branch yet; the only checked-in contracts are Morning Prayer and Rosary.

### Reuse Opportunities
- Reuse the contract loader, fragment expansion, audio cache, and RSS archive merge instead of adding a second publish pipeline.
- Reuse `is_easter_season_for_date(...)` rather than adding a second liturgical calendar check.
- Reuse the `metadata.title_template` / `metadata.description_template` / `metadata.episode_id_template` pattern from the daily podcast metadata release.
- Reuse the Marian Antiphon season precedent from `jobs/playlist/spotify_contracts.py` and `jobs/playlist/refresh_playlist.py` as the behavioral model for ordinary-time vs Easter routing.
- Reuse reusable fragments for the repeated prayer body so only the day/feast intro and season choice change.
- Reuse the current publish tests as the baseline and add only the Marian Antiphon-specific assertions.

### External References
- `romcal` via `jobs/novena/liturgical_helpers.py` is the only external library needed for the season decision.
- No new external API surface appears necessary for this wedge.

### Constraints
- The publish feed dedupes by `episode_id`, so a date-scoped id is required if reruns should collapse to one feed item.
- `build_publish_context(...)` is date-based today, so the id and title can stay date-scoped while the intro fragment carries the day and feast-day wording.
- The contract loader currently only materializes known fields; a top-level season gate would require loader changes, while a metadata-based gate could flow through unchanged.
- Contract validation remains fail closed on malformed input, and the season gate should follow that pattern.
- The output should stay within the existing `docs/audio/` and `docs/podcast.xml` layout.

### Risks
- If the daily intro becomes too dynamic, reruns for the same date may stop feeling like the same episode even though the identity stays stable.
- If season logic is hidden in metadata without validation, maintainers may not understand why one contract is active and the other is skipped.
- If the episode-id template stops being date-scoped, the release will start duplicating feed items across reruns.
- If the RSS dedupe behavior changes later, reruns could start duplicating items even when the episode id stays date-scoped.

### Assumptions To Validate
- The intended product shape is one RSS item per day, not one item per season.
- The day/feast intro should be generated from the current target date and any liturgical celebration data, then reused as a fragment when rerunning the same date.
- The new contracts can stay on the existing `daily-prayer` contract type unless the team wants a separate seasonal type for clarity.
- The season gate should probably live in contract metadata unless there is a strong reason to promote it into a first-class top-level field.

### Unknowns
- The exact field name and location for the season gate.
- The exact stable `episode_id` template and filename pattern, as long as it stays date-scoped.
- Whether the Marian Antiphon title and description should explicitly mention the season or stay plain and rely on the feed identity only.
- Whether the feast-day announcement should be one generated block or several reusable fragment blocks.

### Recommended Direction
- Keep the contract shape narrow, add an explicit season gate, and keep the `episode_id` date-scoped so each day can write one unique RSS item and reruns remain idempotent.
- Before planning, confirm the exact intro fragment breakdown for the day/feast announcement and where the generated intro should sit relative to the sign of the cross.

## Plan

### Summary
- Add two new Marian Antiphon publish-audio contracts: one Easter Season source and one non-Easter source.
- Keep the audio render, archive, and RSS pipeline intact.
- Use season-gated job building so each contract emits one stable season-scoped episode per year.

### What Already Exists
- `jobs/publish/contracts.py` already loads contracts, validates them, and builds jobs.
- `jobs/publish/audio.py` already renders the MP3 and writes the JSON sidecar from a stable `episode_id`.
- `jobs/publish/run_audio_pipeline.py` already orchestrates the render-and-rebuild flow.
- `jobs/publish/rss.py` already rebuilds the podcast feed from the archived sidecars.
- `jobs/novena/liturgical_helpers.py` already knows how to detect Easter Season.
- `tests/test_publish_contracts.py`, `tests/test_publish_audio_pipeline.py`, and `tests/test_publish_audio_fragments.py` already cover the main publish-audio seams.

### Architecture
- Marian Antiphon contracts will live under `config/publish/contracts/` as two separate files.
- Each contract will carry a season gate and a season-scoped episode id template.
- `build_audio_jobs(...)` will include only the contract that matches the current liturgical season.
- `render_audio_job(...)` will continue to derive the MP3 path, sidecar path, and RSS guid from the season-scoped episode id.

```text
config/publish/contracts/*.json
  -> load_publish_contracts()
  -> build_audio_jobs()
  -> season gate via is_easter_season_for_date(...)
  -> render_audio_job()
  -> docs/audio/<season-id>.mp3 + .json
  -> load_published_audio_jobs()
  -> build_rss_feed()
  -> docs/podcast.xml
```

### Concrete Changes
- `jobs/publish/contracts.py`
  - Add season-aware fields to contract normalization and job building.
  - Build season-scoped context values for Marian Antiphon episode ids and titles.
  - Skip contracts that do not match the current season.

  - New Easter Season contract.
- `config/publish/contracts/marian-antiphon-angelus.json`

- `tests/test_publish_contracts.py`
  - Add acceptance and rejection tests for the season-aware Marian Antiphon contract shape.
- `tests/test_publish_audio_pipeline.py`
  - Add coverage proving the Easter and non-Easter contracts render the expected season-scoped jobs and RSS items.
- `tests/test_publish_audio_fragments.py`
  - Add/adjust coverage only if the new season-scoped episode ids affect render caching or content hashing.
- `README.md`
  - Document the two Marian Antiphon audio contracts and the season-aware output.

### UX And States
- No UI changes.
- Success state: the correct Marian Antiphon audio source renders for the current season and rebuilds the feed with a stable episode id.
- Empty state: if the current date does not match a contract’s season gate, that contract is skipped without failing the run.
- Error state: malformed season metadata fails during contract loading before any audio rendering starts.
