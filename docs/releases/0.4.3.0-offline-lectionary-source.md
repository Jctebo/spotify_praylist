# Release 0.4.3.0 - offline-lectionary-source

- Status: Shipped
- Created Date: 2026-08-22
- Last Updated: 2026-08-22
- Depends On: 0.4.2.6

## Scope

### Problem

- Ora Pro Nobis currently depends on live `catholic-mass-readings` and USCCB HTML retrieval for Gospel context.
- A provider outage, anti-bot response, network failure, or parser drift can remove Scripture from daily introductions and reflections.
- A second network scraper would reduce one failure mode but would not provide a genuinely offline source.

### Audience

- Primary user: Ora Pro Nobis listeners who should still receive Scripture-grounded daily reflections when external services are unavailable.
- Secondary stakeholders: publish jobs and maintainers who need auditable readings, source metadata, and deterministic recovery.

### Current Status Quo

- `jobs/publish/daily_intro.py` tries the `catholic-mass-readings` package, then USCCB HTML, then allows missing Gospel context.
- `romcal` supplies liturgical dates and observances but not a complete Bible-text cache.
- The repository has no local lectionary citation catalog or local Catholic Bible lookup.

### Goal

- Add a repository-owned offline reading provider that resolves a date to lectionary citations and resolves those citations to cached Douay-Rheims text.
- Use it only after the existing live sources fail, preserving current USCCB wording when available.
- Make fallback source, citation, translation, and cache version auditable in runtime metadata and tests.

### Constraints

- The first implementation targets the General Roman Calendar in English and must support Sunday cycles, weekday cycles, solemnity/feast overrides, and multiple readings.
- Lectionary citations and Bible text must be stored separately so the citation catalog can be verified independently from the translation.
- The fallback must not silently claim USCCB/NAB wording when it is using Douay-Rheims.
- No UI change is required.

### Narrow Wedge

- Implement a local JSON citation catalog and a Douay-Rheims passage resolver/cache interface, then wire Gospel lookup into the existing daily context fallback.
- Include a deterministic cache-building command and fixture coverage; full multi-year catalog population is a data-generation step using the documented schema.

### Non-Goals

- Replacing USCCB as the preferred source.
- Reproducing NABRE/USCCB copyrighted text locally.
- Supporting every national lectionary, language, or extraordinary-form calendar in this release.
- Rewriting the existing liturgical-calendar selector.

### Risks And Unknowns

- A complete citation catalog must correctly represent liturgical overrides and alternate Mass formularies; incorrect data is worse than a transparent missing-data fallback.
- Douay-Rheims versification and wording differ from USCCB/NAB, so generated prompts and sidecars must identify the translation.
- The initial checked-in catalog may need expansion after comparing multiple liturgical years against the USCCB calendar.

### Recommended Next Step

- Add a schema-validated offline provider, populate a small verified seed catalog, and add a generator that can expand the catalog from an approved citation source without embedding copyrighted NAB text.

## Research

- Catholic Resources provides comprehensive Roman Catholic lectionary citation tables for Sunday and weekday cycles.
- The `catholic-daily-readings` project demonstrates a citation-first, translation-agnostic data model.
- Douay-Rheims is available as public-domain structured Bible data and is suitable for local passage resolution.

## Plan

### Summary

- Add an offline provider that reads a repository-owned lectionary catalog and a local Douay-Rheims Bible cache.
- Keep the existing `catholic-mass-readings` and USCCB paths first; use the local provider only when live retrieval fails.
- Preserve explicit source/translation metadata so a Douay-Rheims fallback is never confused with USCCB/NAB text.

### What Already Exists

- `jobs/publish/daily_intro.py` owns Gospel retrieval and `DailyIntroContext`.
- `jobs/publish/saint_centered_theme.py` and `daily_liturgical_context.py` consume Gospel citation/theme data for shared prayer context.
- `catholic-mass-readings` and `romcal` are existing dependencies.
- Tests already mock live Gospel retrieval and cover missing-Gospel behavior.

### Architecture

```text
date -> live catholic-mass-readings -> USCCB HTML -> offline catalog
                                                   |
                                                   v
                                      citation -> local Douay-Rheims cache
                                                   |
                                                   v
                                      DailyIntroContext + source metadata
```

- `jobs/publish/offline_lectionary.py` exposes a small provider interface: load catalog, resolve date, resolve passage, and return a normalized Gospel context.
- `config/publish/offline/lectionary.json` stores date/calendar/readings citations; `config/publish/offline/douay-rheims.json` stores normalized passage text keyed by canonical reference.
- `scripts/build_offline_lectionary_cache.py` validates and builds the two files from approved citation/text inputs; it does not scrape or embed NAB/USCCB text.
- `daily_intro.py` calls the provider only after existing live attempts fail and records `source`, `translation`, and cache version in the context.

### Concrete Changes

- Add `jobs/publish/offline_lectionary.py` with dataclasses, canonical reference normalization, JSON loading, date lookup, and clear missing-data errors.
- Update `jobs/publish/daily_intro.py` to use the offline provider as the final Gospel fallback and carry source metadata through `DailyIntroContext`.
- Add `config/publish/offline/lectionary.json` and `config/publish/offline/douay-rheims.json` with a small verified seed fixture plus schema/version metadata.
- Add `scripts/build_offline_lectionary_cache.py` for deterministic validation/merge of citation and Bible-text inputs.
- Add `tests/test_publish_offline_lectionary.py` and extend `tests/test_publish_daily_intro.py` for successful lookup, missing citation/text, source labeling, and live-provider precedence.
- Document the cache format, generation command, translation limitation, and expansion procedure in `README.md`.

### UX And States

- No interactive UI changes.
- Live success remains unchanged.
- Offline success produces the same Gospel context with explicit `source=offline-douay-rheims` metadata.
- Missing offline data preserves the existing allow-missing-Gospel behavior and records the failure reason.

### Implementation Phases

#### Phase 1: Offline data contract and provider

- Goal: create validated, deterministic local citation/text lookup.
- Files: `jobs/publish/offline_lectionary.py`, both JSON cache files, provider tests.
- Verification: load seed data, resolve exact and normalized references, reject malformed entries.
- Rollback: remove the provider without changing live lookup behavior.

#### Phase 2: Daily Gospel integration

- Goal: use local data after both current live providers fail.
- Files: `jobs/publish/daily_intro.py`, daily-intro tests, `daily_liturgical_context.py` only if metadata propagation requires it.
- Verification: mocked live success wins; mocked live failure reaches local cache; missing local data still fails open when configured.
- Rollback: disable the final provider call and retain existing fallbacks.

#### Phase 3: Cache builder and documentation

- Goal: make expanding the offline cache repeatable and auditable.
- Files: `scripts/build_offline_lectionary_cache.py`, `README.md`.
- Verification: builder validates a temporary input and produces stable JSON; invalid references fail clearly.
- Rollback: keep checked-in seed cache and remove only the builder workflow.

### Failure Modes

- Invalid JSON/schema: provider rejects the cache and live behavior remains available.
- Missing date: offline lookup raises a typed missing-data error; existing `allow_missing_gospel` controls fail-open behavior.
- Missing Bible passage: citation is not presented as resolved text; the provider reports the exact reference.
- Translation mismatch: source metadata identifies Douay-Rheims in context and sidecar-safe fields.
- Liturgical override not yet cataloged: no invented reading; the system falls back transparently.

### QA And Test Matrix

- Exact date lookup returns the configured Gospel citation and Douay-Rheims text.
- Reference normalization handles book aliases, punctuation, and verse ranges without changing meaning.
- Malformed cache entries, duplicate references, missing text, and unknown dates are rejected.
- Live `catholic-mass-readings` success prevents offline lookup.
- Live package and USCCB HTML failure reaches offline lookup.
- Offline failure respects `allow_missing_gospel=True/False`.
- Existing daily-intro, shared-context, and publish contract suites remain green.
- Run focused offline tests, the daily publish tests, full repository tests, `python -m py_compile`, and `git diff --check`.

### Rollout Notes

- Ship the provider with a small verified seed and builder before expanding the catalog.
- Treat catalog expansion as data changes reviewed with date-by-date comparison against an authoritative lectionary reference.
- Do not change the preferred source order or claim NAB/USCCB translation parity.

### Not In Scope

- Complete all-year catalog population in this first code change if the source list has not been independently verified.
- Automatic unreviewed scraping of third-party lectionary pages.
- Full-text copyrighted Catholic translations.

### Open Questions

- The exact initial date range and calendar-year coverage should be expanded after the provider contract is verified.
