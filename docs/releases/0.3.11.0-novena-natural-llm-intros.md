# Release 0.3.11.0 — Novena Natural LLM Intros

## Scope

### Problem
- Generated novena openings need to follow the same liturgical priority as every other intro while remaining a natural entrance into the specific novena prayer.
- Treating Gospel and theme material as merely optional risks losing the deliberate daily hierarchy already used throughout Ora Pro Nobis.

### Audience
- Primary user: listeners beginning a daily Ora Pro Nobis novena episode.
- Secondary stakeholders: maintainers who need predictable, safe LLM output and usable sidecar freshness metadata.

### Current Status Quo
- The novena renderer uses the shared devotional-intro generator and feeds it daily-theme and Gospel-bridge context.
- The shared daily context establishes a priority of major solemnity/feast, Gospel, memorial, liturgical season, then fallback; the current novena profile does not express that priority explicitly.

### Goal
- Generate a concise, natural, spoken novena opening that uses the highest available shared liturgical focus and adapts it to the saint, novena day, and day-specific focus.
- Keep the specific novena central while preserving the established hierarchy: major solemnity/feast, Gospel, memorial, then liturgical season; when none applies, use only a brief saint-and-current-novena introduction.
- Preserve validation, corrective retry, deterministic fallback, audio caching, and sidecar freshness behavior.

### Constraints
- The opening remains one or two TTS-friendly sentences and must not alter the established novena prayer body.
- Generated text must remain reverent, fact-bounded by supplied context, and work when the LLM is unavailable.
- Existing non-novena devotional introductions are out of scope.

### Narrow Wedge
- Refine only the novena profile/prompt, validation expectations, fallback wording, and relevant tests so every generated, short-form, and traditional novena receives a brief hierarchy-aware, novena-specific LLM opening.

### Non-Goals
- Replacing the shared daily liturgical context system.
- Rewriting individual novena contracts or their prayer text.
- Changing audio voices, rendering, RSS behavior, or other prayer-family introductions.

### Risks And Unknowns
- A prompt could mention lower-priority daily material even when a solemnity, feast, or Gospel should govern the connection.
- The fallback must use the same selected hierarchy without becoming a generic theme summary.

### Recommended Next Step
- Plan a novena-specific selection contract that uses the canonical daily context's source and supplies one prioritized liturgical bridge to the existing intro generator.

## Research

- `jobs/publish/devotional_intro.py` owns shared profile definitions, prompt construction, semantic validation, fallback copy, retry handling, and the policy-version metadata used for freshness.
- `jobs/novena_contracts/engine.py` supplies the novena day, saint, feast, and novena-specific focus, then delegates the intro to the shared novena profile.
- The global validator currently requires every profile, including novenas, to repeat at least one daily liturgical anchor. This requirement is the direct mechanism that encourages theme/Gospel-summary prose.
- `tests/test_publish_devotional_intro.py` is the direct unit-test home for prompts, validation, retries, and fallbacks. `tests/test_novena_engine.py` covers novena context and output integration.
- `jobs/publish/daily_liturgical_context.py` resolves the canonical winner as major feast, Gospel, memorial, season, or fallback and persists the winning `source` in `daily_liturgical_context`.
- `jobs/publish/daily_theme_runtime.py` preserves that canonical payload for novena rendering, but `jobs/novena_contracts/engine.py` currently passes several parallel fields to the LLM without declaring which one won.

## Plan

### Summary
- Make the shared `novena` intro profile hierarchy-aware: prompt the writer to give higher-priority liturgical material greater weight, then adapt it to the saint, active day, and novena focus; omit the shared theme as a fallback.
- Keep semantic validation focused on novena identity and focus; do not require a mechanical, word-for-word liturgical bridge.

### What Already Exists
- `DevotionalIntroProfile`, two-attempt LLM generation, deterministic fallback, and sidecar policy-version freshness are already centralized in `jobs/publish/devotional_intro.py`.
- The canonical daily context supplies the celebration, Gospel, season, and shared theme needed for the prompt to honor the existing hierarchy.
- `runtime_context` already provides the saint, day, feast, and day-specific novena focus needed for a self-contained intro.

### Architecture
```text
Novena runtime context (saint + day + focus + optional daily liturgy)
                              |
                              v
              novena-specific LLM prompt and validation
                    |                         |
              accepted prose              retry / fallback
                    \                         /
                     v                       v
                    intro fragment + freshness metadata
```

### Concrete Changes
- Edit `jobs/publish/devotional_intro.py`:
  - advance `DEVOTIONAL_INTRO_POLICY_VERSION` so cached novena sidecars regenerate again;
  - state the existing liturgical hierarchy directly in the novena prompt without a shared-theme fallback;
  - preserve a brief saint-and-current-novena fallback wording.
- Edit `tests/test_publish_devotional_intro.py`:
  - cover the prompt, validation, and fallback using the selected bridge.
- Keep `tests/test_novena_engine.py` focused on passing the complete daily context into the intro.
- Update `docs/releases/0.3.10.5-novena-natural-llm-intros.md` progress, QA, and release notes with actual verification results.

### UX And States
- No UI changes.

- LLM failure: the deterministic opening uses the same selected bridge.
- Invalid LLM copy: one corrective retry occurs; failure then takes the deterministic path.

### Failure Modes
- The model overweights lower-priority material: the explicit hierarchy prompt ends at the liturgical season and otherwise directs a brief novena-only opening.
- The model omits supplied day/saint/focus: validation rejects it, triggering corrective retry/fallback.
- OpenAI is unavailable: deterministic fallback remains a natural entrance into the specific novena.
- Stale artifact reuse: policy-version increment causes target-date sidecar freshness checks to rerender the intro.
