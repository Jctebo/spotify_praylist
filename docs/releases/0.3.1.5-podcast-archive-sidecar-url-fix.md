# Release 0.3.1.5 - Podcast Archive Sidecar URL Fix

Date: 2026-05-02
Status: Shipped
Branch: fix/archive-json-link
Depends On: 0.3.1.4

## Scope

### Problem
- The published archive dashboard showed the JSON sidecar filename, but the link resolved to the wrong path in GitHub Pages.
- The MP3 row worked because it used the published filename, but the sidecar row was still using a filesystem-style path.

### Goal
- Make the archive dashboard's JSON link point at the published sidecar URL.
- Keep the MP3 link behavior unchanged.
- Keep the fix narrow to the archive dashboard generator.

### Constraints
- Do not change how the archive manifest stores filesystem paths.
- Do not change feed generation or audio rendering behavior.
- Keep the fix limited to the dashboard HTML renderer and its test coverage.

### Risks
- If the dashboard still renders filesystem paths, the JSON link will keep 404ing on the live site.
- The fix must preserve the existing filename display and archive table layout.

## Research

### Scope Baseline
- `jobs/publish/audio.py` already stores both `sidecar_path` and `sidecar_url` in the archive manifest.
- The dashboard renderer was still using `sidecar_path`, which is correct for local bookkeeping but wrong for a public URL.
- The archive tests already cover the manifest and HTML generation, so the change could stay very small.

### Relevant Files
- `jobs/publish/audio.py` - generates the archive manifest and the archive dashboard HTML.
- `tests/test_publish_audio_pipeline.py` - covers archive manifest generation and the archive dashboard output.

### Reuse Opportunities
- Reuse the existing `sidecar_url` field already emitted by the archive manifest.
- Reuse the current archive dashboard structure instead of introducing a new route or layout.
- Reuse the existing archive pipeline tests and add one href assertion.

### Risks
- If the dashboard keeps using filesystem-relative paths, the JSON link will still fail on GitHub Pages.
- The fix should not change the archive rows or the MP3 link behavior.

## Plan

### Summary
- Update the archive dashboard renderer to use the published sidecar URL for the JSON link.
- Add a regression assertion that the rendered HTML contains the published JSON URL.

### What Already Exists
- `build_audio_archive_manifest(...)` already produces `sidecar_url`.
- `_archive_index_html(...)` already renders the MP3 and JSON links.
- `tests/test_publish_audio_pipeline.py` already verifies the archive dashboard text and filenames.

### Architecture
- The manifest should continue to carry both local and public link forms.
- The dashboard should use the public `sidecar_url` for the JSON link and the public MP3 URL for the MP3 link.

### Concrete Changes
- `jobs/publish/audio.py`
  - Switch the archive dashboard JSON link from `sidecar_path` to `sidecar_url`.
- `tests/test_publish_audio_pipeline.py`
  - Assert that the archive dashboard contains the published JSON URL.
