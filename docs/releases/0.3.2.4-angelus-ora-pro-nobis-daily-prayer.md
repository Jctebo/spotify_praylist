## Scope

### Problem
- The three Spotify Angelus/Marian Antiphon queue contracts still point at fixed Spotify items with a special Easter replacement URI.
- The podcast/audio pipeline now publishes date-scoped Ora Pro Nobis Marian Antiphon episodes, so the Spotify playlist should resolve the daily prayer from that source instead of queueing stale fixed Angelus or Regina Caeli items.
- The current contract shape makes the playlist less aligned with the generated daily prayer surface and requires future URI maintenance when the source episode changes.
- Future Ora Pro Nobis Angelus and Regina Caeli episodes should share one durable title marker, `Marian Antiphon`, so the Spotify resolver can catch both seasons without hardcoding a separate seasonal title branch.
- Why now: the generic `spotify_episode_lookup` mode already exists and the recent Marian Antiphon publish work gives the Spotify side a daily Ora Pro Nobis source to target.

### Audience
- Primary user: the repo owner maintaining Spotify prayer playlists and the Ora Pro Nobis podcast/audio feed.
- Secondary stakeholders: playlist listeners who expect morning, midday, and evening Angelus entries to point at today's prayer rather than a fixed historical Spotify item.
- Future maintainers who need the Angelus Spotify contracts to follow the same contract-owned lookup pattern as Daily Novenas.

### Current Status Quo
- `config/spotify/contracts/angelus-morning.json`, `angelus-midday.json`, and `angelus-evening.json` use `spotify_url_normal` plus `spotify_uri_easter`.
- The runtime treats those contracts as a seasonal exception instead of using the generic podcast episode lookup mode.
- `config/spotify/contracts/daily-novenas.json` already shows the desired pattern: contract-owned Ora Pro Nobis show id, required title terms, and ordered date formats.
- The publish-audio Marian Antiphon contracts currently title episodes as `Angelus - {date_display}` outside Easter and `Regina Caeli - {date_display}` during Easter, which means a single `Marian Antiphon` lookup term is not available yet.
- The current `spotify_episode_lookup` schema supports one required-name-term set plus multiple date formats; it does not yet express ordered alternate searches such as `Marian Antiphon` first, then legacy `Angelus` / `Regina Caeli` terms if needed.
- The existing Angelus contracts resolve a fixed track/episode outside Easter and a fixed Regina Caeli episode during Easter, which is insufficient once the desired source is the daily Ora Pro Nobis prayer.

### Goal
- Convert all three Angelus/Marian Antiphon Spotify queue contracts to resolve the daily Ora Pro Nobis prayer episode for the target date.
- Retitle future Ora Pro Nobis Marian Antiphon audio episodes so both seasonal prayers include `Marian Antiphon` in the Spotify-visible episode name.
- Reuse the existing `spotify_episode_lookup` contract mode rather than adding another Angelus-specific resolver.
- Extend the daily Spotify episode resolver so a lookup contract can try multiple ordered searches when one title profile does not match.
- Preserve the current Notion row names and playlist membership behavior so only the resolved Spotify item changes.
- Success criteria:
  - Future Angelus and Regina Caeli publish-audio titles include the durable phrase `Marian Antiphon`.
  - Morning, midday, and evening Angelus contracts all declare `spotify_episode_lookup`.
  - Each contract targets the Ora Pro Nobis show id and primarily matches the daily episode by `Marian Antiphon` plus date formats.
  - Lookup config can express multiple ordered search profiles, so the resolver can fall back to legacy seasonal title terms during transition if the primary `Marian Antiphon` title is not present.
  - The old `spotify_url_normal` / `spotify_uri_easter` Angelus exception is removed or becomes unreachable after migration.
  - Regression tests prove the loader accepts the migrated contracts and the refresh path resolves them through the generic lookup branch.
  - README guidance no longer describes the Spotify Angelus contracts as fixed seasonal URI exceptions.

### Constraints
- Keep the change inside the Spotify playlist contract and refresh boundary.
- Do not change Notion membership, playlist ordering, playlist ids, publish-audio generation, or RSS feed behavior.
- Exception: update Marian Antiphon publish-audio title templates only far enough to add the stable `Marian Antiphon` phrase to future episodes.
- Contract validation must continue to fail closed on malformed lookup config.
- The date-format list should stay narrow enough to avoid matching the wrong episode.
- The release must account for Easter-season naming: the daily Ora Pro Nobis source may still mention Regina Caeli during Easter, but the resolver should be able to key off `Marian Antiphon` across both seasons.

### Narrow Wedge
- Migrate exactly the three Angelus Spotify queue contracts to `spotify_episode_lookup`.
- Update the two Marian Antiphon publish-audio title templates so future Spotify episode names contain `Marian Antiphon`.
- Use the existing Ora Pro Nobis show id and a minimal ordered search-profile list for the daily Marian Antiphon prayer.
- Update only the Spotify lookup schema/runtime, the three Spotify contracts, the Marian Antiphon title templates, focused tests, and README text needed to remove the old seasonal exception.

### Non-Goals
- Do not redesign the generic `spotify_episode_lookup` mode.
- Do not redesign the generic `spotify_episode_lookup` mode beyond adding ordered alternate search profiles.
- Do not alter Morning Prayer, Daily Novenas, Rosary, or other Spotify contracts.
- Do not change Marian Antiphon prayer text, season gating, audio providers, feed retention, or how Ora Pro Nobis episodes are generated beyond the future-facing episode title templates.
- Do not add live Spotify API integration tests.
- Do not change playlist refresh schedules or GitHub Actions cadence.

### Risks And Unknowns
- Biggest unresolved risk: existing already-published episodes will not have the new `Marian Antiphon` title marker, so the resolver needs ordered fallback searches during the transition window.
- If the ordered search profiles are too strict, the contracts will fail to resolve on valid days.
- If the ordered search profiles are too broad, multiple unrelated Ora Pro Nobis episodes for the same date could be queued.
- The morning, midday, and evening contracts may intentionally resolve to the same daily episode; that should be explicit in tests and documentation if confirmed.
- The existing seasonal Angelus branch in the runtime may become dead code and should either be removed with tests or clearly left only for backward compatibility.

### Recommended Next Step
- Run `/research-astack` to confirm the future episode title templates, define the ordered search-profile contract shape, and map the narrow runtime/test edits needed for implementation.

### Current System Map
- Publish-audio contracts render one job per eligible date through:

```text
config/publish/contracts/*.json
  -> load_publish_contracts()
  -> build_audio_jobs()
  -> _render_entry_metadata()
  -> docs/audio sidecar title + RSS item title
```

- The two Marian Antiphon publish contracts are already season-gated. This release only needs title-template edits; no season routing, audio provider, cache, or feed-retention change is needed.
- Spotify queue contracts load through `load_spotify_queue_contracts(...)`, which enforces exactly one of legacy resolver, direct URI, seasonal URI pair, or lookup mode.
- The current lookup mode shape is:

```json
{
  "spotify_episode_lookup": {
    "show_id": "...",
    "required_name_terms": ["..."],
    "date_formats": ["..."]
  }
}
```

- `spotify_episode_lookup_uris(...)` already fetches all pages from one show, dedupes by URI/id/name, matches all required terms against episode `name`, matches any configured date rendering, and preserves feed order.
- `resolve_contract_uris(...)` checks the seasonal Angelus fields before lookup mode. Once the three Angelus contracts move to lookup mode, that seasonal branch can remain for backward compatibility or be removed if no checked-in contracts use it.
- Existing queue assembly already supports a lookup returning multiple URIs, so no playlist writer change is needed.

- Reuse existing tests around pagination, dedupe, and queue flattening rather than adding live Spotify tests.

### External References
- Spotify Web API `Get a Show's Episodes` returns paginated episode items with fields including `name`, `uri`, and pagination metadata. Official reference: https://developer.spotify.com/documentation/web-api/reference/get-a-shows-episodes
- No new external API is required; this remains local filtering over the existing show episode endpoint.

### Constraints
- Spotify has no native title tag for `Marian Antiphon`; the durable marker must be added to the generated episode title.
- The resolver should match episode `name` only, consistent with the existing `spotify_episode_lookup` contract.
- The contract loader should fail closed on malformed `searches`, empty terms, empty date formats, or mixed lookup/URI shapes.
- Existing Morning Prayer and Daily Novenas contracts should keep working without requiring an immediate JSON migration.
- The three Angelus Spotify contracts may intentionally resolve to the same Ora Pro Nobis episode URI for morning, midday, and evening.

### Risks
- Existing published episodes will not have the new `Marian Antiphon` marker, so the transition depends on fallback searches for `Angelus` and `Regina Caeli`.
- A broad fallback search could match multiple same-day Marian episodes if title patterns overlap; the implementation should stop after the first search profile with matches.
- If implementation fetches Spotify pages once per search profile, it can do unnecessary API work; fetch once per lookup and apply all search profiles locally.
- Tests that assert the old seasonal Angelus branch will need to be rewritten or narrowed to legacy-only behavior.

### Assumptions To Validate
- `Marian Antiphon - Angelus - {date_display}` and `Marian Antiphon - Regina Caeli - {date_display}` are acceptable future Spotify-visible titles.
- It is acceptable for all three Angelus playlist rows to queue the same daily Ora Pro Nobis episode.
- Ordered search semantics should be "first profile with any matches wins" rather than merging matches across all profiles.

### Unknowns
- Whether the seasonal URI branch should be removed immediately or retained as compatibility for any future non-checked-in config. Planning can resolve this; the checked-in migration does not require retaining it.
- Whether legacy fallback profiles should include just the seasonal prayer name plus date, or include both the seasonal prayer name and `Marian Antiphon` after title-template rollout. The safer transition is separate profiles.

### Recommended Direction
- Add a `SpotifyEpisodeLookupSearch` model and a `searches` array under `spotify_episode_lookup`, while keeping top-level `required_name_terms` / `date_formats` as backward-compatible shorthand.
- Fetch the show episode pages once, then evaluate ordered search profiles locally; return matches from the first profile that succeeds.
- Retitle the two publish-audio Marian Antiphon contracts to include `Marian Antiphon` and migrate all three Angelus Spotify contracts to the new ordered-search lookup.
- Update focused contract, resolver, publish, README, and release artifact coverage before implementation is considered complete.

## Plan

### Summary
- Build ordered search profiles for `spotify_episode_lookup`, then use them to migrate the three Angelus Spotify contracts to daily Ora Pro Nobis episode lookup.
- Retitle future Marian Antiphon publish-audio episodes with a stable `Marian Antiphon` marker so one primary resolver term covers both Angelus and Regina Caeli seasons.
- This is the chosen approach because it keeps the existing contract-first lookup model, avoids another Angelus-specific resolver, and gives a controlled fallback path for already-published legacy titles.

### What Already Exists
- `spotify_episode_lookup` already supports show-id lookup, required title terms, ordered date-format candidates, pagination, dedupe, and multi-URI return.
- Publish-audio contracts already render season-aware daily Marian Antiphon episodes through title templates.
- Spotify queue assembly already flattens lookup returns and preserves playlist order.
- Tests already cover lookup matching, checked-in lookup contracts, seasonal Angelus contracts, and publish-audio title/feed behavior.

### Architecture
- Add a nested search profile model:

```json
{
  "spotify_episode_lookup": {
    "show_id": "4PNxb0OazrkcEp3FAggRoD",
    "searches": [
      {
        "required_name_terms": ["Marian Antiphon"],
        "date_formats": ["{month_name} {day}, {year}"]
      },
      {
        "required_name_terms": ["Angelus"],
        "date_formats": ["{month_name} {day}, {year}"]
      },
      {
        "required_name_terms": ["Regina Caeli"],
        "date_formats": ["{month_name} {day}, {year}"]
      }
    ]
  }
}
```

- Keep the old flat lookup shape as shorthand by converting it to one search profile during load.
- Runtime flow:

```text
Publish audio:
Marian contract title_template
  -> RSS title includes "Marian Antiphon"
  -> Spotify show episode name eventually contains that marker

Spotify refresh:
Angelus Spotify contract
  -> spotify_episode_lookup.show_id
  -> collect show episodes once
  -> search[0] Marian Antiphon + date
       if matches: return those URIs
       else search[1] Angelus + date
       else search[2] Regina Caeli + date
  -> queue returned URI(s)
```

### Failure Modes
- Invalid `searches` config: contract loading fails before any Spotify playlist write.
- No profile matches the current date: Angelus row is marked unresolved and contributes no URI, preserving existing fail-closed behavior.
- Primary and fallback profiles both match different episodes: only the first successful profile is used, preventing accidental queue expansion.
- Future title template typo omits `Marian Antiphon`: primary search misses, but fallback seasonal terms may still resolve during transition; tests should catch the template expectation.
- Spotify pagination failure: existing safe-call behavior returns whatever pages can be collected; no new failure mode is introduced.

### QA And Test Matrix
- Contract loading
  - Flat lookup still works for Morning Prayer and Daily Novenas.
  - `searches` lookup works for the three Angelus contracts.
  - Empty `searches`, empty term lists, empty date-format lists, and mixed lookup/URI fields fail closed.
- Resolver behavior
  - Primary `Marian Antiphon` profile resolves when present.
  - Fallback `Angelus` profile resolves when primary has no matches.
  - Fallback `Regina Caeli` profile resolves when primary and Angelus have no matches.
  - Search stops after the first successful profile and does not merge later matches.
  - Spotify show pages are fetched once per contract resolution.
  - Pagination, dedupe, and URI order stay unchanged.
- Checked-in contracts

  - All three can resolve the same daily Ora Pro Nobis episode.
