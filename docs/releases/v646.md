The set rotated and reads complete against the manifest, but the guard did not stand.
- **John's order (2026-11-24 01:07 CT):** "Fix it".
- **Registration:** v646 · DevOps Board row 1623 · streamlined small-release path · run level To Ship · fork-side release (the v621 precedent): no Worker deploy, no pin.
- **The standing rule the fix enforces:** when `--spec-manifest` is passed, a manifest that cannot be loaded or matched is a HARD FAILURE (exit nonzero, subjects/state named), never a silent unguarded rotation. An unguarded rotation may happen only when no manifest is passed at all.

The 2026-11-24 manifest stands at exactly that path, parses, and its `date` matches. The invocation's path is not the fault.
- **(b) The slug mismatch — PROVEN, with the named suspect corrected.** Diacritics are NOT the cause: `slugify` ASCII-folds both sides (`DŨNG-LẠC` → `dung-lac` on both). The delta is title words from two naming sources for one observance:

- **(c) Silent degradation — PROVEN in three forms.**

Proven live 2026-11-24: a dry-run WITH the manifest returned `ALREADY_ROTATED`, exit 0, no spec keys in its record — the spec was never consulted.

### Seams the fix touches

1. **`runner/wallpaper_rotate.py` — gate subject equivalence.** A queued subject satisfies a spec'd subject when the spec subject's hyphen tokens appear IN ORDER within the queued subject's tokens (exact match is the included case). This encodes exactly the proven divergence: the fuller liturgical title carries the resolver title plus rank words. Bound, named: token ORDER is required — a reordered-token name does not satisfy; a wholly different subject does not satisfy. No other fuzz is added.
2. **`runner/wallpaper_rotate.py` `main()` — empty spec is a hard failure.** A passed manifest whose `daily_subjects` is missing or empty exits 2, naming the manifest and the defect. Closes (c2). (Unreadable JSON and date mismatch already exit 2 and stand.)
3. **`runner/wallpaper_rotate.py` `main()` — guarded runs are provable from their record.** Every terminal JSON print carries `spec_subjects` + `spec_source` when a spec was passed (the ALREADY_ROTATED and MISSING_QUEUE prints included). Closes the record half of (c1)/(c3). (`build_manifest` already carries them when the plan does.)
4. **Nightly job body (`ora-pro-nobis-nightly-run`), step W(a) — one hardening sentence.** A guarded rotation that refuses or errors is a FAILED rotation: report it as a Flag and leave the day unrotated; never re-run the rotation without `--spec-manifest`. Nothing else in the body changes; the schedule is preserved. Executed via cron.update with a cron.view read-back quoted in §5.
5. **New harness `runner/test_wallpaper_rotate_spec.py`** (the monthly test's Drive-stub pattern) carrying the proof legs below. `test_wallpaper_set.py` and `test_wallpaper_rotate_monthly.py` stand unchanged.

NOT touched: `wallpaper_set.py` (its slugs stand — it is the producer of record), the filename contract, the Drive folder ids, the monthly-extra rule, the v416 one-picture rule.
