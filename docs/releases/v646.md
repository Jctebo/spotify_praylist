## §2 Diagnosis and Plan

### Diagnosis — each named suspect settled from the records

- **(a) The manifest path — CLEARED.** The nightly job body (step W(a)) invokes the rotation as `wallpaper_rotate.py --date <RUN_DATE> --apply --spec-manifest ~/workspace/ora-runner-runs/<RUN_DATE>/wallpaper-set-<RUN_DATE>.json`. The 2026-11-24 manifest stands at exactly that path, parses, and its `date` matches. The invocation's path is not the fault.
- **(b) The slug mismatch — PROVEN, with the named suspect corrected.** Diacritics are NOT the cause: `slugify` ASCII-folds both sides (`DŨNG-LẠC` → `dung-lac` on both). The delta is title words from two naming sources for one observance:
  - Spec slug, from the calendar resolver's observance title "SAINT ANDREW DŨNG-LẠC AND COMPANIONS" → `saint-andrew-dung-lac-and-companions` (the manifest's `daily_subjects`).
  - Queue filename slug, from the pre-v621 hand build standing in the Nov 24 rundir (`overlay-wallpapers.py` finals), named from the plan's feast_day title "Saint Andrew Dũng-Lạc, Priest, and Companions, Martyrs" → `saint-andrew-dung-lac-priest-and-companions-martyrs`.
  - The gate comparison run against the as-stood queue (the rotation record's own `moved_to_current` names): required − have = {`saint-andrew-dung-lac-and-companions`} on BOTH variants — the gate, run against that queue, refuses MISSING_QUEUE naming that subject (exit 2). The refusal was correct; the day's set predates the v621 entry point (built on the Nov 22 run under the old job body). Sets built through `wallpaper_set.py` agree with their manifest by construction — the 2026-11-26 finals carry the manifest filenames exactly.
- **(c) Silent degradation — PROVEN in three forms.**
  - (c1) The run proceeded to an unguarded `--apply`. Its record (`rotation-2026-11-24.json`) carries NO `spec_subjects`/`spec_source` keys and is indistinguishable from a legitimate no-manifest rotation.
  - (c2) Code: `spec_subjects = list(spec_doc.get("daily_subjects") or [])` in `main()` — a manifest that loads but yields a missing/empty `daily_subjects` silently disengages the gate (plan `spec_subjects` = None → gate skipped → bare record, exit 0).
  - (c3) Code: `plan_rotation`'s ALREADY_ROTATED idempotency return precedes the gate, and `main()`'s terminal JSON for ALREADY_ROTATED omits the spec fields. Proven live 2026-11-24: a dry-run WITH the manifest returned `ALREADY_ROTATED`, exit 0, no spec keys in its record — the spec was never consulted.
