## Scope

### Problem
- Nightly Daily Reflection audio continues to expose prompt wording because the model is constrained to a rigid, instruction-heavy paragraph template and validation treats that template as a spoken-content contract.

### Audience
- Primary user: listeners praying with the nightly Daily Reflection audio.
- Secondary stakeholders: maintainers of generation, contract, and TTS assembly.

### Current Status Quo
- The prompt dictates exactly four paragraphs, opening and closing phrases, and paragraph-specific content.
- Validation and the audio boundary repeat the same rigid format, while a finite marker list catches only known prompt leakage.

### Goal
- Let the LLM choose a natural reflection structure and progression from supplied liturgical context.
- Keep generated speech listener-facing and reject obvious instruction/schema leakage before it enters TTS.
- Preserve deterministic fallback behavior when model generation fails.

### Constraints
- Preserve the existing episode title, segment/pause interface, context inputs, and fallback availability.
- Do not loosen checks for empty output, markdown/instructions, or audio safety.

### Narrow Wedge
- Simplify the generation brief to contextual guidance and listener-facing intent.
- Remove fixed paragraph count, mandatory opening/closing strings, and mandatory saint/observance mentions from generated-output validation.
- Make audio validation enforce the same safety boundary without imposing the model's narrative structure.
- Adapt regression tests for natural variable-structure output and prompt leakage.

### Non-Goals
- Changing schedule, episode naming, liturgical-context resolution, TTS provider, or pause duration.
- Replacing deterministic fallback prose.

### Risks And Unknowns
- Downstream contract consumers may assume paragraph-based segments; verify that segment expansion supports variable counts.
- Prompt leakage detection must catch explicit instruction-like output without rejecting normal reflective language.

### Recommended Next Step
- Review and merge PR #134 to release the model-led nightly reflection.

## Plan

### Summary
- Replace the prescriptive reflection script with a compact context-led brief so the model chooses the reflection's structure and emphasis.
- Keep output safety checks for empty text and explicit prompt/schema artifacts, but stop requiring fixed paragraphs, exact welcome/closing lines, or named context terms.
- Keep fallback prose and preserve paragraph-derived segments for pause timing when the model supplies paragraphs.

### What Already Exists
- `jobs/publish/ignatian_reflection.py` owns the prompt, model call, deterministic fallback, validation, and segment extraction.
- `jobs/publish/contracts.py` applies `validate_ignatian_reflection_audio_text` at the contract-to-audio boundary; TTS uses the full validated text.
- Existing tests cover leakage rejection, deterministic fallback, and audio boundary behavior.

### Architecture
```text
liturgical context -> concise LLM brief -> safe listener-facing text
                                      \-> deterministic fallback on error
episode text -> audio boundary safety check -> TTS fragment(s)
```

### Concrete Changes
- `jobs/publish/ignatian_reflection.py`: simplify `_build_prompt`; relax `_validate_episode` and `validate_ignatian_reflection_audio_text` to variable narrative structure while retaining leakage and formatting guards; retain fallback behavior and derive segments from available paragraphs.
- `tests/test_publish_ignatian_reflection.py`: cover variable structure, context-led output, true prompt leakage fallback, and audio-boundary acceptance/rejection.
- `README.md`: describe model-led generation, listener-facing validation, and variable paragraph-based pause timing.
- `docs/releases/0.4.15.0-nightly-reflection-llm-driven.md`: maintain implementation and QA status.

### UX And States
- Listeners hear a model-shaped reflection grounded by today's supplied context; on generation or validation failure they hear the established deterministic fallback.

### Failure Modes

- Downstream audio conversion could assume four segments; confirm contract assembly uses full episode text and does not require a fixed segment count.

### QA And Test Matrix
- Generated reflection with a different number of paragraphs is accepted and segments reflect those paragraphs.
- Normal reflective prose that mentions a theme, saint, or observance is not falsely rejected.
- Explicit prompt labels/instructions and markdown are rejected before TTS and trigger deterministic fallback in the generator.
- Missing OpenAI configuration still yields the existing valid fallback.
- Run `python -m unittest tests.test_publish_ignatian_reflection tests.test_publish_contracts tests.test_publish_audio_pipeline`.

### Rollout Notes
- No schema, storage, or scheduling migration; new generated text naturally replaces existing episode text when the nightly job runs.

### Not In Scope
- Revising fallback prose or changing audio providers, pause duration, titles, or liturgical-context resolution.

### Open Questions
- None; downstream consumes the full text and has no fixed segment-count requirement.
