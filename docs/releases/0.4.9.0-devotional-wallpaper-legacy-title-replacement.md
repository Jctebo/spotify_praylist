- Source: production OneDrive audit after the calendar resolver began using canonical subject titles.

## Scope

### Problem
- The existing Sept. 28 Wenceslaus pair is named `saint-wenceslaus-martyr__2026-09-28.jpg`, while the updated calendar resolver now names the subject `saint-wenceslaus`.
- Rotation compares the literal filenames, so it can keep the obsolete pair beside its corrected replacement after the corrected phone/watch pair is complete.

### Audience
- The operator using the devotional wallpaper pipeline and OneDrive current/queue folders.

### Current Status Quo
- The old managed Wenceslaus phone/watch pair is in `phone-current` and `watch-current`.
- The corrected Saint Lawrence Ruiz phone image is queued; three other Sept. 28 subject/device slots still need generation.
- Current rotation archives all managed files before it replaces or cleans up the current set, but it does not identify this old title suffix as a same-subject alias.

### Goal
- Once both device variants for a corrected canonical subject are queued, replace any managed same-day current filename whose only difference is the legacy `-martyr` or `-martyrs` suffix.
- Archive and checksum-verify the old files before cleanup; retain unrelated saints/devotions; do not change current files while the incoming subject set is incomplete.
- Success means Sept. 28 current folders contain one Wenceslaus pair and one Lawrence Ruiz pair, while the original Wenceslaus pair remains in the private archive.

### Constraints
- Keep rotation limited to the wallpaper-specific OneDrive folders and preserve journal recovery and unmanaged-file protections.
- Alias matching is only a replacement rule for old current filenames when a matching canonical queued subject exists.
- Existing infographic, web publication, and local rotation pipelines remain unchanged.

### Narrow Wedge
- Normalize the two known legacy martyr suffixes only while selecting same-day replacements; add complete-set and incomplete-set regression tests.

### Non-Goals
- Calendar parser changes, new subject inference, image-prompt changes, and any modification to the original devotional infographic pipeline.

### Risks And Unknowns
- A false alias match could remove a distinct subject, so canonicalization is suffix-limited and only compares an existing current asset with an actual queued subject for the same date and device.

### Recommended Next Step
- Implement the replacement preference, verify archive-before-cleanup and incomplete-set behavior, then deploy and reconcile Sept. 28 in OneDrive.

## Research

- `inventory_assets` extracts the subject slug from the dated filename.
- `rotate_current` previously selected every current and queued asset for the date, so `saint-wenceslaus-martyr` remained after `saint-wenceslaus` was queued.
- `_archive_current_pair`, `_promote_verified`, the rotation journal, and `_cleanup_old_current` already provide checksum verification, archive-before-cleanup, and crash recovery; the patch reuses these paths.
- The live resolver report showed two subjects on Sept. 28: Saint Lawrence Ruiz and Companions and Saint Wenceslaus. Ruiz phone was already queued; Ruiz watch and both Wenceslaus variants were absent.

## Plan

- Add a rotation-only canonicalizer for the known `-martyr` and `-martyrs` legacy suffixes.
- Before constructing the next managed current set, omit an old current alias only if the same device has the canonical queued subject; continue requiring complete matching phone/watch subject sets.
- Verify a completed repair archives the old pair and promotes every named subject, while a partial phone-only replacement leaves the old current pair and queue untouched.
- Run the focused wallpaper tests, full repository tests, compile checks, diff review, and the production missing-only workflow.
