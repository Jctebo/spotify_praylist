## Scope

### Problem
- The repo has a Spotify queue contract for `auxilium-christianorum`, but it still depends on the legacy `AUXILIUM` resolver path and does not produce a complete, source-faithful daily prayer episode.
- Auxilium Christianorum lay members need a daily prayer surface that assembles the required every-day prayers, the correct weekday prayer, and the daily conclusion from reusable pieces.
- The requested experience is not just a static prayer list; it should behave like a date-scoped daily episode generator with a liturgical-style opening announcement and resumable sections.
- Why now: the repo already has a contract-driven publish pipeline, reusable file blocks, `daily_intro`, `weekday_map`, fragment audio caching, episode sidecars, and date-scoped podcast output. The new work can mostly extend those existing primitives instead of adding a separate subsystem.

### Audience
- Primary user: a lay member of Auxilium Christianorum who wants the correct daily prayers for the current date in one structured episode.
- Secondary stakeholders: the repo owner maintaining Ora Pro Nobis publish contracts, podcast audio, and Notion bookmark/resume surfaces.
- Future maintainers who need feast, saint, seasonal, and devotional inserts to plug into the same episode-generation model without rewriting the prayer content.

### Current Status Quo
- `config/spotify/contracts/auxilium-christianorum.json` declares `resolver: "AUXILIUM"` and the Notion name `Auxillium Christianorum`.
- `jobs/playlist/refresh_playlist.py` still has an `AUXILIUM` resolver branch that searches Spotify show episodes by weekday token, which is playlist lookup behavior rather than publish-time daily episode generation.
- The active publish contract system in `config/publish/contracts/*.json` can assemble daily text/audio jobs from reusable blocks, including file fragments, sequences, repeats, weekday maps, and daily intros.
- The active publish audio path already caches leaf fragments under `.cache/publish_audio/`, writes date-scoped JSON sidecars under `docs/audio/`, and rebuilds the feed from archived sidecars.
- Morning Prayer already has a liturgical intro generator that pulls Romcal celebrations and optionally Gospel context, but its current prompt shape is too Morning Prayer-specific for Auxilium unless scoped carefully.
- The official Auxilium site separates priest prayers and lay-member prayers; this release must use lay-member content only.

### Goal
- Build a lay-member Auxilium Christianorum daily prayer episode system that generates exactly one structured episode for each target calendar day.
- Assemble each episode dynamically from reusable prayer components:
  - opening section
  - liturgical-style calendar announcement
  - current weekday and date
  - every-day required prayers
  - weekday-specific prayer
  - recurring litanies/prayers
  - closing section
- Ground the content model in the official requirements page, FAQ, prayers page, and lay-member daily prayer PDF.
- Reuse the existing publish contract and fragment caching systems wherever possible.
- Support bookmarking/resume within a daily episode by exposing stable section and fragment identity in the generated sidecar/output metadata.
- Success criteria:
  - A checked-in Auxilium publish contract can render one text job and one audio job for a given date.
  - The generated content includes the source-defined every-day prayers, the correct weekday block, and the daily conclusion for all seven weekdays.
  - The system rejects priest-only prayer content for this contract.
  - The liturgical announcement includes date, weekday, and Romcal celebration context, with hooks for memorials, feasts, solemnities, and future season inserts.
  - Fragment cache reuse works for unchanged reusable prayers across multiple dates.
  - Generated sidecars expose ordered section/fragment metadata sufficient for bookmark/resume.

### Constraints
- Use lay-member prayers only; priest-only Auxilium material is explicitly out of scope.
- Avoid inventing a parallel cache or episode architecture; build on `jobs.publish.contracts`, `jobs.publish.fragments`, and existing audio sidecar behavior.
- Keep official-source wording and content boundaries visible in the contract/templates so future edits do not accidentally mix priest and lay forms.
- Do not treat the daily Rosary as part of the generated Auxilium episode for this release; the official requirements exhort daily Rosary, but the daily Auxilium vocal-prayer PDF is the source for this episode.
- Do not add feast, saint, or seasonal inserts in the first wedge unless they are represented as no-op extension hooks.
- Do not update the Spotify Auxilium queue contract in this release; leave playlist integration for a follow-up after generated episode titles and sidecars are stable.
- Announcement style should feel like a sober Liturgy of the Hours / Morning Prayer introduction, but it must not imply the episode is an official Liturgy of the Hours office.
- Date behavior should follow the repo's existing `America/Chicago` publish timezone unless research finds a stronger reason to use a different default.
- Copyright and source-use handling was reviewed with the repo owner on 2026-06-02; the owner approved checking in the English lay-member prayer text for this project.

### Narrow Wedge
- Add a new Auxilium Christianorum lay-member publish contract and template set under the existing publish contract structure.
- Model the prayer content as reusable components:
  - shared opening invocation and daily offering block
  - reusable common prayers such as St. Michael, Guardian Angel, Our Father, Hail Mary, and Glory Be
  - reusable Litany of the Most Precious Blood block
  - one weekday-map block for Sunday through Saturday prayers
  - reusable daily conclusion block
- Add or adapt a contract block for a liturgical calendar announcement that can render:
  - "Today is {weekday}, {date}."
  - a Romcal celebration clause for optional memorials, feasts, solemnities, and ordinary weekdays
  - a future-facing season field/hook without requiring seasonal inserts now
- Ensure publish text/audio jobs and audio fragments carry stable labels/keys for resume points.
- Add focused tests for contract validation, weekday selection, announcement rendering, fragment expansion, and sidecar resume metadata.

### Non-Goals
- Do not implement priest Auxilium prayers.
- Do not build a general devotional module marketplace.
- Do not add saint-specific, feast-specific, or seasonal insert content yet.
- Do not redesign the Morning Prayer `daily_intro` generator beyond what is needed to support a reusable liturgical announcement block.
- Do not rewrite the publish pipeline, audio cache, RSS feed builder, or Spotify playlist refresh architecture.
- Do not update `config/spotify/contracts/auxilium-christianorum.json` or remove the existing `AUXILIUM` resolver path in this release.
- Do not add live Spotify, Notion, Romcal, OpenAI, or TTS integration tests for this release.
- Do not change the Rosary publish contract or merge Rosary audio into this Auxilium episode.

### Risks And Unknowns
- Full prayer-text republication was reviewed with the repo owner on 2026-06-02, and the owner approved checking in the English lay-member prayer text for this project.
- The official PDF's layout extraction is noisy in places, so transcription should be verified manually against the PDF before generating user-facing text/audio.
- Some wording differs between the requirements page and the PDF; the daily prayer PDF should likely be canonical for episode content, while requirements/FAQ guide membership framing and guardrails.
- The existing `daily_intro` block currently generates a Gospel-focused Morning Prayer intro. Auxilium likely needs a more deterministic liturgical announcement block that does not require Gospel text.
- Bookmark/resume semantics are not yet a first-class public API in publish sidecars; research should confirm whether existing `sections` and `audio_fragments` are enough or whether sidecars need explicit resume markers.
- The existing Spotify Auxilium resolver may keep pointing at an external show during this release; that is acceptable because playlist migration is explicitly deferred.

### Current System Map
- Publish contract flow:

```text
config/publish/contracts/*.json
  -> load_publish_contracts()
  -> build_text_jobs() / build_audio_jobs()
  -> resolve_block_content() / expand_audio_fragments()
  -> Notion text rows or docs/audio sidecars + podcast.xml
```

- `jobs/publish/contracts.py` supports block kinds `sequence`, `repeat`, `weekday_map`, `monthly_template`, `file`, `inline`, and `daily_intro`.
- `weekday_map` already selects by target date and adds a stable fragment path segment like `weekday-map/monday`, which is the right shape for the Auxilium weekday prayer block.
- Text jobs already include ordered `sections` with section titles, text, and kind. Audio jobs already include ordered `audio_fragments` with `fragment_key`, `block_path`, `kind`, `label`, and `text`.
- Audio sidecars currently persist fragment metadata under `fragments`, but they do not persist top-level text `sections` or an explicit `resume_markers` list.
- `daily_intro` is currently LLM-backed and Gospel-oriented. It is useful as a Romcal data source, but Auxilium needs a deterministic liturgical announcement that does not depend on OpenAI or USCCB Gospel text.
- The publish audio pipeline loads every checked-in publish contract. Adding an approved audio-enabled Auxilium contract will add the episode to the Ora Pro Nobis feed for the target publish dates.

### Risks
- The official PDF is public but copyrighted. The repo owner has approved checking in the English lay-member prayer text for this project, but implementation should preserve source attribution and avoid unnecessary wording changes.
- PDF text extraction contains artifacts such as joined words and page-number bleed, so templates must be manually verified against the official PDF rather than copied blindly from extracted lines.
- A new block kind can create mismatches if text rendering, audio fragment expansion, and section metadata are not updated together.
- Adding an approved audio-enabled contract increases daily feed output count; tests that assume current counts for ordinary/Easter days will fail until updated.
- Existing sidecars have no `resume_markers`; archive loading must tolerate old sidecars while new sidecars include richer metadata.

## Plan

### Summary
- Build a source-grounded Auxilium Christianorum daily episode in the Ora Pro Nobis publish pipeline.
- Add a deterministic liturgical announcement block, a lay-member Auxilium publish contract/template set, and explicit resume markers in generated jobs/sidecars.
- This plan is the chosen approach because it reuses the existing publish contract and fragment cache architecture while avoiding Spotify changes and avoiding an LLM dependency for the Auxilium calendar announcement.

### What Already Exists
- Contract loading and validation in `jobs/publish/contracts.py`.
- Daily text/audio job rendering through `build_text_jobs()` and `build_audio_jobs()`.

### Architecture
- Add one block kind: `liturgical_announcement`.
- Data flow:

```text
target date
  -> Auxilium publish contract
  -> liturgical_announcement block
       -> Romcal celebration names + weekday/date formatting
  -> static common prayer file blocks
  -> weekday_map selects one weekday prayer
  -> conclusion file block
  -> text sections + audio fragments
  -> resume_markers
  -> Notion text job and docs/audio sidecar
```

- `liturgical_announcement` should be deterministic:
  - includes weekday and long date
  - includes celebration clause when Romcal returns usable celebrations
  - includes optional `calendar`, `locale`, `title`, and future-facing `include_season` config
  - fails with `PublishMissingDataError` unless `skip_if_missing` is true
- Resume markers should be generated from the same ordered data the system already computes:
  - text jobs: one marker per section
  - audio jobs/sidecars: one marker per audio fragment
  - marker fields: `marker_id`, `label`, `kind`, `source`, `fragment_key` or `section_index`, and `order`

### Failure Modes
- Missing or malformed Auxilium template: contract validation fails with the missing path or unsupported block kind.
- Romcal unavailable: `liturgical_announcement` fails unless configured with `skip_if_missing`; user sees a publish pipeline error before feed write.
- Wrong weekday selected: caught by unit tests that render known dates for all seven weekdays.
- Full-text source issue: implementation may proceed with the repo owner's 2026-06-02 approval, while preserving source attribution and avoiding unnecessary wording changes.
- Sidecar compatibility regression: caught by tests that load older sidecars without `resume_markers`.
- Added contract unexpectedly increases feed output: caught by pipeline tests and documented as expected behavior.
