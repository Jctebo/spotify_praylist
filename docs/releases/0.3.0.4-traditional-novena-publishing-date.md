# Release 0.3.0.4 - Traditional Novena RSS Title Date Suffix

Date: 2026-05-01
Status: Shipped
Branch: enhancement/traditional-novena-publishing-date
Depends On: 0.3.0.3

## Scope

### Problem
- Traditional novena RSS item titles currently end with the novena day and do not show the publishing date.
- The published episode title should reflect when it was published, so reruns and delayed publishes stay understandable in the feed and player UI.
- Why now: the traditional novena path is live, and its RSS title should make the publication date visible without changing the underlying novena content.

### Audience
- Primary user: the maintainer who publishes or re-runs traditional novena content and needs the published output to reflect the correct day.
- Secondary stakeholders: listeners who should see a date that matches when the episode was published.
- Secondary stakeholders: future maintainers who need a clear contract for which date the traditional novena path is allowed to use.

### Current Status Quo
- The traditional novena import path writes a title pattern like `Traditional Novena to {saint_name} Day {day}`.
- The novena runtime already carries a publish-date-aware context for other novena rendering paths.
- The traditional novena path does not currently make the publishing date explicit in the rendered title or metadata, so the published result can feel detached from the actual publish day.

### Goal
- Append the publishing date to the traditional novena RSS item title, for example `Traditional Novena to St Damien of Molokai Day 2 - May 2, 2026`.
- Ensure the title is deterministic for a given publish date, even if the job is rerun later.
- Success criteria: the RSS item title visibly ends with the publish date, and regression coverage proves the suffix comes from the publish run date.

### Constraints
- Keep the change narrow to the traditional novena RSS title template and its date context.
- Preserve existing standard novena behavior, contract validation, sidecar writing, and feed ordering unless the title formatting reveals a hidden dependency.
- The solution must work for both scheduled and manual publish modes.
- Do not change Spotify refresh behavior or unrelated audio pipelines.

### Narrow Wedge
- Thread the publish date into the traditional novena RSS title formatter, append it as a suffix, and add regression coverage for a fixed-date publish and a rerun case.

### Non-Goals
- Do not redesign the general novena engine.
- Do not change feast resolution, day numbering, or selector logic.
- Do not rename the novena day number or remove it from the title.
- Do not add a new date storage model or a broader scheduling system.
- Do not touch Spotify playlist refresh or unrelated publish jobs.

### Risks And Unknowns
- We still need to pin down the exact formatter seam that builds the traditional novena RSS title.
- We need to confirm the publish-date value is already available at that point for both scheduled and manual runs, so the title does not fall back to `date.today()`.
- We should verify the ` - May 2, 2026` suffix format displays cleanly in podcast clients and does not create awkward truncation.

### Recommended Next Step
- Run `/research-astack` to map the traditional novena RSS title flow, confirm the source of the publish date, and identify the smallest code seam to change.

## Research
### Scope Baseline
- Append the publish date to traditional novena RSS item titles, e.g. `Traditional Novena to St Damien of Molokai Day 2 - May 2, 2026`.
- Keep the novena day in the title and leave the underlying novena content, day numbering, and feed ordering unchanged.

### Relevant Files
- `jobs/novena_contracts/url_import.py` - generates traditional novena contracts and currently hardcodes `TRADITIONAL_NOVENA_TITLE_PATTERN`.
- `contracts/novenas/feast-days/*.json` - checked-in traditional novena contracts that still use the old title pattern and would not pick up a new import default automatically.
- `jobs/novena_contracts/pipeline.py` - renders the RSS title from `runtime.publishing.rss.episode_title_pattern` and already has the publish date in `runtime.date`.
- `jobs/publish/formatting.py` - provides `date_display` formatting, which already matches the desired `May 2, 2026` suffix shape.
- `jobs/novena_contracts/artifact_writer.py` - persists the rendered title and `published_date` into the sidecar that later becomes feed input.
- `jobs/publish/rss.py` - serializes RSS items from job data and preserves the stored title rather than recomputing it.
- `tests/test_novena_url_import.py` and `tests/test_novena_pipeline.py` - current coverage for imported-contract defaults and final RSS title rendering.

### Current System Map
- The URL importer writes traditional novena contracts with a fixed RSS title template, currently `Traditional Novena to {saint_name} Day {day}`.
- The novena runtime already threads a `date_display` field through the shared publishing context, so the title formatter has the exact date string needed for the suffix.
- The pipeline resolves active novenas from a concrete publish date, renders the title, stores it in the artifact sidecar, and then builds the RSS feed from those stored jobs.
- RSS feed generation reads the job titles back from the sidecar/feed job objects; it does not derive the title independently from the date.
- Because many existing contracts already live under `contracts/novenas/feast-days/`, changing only the importer default would affect future imports but leave the checked-in traditional novenas unchanged.

### Reuse Opportunities
- Reuse `date_display` from `jobs/publish/formatting.py` instead of adding a new date-formatting path.
- Reuse the existing RSS title formatter in `jobs/novena_contracts/pipeline.py` rather than introducing a second title builder.
- Reuse the current sidecar + RSS job flow so the new suffix is captured once at publish time and preserved through feed rebuilds.
- Reuse existing novena contract tests by adding fixture coverage for both importer-generated contracts and final RSS item titles.

### External References
- No new external API or library is needed for the title suffix itself.
- Podcast client display behavior is the only external concern worth validating informally, because long titles may truncate in clients.

### Constraints
- The date suffix must be deterministic for a given publish date and should not depend on the wall clock at render time.
- The change needs to cover both newly imported traditional novenas and the existing checked-in traditional novena contracts.
- Standard novena titles and non-traditional publish paths should remain unchanged.

### Risks
- Updating only the importer default would leave existing traditional novena contracts with the old title format.
- A too-broad contract rewrite could accidentally change non-traditional novena titles or unrelated RSS metadata.
- The suffix could make some podcast-client displays truncate earlier than before, even though the underlying content is correct.

### Assumptions To Validate
- The publish date is already available as `runtime.date` when the title is rendered for both scheduled and manual runs.
- The desired suffix format is exactly ` - May 2, 2026`, with a leading space-hyphen-space separator.
- Existing traditional novena contracts should be updated in place, not just the importer template.

### Unknowns
- Whether the suffix should be added by updating every traditional novena contract, by changing a shared default, or by both.
- Whether any downstream release notes or migration notes should call out the title change for already-published feed items.

### Recommended Direction
- Plan a small two-part change: update the traditional novena title source used by new imports and migrate the checked-in traditional novena contracts to the same suffix, then verify with tests that the RSS item title ends in the publish date.

## Plan

### Summary
- Append the publish date to traditional novena RSS item titles so they read like `Traditional Novena to St Damien of Molokai Day 2 - May 2, 2026`.
- Reuse the existing publish-date context and RSS pipeline instead of introducing a new date source or feed formatter.
- The chosen approach is to update the traditional title template at its source and migrate the checked-in traditional novena contracts that still use the old pattern.

### What Already Exists
- `jobs/publish/formatting.py` already exposes `date_display` with the exact `May 2, 2026` shape.
- `jobs/novena_contracts/pipeline.py` already threads the publish date into runtime context and renders RSS titles from `runtime.publishing.rss.episode_title_pattern`.
- `jobs/novena_contracts/artifact_writer.py` and `jobs/publish/rss.py` already preserve the rendered title through sidecar write and RSS serialization.
- Existing tests already cover traditional contract import shape and the final RSS feed for novena publishes.

### Architecture
- The title flows from the traditional novena contract template into the novena runtime, then into the rendered sidecar job, then into the RSS item title.
- For this change, the only title source of truth should be the traditional novena title template itself.
- No new UI or network surface is needed; this is a contract-and-rendering change inside the existing publish pipeline.

Flow:
```text
traditional import / checked-in contract
  -> episode_title_pattern with {date_display}
  -> runtime.date -> date_display
  -> rendered title
  -> sidecar json
  -> RSS item title
```

### Concrete Changes
- `jobs/novena_contracts/url_import.py`
- `contracts/novenas/feast-days/*.json` for every traditional novena contract that still uses `Traditional Novena to {saint_name} Day {day}`

### Failure Modes
- If only the importer default changes, older checked-in traditional contracts will still publish with the old title pattern.
- If the publish date is not threaded into the title formatter, the suffix could fall back to the wrong day or disappear entirely.
- If the new suffix is too long for some podcast clients, the title may truncate earlier than before, but the episode remains valid.
