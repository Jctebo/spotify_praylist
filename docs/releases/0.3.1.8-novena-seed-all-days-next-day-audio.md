## Scope

### Problem
- The short-form novena pipeline currently treats each publish date as a separate runtime, so the first time a short-form novena shows up it still behaves like a single-day render instead of a fully seeded series.
- That means the system does not pre-create the whole 9-day arc in one pass, even though the short-form novena is conceptually a single devotional journey.
- The prompt path also feels too generic: it can carry a `theme`, but it does not require a short saint introduction and a distinct daily focus grounded in the saint's life for every day.
- Why now: we want the short-form novena to appear as an intentionally structured series, not as isolated day-by-day outputs that get discovered one at a time.

### Audience
- Primary user: the maintainer running the short-form novena publish job and checking the generated artifacts.
- Secondary users: listeners who should hear a saint-aware introduction and a distinct focus each day.
- Secondary stakeholders: future maintainers and automation that rely on stable short-form novena contracts, sidecars, and feed output.

### Current Status Quo
- `resolve_active_novenas()` returns only the short-form novena runtimes active for a specific date.
- `run_novena_pipeline()` renders and audio-builds every resolved short-form runtime in the publish window it is given.
- The prompt context already carries a `theme`, but the generator only sees a single-day prompt and does not enforce a saint intro or a full 9-day story arc.
- Existing short-form novena templates can vary day text, but they do not yet guarantee that each day focuses on a unique part of the saint's life.
- The result is a series that can feel repetitive instead of deliberately sequenced.

### Goal
- When a short-form novena is first encountered, materialize all 9 days, or only the remaining days if the sequence is already partially elapsed.
- Generate audio only for the next publishable day, which is tomorrow in the normal daily flow.
- Make every generated day begin with a 1-2 sentence saint introduction that leads into a daily focus based on that saint's life.
- Ensure each day's prayer or prompt theme is unique across the 9-day arc.
- Success criteria: one seeding run can create the whole series, future days remain represented as structured artifacts, only tomorrow gets synthesized audio, and reruns keep the daily focus structure stable.

### Constraints
- Preserve the existing short-form novena contract and RSS/archive model unless we prove a schema change is necessary.
- Keep backward compatibility with already-checked-in short-form novena contracts and previously published short-form novena items.
- Avoid changes to non-novena publish jobs, Spotify playlist logic, or unrelated prayer generators.
- Keep the prompt output deterministic enough for reruns, dedupe, and regression tests.
- If we add new metadata for day focuses, it should live in the novena contract or prompt layer rather than in an ad hoc runtime branch.

### Narrow Wedge
- Add a seeding step that expands one discovered short-form novena into a full 9-day schedule up front.
- Introduce prompt metadata for a saint intro and a unique day focus per day, derived from the saint's life.
- Gate TTS and audio generation so only the next publishable day is rendered during the seeding run.
- Keep the other days as text-only or contract-only artifacts until their publish date arrives.

### Non-Goals
- Do not redesign the entire novena engine.
- Do not build a saint biography editor or authoring UI.
- Do not rewrite all existing novena content by hand.
- Do not change feed URLs, playlist selection, or other prayer families.
- Do not retroactively regenerate every historical novena unless the new seeding path requires it.
- Do not add a new external dependency if the existing prompt and data model can carry the needed fields.

### Risks And Unknowns
- We do not yet know whether the unique daily focus should come from curated saint facts, an LLM-generated outline, or contract-stored theme data.
- If the "remaining days" logic is wrong, the seeding run could backfill past days or skip late-start novenas.
- Precreating contracts without audio may expose a mismatch between text artifacts and feed items unless the archive writer and RSS builder are updated together.
- If the prompts are too free-form, daily themes may drift or repeat instead of staying distinct.
- There may already be a reusable place in the novena contract schema for per-day prompts that we should extend instead of inventing a new structure.

### Recommended Next Step
- Run `/research-astack` to map the current short-form novena seeding, prompt, and publish paths, confirm where the full 9-day expansion should live, and identify the smallest schema change that can carry saint intro plus unique day-focus metadata.

## Research

### Scope Baseline
- The scoped change targets the short-form novena variant only.
- The desired behavior is to seed the whole 9-day series, or only the remaining days if the novena is already in flight, while generating audio only for tomorrow's publishable day.
- The prompt layer needs a saint introduction at the start of every day plus a unique daily focus grounded in that saint's life.

### Relevant Files
- `jobs/novena_contracts/pipeline.py` - orchestrates novena resolution, render, audio, artifact writing, and RSS publication; already accepts `publish_dates` and the `daily` / `bootstrap` / `reset` mode split.
- `jobs/novena_contracts/resolver.py` - computes each runtime's `active_day` from the feast window and decides which novenas are active on a given date.
- `jobs/novena_contracts/contracts.py` - owns `NovenaRuntime`, `NovenaRule.ai_config`, the default short-form title pattern, and the shared `theme` derivation from `ai_config.themes`.
- `jobs/novena_contracts/engine.py` - builds the prompt context, calls the model, and turns one runtime into text and audio fragments.
- `jobs/novena_contracts/audio.py` - turns one rendered runtime into one audio job and one MP3 sidecar pair.
- `jobs/novena_contracts/artifact_writer.py` - writes the JSON sidecar that later feeds RSS/archive output.
- `jobs/novena_contracts/rss_publisher.py` and `jobs/publish/rss.py` - rebuild the feed and dedupe by episode identity.
- `contracts/novenas/families/standard-9-day.json` - shared short-form novena family template and title pattern.
- `contracts/novenas/feast-days/our_lady_of_fatima_short_form.json` - concrete short-form feast contract that already uses the shared 9-day template.
- `contracts/novenas/templates/standard-9-day.json` - current generated-petition prompt for day-specific novena text.
- `tests/test_novena_pipeline.py` - covers multi-date novena publishing, title generation, and Fatima short-form coexistence.
- `tests/test_novena_contracts.py` - covers contract loading, title patterns, and `ai_config.themes` preservation.
- `tests/test_novena_engine.py` - covers prompt rendering, fragment assembly, and reusable novena text output.
- `tests/test_novena_resolver.py` - covers active-date selection and explicit-vs-selector coexistence.
- `.github/workflows/publish_audio.yml` - documents the existing daily / bootstrap / reset cadence for the novena pipeline.

### Current System Map
- A novena runtime is built for one active feast date, and `active_day` is derived from the current date relative to the feast window.
- `render_novena()` currently renders the current day's content; it does not seed future days by itself.
- The default prompt context already includes `day`, `saint_name`, `feast_name`, `date_display`, and a single `theme` value selected from `ai_config.themes`.
- `ai_config.themes` is the only built-in structured notion of daily variation today; it is indexed by day number but does not explicitly encode saint biography milestones.
- `run_novena_pipeline()` can process multiple dates in one run, but it still expects each date to resolve into the runtime(s) to be rendered and audio-built.
- Audio, artifact writing, and RSS publication are all keyed off one `episode_id` per runtime, so the current persistence model assumes one rendered day equals one published item.
- The RSS layer dedupes by episode identity, so keeping the identity stable matters if we introduce pre-seeded future-day artifacts.

### Reuse Opportunities
- Reuse `publish_dates` in `run_novena_pipeline()` as the existing multi-date orchestration seam rather than inventing a new top-level runner.
- Reuse the existing `ai_config.themes` and `runtime_context()` shape to carry richer day-focus metadata before adding a new prompt system.
- Reuse `TemplateSection.prompt` / `generate_text()` so the change can stay in prompt composition and contract shape instead of changing the OpenAI client path.
- Reuse the current sidecar and RSS idempotence model, which already key off episode identity and content hashes.
- Reuse the current short-form novena tests as the starting point for regression coverage instead of building a new harness.

### External References
- No external API or library change appears required for the scope itself.
- The only notable external dependency in the code path is the OpenAI SDK used by `jobs/novena_contracts/engine.py`, but the task should be solvable without changing SDK behavior.

### Constraints
- The change is scoped to short-form novenas and should not alter the traditional novena contract path.
- Existing published short-form novena items must remain valid and should not be renamed retroactively.
- The current schema only validates `ai_config.themes` as a list of strings; richer per-day saint-focus data likely needs either a new contract field or a more explicit prompt convention.
- `audio.py` and `artifact_writer.py` currently assume one runtime maps to one audio artifact, so a seeding-only future-day artifact may need to stay text-only until publish time.
- Any full-series seeding must stay compatible with the RSS/archive dedupe rules so tomorrow's audio does not overwrite seeded placeholders.

### Risks
- A naive "seed all days" change could accidentally publish audio for every day instead of only tomorrow.
- If the per-day focus data is too loose, multiple days may drift onto the same saint-life milestone or theme.
- If we add new artifact records without adjusting episode identity carefully, the RSS feed could collapse distinct days or create duplicate entries.
- There may not be an obvious existing place to store "remaining days" state for a novena that begins partway through its window.
- Because the feature touches prompt generation, output quality risk is high even if the plumbing is straightforward.

### Assumptions To Validate
- The short-form novena family is the only target, not the traditional Fatima novena or other prayer families.
- "Create all 9 contracts immediately" means create durable per-day artifacts up front, not necessarily render audio for each day.
- The daily publish cadence should remain tomorrow-only for audio unless the seeding run is explicitly bootstrapping.
- Unique daily focus can be derived from existing saint data, contract metadata, or deterministic LLM prompt scaffolding without a new authoring UI.
- The team is okay with contract/schema changes if that is the cleanest way to carry day-specific focus metadata.

### Unknowns
- Where the 9-day expansion should live: contract JSON, a seeding manifest, or a new runtime branch.
- Whether the seeding step should happen inside `jobs/novena_contracts/pipeline.py` or as a separate short-form novena seeder.
- How to represent late-start novenas so "remaining days" are created without backfilling already-passed days incorrectly.
- Whether the new saint intro / day focus text should be authored manually, generated from saint facts, or mixed.
- Whether existing tests should assert exact prompt text, exact contract shape, or only the observable output shape.

### Recommended Direction
- Run `/plan-astack` next. The codebase already has a workable short-form novena contract, runtime, and multi-date publish path, so planning should focus on the smallest schema and orchestration change that can seed all days while keeping audio publication limited to tomorrow.

## Plan

### Summary
- Build the short-form novena as a seeded 9-day series: the first eligible run should create durable artifacts for the full remaining window, while only the publishable day gets MP3 generation.
- Tighten the short-form prompt contract so every day starts with a 1-2 sentence saint introduction and then moves into a unique saint-life focus for that day.
- Reuse the existing `ai_config.themes` day-selection mechanism, but make it a 9-item saint-life outline for the short-form family instead of a small generic list.

### What Already Exists
- `jobs/novena_contracts/pipeline.py` already accepts multi-date publishing and already separates the RSS publish path from audio rendering.
- `jobs/novena_contracts/contracts.py` already derives one `theme` per active day from `ai_config.themes`, so the day-by-day selection seam is already there.
- `jobs/novena_contracts/engine.py` already passes saint, feast, day, and theme into the model prompt.
- `contracts/novenas/families/standard-9-day.json` and the checked-in short-form feast contracts already own the shared short-form title and theme shape.
- `scripts/new_novena_contract.py` already writes short-form novena contracts, so it should become the authoring-time guardrail for the new 9-theme expectation.
- `jobs/publish/audio.py::load_published_audio_jobs()` already skips sidecars that do not have a real MP3 file, which we can reuse for seed-only placeholders once they are marked clearly.

### Architecture
- We keep the current short-form novena contract model and do not introduce a separate UI or new service.
- The short-form contract becomes the source of truth for a 9-day saint-life outline through `ai_config.themes`.
- The prompt layer uses that outline to instruct the model to open with a brief saint description and then write the day's prayer around the selected life focus.
- The pipeline expands one active short-form runtime into all remaining days, writes JSON seed artifacts for those future days, and renders MP3 only for the publishable day.
- Future-day seed artifacts stay in `docs/audio/*.json` with `audio.rendered=false`; they are intentionally skipped by audio/archive loaders until the matching MP3 exists.

```text
short-form contract JSON
    -> load_novena_contracts()
    -> resolve_active_novenas(today)
    -> expand active runtime into remaining day dates
    -> render text for every seeded day
    -> write JSON seed artifact for each day
    -> render MP3 only for the publishable day
    -> publish_novena_rss() from MP3-backed jobs only
```

### UX And States
- No UI changes.
- Seeded state: a future novena day has a JSON sidecar with content, metadata, and an expected audio path, but no MP3 yet.
- Published state: tomorrow's day has both JSON sidecar and MP3, and only that day enters the feed/archive.
- Re-run state: rerunning the job should reuse the seed artifact if the content hash matches and only regenerate audio when the MP3 is missing.
- Error state: a short-form contract with fewer than 9 themes should fail validation before any audio or seed artifacts are written.

### Implementation Phases
#### Phase 1: Lock the 9-day short-form prompt contract
- Goal: make the short-form novena contract explicit enough to drive unique daily focuses and saint-intro prompts.
- Exact files to edit: `contracts/novenas/families/standard-9-day.json`, `contracts/novenas/feast-days/most_sacred_heart_of_jesus.json`, `contracts/novenas/feast-days/our_lady_of_fatima_short_form.json`, `contracts/novenas/templates/standard-9-day.json`, `jobs/novena_contracts/engine.py`, `jobs/novena_contracts/validators.py`, `scripts/new_novena_contract.py`
- Symbols/interfaces touched: `NovenaRule.ai_config.themes`, `generate_text()`, template prompt text, short-form contract validation, and the contract authoring CLI.
- Change summary: expand each short-form contract to a 9-item saint-life outline, require that shape at validation time, and teach the prompt layer to ask for a brief saint introduction before the day focus.
- Verification steps or commands: `python -m unittest tests.test_novena_contracts tests.test_novena_engine`
- Rollback note: restore the old theme arrays and prompt wording if the generated saint intro becomes too repetitive or the 9-theme validation is too restrictive.
- Dependencies on earlier phases: none.

#### Phase 2: Seed the remaining short-form days but render audio only for tomorrow
- Goal: make one eligible short-form run create the full remaining series without turning every day into audio.
- Exact files to edit: `jobs/novena_contracts/pipeline.py`, `jobs/publish/audio.py`, `tests/test_novena_pipeline.py`, `tests/test_novena_artifacts.py`
- Symbols/interfaces touched: `run_novena_pipeline()`, the short-form seeding loop, placeholder sidecar handling, and published-audio loading.
- Change summary: expand the active short-form runtime into all remaining days, write seed-only JSON artifacts for future days, render MP3 only for the publishable day, and keep placeholder seed artifacts out of published-audio scans until their MP3 exists.
- Verification steps or commands: `python -m unittest tests.test_novena_pipeline tests.test_novena_artifacts`
- Rollback note: collapse back to the current one-day-per-run behavior if placeholder sidecars prove too noisy or if feed/archive loading starts treating them like published items.
- Dependencies on earlier phases: depends on Phase 1 so the seeded days have a stable 9-item prompt outline.

### Failure Modes
- If the short-form contract still ships with too few themes, the prompt will repeat or drift instead of giving each day a unique saint-life focus.
- If seed-only artifacts are written without a clear placeholder flag, archive scans may warn about missing MP3s or accidentally treat them like published episodes.
- If the seeding loop does not dedupe by `episode_id`, the same future day could be seeded more than once on bootstrap or rerun.
- If audio rendering is not gated tightly enough, the feature could create MP3s for every seeded day instead of only tomorrow.

### QA And Test Matrix
- Contract loading: verify `load_novena_contracts()` accepts the updated short-form fixtures and rejects any short-form contract with fewer than 9 themes.
- Prompt rendering: verify the generated prompt includes a saint introduction instruction and the selected daily focus for the active day.
- Seeding flow: verify a first eligible short-form run writes nine day artifacts for a 9-day window, with only one MP3 created for the publishable day.
- Feed behavior: verify seeded placeholders do not appear in the published feed until the matching audio exists.
- Idempotency: verify rerunning the same date reuses the seed artifact and does not duplicate episode ids.
- Commands: `python -m unittest tests.test_novena_contracts tests.test_novena_engine tests.test_novena_pipeline tests.test_novena_artifacts`

### Rollout Notes
- No feature flag or data migration is planned.
- Existing published short-form episodes remain valid; the new behavior only affects future runs.
- The placeholder seed artifacts are backward-compatible because published-audio loading already keys off the presence of a real MP3, and the plan adds an explicit skip marker for the new seed-only state.
- If a preexisting short-form contract is missing the 9-theme outline, the job should fail closed before publish rather than silently falling back to a generic prompt.

### Not In Scope
- Traditional novena contracts, including the traditional Fatima fixture.
- New UI, editor, or saint biography authoring tool.
- A broader rewrite of the novena engine or RSS format.
- Retrofitting historical published novenas beyond the checked-in short-form contracts.
- Non-novena audio or Spotify playlist behavior.

### Open Questions
- None. The short-form-only scope and the seed-all-days / audio-tomorrow behavior are now fixed.
