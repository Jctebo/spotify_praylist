# v635 — The edit form paints every block at its day position: an off block stands greyed in place, never at the tail

## §1 Scope — the defect

John's words (2026-11-23 12:55 CT, verbatim): "the mid-morning toggle that is empty shows at the bottom. It should show in aligned with where it is in the day"

The defect (grounded firsthand in `app/worker/src/client.ts`): `opnEditSetHtml609(day)` paints the in-place edit form in two passes. Pass 1 iterates `orderedBlocks(day)` — the blocks present in the composed day payload (the ON blocks). Pass 2 appends every canonical block not seen — `['Morning','Midmorning','Midday','Afternoon','Evening','Night','Novenas']` — at the TAIL. An OFF block is absent from `day.blocks` (the fold composes the day from the profile's core list only), so it falls to the tail pass and paints after Novenas, out of its day position. In John's 2026-11-23 recording his standing profile (The Salesian Way: core Morning · Midday · Evening · Night, Novenas on) carries Midmorning OFF — it painted last-but-one at the bottom instead of second, between Morning and Midday. Afternoon, also OFF in his shape, painted at the very tail by the same seam.

John's order: every block stands at its day position regardless of on/off state or emptiness — an off block stands greyed IN PLACE, never at the tail.

Scope: the edit form's paint order only, in `opnEditSetHtml609`. No state, contents, toggle, drag, or write change; no SW pin change (bumps at Ship). Contract 946 (holder chain-v635-implement). Base: 56c156b (v632 ship tree, production pin ora-pro-nobis-v632-1). ## §2 Grounding — the ordering rule and the read-side finding

- The two-pass paint stands in `opnEditSetHtml609` (`app/worker/src/client.ts`, ~line 23989 at base), and its own header comment states the old rule: "Groups ON in the day stand in day order; groups OFF stand after them in canonical order." Pass 1's spine is `orderedBlocks(day)` — the day payload's blocks sorted by the standing block order (the v413 manual block order via `effectiveBlockOrder`), so the spine already carries each present block's standing day position.
- Canonical day order: Morning < Midmorning < Midday < Afternoon < Evening < Night < Novenas — the same list pass 2 carried (v609 repair 2 retired 'Podcasts' from it; no Podcasts group stands in the form).
- A group's own paint is `opnEditGroupHtml609(name)`: the group head with its ON/OFF toggle, the condensed contents rows, the empty note ("Nothing stands in this block.") when no contents stand, and the `p609off` greyed class when `opnGroupOn609(name)` reads off (shape core / Novenas layer). None of that changes — only the ORDER the groups are painted in.
- The form paints from the one function for BOTH scopes: today scope and standing scope both reach the form through `opnSetHtml609` → `opnEditSetHtml609(day)` while `opn604.editing` stands; the scope lives in the writes (`opn604.scope`), not in the paint. One fix covers both scopes.
- Praylist read-side finding (no shared seam, unchanged): `opnSetHtml609`'s read side does NOT share this seam — it builds its runs from `state.dayDescs` in composition order (the fold's order), never from the canonical tail pass. An off block carries no descriptors and paints no read-side run at all. Nothing on the read side changes in this release.

Example: spine [Morning, Midday, Afternoon, Evening, Night, Novenas] + absent Midmorning → [Morning, Midmorning, Midday, Afternoon, Evening, Night, Novenas].
