# Release 0.3.7.0 — TTS Spoken-Text Normalization Skill

## Scope

### Problem
- Prayer source contracts mix words intended for proclamation with print-only notation, rubrics, repetition shorthand, editorial notes, and listener instructions.
- Current TTS cleanup handles a small set of heading labels, but repository contracts still contain literal `V.`/`R.` markers, `St.`/`Sts.` and clergy abbreviations, `x1` notation, contact notes, and more than one thousand spoken “Pause here…” directions.
- Intention pauses need to become audio structure, optionally introduced by a sacred bell, rather than narration that says “pause here.”

### Audience
- Primary user: the repository maintainer preparing prayer contracts and generated fragments for text-to-speech.
- Secondary stakeholders: listeners who need natural proclamation, clear call-and-response voices, and intentional silence without editorial artifacts.

### Current Status Quo
- `jobs/publish/fragments.py` removes a limited set of line-leading labels such as `Prayer:` and `Response:`.
- `config/publish/contracts/auxilium-christianorum.json` already models `audio_role: versicle|response` and role-specific TTS voice overrides.
- Novena source text often embeds print conventions directly in large strings, leaving the renderer unable to attach distinct roles or non-speech cues safely.
- Contract cleanup is manual and inconsistent across active publish contracts and novena contracts.

### Goal
- Create a reusable repository-local Codex skill that audits prayer/audio contracts and converts source text into an explicit spoken-text contract without silently changing prayer meaning.
- Default `V.`/`R.` call-and-response sections to `versicle` and `response` roles, remove the printed labels from spoken text, and recommend distinct configured voices.
- Convert intention directions into a structured pause cue, with a sacred-bell cue before the silence when the target schema/audio pipeline supports it.
- Add first-class publish-contract `audio_cue` and `pause` blocks so normalized intention segments are directly executable by the active audio pipeline.
- Provide a built-in deterministic `sacred_bell` cue that is rendered and cached without requiring an external audio asset.
- Expand unambiguous honorific and saint abbreviations for pronunciation, including `St.` → `Saint`, `Sts.` → `Saints`, and configurable clergy abbreviations.
- Detect and classify repetition shorthand, headings/rubrics, optional directions, citations, editorial/contact notes, URLs/email addresses, and other non-spoken material.
- Produce an auditable report of every removal, expansion, role assignment, cue, ambiguity, and skipped change.

### Constraints
- Preserve prayer wording, theological meaning, names, punctuation needed for prosody, and canonical repeated prayer text.
- Never guess whether ambiguous prose, parentheticals, initials, scripture references, or abbreviations should be removed; flag them for review.
- Prefer structured fragments and metadata (`audio_role`, `audio_cue`, and `pause` blocks) over embedding stage directions in TTS text.
- Reuse the existing publish contract voice-role model where available.
- Treat source contracts as canonical data: require a preview/diff and validation before writing changes.
- Keep the skill concise and progressively disclose detailed normalization rules through a reference file.

### Narrow Wedge
- Add one repo-local skill named `normalize-prayer-tts` with:
  - a concise workflow in `SKILL.md`;
  - a reference catalog of repository-derived spoken/non-spoken conventions;
  - a deterministic read-only audit/normalization script that accepts JSON or plain text and emits normalized text/segments plus diagnostics;
  - fixtures/tests covering intention pauses, sacred-bell cues, `St.`/`Sts.`, `V.`/`R.` roles and two voices, repeat notation, editorial notes, and ambiguity preservation.
- Extend the active publish contract schema and renderer with:
  - `{"kind":"audio_cue","cue":"sacred_bell"}`;
  - `{"kind":"pause","duration_ms":5000,"purpose":"personal_intention"}`;
  - deterministic cue/silence caching, manifest hashing, and sidecar metadata;
  - exact explicit-pause timing without ordinary inter-fragment silence beside the pause.
- Extend structured novena `parts` with the same `audio_cue` and `pause` controls, including validator, renderer, hashing, sidecar, and exact-boundary behavior.
- Migrate `contracts/novenas/feast-days/sts_joachim_and_anne.json` as the first reviewed skill-driven contract:
  - expand `Sts.`/`Sts` to `Saints`;
  - replace the spoken intention direction with a sacred bell and five-second personal-intention pause in canonical `blocks`;
  - remove the spoken direction and keep equivalent prayer prose synchronized in legacy `sections`.
- Do not bulk-rewrite all existing contracts in this release; use the skill and its report to drive reviewed follow-up migrations.

### Non-Goals
- Selecting or purchasing new TTS voices.
- Custom bell uploads, arbitrary cue libraries, or user-authored synthesis parameters.
- Rewriting prayer language for style, modernizing archaic wording, or translating content.
- Automatically deleting every parenthetical, heading, citation, or note without contextual review.
- Migrating every historical novena contract as part of the skill’s initial release.
- Migrating novena contracts other than the explicit Saints Joachim and Anne pilot.

### Risks And Unknowns
- The synthesized bell timbre must remain reverent, audible, deterministic, and compatible with every output format supported by the fragment pipeline.
- Large novena strings can alternate Versicle and Response multiple times, requiring segmentation rather than a single string replacement.
- Some `St.` tokens may mean “Street” and some initials such as `R.` may be ordinary text; normalization must be line/context aware.
- Duplicate `blocks` and legacy `sections` in novena contracts may require both representations to remain synchronized during later migrations.

### Recommended Next Step
- Implement and validate the skill together with publish-contract `audio_cue`/`pause` blocks, then use the new schema in reviewed follow-up contract migrations.

## Plan

### Summary
- Build a repository-local `normalize-prayer-tts` Codex skill that converts prayer-source prose into structured spoken segments and an audit trail.
- Use a deterministic standard-library Python normalizer for repeatable high-confidence transformations, while requiring human review for ambiguous removals and schema-specific edits.
- Add executable publish-contract `audio_cue` and `pause` blocks so the skill’s normalized intention segments map directly into runtime audio.
- Keep bulk contract migration separate; this release makes the reusable normalization capability and runtime primitives trustworthy first.

### What Already Exists
- `jobs/publish/fragments.py::sanitize_tts_input` removes a narrow set of line-leading labels before rendering and establishes the project’s current TTS cleanup boundary.
- `jobs/publish/contracts.py` already carries `audio_role` from blocks into fragments and applies `audio_config.role_overrides`.
- `config/publish/contracts/auxilium-christianorum.json` demonstrates the canonical `versicle`/`response` roles and distinct voice configuration.
- Publish and novena pipelines already assemble ordered fragments with silence between them, so normalized segments map naturally to structured contract blocks.
- `jobs/publish/fragments.py::ensure_silence_fragment` already renders and caches deterministic silence, which can back explicit pause blocks.
- The repository’s skill layout under `.agents/skills/` is the correct location for project-specific Codex behavior.

### Architecture

```text
prayer text / JSON contract
             |
             v
     repository-aware audit
             |
       +-----+------+
       |            |
       v            v
high-confidence   ambiguous finding
normalization     preserved + flagged
       |
       v
ordered segments
(speech / audio_cue / pause)
       |
       v
publish contract expansion
       |
       v
TTS speech + generated bell + exact silence
```

- `SKILL.md` owns the safe workflow, role defaults, preview requirements, and target-schema mapping guidance.
- `references/conventions.md` owns detailed repository-derived classifications, examples, precedence, and ambiguous cases.
- `scripts/normalize_prayer_tts.py` owns pure functions and a CLI:
  - `normalize_text(text, options)` returns ordered segments plus diagnostics.
  - `audit_json(value, source)` recursively inspects likely spoken fields without mutating the input.
  - CLI accepts a text or JSON path, emits JSON to stdout, and exits nonzero only for invalid input or strict-mode unresolved findings.
- Output segments use:
  - `{"kind":"speech","text":"...","audio_role":"versicle|response"}` where a role is known;
  - `{"kind":"audio_cue","cue":"sacred_bell"}`;
  - `{"kind":"pause","purpose":"personal_intention","duration_ms":...}`.
- Diagnostics include stable rule id, severity, source path/line, original text, action, replacement/segments, and review requirement.
- Rule precedence is structural marker segmentation → intention cue/pause extraction → safe abbreviation expansion → artifact classification → whitespace cleanup. This prevents later regexes from erasing role boundaries or cue locations.

### UX And States
- No graphical UI is in scope.
- Default CLI state is preview-only JSON; it never overwrites an input contract.
- Success output contains normalized segments, summary counts, and diagnostics.
- Clean/empty input returns an empty segment list and zero findings.
- Ambiguous input remains present and receives a `review` diagnostic; default mode succeeds, while `--strict` returns a nonzero status.
- Invalid files, invalid JSON, unsupported encodings, or conflicting role markers produce concise stderr errors and nonzero exit codes.
- The skill must show the user a readable before/after summary and exact unresolved items before applying contract edits.
- Publish contracts reject unknown cue names and invalid pause durations with the entry id and source path.

### Failure Modes
- A role marker is mistaken for an initial: require line/start or post-sentence marker context; preserve and flag uncertain cases.
- `St.` meaning “Street” is expanded to “Saint”: use context guards for numbers/addresses and flag ambiguity.
- An intention instruction is narrated: ensure the instruction is removed only when replaced by a cue/pause segment, and test both sentence and standalone forms.
- A prayer sentence is removed as an editorial note: diagnostics default to review-only; no automatic deletion from source JSON.
- Bell synthesis fails or ffmpeg is unavailable: fail the audio job with the exact cue fragment and underlying ffmpeg error; never silently omit the cue.
- An explicit pause receives extra automatic gap time: per-boundary assembly tests verify zero default silence immediately beside a pause.
- Unknown cue names or excessive pause lengths enter a contract: reject them during contract normalization.
- Contract `blocks` and legacy `sections` diverge: detect both representations and require synchronized edits or stop.
- Strict mode finds unresolved artifacts: return a nonzero exit status with all findings rather than partial silent success.

### QA And Test Matrix
- Clean prayer prose remains textually unchanged except whitespace normalization.
- `STS`, `Sts.`, `ST.`, and `St.` expand only in saint-name contexts; street/address usages remain unchanged or review-only.
- `V.`/`R.` labels at line starts and alternating within a paragraph are omitted and create ordered role segments.
- Versicle and response segments map to distinct role overrides using the existing Auxilium contract pattern.
- Intention prompts become `sacred_bell` then `personal_intention` pause by default; disabling bell omits only the cue.
- `audio_cue` and `pause` blocks normalize and expand in sequence order while contributing no readable prayer text.
- Unknown cues, zero/negative durations, nonnumeric durations, and durations over 120 seconds fail validation.
- Sacred-bell audio is nonempty, cached, deterministic by format/version, and does not call a TTS renderer.
- Explicit pause audio uses the requested duration and suppresses ordinary boundary silence on both adjacent joins.
- Cue/pause metadata changes invalidate fragment and episode hashes.
- Sidecars identify generated control fragments without fake TTS provider metadata.
- Multiple intention prompts preserve surrounding prayer order.
- `x1`, `x3`, “repeat three times,” and similar shorthand produce explicit diagnostics and are never spoken literally.
- `Note:`, source/copyright/contact lines, postal addresses, emails, and URLs are review/removal candidates, not silent automatic deletions.
- Parentheticals and scripture citations remain unless a high-confidence rubric pattern applies.
- JSON audit reports stable paths for nested `text` fields and does not mutate the loaded object.
- Empty text/JSON structures return valid empty results.
- Invalid JSON and missing files return nonzero with readable errors.
- `--strict` succeeds for clean input and fails for unresolved review/error findings.
- Skill validation passes and contains no TODO placeholders.
- Existing repository tests remain green because no runtime behavior is changed.
