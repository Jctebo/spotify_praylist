# Release

- Version: 0.4.3.2
- Slug: daily-reflection-prompt-leakage
- Status: In progress

## Scope

### Problem
- Yesterday's Daily Reflection audio exposed prompt/instruction-like text and was incoherent to a listener.
- The failure is at the generated-reflection trust boundary: model output can pass validation even when it contains prompt or schema commentary, then flow directly into TTS.
- The current prompt also embeds a raw serialized helper-context payload, increasing the chance of instruction-shaped text being echoed.

### Audience
- Primary user: listeners of the Daily Reflection audio episode.
- Secondary stakeholders: the audio publishing pipeline and maintainers reviewing generated sidecars.

### Current Status Quo
- `jobs/publish/ignatian_reflection.py` requests plain narration and validates paragraph count, required markers, and word count.
- Validation rejects only a small fixed list of legacy headings; it does not reject prompt/schema leakage or enforce a prose-only output boundary.
- `jobs/publish/run_audio_pipeline.py` and the contract renderer trust the validated episode and send its fragments to TTS.

### Goal
- Publish a coherent Daily Reflection whose spoken text contains only listener-facing prayer/reflection prose.
- Success criteria:
  - prompt, schema, instruction, and model-commentary leakage is rejected and falls back deterministically;
  - a regression test proves a leaked response cannot reach audio fragments;
  - the full relevant test suite passes;
  - the deployed audio pipeline produces a Daily Reflection sidecar/audio artifact with no leakage markers, and the generated text is coherent on inspection.

### Constraints
- Preserve the four-paragraph, pause-oriented Daily Reflection contract and existing fallback behavior.
- Keep the patch narrowly scoped to the reflection generation/validation path and its tests.
- Deploy through the repository's GitHub Actions publish workflow; do not bypass the normal release path.
- The original yesterday MP3 is unavailable in this checkout, so verification must use the regenerated artifact plus sidecar/text and audio metadata inspection.

### Narrow Wedge
- Harden the Daily Reflection prompt/output boundary, add deterministic leakage detection and regression coverage, regenerate the target audio, and verify the resulting spoken contract.

### Non-Goals
- Rework the general TTS provider layer, Rosary generation, liturgical context resolution, or podcast UX.
- Change the Daily Reflection theological structure beyond coherence and output safety.
- Recover or retroactively replace an unavailable historical MP3 outside the normal pipeline.

### Risks And Unknowns
- Leakage may use novel wording not covered by a finite marker list; validation should combine explicit markers with structural prose checks and preserve safe fallback behavior.
- Production credentials/provider availability may prevent a local audio render; the deployed workflow must remain the final verification path if local rendering is unavailable.

### Recommended Next Step
- `/research-astack` should trace the exact generated-text-to-fragment-to-TTS path, inspect existing leakage validators in adjacent devotional generators, and identify the repository's deploy/run commands and artifact checks.

## Research

### Repository Map
- `jobs/publish/ignatian_reflection.py` builds the Daily Reflection prompt, calls OpenAI, applies the deterministic fallback, and validates the final four-paragraph episode.
- `jobs/publish/contracts.py` reconstructs the liturgical context, caches the episode, splits its four paragraphs into labeled audio fragments, and places the fragments in the audio job.
- `jobs/publish/audio.py` renders each fragment through the configured provider fallback, assembles the MP3, writes the JSON sidecar, and records readable text/resume markers.
- `jobs/publish/run_audio_pipeline.py` targets tomorrow by default, renders jobs, rebuilds the RSS feed, and writes the local audio archive.
- `.github/workflows/publish_audio.yml` runs the audio pipeline, syncs MP3s to R2, and deploys the Pages artifact on `main`; manual `bootstrap-no-cache` forces regeneration.

### Existing Safeguards
- Daily Reflection validation already enforces non-empty text, required welcome/final peace, selected observance and saint presence when supplied, exactly four paragraphs, and an 80–400 word spoken body.
- Rosary generation has reusable output-boundary checks for markdown and prompt/schema echoes, including `requirements:` and `return json`; this is the closest established pattern to reuse.
- The current reflection validator only rejects exact legacy headings and therefore allows other prompt leakage.

### Root Cause Confirmation
- The model receives a large user prompt containing rules, labels, episode title, and a serialized `DailyLiturgicalContext` payload. The response is plain text, but no structured response schema or generic prompt-commentary filter protects the boundary.
- Recent history shows the reflection validator was relaxed in `2c713ae` from strict saint/quote/examen requirements to looser checks while adding more context fields to the prompt. That change widened the accepted output space without adding equivalent leakage checks.
- The generated episode is cached and reused by both readable text and audio expansion, so leakage accepted by `_validate_episode` is deterministically propagated to TTS and the sidecar.
- No yesterday MP3/sidecar exists in the checkout, so the historical artifact cannot be sampled locally; the regenerated target artifact and sidecar text will be the reproducible verification target.

### Deployment And Verification
- Local command: `python -m jobs.publish.run_audio_pipeline` (default tomorrow; set `PUBLISH_MODE=bootstrap-no-cache` for today and tomorrow with cache bypass).
- Production command: dispatch the `Publish Prayer Audio` GitHub Actions workflow with `bootstrap-no-cache` after the change lands on `main`.
- Verification will inspect the generated Daily Reflection sidecar `text` and `audio_fragments`, scan for prompt/schema markers, confirm the MP3 exists and has non-zero duration, and confirm the public feed entry points to the regenerated episode.

## Plan

### Summary
- Harden the Daily Reflection generated-text trust boundary and regenerate the target audio.
- Use a narrow source/test patch: reduce instruction-shaped context exposure, add a shared leakage detector for reflection prose, and make validation fail closed to the existing deterministic fallback.

### What Already Exists
- Existing OpenAI Responses call and deterministic fallback in `ignatian_reflection.py`.
- Existing four-paragraph validator and contract/audio fragment pipeline.
- Existing Rosary prose validation pattern and audio pipeline workflow.

### Architecture
- Keep generation and fallback unchanged at the contract boundary.
- In `ignatian_reflection.py`, pass labeled context values needed for the prayer rather than a raw serialized helper dictionary, and add a centralized `_reject_prompt_leakage` check used by episode validation.
- If generated prose contains markdown, headings, prompt instructions, schema keys, or model commentary, raise validation error; `build_ignatian_reflection_episode` catches it and emits the deterministic fallback.
- The contract layer continues to cache only the validated episode, so both text and TTS fragments receive the safe result.

### Concrete Changes
- Edit `jobs/publish/ignatian_reflection.py`:
  - replace raw `context.to_dict()` prompt injection with explicit labeled values;
  - add prompt/schema/commentary marker validation and markdown/heading checks;
  - preserve existing structural, observance, saint, word-count, and final-line checks.
- Edit `tests/test_publish_ignatian_reflection.py`:
  - add a generated-response regression case containing prompt leakage and assert deterministic fallback;
  - add direct validator coverage for representative heading/schema/commentary echoes;
  - assert fallback text remains listener-facing and contains no leakage markers.
- Update this release artifact's `Progress`, `QA`, and `Release Notes` during implementation and shipping.

### UX And States
- No UI changes.
- Generated valid prose: published normally as four labeled audio fragments.
- Invalid/leaked model output: rejected and replaced with deterministic, coherent four-paragraph prose; sidecar records the fallback reason.
- Missing provider credentials: existing deterministic fallback remains the safe path.

### Implementation Phases

#### Phase 2: Full validation and review

#### Phase 3: Deploy and audio verification
- Goal: publish regenerated Daily Reflection audio and prove the artifact is clean.
- Commands: ship to `main`, dispatch `publish_audio.yml` with `bootstrap-no-cache`, inspect sidecar/audio/feed outputs.
- Rollback: rerun the prior known-good release/workflow if production artifact verification fails.
