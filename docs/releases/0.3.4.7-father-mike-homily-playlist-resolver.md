## Scope

### Problem
- The Spotify `Sunday` playlist should keep Sunday homily items current even when the refresh job runs on a non-Sunday weekday.
- `config/spotify/contracts/fr-mike-sunday-homily.json` and `config/spotify/contracts/barron-sunday-sermon.json` both already resolve the latest available episode by release date.
- Both contracts were still gated with `weekdays: ["Sunday"]`, so the queue builder skipped them unless the job's local runtime weekday was Sunday.
- The user clarified that the desired behavior is to pull the latest homily whenever it is available and to include Bishop Barron alongside Father Mike.

### Audience
- Primary user: the maintainer running the automated Spotify playlist refresh.
- Secondary stakeholders: Sunday playlist listeners who expect the latest Father Mike and Bishop Barron homilies to remain present.

### Current Status Quo
- Playlist identity is repo-owned in `config/spotify/playlists/sunday.json`.
- Playlist membership and ordering are Notion-owned; a row must be enabled, have `Output Folder` matching `Sunday`, match contract `notion_name`, and have an `Order`.
- The homily resolvers already call `latest_by_release_date(...)`:
  - `SUNDAY_FRMIKE` uses `DEFAULT_SHOWS["FRMIKE_SUNDAY"]`.
  - `SUNDAY_BARRON` uses `DEFAULT_SHOWS["BARRON_SUNDAY"]`.
- The contract-level weekday gates were the only repo-owned reason these contracts would not run on non-Sunday refreshes.

### Goal
- Let `Fr. Mike Sunday Homily` and `Bp. Barron Sunday Sermon` resolve on the Spotify `Sunday` playlist regardless of the refresh weekday.
- Keep the existing latest-episode resolver semantics.
- Keep Notion-owned playlist membership and order unchanged.
- Add regression coverage proving both checked-in homily contracts are ungated and resolve during a non-Sunday Sunday-playlist queue build.

### Constraints
- No Spotify playlist id change.
- No Notion schema change.
- No runtime resolver rewrite.
- No live Spotify or Notion dependency in tests.

### Narrow Wedge
- Remove `weekdays` from both homily contract JSON files.
- Add focused offline tests around contract loading and non-Sunday queue resolution.

### Non-Goals
- Do not migrate homily contracts to `spotify_episode_lookup`.
- Do not change other latest-release resolvers.
- Do not repair or create Notion rows in this release.
- Do not change publish-audio or podcast RSS generation.

### Risks And Unknowns
- Bishop Barron still needs an enabled Notion row mapped to `Sunday`; the repo can make the contract eligible, but Notion controls whether it is selected.
- `latest_by_release_date(...)` selects the newest published episode, not a title-verified Sunday-specific episode.
- The latest resolver scans only the first page plus one `next` page per market, which is existing behavior outside this change.

### Recommended Next Step
- Run targeted tests, then validate a selected `Sunday` playlist refresh with credentials if needed.
