# Release 0.1.5.7 - Morning Prayer Spotify Show Remap

## Scope

### Problem
- The Morning Prayer Spotify source still points at the old show id, so the playlist can be wired to the wrong podcast show even when the publish pipeline is correct.
- Morning Prayer publishing already uses date-scoped titles like `Morning Prayer for April 27, 2026`, so the Spotify mapping needs to follow the new show source cleanly.
- The publish workflow also runs too late for the downstream Spotify refresh to treat the new episode as immediately available.
- Morning Prayer should publish earlier in the day so the playlist refresh can consume the newly published episode with minimal delay and fewer race conditions.

### Audience
- Primary user: the maintainer who publishes Morning Prayer and expects the Spotify playlist to reflect the correct Morning Prayer show.
- Secondary stakeholders: listeners who expect the Morning Prayer playlist to surface the latest published episode.
- Secondary stakeholders: future maintainers who need the show source and schedule to live in repo-owned config instead of hidden assumptions.

### Current Status Quo
- `jobs/publish/contracts.py` already produces date-scoped Morning Prayer titles, descriptions, and episode ids.
- `jobs/playlist/refresh_playlist.py` still resolves `MORNING_PRAYER_MONTHLY` against the show id wired into the resolver defaults, and its matching logic still assumes the old month/year title shape.
- The current Spotify show id for `MORNING_PRAYER_MONTHLY` is hard-coded in the resolver defaults at `3oP4SunSyZhwX7GUWw3HcR`.
- The requested Spotify show URL points at a different show id: `4PNxb0OazrkcEp3FAggRoD`.
- `config/spotify/contracts/morning-prayer.json` and `config/spotify/contracts/morning-prayer-monthly.json` both point at the same resolver today.
- `jobs/publish/run_audio_pipeline.py` already publishes Morning Prayer audio and RSS, but the dedicated publish workflow does not yet run on its own early-morning schedule.
- `.github/workflows/daily.yml` currently runs the Spotify refresh at `07:00 UTC`, which is later than the proposed publish window.

### Goal
- Point the Morning Prayer Spotify resolver at the correct Spotify show id the user provided.
- Change the resolver behavior so it fits the new date-scoped Morning Prayer show format, not just the old month/year matching rule.
- Keep the resolver aligned with the new date-scoped Morning Prayer show format while changing the show source it maps to.
- Run the Morning Prayer publish workflow separately at `06:00 UTC` so the episode is published well before the Spotify refresh runs.
- Keep the playlist refresh and publish pipeline idempotent so same-day reruns still replace only the intended episode and do not disturb older content.

### Constraints
- Keep the change repo-owned and declarative where possible; the show id should come from config or resolver defaults, not an ad hoc local override.
- Preserve the existing daily Spotify refresh workflow; this change should add an earlier publish window, not rework the refresh job itself.
- Do not change the existing Morning Prayer publish title format; the date-scoped title is already the contract surface the resolver should align with.
- GitHub Actions schedules are UTC-based, so the new publish cron must be expressed in UTC.

### Narrow Wedge
- Update the Spotify show source to the requested show id and keep the contract names stable so existing playlist membership continues to work.
- Update the Morning Prayer resolver match rule so it understands the new date-scoped episode format on that show.
- Add a separate `06:00 UTC` schedule for the Morning Prayer publish workflow so publication runs before the downstream Spotify refresh cadence.

### Non-Goals
- Do not redesign the broader Spotify playlist refresh system.
- Do not change other resolver keys or other podcast contracts.
- Do not add a UI for choosing a show or schedule.
- Do not backfill historical playlist membership beyond what the resolver naturally surfaces.
- Do not change the published Morning Prayer text/audio title format, which is already handled by the publish pipeline.

### Risks And Unknowns
- The requested Spotify show change is intentionally limited to the `MORNING_PRAYER_MONTHLY` resolver source, so other Morning Prayer contract references stay unchanged.
- If the new show id is wrong, the resolver could still point at the wrong podcast even though the publish pipeline is healthy.
- The resolver may need a matching rule that understands the new date-scoped Morning Prayer episode titles on that show, or it may need to select the latest episode by release order if the new show is consistently date-scoped.
- A `06:00 UTC` publish schedule is earlier than the current refresh schedule, and it leaves a safer buffer before the downstream refresh.

### Recommended Next Step
- Run `/research-astack` to confirm the correct show id source of truth, determine whether the new show should be matched by exact date-scoped title or by newest-episode ordering, and map the exact workflow and resolver-default files that should move to the new 06:00 UTC publish window.
