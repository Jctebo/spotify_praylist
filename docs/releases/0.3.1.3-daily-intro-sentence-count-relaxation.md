# Release 0.3.1.3 - Daily Intro Sentence Count Relaxation

Date: 2026-05-02
Status: Shipped
Branch: fix/daily-intro-sentence-count
Depends On: 0.3.1.2

## Scope

### Problem
- The Gospel-free Morning Prayer daily intro fallback was still too strict about sentence count.
- Any extra sentence could turn a tolerable response into a fatal publish error even after the Mass-reading fallback succeeded.

### Goal
- Allow the Gospel-free daily intro path to accept a flexible sentence count.
- Keep the Gospel-present path strict at exactly three sentences.
- Keep the rest of Morning Prayer behavior unchanged.

### Constraints
- Do not relax the Gospel-present validation path.
- Do not change the liturgical content requirements or downstream audio/text assembly.
- Keep the fix narrow to the Gospel-free daily intro validator.

### Risks
- Over-permissive validation could let poor OpenAI output through.
- The relaxed check should still reject obviously malformed intros.

## Research

### Scope Baseline
- `jobs/publish/daily_intro.py` already has the Gospel-free prompt path, but `_validate_daily_intro(...)` still enforced a sentence-count limit when `allow_missing_gospel` was true.
- The failure mode was runtime-only: the prompt could return a readable intro with an extra short sentence, but the validator would abort the publish.
- The existing daily intro tests already cover the Gospel-free path, so the change could stay narrow and be proven with a single regression test update.

### Relevant Files
- `jobs/publish/daily_intro.py` - contains `_validate_daily_intro(...)`, the Gospel-free prompt branch, and the OpenAI prompt path.
- `tests/test_publish_daily_intro.py` - covers the Gospel-free fallback and the daily intro validation rules.

### Reuse Opportunities
- Reuse the existing Gospel-free prompt path instead of changing the prompt wording.
- Reuse the current sentence-splitting helper and only relax the count check for the Gospel-free branch.
- Reuse the current daily intro tests to prove the new tolerance.

### Risks
- If the validator becomes too loose, a malformed Gospel-free intro could slip through.
- If the validation rules diverge too far between the Gospel-present and Gospel-free paths, future debugging will get harder.

## Plan

### Summary
- Relax the Gospel-free daily intro validator so the Gospel-free path tolerates extra sentences as long as the opening line is correct.
- Keep the Gospel-present path strict at exactly three sentences.
- Update the Gospel-free regression test so a longer response is accepted.

### What Already Exists
- `_validate_daily_intro(...)` already takes `allow_missing_gospel`.
- `build_daily_intro_text(...)` already chooses the Gospel-free prompt when the Gospel is unavailable.
- `tests/test_publish_daily_intro.py` already proves the fallback path works end to end.

### Architecture
- The validation rule should only differ by the Gospel flag:
  - Gospel present: exactly three sentences.
  - Gospel omitted: at least one sentence, with no hard upper bound.

### Concrete Changes
- `jobs/publish/daily_intro.py`
  - Relax `_validate_daily_intro(...)` so the Gospel-free branch accepts 2 or 3 sentences.
- `tests/test_publish_daily_intro.py`
  - Update the Gospel-free fallback test to assert that a three-sentence response is tolerated.
