# Release 0.1.0.1 - morning-prayer-audio-construction-cleanup

- Status: Shipped
- Last Updated: 2026-03-23

## Scope

### Problem
- Morning Prayer still carries old construction logic that we do not want to repeat when future prayers are added.
- The current page-content path still reflects legacy construction instead of a generic reusable pattern.
- We want the audio construction layer to stay focused on audio, not on playlist building or other side effects.
- The current Morning Prayer flow has enough old construction baggage that it is easier to cleanly remove it now than keep carrying it forward.
- Spotify playlist jobs still exist in the repo, and for now we only want to disable those jobs while leaving the underlying code in place for a later prune-or-keep decision.
- The Notion Opus Dei page itself should be completely replaced by the new Morning Prayer construction, not incrementally patched.

### Audience
- Primary user: the maintainer who needs Morning Prayer audio construction to be simpler and easier to reason about.
- Secondary stakeholders: future prayer configs that will reuse the same construction pattern without inheriting Spotify-specific baggage or page-content assumptions.

### Current Status Quo
- The Morning Prayer config still contains Spotify resolver metadata.
- The current construction path still knows about Spotify playlist creation even though this branch should focus on audio.
- Page content is still partially shaped by the old construction model.
- Morning Prayer already has a JSON-driven contract, so the remaining cleanup is about removing unused construction concerns and rewriting the content path.

### Goal
- Build a generic prayer construction pattern that can apply to future prayers we add.
- Remove Spotify configuration from the construction path.
- Disable Spotify playlist jobs for now.
- Rewrite Morning Prayer page content generation so it reflects the new generic contract cleanly.
- Replace the Notion Opus Dei page entirely with the new construction pattern.
- Keep audio construction working end to end while simplifying the page-content side.

### Constraints
- Morning Prayer must still generate audio files for the existing OneDrive flow.
- The branch should not reintroduce novena generation or broader prayer rebuild work.
- Do not carry Spotify playlist creation through the Morning Prayer contract once the cleanup is applied.
- The branch should disable Spotify playlist jobs without immediately deleting the underlying Spotify code paths.
- The page-content rewrite should establish the generic pattern we will reuse when future prayers are added.

### Narrow Wedge
- Strip Spotify fields and playlist-creation behavior from the construction path.
- Disable the Spotify playlist jobs so no active workflow depends on them.
- Replace the Notion Opus Dei page content with the new Morning Prayer construction rather than preserving the old page shape.
- Rewrite the Morning Prayer content composition so it becomes the reusable pattern for future prayers.
- Keep the change anchored in Morning Prayer first, but shape it so future prayers can plug into the same construction pattern.

### Non-Goals
- Rebuilding Spotify playlist automation.
- Re-adding other prayers in this branch.
- Reworking the devotional image job.
- Reintroducing novena generation in this branch.
- Preserving the old Notion Opus Dei page content layout or page-construction behavior.

### Risks And Unknowns
- Removing Spotify configuration may reveal other code paths that still assume playlist construction exists.
- The page-content rewrite may require trimming more legacy helper branches than expected.
- Audio construction could regress if page-content cleanup accidentally removes shared resolver behavior.

### Recommended Next Step
- Use `/research-astack` to map exactly where Spotify playlist construction and page-content generation are still coupled to Morning Prayer, so the cleanup can delete the right branches without breaking audio.

## Research

### Scope Baseline
- This branch is about making the Morning Prayer construction path reusable for future prayers while cleaning out Spotify playlist jobs and replacing the Notion Opus Dei page construction.
- Morning Prayer remains the concrete pilot, but the desired shape should work for later prayer configs without copying the old construction baggage.

### Relevant Files
- `jobs/notion/generate_prayer.py`: generic prayer runner entrypoint that loads the prayer JSON contract and selects the target Notion row.
- `jobs/notion/generate_page_audio.py`: current construction engine; Morning Prayer still delegates into this file for resolver planning, page-content blocks, and audio assembly.
- `config/morning-prayer/morning-prayer.json`: the Morning Prayer contract that still contains the Spotify resolver at the end of the resolver list.
- `config/morning-prayer/content/*.txt`: file-backed prayer text sources already used by the Morning Prayer contract.
- `config/morning-prayer/templates/monthly-intention/`: monthly rotation content for the monthly intention resolver.
- `.github/workflows/daily.yml`: the active Spotify playlist refresh workflow that should be disabled in this branch.
- `jobs/playlist/refresh_playlist.py`: the Spotify playlist refresh runtime that the disabled workflow still invokes.
- `scripts/run_daily_refresh_local.ps1`: local mirror of the Spotify playlist refresh workflow.
- `tests/test_generate_prayer.py`: current coverage for the generic Morning Prayer runner entrypoint.
- `tests/test_page_audio_job.py`: current coverage for Morning Prayer planning, page content, and audio assembly.

### Current System Map
- The Morning Prayer runner now loads a repo-local JSON contract and passes it into the page-audio engine.
- `build_morning_prayer_plan(...)` in `jobs/notion/generate_page_audio.py` still drives the actual content assembly by resolver kind.
- Morning Prayer currently emits `page_content` blocks for text targets and audio fragments for every resolver except the disabled Spotify branch.
- The `spotify` resolver is still present in the Morning Prayer contract, but the current plan is to remove its construction effect and replace the Notion Opus Dei page content wholesale.
- Spotify playlist creation is a separate repo capability today: the daily refresh workflow, local refresh script, and `jobs/playlist/refresh_playlist.py` are the active path.
- The Spotify job path is therefore a workflow/runtime boundary question, not a Morning Prayer-only concern.

### Reuse Opportunities
- Reuse the generic prayer runner entrypoint as the stable input layer for future prayer configs.
- Reuse the `build_morning_prayer_plan(...)` resolver traversal shape as the template for later prayer construction.
- Reuse the file-backed Morning Prayer text sources and the monthly-intention template folder as the first generic content pattern.
- Reuse the existing OneDrive audio materialization path; the cleanup should simplify page/content construction, not rebuild audio delivery.
- Reuse the Spotify refresh code only as orphaned legacy code for now, if the branch merely disables jobs rather than deleting the runtime.

### External References
- Notion API page and relation update behavior for Opus Dei row replacement.
- GitHub Actions workflow triggers for daily refresh jobs.
- Spotify playlist refresh behavior in the repo’s existing refresh script and workflow.

### Constraints
- The branch should not reintroduce novena generation.
- Audio must still be written out as files for the OneDrive flow.
- The new content construction pattern should be reusable for later prayer configs.
- Spotify playlist jobs should be disabled without necessarily deleting the underlying implementation in this branch.
- The Notion Opus Dei page content should be replaced, not tweaked in place.

### Risks
- The Morning Prayer content rewrite may still depend on helper branches that also serve audio, so trimming too aggressively could break the surviving path.
- The Spotify resolver is still embedded in the contract, so disabling the job without cleaning the contract could leave confusing dead metadata behind.
- Disabling the Spotify workflow could break any existing manual or scheduled runs that still expect that job name.
- Replacing the Opus Dei page wholesale could remove page layout behavior that current tests assume.

### Assumptions To Validate
- The generic construction shape can be extracted from Morning Prayer without needing a second parallel implementation.
- The Spotify playlist job can be disabled independently of the Morning Prayer contract cleanup.
- The page-content rewrite can be made generic enough to support future prayers without bringing back playlist creation.
- The current audio output path can stay intact while the page-content path is replaced.

### Unknowns
- Whether the Spotify resolver should be removed from the Morning Prayer contract immediately or left orphaned until a later prune pass.
- Whether disabling the Spotify job means deleting the workflow file, changing its trigger, or skipping the job at runtime.
- Which parts of `build_morning_prayer_plan(...)` are genuinely generic enough to reuse for future prayers versus Morning Prayer-specific scaffolding.
- How much of the existing Opus Dei page body can be replaced without needing a separate migration/repair phase.

### Recommended Direction
- Treat Morning Prayer as the first generic construction example, disable Spotify playlist jobs in parallel, and use `/plan-astack` next to separate what must be rewritten from what can simply be orphaned for later pruning.
