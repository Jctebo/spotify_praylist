# Release 0.3.10.2 — Novena Intention Pause Normalization

Status: Shipped
Branch: enhancement/novena-intention-pause-normalization
Last Updated: 2026-07-25

## Scope

### Problem
- Some novena source text includes a request/intention instruction that reaches TTS without the intended sacred bell and personal-intention pause.
- The normalizer recognizes some natural variants, but the catalog still contains an embedded instruction such as `grace we implore mention your intentions here` that does not have an isolated sentence boundary.

### Audience
- Primary user: listeners praying along with Ora Pro Nobis novena audio.
- Secondary stakeholder: maintainers importing or authoring novena prayer text.

### Current Status Quo
- The prayer-TTS normalizer maps clear standalone request/intention directions to a `sacred_bell` followed by a five-second personal-intention pause.
- The 93 checked-in novena contracts already contain 232 sacred bells and 232 matching personal-intention pauses, but an audit found six remaining spoken candidate fields in `st_clare.json`, across both `blocks` and legacy `sections`.

### Goal
- Audit every checked-in novena contract against the expanded personal-intention rules.
- Detect high-confidence request/intention instructions, including embedded variations of “mention your intentions here.”
- Emit one non-spoken `sacred_bell` cue and one 5,000 ms `personal_intention` pause in their place.
- Migrate every confirmed finding into synchronized structured `blocks` and readable legacy `sections`, while preserving prayer text and routing ambiguous language to review.

### Constraints
- Do not alter theology, canonical prayer wording, or unrelated editorial notes.
- Keep the normalizer preview-only; it must not rewrite contracts itself.
- Preserve the existing JSON output contract and strict-mode behavior except for newly resolved high-confidence phrases.
- Validate all 93 contracts after migration; each inserted bell must have exactly one matching personal-intention pause.

### Narrow Wedge
- Extend the normalizer for the verified embedded wording family, audit all 93 novena contracts, and migrate only the catalog findings it identifies with high confidence.

### Non-Goals
- Changing bell synthesis, pause duration, TTS providers, or voice assignments.
- Removing unclear requests embedded in ordinary prayer prose.
- Rewriting unrelated novena prose or reformatting contracts with no confirmed finding.

### Risks And Unknowns
- Broad matching could mistake a devotional petition for an instruction to the listener.
- `blocks` and legacy `sections` can drift if their migrations are not generated and verified together.
- The catalog may expose further wording forms after the first audit pass; those must remain review-only until tested.

### Recommended Next Step
- Define the exact migration boundary, implement an auditable catalog scanner, and plan a contract-by-contract update with paired artifact verification.

## Research

### Relevant Files
- `.agents/skills/normalize-prayer-tts/scripts/normalize_prayer_tts.py`: preview-only normalizer; `INTENTION_RE` identifies personal-intention directions and `_append_speech` emits the cue/pause segments.
- `.agents/skills/normalize-prayer-tts/scripts/test_normalize_prayer_tts.py`: direct unit coverage for text normalization and CLI behavior.
- `.agents/skills/normalize-prayer-tts/references/conventions.md`: user-facing rule documentation for personal-intention structure.

### Findings
- The current expression already recognizes several `pause …` forms and `mention your request/intention here`, but it does not recognize standalone listener prompts such as `mention your request` or imperative `state/offer your intention` forms.
- The existing structured output, 5,000 ms default, `--no-bell` behavior, and `personal-intention-pause` diagnostic already provide the required rendering contract.
- Novena JSON contains numerous historical notes describing `mention request here`; those are intentionally ignored because the auditor only scans likely spoken keys.

## Plan

### Summary
- Complete the normalizer vocabulary, audit all 93 checked-in novena contracts, then migrate every high-confidence finding into existing structured controls.
- Treat `blocks` as the audio source of truth and update matching legacy `sections` in the same change so listeners never hear a direction while readable text remains truthful.

### What Already Exists
- `INTENTION_RE` finds a personal-intention instruction before `_append_speech` splits speech into structured segments.
- `_append_speech` emits `sacred_bell` and a 5,000 ms `personal_intention` pause, or only the pause when `--no-bell` is selected.
- The catalog has 93 contracts, 232 `sacred_bell` controls, and 232 paired personal-intention pauses.
- `jobs/novena_contracts/validators.py` validates structured `audio_cue` and `pause` parts; `tests/test_novena_contracts.py` and `tests/test_novena_engine.py` cover contract loading and rendered fragment order.

### Architecture

```text
93 novena JSON contracts -> recursive read-only audit -> reviewed findings report
                                                    | high confidence
                                                    v
       legacy sections <- synchronized migration <- structured blocks/parts
                                                    |
                                                    v
                                     sacred_bell -> 5,000 ms personal-intention pause
```

### UX And States
- No UI changes.
- Clear instruction: audit reports an actionable source path; migration produces non-spoken bell/pause controls at that exact position.
- No findings: audit succeeds without source changes.
- Ambiguous phrase: audit retains it as review-only and the migration halts rather than guessing.
- Invalid contract or unpaired controls: validation fails before audio publishing.

- Goal: prevent future imports or edits from reintroducing spoken personal-intention directions.

- Verification: run the normalizer suite, relevant novena contract/engine suites, strict catalog audit, and `git diff --check`.
- Rollback: retain the migrated controls while relaxing only a test if the policy is deliberately revised.

### Failure Modes
- An overly broad expression removes part of a petition; explicit negative cases and review-only routing detect it.
- A legacy section and structured block diverge; paired migration checks and contract rendering tests detect it.
- A source is missed; the deterministic 93-contract audit exposes its path for a follow-up rule or manual review.
- A cue lacks its pause or the pause duration changes; count and fragment-order assertions fail.

### QA And Test Matrix
- Canonical, standalone, and embedded prompts emit speech → bell → 5,000 ms pause → speech.
- Petitions containing `ask`, `implore`, or `intention` without the specific listener instruction remain speech.
- Directory audit scans 93 contracts in deterministic order and does not modify a source file.
- Saint Clare’s affected days render a bell/pause at each migrated instruction and do not send the direction to TTS.
- Each migrated contract has matching counts of `sacred_bell` and `personal_intention` controls.
- Run `python .agents/skills/normalize-prayer-tts/scripts/test_normalize_prayer_tts.py`, targeted novena tests, the full contract suite, strict catalog audit, and `git diff --check`.

### Rollout Notes
- Land the rule and audit helper with the contract migration in one release so there is no window where a detected instruction remains spoken.
- Keep the generated audit report out of version control unless it becomes a documented fixture; the tests are the durable enforcement point.

### Not In Scope
- Bell synthesis, pause duration, TTS provider/voice changes, and unrelated prose cleanup.
- Removing ambiguous rubrics, citations, provenance, or other audit findings not classified as high-confidence personal-intention instructions.

### Open Questions
