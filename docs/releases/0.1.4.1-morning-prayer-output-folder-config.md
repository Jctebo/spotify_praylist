- Notes: The shipped fix moved Morning Prayer's OneDrive destination into the custom TTS contract, removed the `random-intention` resolver, and switched the remote publish step to sync the contract-owned folder so stale files are pruned.

## Scope

### Problem
- Morning Prayer needed one config-owned OneDrive destination instead of a hardcoded folder.
- The remote publish step needed to mirror that destination so extra files could not linger.
- The contract no longer needed the `random-intention` resolver.

### Goal
- Keep the OneDrive destination in `config/custom_tts/morning-prayer.json`.
- Mirror only the contract-owned Morning folder during remote publish.
- Remove the `random-intention` resolver from the active contract.

### Constraints
- Preserve the rest of the Morning Prayer assembly and the custom TTS loader boundary.
- Keep the managed-output cleanup behavior for generated audio and metadata.
- Do not reintroduce legacy contract discovery or fallback paths.

## Research

- The Morning Prayer contract already drives the local runtime through `output_path`.
- The wrapper and remote workflow can both derive the publish folder from the same config value.
- Local managed-output cleanup can prune stale `.mp3` and `.json` files before regeneration.

## Plan

- Normalize the runtime output folder from `output_path`.
- Read the same config value in the remote publish step.
- Switch the remote copy to `rclone sync`.
- Remove `random-intention` from the contract and adjust the resolver order.
- Cover the cleanup, config shape, and contract-shape expectations with tests.
