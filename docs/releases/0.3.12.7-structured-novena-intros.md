# Release 0.3.12.7 — Structured Novena Intros

## Scope

### Problem

- The live generated novena introduction can repeat daily context that listeners do not want in a novena opening.

### Audience

- People listening to daily novena audio.

### Goal

- Give every generated novena intro a listener-first spoken structure: two to four sentences about the saint or devotion, one sentence introducing that day's novena, then a distinct invitation into prayer, with no daily liturgical material.

### Constraints

- Preserve no length ceiling and the existing identity, day, markdown, prompt-echo, Gospel, and Scripture-citation protections.
- Do not rewrite novena contracts.

### Narrow Wedge

- Remove daily liturgical material from the novena prompt and fallback, reject it if generated, and force refreshed sidecars through a policy version.

### Non-Goals

- Changing non-novena devotional intro structures.

### Risks And Unknowns

- Sentence-count validation must accommodate concise contracts with limited saint metadata while still enforcing a clear transition.

### Recommended Next Step

- Implement the structure and regression-test the St Mary MacKillop repeat scenario.

## Research

- The live St Mary MacKillop sidecar used a successful OpenAI intro, not the fallback. It repeated “hidden holiness and trust” before and inside the calendar bridge.

## Plan

- Direct the model to organize only saint context, the named novena day, and a final prayer invitation in separate sentences.
- Exclude daily theme, Gospel, calendar bridge, feast, season, and novena-focus context from the prompt and reject it in generated prose.
- Make the deterministic fallback follow the same ending structure, advance the policy version, and test generated and fallback results.

## Progress

- Implemented the prompt, validation, fallback structure, and regression coverage.
