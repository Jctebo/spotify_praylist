## Scope

### Problem
- Rotation aborted while verifying the previous current set because the saved manifest listed `watch-current/saint-wenceslaus__2026-09-28.jpg`, but OneDrive reported that the object/path was missing.
- `_verify_managed_current` treats any missing current asset as fatal before rotation can advance, even though that asset is already absent and may have a verified archive copy.

### Audience
- The operator relying on daily devotional phone and watch images being promoted from OneDrive queue into current.

### Current Status Quo
- Workflow dates are selected from Chicago-local today; the Sep. 29 run attempted to promote Sep. 29 content and failed while validating the saved Sep. 28 state.
- Image filenames include their date (`subject__YYYY-MM-DD.jpg`); phone/watch identity is distinguished by the existing four device/state folders.
- A failed rotation leaves queued images in place, but stale managed-current state can prevent later runs from advancing.

### Goal
- Allow rotation to advance safely when a managed previous-current file has been removed from OneDrive, while still verifying any available archive copy and failing on real checksum conflicts or non-missing storage errors.
- Success means a missing old current object no longer blocks a complete, matched current-day phone/watch set from being promoted; existing assets are archived when present and current-day selection remains date-driven.

### Constraints
- Do not delete or move user files during investigation or testing; tests use an in-memory store.
- Preserve checksum verification, archive-before-cleanup, journal recovery, subject-set completeness, and the infographic folders.
- Keep the four existing OneDrive folders: `phone-current`, `phone-queue`, `watch-current`, and `watch-queue`. The user confirmed this layout; a different folder layout does not correct stale state and would require a separate migration.

### Narrow Wedge
- Distinguish a genuine missing-object response from other rclone failures in the managed-current verification/archive path.
- If the prior current object is absent, accept it only if a matching checksum-verified archive exists, or treat it as already absent when no copy exists; retain hard failure on checksum mismatch and non-not-found errors.
- Add regression tests for missing-current with verified archive, missing-current with no archive, and non-missing storage failures.

### Non-Goals
- Renaming OneDrive folders, changing date parsing or Chicago-local target-date selection, regenerating images, calendar changes, or modifying local rotation and infographic pipelines.

### Risks And Unknowns
- An asset absent from both current and archive has already been lost outside the rotation flow; continuing allows the next complete day to advance, but cannot restore the old image.
- If OneDrive returns an ambiguous transport error that looks like not-found, it must not be mistaken for a missing object; classification must use specific error signatures and tests.

### Recommended Next Step
- Implement the scoped missing-object recovery in `sync/devotional_onedrive.py`, verify with rotation and storage tests, then run the required review and ship checks without invoking production rotation.

## Research

- Workflow run 36544405562 (manual, 2026-09-29 08:42 UTC) failed in “Run wallpaper pipeline”; rclone reported `directory not found` for `watch-current/saint-wenceslaus__2026-09-28.jpg`.
- Read-only OneDrive inspection confirmed the cause and showed `phone-current`, `phone-queue`, `watch-current`, and `watch-queue` are present. Sept. 29 Archangels was queued for phone, while its watch counterpart was missing; the rotation correctly must wait until both variants exist.
- The Sept. 28 archive held the legacy Wenceslaus alias, not the canonical filename recorded by rotation state. Consequently that exact old watch asset was absent from both current and archive; no manual migration or production write was needed to diagnose it.
- `run_pipeline` calls `rotate_current(store, actual_today.isoformat())`; `actual_today` is `local_today()` in `America/Chicago`. The old date came from `rotation-state.json` as the prior managed-current date, not from target-date selection.
- `rotate_current` calls `_verify_managed_current` before reading today's queue set. `_verify_managed_current` unconditionally downloads every manifest-listed current file, so one externally missing file aborts the whole run.
- `_archive_current_pair` already attempts a fallback to an existing archive, but it is unreachable when the earlier strict verification fails. It also currently catches broad `RuntimeError` values and should distinguish not-found from real storage errors.
- `build_filename` and inventory parsing use `__YYYY-MM-DD` date tags. Four folders encode the device/state dimensions and remain unchanged in this repair.
- `resolve_calendar` applies that month's devotion only when a represented calendar date contains no named subject; dates absent from the calendar are intentionally skipped. Generation and inventory selection key each image by exact date, subject, and phone/watch variant.

## Plan

### Design
- Keep the Chicago-local run date and the four current/queue plus phone/watch folders unchanged.
- Preserve date-tagged filenames and exact date/subject/device matching. Continue using the monthly devotion only for represented calendar dates without a named devotion or feast; skip dates missing from the calendar feed.
- Treat explicit OneDrive “directory/object not found” responses as absence; propagate permission, network, throttling, and other rclone errors.
- For each managed prior-current asset: verify its current bytes when present; if missing, verify the corresponding dated archive copy when present; if both are absent, record it as already missing and continue. Any available copy with a checksum mismatch remains a hard error.
- Ensure archive-before-cleanup does not retry copying a missing source and does not mask unrelated download failures.

### Implementation
1. Add a narrow helper that recognizes only the known rclone missing-object/path diagnostics.
2. Update `_verify_managed_current` to accept a prior current object only when its bytes match the recorded checksum, or its archive fallback matches; safely tolerate current and archive both absent.
3. Update `_archive_current_pair` to use the same missing-error classification and skip copy only when current bytes are confirmed missing and there is no archive to verify.
4. Add regression coverage for the reported Sept. 28 missing watch-current scenario, incomplete target pairs waiting safely, checksum conflicts, and unrelated rclone failures.
5. Verify exact-date inventory and monthly-fallback selection contracts with existing selector tests; run rotation, OneDrive storage, calendar, and wallpaper pipeline tests. Review the complete diff. Do not run GitHub Actions production generation/rotation.

### Acceptance Criteria
- A complete Sep. 29 queue set can rotate when a manifest-listed Sep. 28 current file is missing.
- Existing archive data is checked against the manifest checksum and conflicts still stop rotation without cleanup.
- Non-not-found storage failures still stop rotation.
- Current-date selection, four folder names, filenames/date tags, and unrelated infographic assets are unchanged.
