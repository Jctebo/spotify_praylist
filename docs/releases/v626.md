# v626 — Sing the Hours fallback restored: fills on a Divine Office failure too, and every fill names its source

## §1 Scope

John's order (voice call, Ora thread, 2026-11-23 08:40–08:43 CT), verbatim in substance: restore the Spotify-era Sing the Hours fallback for Morning Prayer + Evening Prayer in the v624 server watcher — like the old Spotify-playlist logic (release 0.3.6.1; carried into the app at v324) — when the day's Divine Office Morning Prayer or Evening Prayer does not resolve, the server watcher resolves that slot from the Sing the Hours feed (https://feeds.castos.com/x8g54) for the same day and stands that pointer in the slot. The order was given the same morning the Divine Office feed stood broken (HTTP 500, per the v625 ship record): on 2026-11-23 the office hours stood "Not available" in the app with no fallback standing — the failure case is the case that prompted the order, and "does not resolve" includes a failed read.

## §2 Plan / decisions

### Grounding (verified firsthand on the v625 tree)

The v624 watcher (`resolveExternalsPass`, `app/worker/src/index.ts`) already carried a Sing the Hours fill block using the standing `extMatchSth` (title prefix `M.D.YY` + token Lauds/Vespers). Three gaps stood between that block and the order:

1. **GAP 1 — failure never fills.** The block ran only when `doOkToday` (the DO feed's last successful read is today). On a DO feed FAILURE — the 2026-11-23 HTTP 500 case — it skipped with "primary-not-resolved" and the slot stood unresolved all day.
2. **GAP 2 — no source recorded, no label exists.** `ext_resolutions` had no source column; primary and fallback writes both stored the bare slot title. The live payload serves `res.title`; the client descriptor title is that title (`extSlotTrack`), and the Praylist row + opened view paint it. The labeling seam is therefore the stored title — compose at write time.
3. **GAP 3 — stand-down can strand a fallback.** `extFeedStoodDown` counts a slot resolved when its row's `resolved_at` Chicago date is today — a fallback fill writes exactly that, so the DO feed could stand down for the day and never flip the slot back when the primary posted late.

Also standing in the old block: it fetched the StH feed before testing need, and its StH stand-down (last success today → skip) could block a later-needed fill.

### Decisions

- **D1 — Migration 0049** adds `source TEXT` to `ext_resolutions` (0048 was v625's; not reused). `extResolutionWrite` gains the source stamp appended AFTER `episode_date` — last column, last bind, last upsert term — preserving the positional discipline harness-v624/v625's FakeDBs destructure against (their existing legs stay green unextended; only harness-v626's fake reads the 13th arg).
- **D2 — Writers.** `runSlotFeed` gains an optional `sourceFor`: the Divine Office leg stamps **'Divine Office'** on the two labeled slots only (present rows); the other six office slots and every other slot feed stamp **NULL** — minimal, only DO/StH sources are read. The StH fill stamps **'Sing the Hours'**. A missing write stamps NULL (no source filled it).
- **D3 — Labels at write time**, for `ext-morning-prayer` + `ext-evening-prayer` ONLY: stored title = `"<slot title> - <source>"` on present rows. Every other slot's title is byte-unchanged. **Missing-row decision (recorded):** a missing row for the two slots keeps the **bare slot title** — no source filled it, and the payload's missing paint does not name a source. **Courier path (checked):** `externalsCourierPayload`'s no-row fallback composes the bare slot title for a primary fill of the two slots, so its present entries now compose `"<title> - Divine Office"` for consistency; its missing entries keep the bare title. The courier carries **no** Sing the Hours leg (`EXT_COURIER_SLOTS` stands empty), so no StH title is composed there.
- **D4 — Fallback trigger widened.** The `doOkToday` gate is removed. After the DO leg of the pass, for each date (today, tomorrow) × each of the two slots, the slot NEEDS a fill when: it stands (`standingOn`), the fallback settings row is enabled and fills (the standing `fbRow` test), and the current row is **absent OR state='missing'**. Present-from-primary: no need. Present-from-StH: already filled, no need. Need is computed from the rows BEFORE any StH fetch; the StH feed is fetched only when at least one slot needs a fill (the old StH stand-down skip yields to need — need is computed from rows, not feed state; the pass's `forceFeedKeys` no longer gates this block either). On a successful StH read, each needed slot whose `extMatchSth` matches is filled: state present + the StH pointer + the Sing the Hours title + source 'Sing the Hours' + **episode_date = row date** (v625's fill discipline preserved, so a today's fallback is automatically NOT stale under the v625 day predicate — the predicate itself is untouched). A StH read that matches nothing writes NO row for that slot (missing remains the primary's word; an absent row keeps the unresolved paint). A failed/zero-yield StH read writes nothing and records the feed-state error, as before. The fill never overwrites a present row.
- **D5 — DO stand-down exclusion.** A source-aware variant (`extFeedStoodDownDo`) serves the DO call site only: a Morning/Evening row whose source = 'Sing the Hours' does NOT count as resolved. NULL source counts — legacy rows were primary-written by construction. **One-day self-healing edge (named):** a fallback row written by the OLD code (pre-0049, source NULL, bare title) counts as resolved for stand-down on its first day; it self-heals the next day, when its `resolved_at` is no longer today and the DO feed fetches again. Other slots/feeds keep the generic test unchanged. While a fallback stands, the DO feed keeps fetching each pass, and the next successful DO read overwrites the fallback row wholesale (upsert) — pointer + label flip together.
- **D6 — Client leg retired.** The client (`client.ts`) carried a live client-side StH fallback: after the courier settled, a Morning/Evening slot standing 'missing' triggered a client fetch of the StH feed and settled with the BARE slot title + source 'Sing the Hours'. **Decision (coordinator, recorded): RETIRE that firing block** — the v624 §1 item 8 Saint-leg precedent; the server now covers the missing case AND the failure case, and a client fill would paint without John's " - Sing the Hours" name (two governors, two labels). Removed: only the firing block (the `courierP.then(...)` StH leg). Deliberately left standing: the shared helpers — the client copy of `extMatchSth`, `EXT_STH_URL`, the `EXT_SLOTS` `fallbackToken` fields, and the `fbRow` plumbing — because the audio pass-through's source routing (client.ts ~19686–19688, ~20147–20154) and the settings surfaces still read them. Verified by grep: `openEpisodeCard` paints `model.titleText || d.title` (the descriptor title), so the labeled payload title reaches the opened view; nothing in the client matches on the bare "Morning Prayer"/"Evening Prayer" **payload** title — `EXT_TOKENS` is client-side **feed** matching, not payload-title matching (confirmed).
- **D7 — The coordinator plan file's item 5 is NOT built.** The pre-v625 plan proposed making the stale predicate source-aware (staleness reading the filling feed's state). The Implement brief post-dates the v625 ship and supersedes it: v625 replaced that predicate with the day rule keyed on `episode_date`, and a title-date-exact StH fill stamps episode_date = row date — so a today's fallback is not stale by construction, and a not-today row cannot arise from the fill. The predicate stands untouched.
