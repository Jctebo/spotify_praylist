## Scope

### Problem
- The daily episode publisher depends on Notion for episode text and completion state, adding an external service and secret to a pipeline that already has repository-owned contracts and artifacts.

### Audience
- Primary user: repository maintainer operating the daily publishing workflows.
- Secondary stakeholders: listeners consuming the existing podcast feed and site.

### Current Status Quo
- `config/publish/contracts/*.json` defines episode metadata and audio behavior, while Notion stores mutable episode fields and completion state.
- The novena contract system already validates local JSON and writes RSS/audio artifacts.

### Goal
- Store episode data and pipeline completion state locally while preserving feed XML, titles, descriptions, audio branding, and workflow behavior.
- Success: migration preserves every exported Notion field; new local episode contracts load and validate; tests cover loader and migration; later pipeline work passes without Notion.

### Constraints
- Reuse novena contract validators, resolver, artifact writer, and RSS publisher when they fit.
- Preserve episode IDs, dates, status, text, hashes, audio paths/URLs, and existing audio config behavior.
- Do not affect novena pipelines or devotional wallpaper jobs.
- Stop after design and migration are implemented and reviewed, before deleting Notion code.

### Narrow Wedge
- Define the local episode schema and file layout, convert existing publish contracts, and build a one-time Notion export/migration with tests. Pause for user review before pipeline rewiring and Notion deletion.

### Non-Goals
- Changing RSS contents or audio production/branding.
- Removing Notion code or changing pipelines in this review checkpoint.

### Risks And Unknowns
- The currently accessible `Opus Dei` database has playlist properties rather than the episode properties required by the task; the correct source database is unresolved.
- The compatibility boundary between existing publish-specific blocks and novena machinery must be explicit to avoid changing generated output.

### Recommended Next Step
- Review the schema and migration, then continue with local pipeline state and remove Notion machinery only after end-to-end parity is verified.

## Research

- `jobs/publish/contracts.py` already parses metadata, entries, blocks, and audio configuration; current publish contracts can retain those fields and add persisted episode state.
- `jobs/novena_contracts` provides validated contract loading, resolution, artifact writing, and RSS publishing patterns; publish-specific block rendering remains in `jobs/publish`.
- `jobs/publish/audio.py` already writes archive sidecars and `docs/podcast.xml` is produced by the shared RSS builder.
- Current local task is intentionally limited to design and migration; pipeline rewiring and Notion deletions await review.

## Plan

### Summary
- Extend the current publish entry schema with an `episode_state` record and use a repository contract directory as the authoritative state store. Keep generated text/template blocks and audio config in their current locations.

### What Already Exists
- Publish contract loader and generation logic: `jobs/publish/contracts.py`.
- Reusable validation and publishing components: `jobs/novena_contracts/`.
- One RSS output and archive sidecars: `jobs/publish/rss.py`, `jobs/publish/audio.py`.

### Architecture
```text
Notion API (one-time) -> migration -> config/publish/contracts/*.json
                                       | contract entries + episode_state
                                       v
                           future local pipeline/state + docs artifacts
```

### Concrete Changes
- `docs/architecture/local-episode-contracts.md`: schema and state design.
- `scripts/migrate_notion_episodes.py`: one-time paginated export and deterministic contract update.
- `jobs/publish/contracts.py` and `tests/test_publish_contracts.py`: future local state loader coverage.
- `tests/test_notion_episode_migration.py`: migration preservation and error handling.
- Do not delete `jobs/publish/notion.py`, `jobs/notion/`, Notion workflows, or setup scripts in this checkpoint.

### UX And States
- No interactive UI. Migration is an explicit operator command; it must fail without writing partial contract updates when required fields or target contracts are invalid.

### Implementation Phases
#### Phase 1: Design and migration
- Goal: document the file contract and add a one-time export that preserves source values.
- Files: architecture document, migration script, tests, converted publish contract JSON.
- Verification: unit tests for API pagination/parsing, complete field preservation, deterministic output, duplicate/missing IDs, and loader compatibility.
- Rollback: restore the contract JSON from git; the migration is repeatable and writes via temp files/atomic replacement.

#### Phase 2: Local pipeline and state
- Goal: load/store episode records and daily completion state locally; retain output parity.
- Files: publish loader/pipelines, workflow env requirements, tests, local state file.
- Verification: existing plus new pipeline tests and comparison of RSS/title/description/audio metadata.
- Rollback: restore previous pipeline entrypoints while retaining exported JSON.
- Dependency: Phase 1 review.

#### Phase 3: Remove Notion-only machinery
- Goal: remove unused Notion episode storage code and secrets after pipelines operate locally.
- Files: Notion modules/scripts/workflow, `.env.example`, workflow configuration, docs.
- Verification: full suite and repository-wide search for stale publish Notion dependencies.
- Rollback: restore code from version control; exported contract records remain usable.
- Dependency: Phase 2 parity verification and user review.

### Failure Modes
- Missing or malformed source fields: abort migration with row/field detail before writing.
- Duplicate entry IDs or ambiguous contract mapping: abort without overwriting files.
- Partial filesystem write: stage all output then atomically replace each file after validation.
- Existing publish output drift: detected by parity tests over RSS metadata and audio config.

### QA And Test Matrix
- Load every migrated JSON contract and validate required IDs, dates, statuses, text/hash/audio state.
- Mock Notion pagination and page-body retrieval; verify rich text concatenation and empty/null field handling.
- Ensure repeat migration has byte-stable output and failure cases leave originals unchanged.
- Later phase: full pipeline tests plus `docs/podcast.xml` parity for titles, descriptions, IDs, and enclosure URLs.

### Rollout Notes
- Export and review all repository changes before switching production workflows.
- Keep the Notion implementation available until local pipeline verification is complete.

### Not In Scope
- Pipeline rewiring or Notion deletion in Phase 1.
- Novena or devotional wallpaper changes.

### Open Questions
- Confirm actual Notion schema/property types against live export during migration; preserve unknown source properties in a migration report if any appear.
