# Release 0.3.6.12 - Novena Shared Daily Theme Sidecars

Date: 2026-06-16
Version: 0.3.6.12
Status: Shipped
Last Updated: 2026-06-16
Branch: enhancement/novena-shared-daily-theme-sidecars
Depends On: 0.3.6.11

## Scope

### Problem
- The `0.3.6.11` fix successfully made publish-contract daily prayer sidecars share one canonical daily theme for a target date.
- A forced remote rebuild for **Tuesday, June 16, 2026** confirmed all five daily prayer sidecars now share:
  - `daily_theme_title=Humility And Trust`,
  - `gospelCitation=Matthew 5:43-48`,
  - empty `fallbackReason`,
  - identical calendar/Gospel/season source lists.
- The same remote run also rebuilt seven June 16 novena sidecars, but every novena sidecar still lacked:
  - `daily_liturgical_context`,
  - `sharedThemeTitle`,
  - `gospelCitation`,
  - `fallbackReason`.
- Novena sidecars currently expose only novena-local `context.daily_theme_title` values such as `St. Thomas More` or `John's Prenatal Recognition Of Jesus In Elizabeth's Womb`.
- This means the listener-facing publish day is still split: daily prayers carry the canonical day theme, while novenas carry unrelated local theme metadata and cannot be validated against the day's shared focus.

### Audience
- Primary maintainer: needs one published sidecar contract that can verify theme consistency across daily prayers and novenas after a remote run.
- Daily listeners: should hear only a brief intro/transition connecting every novena style to the same daily focus, without changing the saint-specific novena day or traditional prayer text.
- Future maintainers: need one clear boundary for canonical daily liturgical context in both publish-contract and novena-contract pipelines.
- Site/feed consumers: should be able to read novena sidecars and know the daily theme, Gospel citation, fallback status, and novena-local focus separately.

### Current Status Quo
- `jobs/publish/contracts.py` now resolves one canonical daily theme per `(date, calendar, locale)` for publish-contract text/audio jobs.
- `jobs/novena_contracts/engine.py` builds novena-local daily theme fields inside `runtime_context()` through `_novena_daily_theme_context()`.
- `jobs/novena_contracts/pipeline.py` treats sidecars with `context.daily_theme_version == "daily-theme-v1"` as current, even though that version may only mean "novena-local theme exists."
- `jobs/novena_contracts/artifact_writer.py` writes the rendered novena `context` into the sidecar, but does not write a top-level `daily_liturgical_context` payload.
- Remote June 16 novena sidecars were present and refreshed, but all seven were missing canonical daily liturgical context fields.
- The novena runtime must preserve its saint/day focus because novenas have their own devotional arc. The missing piece is not replacing novena focus; it is attaching and lightly using the shared publish-day theme.

### Goal
- Make novena sidecars participate in the same canonical daily theme contract as daily prayer sidecars.
- For any target date, every active novena sidecar should carry:
  - a top-level `daily_liturgical_context` payload,
  - flattened canonical `daily_theme_*` fields in `context`,
  - `sharedThemeTitle`, `gospelCitation`, `fallbackReason`, and `sharedThemeSources` matching the daily prayer sidecars for that date.
- Preserve novena-local focus as a separate field so the novena can still say "Day 4 of St. Thomas More" or use its generated short-form focus.
- Novena intro text should lightly reinforce both layers only as a short opening bridge:
  - canonical daily theme: the day/Gospel/season focus shared with all prayers,
  - novena focus: the saint-specific day or theme.
- The shared daily theme should not drive the novena body, generated petition, or full reflection. It is only for a small intro and transition into the novena.
- This applies to both generated/short-form novenas and traditional/fixed novenas. Traditional novenas should receive the same small daily-theme bridge before the existing traditional prayer text.
- Existing stale sidecars should be considered stale if they only have novena-local `daily_theme_version` and lack canonical `daily_liturgical_context`.

### Constraints
- Do not collapse all novenas into one shared novena theme. Multiple active novenas should keep distinct saint/day focus.
- Do not change novena episode IDs, RSS GUID strategy, active-day scheduling, or feed retention behavior.
- Do not change traditional novena prayer bodies. Traditional novenas should get the same short intro/transition bridge, then proceed into the existing prayer text unchanged.
- Do not add a new external readings/calendar dependency; reuse `jobs.publish.daily_liturgical_context.build_daily_liturgical_context()`.
- Avoid double-fetching daily liturgical context once per novena if a per-date cache can be used safely.
- Preserve compatibility with existing sidecar readers that expect `context.daily_focus`, `context.daily_theme_title`, or novena `content` fields.
- Keep publish-contract and novena-contract pipelines aligned without duplicating large helper logic.

### Narrow Wedge
- Add a per-date/calendar/locale canonical daily theme payload to the novena pipeline and sidecar writer for validation and intro-bridge rendering.
- Keep novena-local theme/focus under explicit novena-specific names, for example `novena_daily_focus`, `novena_theme_title`, or equivalent.
- Make `context.daily_theme_title` refer to the canonical shared daily theme for new novena sidecars, not the novena-local focus.
- Write top-level `daily_liturgical_context` into novena sidecars with the same shape used by daily prayer sidecars.
- Ensure traditional/fixed novena sidecars and audio fragments receive the same canonical daily-theme intro bridge as generated/short-form novenas.
- Update stale-sidecar detection so sidecars without canonical daily liturgical context are regenerated or rewritten with current metadata.
- Add regression coverage that builds active novena sidecars for a date and proves every novena carries the same canonical theme/Gospel/fallback fields while preserving distinct novena-local focus.

### Non-Goals
- Do not redesign the novena contract model.
- Do not rewrite all novena prompts, generated novena content, or traditional novena prayer text.
- Do not make novenas deeply develop the Gospel theme in the same way the Rosary or Daily Reflection does; the shared theme is only a brief intro/transition cue.
- Do not change the remote workflow inputs in this release.
- Do not change R2, Pages, Spotify, Notion, or audio fragment cache behavior.
- Do not backfill every historical novena sidecar manually; the target is current/future publish runs and stale detection for regenerated sidecars.

### Risks And Unknowns
- `context.daily_theme_title` currently means novena-local focus in novena sidecars. Changing it to canonical daily theme may affect site rendering or tests that assume the old meaning.
- Some short-form novena generation uses `daily_focus` and `theme` as prompt inputs. Research must identify which fields are prompt inputs versus sidecar metadata to avoid weakening novena-specific content.
- The pipeline currently uses `context.daily_theme_version == "daily-theme-v1"` as a freshness marker. That version is now ambiguous and may need a stricter sidecar freshness contract.
- Existing sidecars may be reused from cache if stale detection is not tightened, preventing the fix from showing up remotely.
- If canonical daily context fetch fails, novenas need the same shared fallback behavior as daily prayers rather than reverting to novena-only metadata.
- The exact sidecar shape should be stable enough for site pages, RSS archive readers, and future validation scripts.

### Recommended Next Step
- Run `/research-astack` next.
- Research should map:
  - `jobs/novena_contracts.pipeline.run_novena_pipeline()` sidecar reuse and stale detection,
  - `jobs/novena_contracts.engine.runtime_context()` and `_intro_fragment()`,
  - `jobs/novena_contracts.artifact_writer.write_novena_artifact()`,
  - site readers that consume novena sidecars,
  - tests in `tests/test_novena_engine.py`, `tests/test_novena_pipeline.py`, `tests/test_novena_artifacts.py`, and `tests/test_publish_site.py`.
- Research should decide the exact canonical/novena-local field names and the smallest injection point for a shared per-date daily theme cache.

## Research

### Scope Baseline
- The publish-contract pipeline already has the desired shared-theme behavior for daily prayers: one canonical daily theme is resolved per `(date, calendar, locale)` and copied into each job's render context.
- The novena pipeline still treats `daily_theme_*` as novena-local metadata. This makes the field name look compatible while the meaning differs from daily prayer sidecars.
- The June 16 remote sidecars confirm the production symptom: daily prayers shared `Humility And Trust` with `Matthew 5:43-48`, while novenas had no top-level `daily_liturgical_context` and used saint/day-local `context.daily_theme_title` values.

### Relevant Files
- `jobs/publish/daily_liturgical_context.py`
  - Defines `DailyLiturgicalContext`, `SHARED_THEME_VERSION`, `build_daily_liturgical_context()`, and the canonical sidecar payload fields including `sharedThemeTitle`, `sharedThemeSources`, `gospelCitation`, and `fallbackReason`.
- `jobs/publish/contracts.py`
  - Contains reusable daily-theme runtime helpers:
    - `_daily_liturgical_context_to_payload()`
    - `_daily_theme_runtime_fields()`
    - `_daily_theme_cache_key()`
    - `_copy_daily_theme_runtime_fields()`
    - `_build_canonical_daily_theme_runtime_context()`
    - `_PublishDailyThemeRuntimeCache`
  - Current helper placement is publish-specific even though the logic is now needed by novenas.
- `jobs/novena_contracts/pipeline.py`
  - Resolves active novenas by publish date, seeds remaining short-form runtimes, loads/reuses sidecars, renders audio for target dates, and writes novena artifacts.
  - `_sidecar_has_current_daily_theme()` currently accepts `context.daily_theme_version == "daily-theme-v1"`, which is insufficient because legacy novena-local themes also use that version.
- `jobs/novena_contracts/engine.py`
  - `runtime_context()` builds novena render context and currently sets `theme`, `daily_focus`, and novena-local `daily_theme_*` fields.
  - `_novena_daily_theme_context()` is the source of the novena-local `daily_theme_*` collision.
  - `generate_text()` uses `daily_focus`/`theme` as prompt inputs, so those fields should remain novena-specific for generated novena sections.
  - `_intro_fragment()` reads `daily_theme_title` and `daily_theme_transition`, so switching those fields to canonical daily theme will lightly reinforce the shared day theme in audio intros.
  - `render_novena()` currently adds `_intro_fragment()` only for compact block templates. Non-compact fixed/traditional outputs use rendered sections directly, so the implementation must ensure the short bridge is present for traditional/fixed novenas too.
- `jobs/novena_contracts/contracts.py`
  - `_build_context_for_patterns()` separately creates novena-local `daily_theme_*` fields for title/description publishing patterns. This second source must be aligned, or titles/descriptions and rendered sidecars can disagree.
- `jobs/novena_contracts/artifact_writer.py`
  - Writes novena sidecars but currently nests all render context under `context` and does not write a top-level `daily_liturgical_context`.
  - It returns early when existing and next `content_hash` match, which can block metadata-only sidecar rewrites unless freshness logic forces a rerender/rewrite.
- `jobs/novena_contracts/audio.py`
  - Builds and renders novena audio jobs. The pipeline calls it with `write_sidecar=False` and then delegates sidecar writing to `artifact_writer.py`, so canonical sidecar metadata should be added through rendered context/artifact writer rather than the direct audio sidecar path only.
- `jobs/novena_contracts/resolver.py`
  - Resolves active novena runtimes and active days. This logic should remain unchanged.
- Tests to extend:
  - `tests/test_novena_engine.py`
  - `tests/test_novena_pipeline.py`
  - `tests/test_novena_artifacts.py`
  - `tests/test_publish_contracts.py`
  - `tests/test_publish_site.py`

### Current System Map
- Publish daily prayers:
  - `build_audio_jobs()` creates a `_PublishDailyThemeRuntimeCache`.
  - Each effective publish date gets one canonical daily theme payload.
  - Runtime context receives both:
    - top-level `daily_liturgical_context` inside render context,
    - flattened `daily_theme_*` fields derived from that payload.
- Novenas:
  - `run_novena_pipeline()` resolves active runtimes for target dates and seeds short-form future days.
  - `render_novena()` calls `runtime_context()`.
  - `runtime_context()` chooses a novena-local focus from `ai_config.themes` or feast/saint fallback.
  - That same focus is written to `theme`, `daily_focus`, and novena-local `daily_theme_*`.
  - Compact-block novena templates get an intro fragment before the reusable day block. Non-compact templates do not currently get that intro fragment, which is the main implementation gap for traditional/fixed parity.
  - `write_novena_artifact()` writes `context` but no top-level canonical daily context.
- Sidecar reuse:
  - If a sidecar exists and `_sidecar_has_current_daily_theme()` passes, the pipeline reconstructs rendered data from the sidecar.
  - For target dates, audio may still be rendered/reused, but the sidecar is not rewritten on the reuse path.
  - For non-target seeded sidecars, stale rendered sidecars are intentionally preserved if they already have rendered audio.

### Reuse Opportunities
- Reuse `jobs.publish.daily_liturgical_context.build_daily_liturgical_context()` for novenas.
- Prefer extracting or sharing the publish daily-theme runtime helper logic instead of copying it into novena modules:
  - convert `DailyLiturgicalContext` or dict payload into flattened runtime fields,
  - copy nested source lists safely,
  - cache by `(date, calendar, locale)`,
  - fall back from `allow_missing_gospel=False` to `True` like daily prayers.
- Preserve novena-local focus under explicit names:
  - `novena_daily_focus`
  - `novena_theme_title`
  - `novena_theme_slug`
  - `novena_theme_explanation`
  - `novena_theme_transition`
  - optionally `novena_theme_sources` and `novena_theme_version`
- Keep `theme` and `daily_focus` as novena-local compatibility fields for prompts and existing templates.
- Make `context.daily_theme_title` canonical for new sidecars, matching daily prayer semantics.

### External References
- No new external dependency is needed.
- Existing external data sources remain the current Romcal helper and Gospel fetch path behind `build_daily_liturgical_context()`.
- The same fallback strategy as daily prayers should apply: attempt canonical context with Gospel required, then fall back to missing-Gospel mode if needed.

### Constraints
- Do not change novena IDs, active-day calculation, RSS GUIDs, feed retention, or remote workflow inputs.
- Do not replace novena-local devotional focus with the shared day theme in generated novena prompts or traditional novena bodies.
- Do not force all active novenas on a date to share one novena focus. Only the canonical daily theme should be shared.
- Avoid duplicate daily context fetches for multiple novenas on the same date.
- Do not break the existing site page that lists individual novena sidecar episodes; it primarily reads title, audio URL, and fragments.
- Keep the existing behavior that stale rendered sidecars outside target publish dates can be preserved.

### Risks
- Field semantics change: `context.daily_theme_title` in novena sidecars will move from novena-local to canonical daily theme. Tests and any downstream readers must use the new explicit novena fields for novena-local focus.
- There are two novena context builders (`engine.runtime_context()` and `contracts._build_context_for_patterns()`). Changing only one would leave titles/descriptions and audio sidecars inconsistent.
- Traditional/fixed novenas may not enter the current compact-block intro path, so a fix that only changes `_intro_fragment()` would still miss some traditional sidecars.
- The current freshness check is ambiguous. A sidecar with only novena-local `daily_theme_version=daily-theme-v1` can be incorrectly treated as current.
- `write_novena_artifact()` can skip a rewrite if the audio/content hash is unchanged. A metadata-only canonical context fix needs either a stricter stale path or a writer-level metadata freshness check.
- Short-form seeding can create sidecars for dates beyond the target publish dates. If canonical context is added to every seeded runtime, the implementation needs per-date caching to avoid unnecessary repeated calendar/Gospel work.
- If canonical context generation fails, novenas must not silently regress to novena-local-only `daily_theme_*`.

### Assumptions To Validate
- Daily prayer sidecar validation expects top-level `daily_liturgical_context`; novena sidecars should match that shape instead of inventing novena-only top-level names.
- Keeping `theme` and `daily_focus` novena-local is safer than switching them to canonical, because `generate_text()` and existing template tests rely on them for saint/day-specific content.
- The site renderer does not currently depend on novena `context.daily_theme_title`, so adding top-level canonical context should be non-breaking for the public pages.
- The remote publish validation can compare novena sidecars against daily prayer sidecars by checking:
  - `daily_liturgical_context.sharedThemeTitle`
  - `daily_liturgical_context.gospelCitation`
  - `daily_liturgical_context.fallbackReason`
  - `daily_liturgical_context.sharedThemeSources`

### Unknowns
- Whether any private/manual consumer reads novena `context.daily_theme_title` as novena-local focus. The codebase does not show a public site dependency, but the sidecar contract is externally visible.
- Whether direct calls to `render_novena_audio_job(write_sidecar=True)` need the same top-level canonical payload. Pipeline writes are the main path, but tests cover direct audio sidecar writing.
- The best home for shared helper extraction:
  - a new small module under `jobs/publish/`,
  - a neutral module under `jobs/common/`,
  - or public functions exported from `jobs.publish.contracts`.

### Recommended Direction
- Extract the daily-theme payload/runtime helper from `jobs/publish/contracts.py` into a small reusable module, then update publish contracts to import it. This keeps daily prayers and novenas on one canonical conversion path.
- Add a per-date daily-theme cache to `run_novena_pipeline()` and inject canonical fields into each novena runtime/render context for sidecar metadata and the short intro bridge.
- Rename novena-local `daily_theme_*` output to explicit `novena_theme_*` fields while preserving `theme` and `daily_focus` as novena-local compatibility aliases for the novena body and generated sections.
- Write top-level `daily_liturgical_context` in `write_novena_artifact()` from `rendered["context"]["daily_liturgical_context"]`.
- Tighten `_sidecar_has_current_daily_theme()` so current novena sidecars require:
  - top-level `daily_liturgical_context`,
  - `sharedThemeVersion == "daily-theme-v1"`,
  - non-empty `sharedThemeTitle`,
  - matching sidecar/context date when available.
- Add regression tests proving:
  - multiple active novenas on one date share the same canonical daily theme payload,
  - each novena preserves distinct novena-local focus,
  - traditional/fixed novenas receive the same short daily-theme intro bridge without changing the traditional prayer body,
  - old sidecars with only `context.daily_theme_version` are regenerated for target dates,
  - non-target stale sidecar preservation remains intentional,
  - public daily-novenas site rendering still lists individual episodes.

## Plan

### Summary
- Build one canonical daily-theme sidecar contract for novenas that matches daily prayer sidecars while keeping the novena body saint/day-specific.
- The shared daily theme will be used in novenas only for:
  - top-level sidecar metadata,
  - flattened `context.daily_theme_*` fields,
  - one short intro/transition bridge before the novena prayer.
- Traditional/fixed novenas get the same bridge as generated/short-form novenas, but their existing prayer text remains unchanged.
- The chosen approach reuses the daily prayer canonical theme builder instead of adding a second novena-specific version.

### What Already Exists
- `jobs.publish.daily_liturgical_context.build_daily_liturgical_context()` already produces canonical daily context with Gospel, season, calendar, fallback, and shared theme fields.
- `jobs.publish.contracts` already has working helper logic for converting that canonical payload into runtime `daily_theme_*` fields and caching by date/calendar/locale.
- `jobs.novena_contracts.pipeline.run_novena_pipeline()` already has one central path where active and seeded novena runtimes are rendered and sidecars are written.
- `jobs.novena_contracts.engine._intro_fragment()` already creates a listener-facing novena intro bridge for compact-block templates.
- Existing novena sidecar and pipeline tests already cover artifact writing, stale sidecar preservation, audio reuse, RSS feed rebuilds, and site listing of individual novena episodes.

### Architecture
- Move the reusable daily-theme runtime conversion/cache out of `jobs.publish.contracts` into a small shared publish module.
- Publish-contract jobs and novena jobs both call that shared module.
- Novena render context will carry two separate theme layers:
  - canonical daily layer: `daily_liturgical_context`, `daily_theme_title`, `daily_theme_transition`, etc.
  - novena-local layer: `theme`, `daily_focus`, `novena_daily_focus`, `novena_theme_title`, etc.
- Novena sidecars will write `daily_liturgical_context` at the top level and keep the full render context under `context`.
- Stale sidecar detection will require top-level canonical daily context, so old sidecars with only novena-local `daily_theme_version` are regenerated for target dates.

```text
publish date
  |
  v
shared daily theme cache -- one payload per date/calendar/locale
  |                          |
  |                          +--> publish-contract jobs
  |
  +--> novena runtime context
        |
        +--> sidecar.daily_liturgical_context
        +--> context.daily_theme_*      canonical day bridge
        +--> context.novena_theme_*     novena-local focus
        +--> audio intro fragment       short bridge only
        +--> existing novena body       unchanged
```
