# Release 0.0.5.1 - holy-week-weekday-novena-audio-regression

- Status: Shipped
- Shipped On: 2026-03-22
- Last Updated: 2026-03-22

## Scope

### Problem
- The daily novena workflow is creating saint-style novena audio for Monday and Tuesday of Holy Week even though those are ferial weekdays, not saint feast days.
- In 2026, the concrete examples are Monday of Holy Week on March 30, 2026 and Tuesday of Holy Week on March 31, 2026.
- This is a user-facing bug because the system is generating devotional outputs for days that should not receive saint novenas at all.

### Audience
- Primary user: the maintainer running the daily novena and novena-audio automation from the Liturgical Calendar workflow.
- Secondary stakeholders: anyone consuming the generated novena audio or Saint Radar rows that were created from a non-saint weekday.

### Current Status Quo
- The novena job builds a 9-day saint window from Romcal and can also generate day-by-day novena sections and audio on Saint Radar calendar pages.
- The same shared Romcal helper now normalizes some special Sundays and the Easter Octave into app-level ranks for other devotional workflows.
- The current saint-window collector explicitly falls back to generic calendar-day names when no saint-like celebrations are found in the requested window.
- The job already carries `celebration_rank` and `precedence` alongside each collected row, but novena eligibility is not currently expressed as an explicit rank-based contract.
- That means Holy Week weekdays may be entering because of fallback naming, because there is no qualifying rank gate, or because both are true.

### Goal
- Confirm why Holy Week weekdays are entering the daily novena and novena-audio pipeline.
- Evaluate whether novena eligibility should be defined by celebration rank instead of saint-name detection.
- Clarify whether the devotional-image pipeline currently includes `solemnity-easter octave`, and whether that pseudo-rank should now be excluded from both devotional images and novena generation.
- Lock the product contract so novena eligibility is rank-based rather than saint-name-based.
- Identify the narrowest safe fix so novena audio is generated only for the intended liturgical cases, without regressing intended special-day handling elsewhere.
- Produce enough implementation context to plan a fix and regression coverage.

### Constraints
- This pass should not change production code yet.
- The devotional-image flow intentionally supports some non-saint liturgical celebrations, so the novena fix cannot blindly reuse its allowlist or remove the shared rank normalization.
- Product decision: the novena pipeline should now follow a rank-based contract, not a saint-name/entity contract.
- If `solemnity-easter octave` remains in the shared rank contract, a simple rank-only allowlist will continue to admit Easter Octave weekdays unless there is an explicit precedence or pseudo-rank exclusion.
- The repo now uses versioned release artifacts under `docs/releases/`, so this bug should be tracked in its own artifact and branch.

### Narrow Wedge
- Focus on the daily novena prayer and novena-audio generation path in `jobs/novena/generate_daily_novena_prayer.py`.
- Trace how Romcal events are classified by celebration rank and precedence.
- Verify whether Holy Week weekdays reach novena generation because there is no explicit rank/precedence gate today.
- Determine whether a precedence-based deny rule is the right way to exclude Easter Octave weekdays while otherwise moving toward the devotional-image contract.
- Defer implementation until planning.

### Non-Goals
- Do not redesign the entire Saint Radar content model.
- Do not remove valid Easter Octave or special-Sunday handling from unrelated devotional-image workflows unless research proves they directly cause this bug.
- Do not broaden this into a general liturgical-calendar eligibility rewrite for every job in the repo.

### Risks And Unknowns
- The real bug still involves legacy saint-window fallback behavior, but the fix direction is now to replace that with a rank-based contract rather than preserve two parallel eligibility models.
- Holy Week weekdays might be entering through multiple routes: direct saint-window fallback, Saint Radar backfill, or forced test/backfill settings.
- A pure rank-only fix could still admit non-saint liturgical days if their ranks fall inside the allowed set, depending on how Romcal classifies Holy Week weekdays and other high-precedence days.
- A fix that is too broad could break legitimate saint fallback behavior in sparse calendars or suppress non-saint calendar rows the user still wants mirrored for other features.

### Recommended Next Step
- Use `/research-astack` to map the novena eligibility path end to end, including saint collection, Saint Radar sync, day-by-day novena generation, and existing regression coverage.

## Research

### Scope Baseline
- Investigate why the daily novena workflow creates novena audio for Holy Week weekdays that are not saint feast days.
- Focus on implementing a rank-based devotional-output contract and removing the older non-rank novena eligibility path.

### Relevant Files
- `jobs/novena/generate_daily_novena_prayer.py`
  Why it matters: this is the daily novena and novena-audio entrypoint, and it owns saint-window collection, Saint Radar sync, and the day-by-day novena/audio generation loop.
- `jobs/novena/generate_devotional_image.py`
  Why it matters: this job reuses the same Romcal rank inference but intentionally allows some non-saint liturgical celebrations, so it defines an important boundary for the fix.
- `tests/test_novena_job.py`
  Why it matters: it already contains regression coverage for saint-window selection, including the current fallback behavior that accepts generic weekdays when no saint markers exist.
- `tests/test_devotional_image_job.py`
  Why it matters: it verifies Easter Octave pseudo-rank behavior for devotional images, which helps separate desired rank normalization from novena-specific eligibility.
- `README.md`
  Why it matters: it documents the intended novena workflow and explicitly describes the shared overlay/rank normalization behavior.

### Current System Map
- `build_romcal(...)` wraps the requested Romcal calendar in a synthetic overlay that normalizes named special Sundays to `solemnity`.
- `infer_celebration_rank(...)` also maps `Precedence.weekday_of_easter_octave_*` to the app-level pseudo-rank `solemnity-easter octave`.
- `romcal_fetch_day(...)` reads from `mass_calendar(...)` first, expands `optional_celebrations`, and falls back to the yearly liturgical calendar when needed.
- `collect_saints_window(...)` iterates the requested day window, builds rows with `date`, `name`, `celebration_rank`, `precedence`, and `entry_kind`, and appends every row to `fallback_names`.
- The same function separately appends only saint-like rows to `saints` using `looks_like_saint(...)`.
- The collector stores rank metadata for every row, but does not use rank as the primary eligibility filter for novena generation.
- If any saint-like rows are found, the function returns only `saints`.
- If no saint-like rows are found anywhere in the window, the function returns `fallback_names` instead.
- That means a saint-empty window does not return an empty list; it returns generic liturgical day names such as `Tuesday of Lent` or likely `Monday of Holy Week`.
- `main()` uses `collect_saints_window(...)` as the source for `saints`, then passes those rows into:
  - OpenAI litany generation for the daily novena page
  - `sync_saint_radar(...)`
  - the day-by-day novena/audio generation loop when `NOTION_WRITE_DAILY_NOVENA_PAGE=false` and `NOTION_SAINT_RADAR_ENABLED=true`
- The day-by-day novena/audio loop does not appear to re-check saint eligibility; it trusts the collected rows and generates devotional payloads and optional audio for every qualifying target saint row.
- In parallel, `generate_devotional_image.py` already demonstrates a different contract: it ignores saint identity and instead filters by an explicit set of allowed celebration ranks.
- That devotional-image allowlist explicitly includes `solemnity-easter octave`, and `tests/test_devotional_image_job.py` currently verifies that Easter Monday is accepted as an image candidate.

### Reuse Opportunities
- Reuse `celebration_rank` and `precedence` because those values already flow through collection, Saint Radar sync, caching, and downstream generation.
- Reuse the existing novena tests around `collect_saints_window(...)` and extend them with Holy Week weekday regressions instead of creating a separate test harness.
- Reuse the devotional-image rank gating pattern as a reference implementation if the novena workflow adopts an explicit rank qualifier.
- Reuse the devotional-image tests as a safety boundary so the novena fix does not accidentally remove intended Easter Octave image support.

### External References
- No external web research was required for this pass.
- Primary sources were local code, tests, and repo documentation.

### Constraints
- Fact: `collect_saints_window(...)` currently returns fallback calendar-day names when no saint-like rows exist in the window.
- Fact: `tests/test_novena_job.py` currently codifies that fallback with `test_collect_saints_window_falls_back_when_no_saint_markers`, using `Tuesday of Lent` as the expected result.
- Fact: the day-by-day novena/audio path trusts the collected `saints` rows and does not revalidate whether a row is actually saint-like before generating devotional payloads or audio.
- Fact: `generate_devotional_image.py` intentionally uses a different eligibility model based on allowed celebration ranks, not saint identity.
- Fact: the novena pipeline already stores `celebration_rank` and `precedence`, so switching to rank-based qualification would not require a new data model.
- Fact: `generate_devotional_image.py` currently includes `solemnity-easter octave` in `DEVOTIONAL_ALLOWED_RANKS`.
- Fact: `tests/test_devotional_image_job.py` currently asserts that `collect_image_candidates_window(...)` accepts Easter Monday as `solemnity-easter octave`.
- Inference: the Holy Week bug is still more likely rooted in novena eligibility design than in the Romcal overlay itself, but rank-only qualification is now a credible alternative fix shape because the necessary metadata is already present.

### Rank-Qualified Inventory
- Using the same allowlist as `generate_devotional_image.py`, the qualifying novena ranks would be:
- `optional_memorial`
- `memorial`
- `feast`
- `solemnity`
- `solemnity-easter octave`
- On the current `general_roman` + `en` calendar data for 2026, that produces:
- `optional_memorial`: 90 celebrations
- `memorial`: 54 celebrations
- `feast`: 15 celebrations
- `solemnity`: 23 celebrations
- `solemnity-easter octave`: 6 celebrations
- Important consequence: this contract would exclude Monday and Tuesday of Holy Week, but it would still allow many non-saint liturgical days such as Epiphany, Palm Sunday, Easter Sunday, Pentecost Sunday, the Presentation of the Lord, and the Easter Octave weekdays.
- Updated product direction: the user wants Easter Octave weekdays excluded from both devotional images and the novena correction, so the final contract should no longer admit the `solemnity-easter octave` pseudo-rank.

### Risks
- Highest risk: simply removing the fallback could change existing behavior for all saint-empty windows, including calendars or periods where the current daily novena page intentionally mirrors generic liturgical days.
- Highest risk for the new idea: a rank-only allowlist may not map cleanly to "days that deserve novena audio," because liturgical rank measures calendar precedence, not whether the day represents a saint-focused novena subject.
- Highest risk for the refined idea: if we exclude Easter Octave by rank label alone, we may diverge from the rest of the overlay model in a brittle way; a precedence-based exclusion is more explicit and future-proof.
- Secondary risk: fixing only the top-level saint collector may leave downstream Saint Radar or audio code paths vulnerable if non-saint rows enter through another route such as manual/test backfill.
- Integration risk: the repo now has two adjacent devotional behaviors with different eligibility rules, so a fix must keep novena and devotional-image logic intentionally separate.

### Assumptions To Validate
- We have not yet confirmed from a live run log whether Holy Week weekday audio was produced through the standard `saints` window or through a backfill/test flag.
- We assume the problematic output was produced by the day-by-day Saint Radar novena path, because that is where saint-specific audio is generated.
- We assume Holy Week weekdays do not include saint-like metadata that would make `looks_like_saint(...)` return true.
- We have confirmed that Easter Octave weekdays are surfaced through precedence values like `Precedence.weekday_of_easter_octave_2` and are converted into the pseudo-rank `solemnity-easter octave`.
- We assume a precedence-based exclusion against `Precedence.weekday_of_easter_octave_*` is the desired mechanism for removing Easter Octave from both pipelines while preserving the rest of the rank-based contract.

### Unknowns
- Should saint-empty windows produce no novena at all, or should the daily novena page still mirror the primary liturgical day while suppressing saint-specific day-by-day novena audio?
- If rank-only is chosen, should the contract be:
- the devotional-image rank allowlist minus `solemnity-easter octave`;
- or the devotional-image rank allowlist plus an explicit precedence deny rule for `Precedence.weekday_of_easter_octave_*`?
- Are there other non-saint periods besides Holy Week where the current fallback behavior is relied on intentionally?

### Recommended Direction
- Treat this as a novena eligibility bug, not as a generalized Romcal rank bug.
- Clarified answer: yes, devotional images currently use `solemnity-easter octave`, both in the production allowlist and in regression tests.
- Updated desired direction: move toward the devotional-image-style contract, but exclude Easter Octave weekdays from both pipelines.
- Product decision: adopt the precedence-qualified rank fix and remove non-rank novena eligibility code rather than carrying both contracts.
- The strongest current recommendation remains the precedence-qualified rank fix, because it matches the user's stated direction and removes Easter Octave without depending on the pseudo-rank label alone.

## Plan

### Summary
- Introduce one shared liturgical eligibility contract for devotional outputs based on allowed celebration ranks plus an explicit precedence deny rule for Easter Octave weekdays.
- Apply that contract to both the devotional-image pipeline and the novena pipeline so Monday and Tuesday of Holy Week stop qualifying, and Easter Octave weekdays stop qualifying even though they currently map to the pseudo-rank `solemnity-easter octave`.
- Remove non-rank novena eligibility logic so the repo has one clear devotional-output contract instead of parallel saint-name and rank-based paths.
- Choose this plan because it matches the user's desired product direction, reuses the existing rank-oriented model, and avoids brittle logic based only on display names or the pseudo-rank label.

### What Already Exists
- `jobs/novena/generate_daily_novena_prayer.py` already computes and carries `celebration_rank` and `precedence` for every collected row.
- `jobs/novena/generate_devotional_image.py` already uses an explicit allowed-rank contract in `DEVOTIONAL_ALLOWED_RANKS`.
- `infer_precedence(...)` already exposes the exact precedence keys needed for an Easter Octave deny rule.
- `tests/test_novena_job.py` and `tests/test_devotional_image_job.py` already cover the current behavior, including weekday fallback and Easter Octave image acceptance.
- The release artifact already contains the 2026 inventory of celebrations affected by the proposed contract.

### Architecture
- Add a shared eligibility helper in the novena runtime module that answers one question: "Is this liturgical row eligible for devotional output?"
- That helper should accept at least:
  - `celebration_rank`
  - `precedence`
- The helper should implement this contract:
  - allow ranks: `optional_memorial`, `memorial`, `feast`, `solemnity`
  - deny precedences: any value starting with `Precedence.weekday_of_easter_octave_`
- Use the helper in both places that currently rely on broader logic:
  - devotional image candidate collection
  - novena collection / downstream novena generation eligibility
