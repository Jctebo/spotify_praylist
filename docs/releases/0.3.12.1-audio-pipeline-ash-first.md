# Release 0.3.12.1 — Audio Pipeline Ash First

Branch: fix/audio-pipeline-ash-first

## Scope

### Problem
- The scheduled audio pipeline attempts ElevenLabs first even though Ash is the desired voice; an invalid ElevenLabs credential creates repeated 401 delays.
- A deterministic novena fallback can sound ungrammatical when required devotional metadata is truncated to satisfy a presentation limit.

### Audience
- Ora Pro Nobis listeners and the operator of the scheduled publishing pipeline.

### Goal
- Render with OpenAI Ash first, retaining ElevenLabs only as an available fallback.
- Preserve complete deterministic novena metadata and ensure fallback prose remains natural when narrated.

### Constraints
- Preserve provider fallback behavior and existing contract settings other than provider preference.
- Keep generated-intro length validation for model output.
- Do not truncate deterministic fallback summary, patronage, or calendar-bridge metadata.

### Narrow Wedge
- Centralize provider preference at rendering time and keep deterministic novena fallback metadata intact.

### Non-Goals
- Replacing ElevenLabs credentials or removing ElevenLabs support.
- Relaxing the generated-intro character limit.
- Redesigning the generated-intro prompt or normal novena prayer body.

### Risks And Unknowns
- Complete fallback metadata may exceed the current presentation limit; this is acceptable because the fallback must preserve intelligible spoken prose.

### Recommended Next Step
- Remove fallback metadata truncation and test the July 30 Saint Peter Julian Eymard reproduction.

## Research

- Run 30436189999 failed at `validate_devotional_intro` because a novena deterministic fallback exceeded the 420-character limit; ElevenLabs 401s fell back successfully and were not the terminal failure.
- Audio rendering already consumes ordered provider lists, while novena fallback text is built in `jobs/publish/devotional_intro.py`.
- The July 30 Saint Peter Julian Eymard fallback truncates its summary and patronage mid-sentence, then injects those fragments into fixed prose. This is the direct cause of the narration-flow defect.

## Plan

### Summary
- Prefer OpenAI Ash ahead of ElevenLabs in the runtime provider resolver, and remove deterministic novena fallback metadata truncation so spoken fallback prose remains complete.

### What Already Exists
- `jobs/publish/devotional_intro.py` builds and validates generated and deterministic devotional introductions.
- `tests/test_publish_devotional_intro.py` already exercises deterministic novena fallback behavior.

### Architecture

```text
novena context -> deterministic fallback -> spoken intro
                    (complete metadata; no truncation)
```

### Concrete Changes
- Update `jobs/publish/audio.py` to order usable providers with OpenAI first.
- Remove `_compact_novena_fallback_context` and pass the original context to the deterministic fallback builder and validator.
- Replace the compact-metadata regression with a Saint Peter Julian Eymard-style test that asserts complete summary and patronage are preserved without ellipses.

### UX And States
- No UI change. A listener hears complete, grammatical fallback prose when text generation fails.

### Implementation Phases

#### Phase 1: Remove fallback truncation
- Edit `jobs/publish/devotional_intro.py`.
- Remove the truncation helpers and use the original context in `_fallback_result`.
- Verify deterministic fallback output preserves full supplied metadata.
- Rollback: restore the prior helper-based context compaction.

#### Phase 2: Add regression coverage
- Edit `tests/test_publish_devotional_intro.py`.
- Replace the length-bound assertion with a complete-prose regression modeled on St. Peter Julian Eymard.
- Verify with `python -m unittest tests.test_publish_devotional_intro -q`.
- Rollback: revert the test with the production change.

### Failure Modes
- A long fallback may exceed the profile maximum, which is intentional under this amendment; generated text remains validated against that limit.
- Missing metadata remains handled by the existing fallback defaults.

### QA And Test Matrix
- Force intro generation to fail with St. Peter Julian Eymard context; assert complete summary and patronage appear and no ellipsis is introduced.
- Run the focused devotional-intro tests and the novena artifact tests.

### Rollout Notes
- No migration or configuration update. The next fallback render uses the corrected behavior.

### Not In Scope
- Changing the generated-intro character limit.
- Rewriting generated-intro prompts.

### Open Questions
- None.

### Verification
- Run focused devotional-intro and novena-artifact tests, including a July 30 Saint Peter Julian Eymard fallback regression.
