# Release 0.0.5.6 - morning-prayer-redesign

- Status: Draft
- Last Updated: 2026-03-23

## Scope

### Problem
- Morning Prayer has been hard to stabilize because the current runtime is still shaped around a broader multi-prayer system.
- The job structure mixes prayer execution, novena/calendar logic, and compatibility code in a way that makes it hard to narrow safely.
- We do not want a new layer stacked on top of the old one.
- We want a deeper refactor that deletes the old shape and leaves a smaller core behind.

### Audience
- Primary user: the maintainer who needs Morning Prayer to work reliably in GitHub Actions and Notion.
- Secondary stakeholders: later prayer configs and the devotional image job, which should reuse the same calendar service.

### Current Status Quo
- The repo still contains old prayer-specific constructions and compatibility paths that were built to keep multiple prayer flows alive.
- Morning Prayer has already been moved toward a repo-local JSON contract.
- The job structure still tries to serve too many prayer modes at once instead of treating prayer configs as data.
- The current codebase is carrying around too much old surface area for a future state we no longer want.

### Goal
- Make Morning Prayer the only active prayer flow in the repo for now.
- Rework the job structure into a generic runner that takes prayer configs as input.
- Remove legacy prayer constructions instead of adapting them forever.
- Preserve Morning Prayer’s page content generation, audio file materialization, OneDrive upload flow, and Spotify resolver behavior.

### Constraints
- Morning Prayer must continue to run in GitHub Actions.
- Audio must still be written out as files so OneDrive upload keeps working.
- Do not keep old prayer compatibility layers once the Morning Prayer cutover is stable.
- Other prayers can be removed or disabled during this cutover.
- Morning Prayer should only consume novena output if it is already available; it should not generate novenas itself.
- Prefer deleting old branches of logic over keeping them behind feature flags.

### Narrow Wedge
- Keep only the Morning Prayer config, its special resolvers, and the minimum runner plumbing needed to run it.
- Remove or isolate other prayer code paths so they no longer interfere.
- Prefer a tree-pruning refactor over additive compatibility work.
- Make novena an optional shared input to Morning Prayer, not a responsibility of the prayer runner.

### Non-Goals
- Rebuilding the other prayers now.
- Reworking Spotify infrastructure beyond what Morning Prayer needs.
- Changing OneDrive itself.
- Redesigning the Notion database schema beyond Morning Prayer support.

### Risks And Unknowns
- Removing shared prayer code may expose hidden coupling in helper functions or workflows.
- A cleaner job split may require touching GitHub Actions and local runner scripts, not just Python modules.
- Morning Prayer live data may still need one final relation/order cleanup after the code cutover.
- A deeper cut may touch more files than the current Morning Prayer tests cover.

### Recommended Next Step
- Use `/research-astack` to map the Morning Prayer-only cutover: which job files can be trimmed and which runtime branches can be deleted outright.

## Plan

### Summary
- We are building a Morning Prayer-only runtime with a generic prayer runner.
- Morning Prayer should consume novena if it exists, but not generate it.
- The plan favors a deeper refactor over compatibility scaffolding: Morning Prayer stays, the rest should be removed or isolated.
- If the current job structure is too broad, we will narrow or split it so Morning Prayer has a dedicated path, then delete the old branches.

### What Already Exists
- `config/morning-prayer/morning-prayer.json` defines the surviving Morning Prayer contract.
- `docs/architecture/morning-prayer-contract.schema.json` defines the JSON schema for the contract.
- `jobs/notion/generate_prayer.py` is the generic prayer runner entrypoint for Morning Prayer config-driven execution.
- `jobs/notion/generate_page_audio.py` remains the supporting render engine for audio/page materialization.
- `scripts/migrate_page_audio_notion_schema.py` already knows how to repair the live Morning Prayer rows.
- `tests/test_page_audio_job.py` and `tests/test_migrate_page_audio_schema.py` already give us a starting regression suite.
- The current codebase already has enough structure to refactor from; we do not need to invent a second parallel system.

### Architecture
- Morning Prayer remains the only active prayer flow for now.
- Morning Prayer stays driven by a single ordered JSON resolver list.
- A generic prayer runner should own:
  - contract loading
  - resolver ordering
  - page content generation
  - audio file output
  - Spotify resolver handling
- Morning Prayer can consume novena output if it is already present, but it should not call the novena generator itself.
- The job structure should use a generic prayer runner entrypoint with a prayer config file parameter.
- Morning Prayer is the first config using that runner.
- The choice should optimize for the smallest stable surface area, not for preserving old scaffolding.
- The refactor should delete old prayer-specific code paths once the new runner is proven.

ASCII flow:
```text
Morning Prayer JSON contract
        |
        v
generic prayer runner
        |
        +--> page content
        +--> audio files -> OneDrive upload
        +--> Spotify resolver

shared novena/calendar service
        |
        +--> prayer runner novena resolver
        +--> devotional image job
```

### Concrete Changes
- Remove the old Morning Prayer legacy tests from `tests/test_page_audio_job.py`.
- Narrow `jobs/notion/generate_page_audio.py` so the surviving Morning Prayer path no longer depends on old multi-prayer constructions, then delete dead branches that are no longer reachable.
- Keep `jobs/notion/generate_prayer.py` as the active Morning Prayer runner entrypoint.
- Ensure Morning Prayer only consumes novena output if it is present and does not call the novena generator directly.
- Narrow `.github/workflows/daily_novena_prayer.yml` to call the generic prayer runner with the Morning Prayer config.
- Keep `config/morning-prayer/morning-prayer.json` as the source of truth.
- Keep `scripts/migrate_page_audio_notion_schema.py` only if Morning Prayer still needs live Notion repair during the cutover.
- Update or replace tests so they only cover the new Morning Prayer-only path.
- Delete old prayer-only job branches and helper paths after the new runner is verified.

### UX And States
- Morning Prayer should continue to produce page content and audio without manual intervention.
- Anything outside Morning Prayer should be absent or clearly disabled during the cutover.
- If the job split happens, the remote workflow should still present a single obvious Morning Prayer lane.
- Missing Morning Prayer metadata should fail early with a clear error.
- Morning Prayer should read novena only when the shared output is available.
