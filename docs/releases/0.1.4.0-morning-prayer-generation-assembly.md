# Release 0.1.4.0 - morning-prayer-generation-assembly

- Status: Shipped
- Shipped Date: 2026-03-28
- Last Updated: 2026-03-28
- Created Date: 2026-03-28
- Depends On: 0.1.3.2
- Roadmap: `docs/roadmaps/stabilization.md`
- Notes: This release shipped the custom TTS-only boundary for Morning Prayer, removed legacy page-audio discovery and fallback paths, and retired the remote Morning Prayer publish workflow so only `config/custom_tts/` contracts remain runnable.

## Scope

### Problem
- The Morning Prayer custom TTS contract still does not describe its OneDrive publish destination, so the wrapper hardcodes where the generated files land instead of letting the contract own that choice.
- The OneDrive publish step can copy a broader generated tree than the Morning Prayer contract actually owns, which risks shipping unrelated files alongside the custom TTS output.
- The existing `output_type` and `path` fields describe the contract file itself, not the OneDrive target, so they do not solve the publish-location problem.
- Legacy contract files still exist elsewhere in the repo, and the current boundary needs to make sure they never get picked up for execution or copied into the OneDrive publish tree.
- Why now: this is already a live output path, so a wrong publish boundary shows up as the wrong files in OneDrive rather than as a harmless local config mismatch.

### Audience
- Primary user: the maintainer running Morning Prayer generation and the OneDrive publish step.
- Secondary stakeholders: anyone consuming the Morning Prayer folder in OneDrive.
- Secondary stakeholders: future maintainers who need a single, obvious publish boundary for custom TTS output.

### Current Status Quo
- `jobs/notion/generate_prayer.py` still hardcodes `output_folder: "Morning"` instead of reading a publish location from the contract.
- `jobs/notion/generate_page_audio.py` writes generated audio and metadata beneath `PAGE_AUDIO_LIBRARY_DIR/<output_folder>`.
- `.github/workflows/morning_prayer_page_audio_remote.yml` publishes the Morning subtree from the sync root with rclone.
- `config/custom_tts/morning-prayer.json` defines the Morning Prayer assembly contract, but not a contract-owned OneDrive destination.
- The custom TTS loader already filters `config/custom_tts/*.json` by `enabled`, so the loader itself is not the problem.
- Legacy contract assets still live under `config/legacy/`, so the safe boundary has to be explicit about excluding them from both execution and publish copy steps.

### Goal
- Make the Morning Prayer custom TTS contract self-describing enough to say where its output should land in OneDrive.
- Ensure the publish workflow only ships the files that belong to `config/custom_tts/` and that no legacy contract output is executed or copied over.
- Success means a Morning Prayer run lands in the expected OneDrive destination and no unrelated or legacy-generated files are copied with it.

### Constraints
- Keep the Morning Prayer content and resolver sequence intact.
- Do not redesign the page-audio library root or the broader custom TTS loader.
- Avoid pulling unrelated prayer families or legacy contract surfaces into this bug fix.
- Preserve the existing local wrapper and GitHub Actions entrypoints.
- Keep the fix compatible with the current `PAGE_AUDIO_LIBRARY_DIR` behavior.
- Treat `config/custom_tts/` as the only runnable custom TTS source of truth for this branch.

### Narrow Wedge
- Add one explicit publish-location field to the Morning Prayer custom TTS contract.
- Teach the Morning Prayer wrapper and remote publish step to read that field instead of relying on a hardcoded folder.
- Restrict the sync step to the contract-owned Morning subtree only.
- Add regression coverage that proves only `config/custom_tts/*.json` loads, that legacy contracts do not run, and that the published OneDrive output is limited to the intended folder.

### Non-Goals
- Rewriting the Morning Prayer assembly text, resolver ordering, or schema beyond the publish field.
- Migrating all custom TTS contracts to a new publish model.
- Reworking the page-audio cache, upload, or render pipeline.
- Generalizing OneDrive sync for every other page-audio contract in the repo.
- Adding new prayer families or changing existing business logic outside the Morning Prayer publish boundary.
- Keeping legacy contract execution or legacy publish copying alive as compatibility behavior.

### Risks And Unknowns
- The right field name for the publish destination may need to be agreed before implementation.
- It is unclear whether the desired destination is exactly the `Morning` folder or a more specific subfolder under it.
- The sync step may still leak unrelated files if the publish root is broader than the contract-owned subtree.
- This branch assumes Morning Prayer is the only custom TTS contract being fixed right now.
- There may be hidden legacy entrypoints still wired to the old contract surfaces, so we need to verify the loader and publish step do not reach outside `config/custom_tts/`.

### Implementation Result
- The branch cut off legacy discovery paths, kept the Morning Prayer wrapper on `config/custom_tts/morning-prayer.json`, and retired the remote Morning Prayer publish workflow so archived contracts no longer run or get copied over.

## Research
### Scope Baseline
- Stop the active page-audio runtime from discovering any legacy contract files.
- Keep the Morning Prayer surface on `config/custom_tts/` only.
- Make legacy override paths fail fast instead of silently falling back.

### Relevant Files
- `jobs/notion/generate_page_audio.py` - owns the main page-audio loader, Morning Prayer contract loader, and output-directory logic.
- `jobs/notion/generate_prayer.py` - standalone Morning Prayer wrapper that still needs to reject legacy config paths.
- `scripts/run_daily_novena_prayer_local.ps1` - local Morning Prayer launcher that still defaults to `config/legacy/morning-prayer.json`.
- `scripts/run_page_audio_local.ps1` - generic page-audio local launcher that forwards `PAGE_AUDIO_CONFIG_FILE` and `PAGE_AUDIO_LIBRARY_DIR`.
- `tests/test_page_audio_job.py` - existing test harness for contract loading and bootstrap behavior.
- `README.md` - still mentions legacy fallback behavior for page-audio and Morning Prayer overrides.
- `docs/releases/0.1.4.0-morning-prayer-generation-assembly.md` - active release artifact that should reflect the new legacy-free boundary.
- `config/custom_tts/morning-prayer.json` - canonical active Morning Prayer contract.
- `config/legacy/*` - archived contract files that should remain inert.

### Current System Map
- `load_custom_tts_contracts_from_dir()` already scans `config/custom_tts/*.json` and filters on `enabled: true`.
- `load_morning_prayer_contract_from_file()` already prefers `config/custom_tts/morning-prayer.json`, but it still accepts arbitrary override paths.
- `load_page_audio_config_from_file()` still auto-scans `config/legacy/page_audio/*.json` when `PAGE_AUDIO_CONFIG_FILE` is unset, which keeps retired contracts runnable.
- `scripts/run_daily_novena_prayer_local.ps1` still injects `config/legacy/morning-prayer.json` when the prayer config is not provided.
- `page_audio_library_dir()` writes outputs under `PAGE_AUDIO_LIBRARY_DIR/<output_folder>`, so any loaded legacy contract still materializes files into the OneDrive sync root.

### Reuse Opportunities
- Reuse the existing custom TTS validation, contract parsing, and Morning Prayer assembly flow.
- Reuse the current `tests/test_page_audio_job.py` temp-root patterns.
- Reuse the existing `PAGE_AUDIO_LIBRARY_DIR` output root and contract-level `output_folder` behavior.

### External References
- None.

### Constraints
- Legacy contract files may remain on disk as archives, but they must not be discovered or executed by the active runtime.
- Any override path should stay inside `config/custom_tts/`; legacy override paths should hard fail.
- Keep Morning Prayer file-backed content and assembly semantics unchanged.

### Risks
- If `load_page_audio_config_from_file()` keeps the legacy directory scan, old page-audio contracts remain runnable through the main entrypoint.
- If `scripts/run_daily_novena_prayer_local.ps1` keeps its legacy default, the local Morning Prayer path can still resurrect retired files.
- If stale legacy output folders already exist in the OneDrive sync root, an external sync process could still copy them even after the loaders are fixed.

### Assumptions To Validate
- Legacy path overrides should be rejected, not silently ignored.
- The page-audio runtime should only load from `config/custom_tts/` by default.
- The Morning Prayer local launcher should default to the custom TTS file, not the archived legacy file.

### Unknowns
- Whether the existing `PAGE_AUDIO_TRUNCATE_MANAGED_OUTPUTS` hook should be wired into the main runtime as a follow-up hygiene pass.
- Whether `PAGE_AUDIO_CONFIG_FILE` should remain as a custom-TTS-only override or be deprecated entirely in docs.

### Implementation Direction
- Cut off the legacy discovery paths in the loaders, update the Morning Prayer local wrapper to point at the custom TTS contract, and add tests that prove legacy files cannot be run through the active entrypoints.

## Plan
### Summary
- Remove the last legacy contract discovery paths from the active page-audio flow.
- Keep Morning Prayer on `config/custom_tts/morning-prayer.json` as the default local contract.
- Update docs and tests so the only runnable surface is `config/custom_tts/` and legacy paths fail fast.

### What Already Exists
- The custom TTS loader already filters `config/custom_tts/*.json` by `enabled: true`.
- The Morning Prayer contract already lives in `config/custom_tts/morning-prayer.json`.
- `jobs/notion/generate_prayer.py` already uses the custom TTS contract shape and Morning Prayer builder.
- `tests/test_page_audio_job.py` already covers the custom TTS contract shape and default-path loading.

### Architecture
- Active flow:

```text
config/custom_tts/*.json
        |
        v
custom_tts loader
        |
        +--> jobs/notion/generate_prayer.py
        |
        v
build_morning_prayer_plan(...)
        |
        v
PAGE_AUDIO_LIBRARY_DIR/<output_folder>
        |
        v
OneDrive Morning sync root
```

- Legacy flow becomes archival only:

```text
config/legacy/*.json
        |
        v
no active loader path
```

- `PAGE_AUDIO_CONFIG_FILE` and `PRAYER_CONFIG_FILE` remain override hooks only for custom TTS files, not for legacy archives.

### Concrete Changes
- `jobs/notion/generate_page_audio.py`
  - Remove the `config/legacy/page_audio` directory scan from `load_page_audio_config_from_file()`.
  - Make the page-audio loader resolve only `config/custom_tts/*.json` or a single custom TTS override file.
  - Reject any `PAGE_AUDIO_CONFIG_FILE` path outside `config/custom_tts/`.
  - Keep the existing Morning Prayer assembly and `PAGE_AUDIO_LIBRARY_DIR` output behavior intact.
- `jobs/notion/generate_prayer.py`
  - Reject any `PRAYER_CONFIG_FILE` path outside `config/custom_tts/`.
  - Keep the default contract pointed at `config/custom_tts/morning-prayer.json`.
- `scripts/run_daily_novena_prayer_local.ps1`
  - Change the fallback `PrayerConfigFile` from `config/legacy/morning-prayer.json` to `config/custom_tts/morning-prayer.json`.
- `tests/test_page_audio_job.py`
  - Add coverage that `load_page_audio_config_from_file()` ignores legacy page-audio files and loads only custom TTS contracts.
  - Add coverage that legacy override paths fail fast in both the page-audio loader and the prayer wrapper.
  - Keep the existing enabled/disabled custom TTS coverage.
- `README.md`
  - Remove the legacy fallback language for Morning Prayer and page-audio overrides.
  - Document that the active loader surface is `config/custom_tts/` only.
- `docs/releases/0.1.4.0-morning-prayer-generation-assembly.md`
  - Sync the Scope/Research/Plan notes to the final legacy-free contract boundary.

### UX And States
- Default state: local Morning Prayer runs use `config/custom_tts/morning-prayer.json`.
- Override state: advanced users can point at another file under `config/custom_tts/` for validation.
- Error state: legacy `config/legacy/*` paths fail fast and tell the user the retired surface is no longer runnable.
- Success state: the active runtime only emits files for contracts discovered under `config/custom_tts/`.
