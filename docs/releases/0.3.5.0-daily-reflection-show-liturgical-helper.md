## Scope

### Problem
- Ora Pro Nobis now has several generated prayer experiences, including Morning Prayer, Auxilium Christianorum, Marian Antiphons, and Daily Rosary, but their daily spiritual focus is resolved separately.
- Daily Rosary already has feast/Gospel/season-aware reflection logic, Morning Prayer has a daily Gospel intro, and Auxilium/Marian Antiphons have deterministic liturgical transition blocks; without a shared daily context, these can drift in theme, tone, saint emphasis, and episode narration.
- The current `Daily Examen` Spotify contract points to a fixed external episode instead of a generated Ora Pro Nobis daily reflection experience.
- The platform needs one centralized, reusable liturgical context helper before adding another generated reflection surface, so future prayers can share one daily spiritual identity instead of duplicating precedence rules.

### Audience
- Primary user: the maintainer producing daily Ora Pro Nobis prayer and reflection episodes.
- Secondary stakeholders:
  - Listeners who move between Morning Prayer, Rosary, Auxilium, Marian Antiphon, and a daily reflection and expect the day to feel spiritually coherent.
  - Future maintainers adding new prayer experiences, music selection, narration, or caching behavior.
  - Spotify playlist automation that needs date-scoped generated episodes instead of fixed evergreen links.

### Current Status Quo
- `jobs/publish/contracts.py` owns the active publish contract expansion for generated text/audio jobs.
- `config/publish/contracts/*.json` currently includes Morning Prayer, Auxilium Christianorum, Marian Antiphons, and Daily Rosary publish contracts.
- `jobs/publish/daily_intro.py` fetches Romcal context plus daily Gospel text for Morning Prayer and related intro blocks.
- `jobs/publish/liturgical_announcement.py` provides deterministic Romcal-backed announcements without OpenAI.
- `jobs/publish/rosary_reflections.py` already implements a feast/Gospel/season precedence model for Daily Rosary, but that model is Rosary-specific.
- `jobs/novena/liturgical_helpers.py` centralizes Romcal fetching, rank inference, and season helpers used by novena, devotional image, and audio branding work.
- `config/spotify/contracts/daily-examen.json` currently uses a fixed `spotify:episode:` URI for the Notion row `Daily Examen`.
- The active publish feed already supports date-scoped Ora Pro Nobis episodes, sidecars, audio fragments, seasonal branding, and Spotify lookup contracts.

### Goal
- Add a global shared daily liturgical helper that returns concise, normalized spiritual context for a given date.
- The helper must define a deterministic daily priority order:
  - Feast day / solemnity / memorial.
  - Daily Gospel.
  - Liturgical season backfill.
- The helper output should include:
  - `date`
  - `liturgicalSeason`
  - `liturgicalWeek`
  - `feastDay`
  - `liturgicalRank`
  - `saintOfDay`
  - `gospelTheme`
  - `primaryTheme`
  - `secondaryThemes`
  - `emotionalTone`
  - `reflectionFocus`
  - `suggestedImagery`
  - `suggestedMusicMood`
  - `openingTone`
  - `closingTone`
  - `saintIntercessions`
  - `shortSummary`
- Add a new generated Ora Pro Nobis daily Ignatian-style reflection prayer experience that consumes the helper as its spiritual foundation.
- Ensure the Daily Reflection audio uses the platform's common background music/branding path, so it shares the same reverent music bed behavior as other Ora Pro Nobis generated episodes.
- The daily reflection episode must include:
  - Episode title.
  - Opening welcome beginning exactly with `Welcome to Ora Pro Nobis, where we pray with the Saints.`
  - Liturgical context introduction using the shared helper.
  - 500-900 word Ignatian reflection written for audio narration.
  - Guided Examen covering gratitude, review of the day, consolation/desolation, speaking with Jesus, and hope for tomorrow.
  - Short Catholic closing prayer aligned with the day.
  - Final closing ending with `Saint [Name], pray for us.` and `And may the peace of Christ remain with you.`
- Replace the current `Daily Examen` Spotify resolver behavior so it resolves the generated Ora Pro Nobis daily reflection episode by title/date lookup instead of a fixed episode URI.
- Preserve all existing prayer generators and prayer flows; this release adds shared context and one new reflection experience only.

### Constraints
- Scope-only pass first; no implementation in this workflow.
- Do not recreate, replace, or rewrite existing Daily Offering, Rosary, Morning Prayer, Evening Prayer, Auxilium Christianorum, Marian Antiphon, or novena prayer content.
- Do not duplicate full prayer logic inside the shared helper; it should produce context metadata, not prayers.
- Do not invent liturgical facts, saint biography, feast status, or Gospel text.
- Keep the helper lightweight, deterministic, cacheable, and safe to reuse across publish jobs.
- Keep generated reflection text suitable for Catholic audio narration with soft background music and existing podcast branding.
- Use the existing centralized audio branding/music-bed system for Daily Reflection audio; do not create a separate per-prayer music mixer in this release.
- Tests must run offline without live Spotify, Notion, OpenAI, ElevenLabs, or USCCB network access.
- Existing Spotify playlist membership should continue using the stable Notion row title `Daily Examen` unless research shows a migration is required.

### Narrow Wedge
- Build a shared publish-layer daily liturgical context helper module that wraps existing Romcal/Gospel helpers and exposes the normalized object.
- Add one new publish contract for the generated daily Ignatian reflection episode.
- Add one new publish block kind or equivalent contract-supported generator for the Ignatian reflection body.
- Cache the resolved helper and generated reflection per publish job so text, audio fragments, render metadata, and sidecars agree.
- Configure the Daily Reflection publish contract so it participates in common background music/audio branding and produces sidecar metadata for the applied bed.
- Update the `daily-examen` Spotify queue contract from fixed URI to `spotify_episode_lookup` against the Ora Pro Nobis show, matching the generated daily reflection title and date.
- Add focused regression coverage for:
  - helper precedence rules
  - helper field shape
  - generated reflection structure and required opening/closing lines
  - deterministic fallback when OpenAI is unavailable or invalid
  - publish text/audio job integration
  - Spotify contract lookup migration

### Non-Goals
- Do not modify existing prayer text or replace Rosary, Morning Prayer, Auxilium, Marian Antiphon, or novena contract flows.
- Do not retrofit every existing prayer to consume the helper in this release unless the research pass finds a tiny metadata-only integration that is required for correctness.
- Do not build a UI for reviewing or editing the helper object.
- Do not create a separate podcast feed unless research proves the existing Ora Pro Nobis feed cannot support this episode family.
- Do not change seasonal podcast music behavior globally; Daily Reflection should consume the existing common behavior unless a missing contract opt-in is discovered during implementation.
- Do not add live saint biography generation.
- Do not expand the helper into a full liturgy generator.
- Do not require all existing playlists to include the new reflection automatically; playlist inclusion remains Notion-owned.

### Risks And Unknowns
- The helper can become too broad if it tries to satisfy every future prayer use case at once; the first version should optimize for shared daily identity and narration prompts.
- Daily Rosary already has a working day-context model; research must decide whether to extract/reuse that logic directly or build a new helper and later migrate Rosary.
- Gospel text availability is not guaranteed; helper fallback behavior must remain useful and auditable without weakening current Morning Prayer rules.
- Optional memorial precedence needs careful product judgment: the user asked that saints' memorials subtly influence tone, but major solemnities should override Gospel emphasis.
- `Saint [Name], pray for us.` needs a safe default when there is no saint of day, such as Saint Ignatius of Loyola, without pretending the date has a saint focus.
- Long generated reflection content affects fragment cache size, TTS cost, and sidecar readability.
- The old `Daily Examen` Notion row title may no longer describe the generated `Daily Reflection` experience perfectly, but changing it could break existing playlist membership.
- Title/date matching must be broad enough for variable themes but narrow enough to avoid resolving the wrong Ora Pro Nobis episode.

### Recommended Next Step
- Run `/research-astack` to map the exact shared helper extraction point, compare Rosary day-context logic with Morning Prayer daily-intro logic, identify the publish block integration shape, and validate the safest Spotify lookup title contract for replacing the fixed `Daily Examen` resolver.

### Current System Map
- Publish contracts are loaded from `config/publish/contracts/*.json` by `load_publish_contracts()`.
- Each entry is normalized by `_normalize_entry()` and `_normalize_block()`, then rendered through `resolve_block_content()`.
- Dynamic block kinds already include `daily-intro`, `liturgical-announcement`, `prayer-intro`, `rosary-intro`, and `rosary-decades`.
- Runtime context is built once per job through `_entry_runtime_context()`. Daily Rosary uses this to cache `rosary_day_context` and `rosary_reflection_set` so text, audio fragments, titles, and sidecars agree.
- `build_text_jobs()` and `build_audio_jobs()` both call `_entry_runtime_context()` and then attach render metadata. Rosary metadata is attached through `_attach_rosary_reflection_context()` and `rosary_reflections`.
- Audio fragments are expanded from the same block graph with `_expand_audio_fragments_from_block()`. Leaf dynamic blocks become one fragment when their resolved text is non-empty.
- Final audio sidecars are written in `render_audio_job()` and already persist `render_context`, `rosary_reflections`, `audio_branding`, `fragments`, and `resume_markers`.
- `apply_audio_branding()` runs after raw spoken audio assembly and before final loudness normalization. It resolves the date's liturgical music season, loops the season asset, renders the common Ora Pro Nobis welcome, and mixes a background bed when `background_bed.enabled` is true.
- Spotify queue contracts can define exactly one of `resolver`, `spotify_uri`, seasonal URI fields, or `spotify_episode_lookup`. Lookup contracts match show id, required name terms, and date formats against Spotify episode names.

### Constraints
- The helper must not generate prayers; it should return concise context metadata only.
- The Ignatian reflection generator may call OpenAI, but it needs deterministic fallback text so publish jobs still succeed without an API key.
- Tests must monkeypatch Romcal, Gospel, and OpenAI seams; no live network calls in unit tests.
- Adding a new publish contract changes the expected active contract set and audio job count in existing tests.
- The generated reflection title should include stable `Daily Reflection` and publish date terms so Spotify lookup stays robust while theme text varies.
- The `Daily Examen` Notion row title can remain unchanged in the Spotify contract to avoid Notion membership churn.
- The final closing needs a saint fallback when no saint-focused celebration exists; `Saint Ignatius of Loyola` is the safest default because the new experience is Ignatian.
- Daily Reflection background music should remain common and centrally configurable through `audio_branding`; any reflection-specific mood from the helper should be metadata for future selection, not a second audio selection path in this release.

### Risks
- Shared helper theme derivation can accidentally become pseudo-liturgical if it over-interprets sparse Gospel text. Keep theme labels conservative and source-aware.
- Optional memorials are currently included in Rosary feast focus. The new helper should include them subtly, but title/primary focus should not overstate suppressed celebrations as a major feast.
- One long generated reflection fragment means a small text change invalidates the whole reflection TTS fragment. This is acceptable for the first release but worth noting.
- If the new reflection title contains too many variable terms, Spotify lookup can miss; if it contains too few terms, it can collide with other Ora Pro Nobis episodes. Use `Daily Reflection` plus date as the stable lookup pair.
- Existing `audio_manifest_hash()` includes title, description, fragments, TTS settings, published date, and audio branding metadata. The helper/generation metadata must affect fragment text or audio config/metadata consistently so stale audio is not reused.
- Sidecar schema consumers are tolerant today, but adding `daily_reflection` should be additive and JSON-safe.
- Common background music is already date/season-driven, not helper-theme-driven. This means `suggestedMusicMood` will not affect the actual music bed until a future release connects mood metadata to music selection.

- The Spotify queue contract key and Notion row should remain `daily-examen` / `Daily Examen` while the generated episode title says `Daily Reflection`.
- A single long reflection fragment is acceptable for TTS/cache behavior in the first release.
- `Saint Ignatius of Loyola` is an acceptable final-closing fallback when the helper has no `saintOfDay`.
- The helper can initially feed only the new Daily Reflection while existing prayers remain untouched; later releases can migrate Morning Prayer/Rosary/etc. to consume it.
- Common background music should be delivered by the existing audio branding pass for the new contract, with no new audio assets required.

- Add a generated Daily Reflection episode powered by that helper, with Ignatian/examen structure and deterministic fallback.

### UX And States
- Listener-facing first words remain the common Ora Pro Nobis welcome.
- Episode title should be recognizable in Spotify even when the theme changes daily.
- Reflection narration should feel personal and contemplative, with sparse optional audio cues only when useful.
- When Gospel text is unavailable, the episode should still publish with a truthful season/feast-based reflection and fallback metadata.
- When OpenAI is unavailable, the fallback reflection should be shorter but structurally complete.
- When background music assets are missing, publish should continue with unbranded spoken audio and `audio_branding.skip_reason` in the sidecar, matching current behavior.

### Implementation Phases
1. Add helper module and tests with mocked Romcal/Gospel inputs.
2. Add Ignatian reflection generation/fallback module and tests.
3. Wire runtime context and new dynamic block into publish contracts.
4. Add `daily-reflection.json` publish contract and update publish contract tests.
5. Update `daily-examen.json` Spotify lookup and queue tests.
6. Verify audio branding metadata is present for Daily Reflection audio jobs.
7. Run targeted tests, then a broader publish/Spotify regression suite.

### Failure Modes
- Romcal unavailable: return season/Gospel-backed context if possible; otherwise deterministic ordinary-time-style fallback with clear source metadata.
- Gospel unavailable: use feast/rank/season data and set Gospel fields conservatively.
- OpenAI unavailable or malformed output: use deterministic fallback reflection.
- No saint focus: final closing uses `Saint Ignatius of Loyola, pray for us.`
- Music asset missing or ffmpeg branding failure: keep raw spoken audio and record existing `audio_branding` skipped metadata.
- Spotify lookup misses: queue refresh should surface the missing episode rather than silently using the old fixed URI.

### QA And Test Matrix
- Unit: `daily_liturgical_context` solemnity beats Gospel, memorial subtly influences tone, ordinary day falls back to Gospel, missing Gospel falls back to season.
- Unit: `ignatian_reflection` validates opening welcome, word-count target, examen sections, exact final peace line, and saint fallback.
- Contract: active publish contracts include Daily Reflection and existing contracts remain unchanged.
- Contract: text/audio jobs include helper/reflection render metadata.
- Audio: Daily Reflection audio config produces `audio_branding` hash metadata and sidecar status.
- Spotify: `daily-examen` validates as a lookup resolver and matches date/title terms.
- Regression: existing Rosary, Morning Prayer, Auxilium, and Marian Antiphon tests still pass without rewritten content.

### Rollout Notes
- This is additive for publish output, but it changes playlist resolution for the existing `Daily Examen` row.
- First production run should inspect the generated sidecar for helper source metadata, reflection source metadata, and `audio_branding.status`.
- Keep the old fixed Spotify URI in git history only; do not add a runtime fallback to the external episode unless production lookup proves unreliable.

### Not In Scope
- Migrating existing prayers to consume the helper.
- Theme-driven music asset selection from `suggestedMusicMood`.
- New music assets.
- New podcast feed.
- Notion row rename from `Daily Examen` to `Daily Reflection`.

### Open Questions

- Should long Ignatian reflections be split into multiple TTS fragments later for lower rerender cost?
- Should future releases migrate Rosary's day-context logic to consume this helper directly?
