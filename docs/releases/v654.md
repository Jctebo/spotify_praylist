# v654 — Shared office links land on the wrong track's page: the day row's share link carries no source

## §1 The item (DevOps Board row 1631 · seam gap found by the v653 chain's Review, live pin ora-pro-nobis-v653-1)

**The model (v643, standing, NOT re-opened):** a track's share link names the track itself — for the two office sides that share one slot (Morning Prayer · Evening Prayer, the v650 two-track shape) the link carries `&src=<source>` as the disambiguator, and opening the link lands on THAT side's own track page (Shape 1: one app page, identity in the query string). The homily carve-out stands: homilies share as attachments, never as links.

**The defect (grounded by the v653 chain — harness-v653 L6 through the real tap path, recorded at docs/releases/v653.md §3.6):** a day row's share link carries **no `&src=` for either office side**. The link still names the slot, so the landing resolves the slot's first-painted side — under the drop down set to Both, a shared **Divine Office** link lands on the **Sing the Hours** track's page. The sender shares one track; the receiver opens its sibling.

**The ask:** a day row's share link for EACH office side carries that side's source, and opening the link lands on that side's own track page — Morning and Evening, both sides. Every other family's share link stands byte-identical to today (podcast · episode · prayer · homily carve-out untouched).

## §2 Plan — the share chain, grounded end to end (base = standing-clone main 9f5f176, the v653 ship tree; production pin ora-pro-nobis-v653-1, Worker 7815ee51; all line numbers are `app/worker/src/client.ts` on that tree)

### 2.1 The chain, link by link

1. **The raw track carries everything.** `extSlotTrack(slot, st)` (17914) builds each office side's raw track whole: `kind: 'external'`, `source: st.source`, its own title / stream / duration. `extPaintTracks650` (2246) emits one raw track per painting side, the second-painted side stamped `_side650`.
2. **The seam drops the kind — THE GAP.** The composed day (`extRebuildDescs`, 19455) emits each side through `expandDescs → trackDesc` (15410). `trackDesc` copies `source` onto the composed descriptor unconditionally, and `_occ` / `_side650` by stamp — but it copies `kind` **only for podcast** (the `if (t.kind === 'podcast')` block, the v620 repair). A composed office descriptor in `state.dayDescs` therefore holds `source` ('Divine Office' / 'Sing the Hours') and its side stamp, and **no kind**.
3. **The builder keys on the dropped field.** `shareAppUrlFor(t)` (16439) builds the day form `?s=day&date=…&id=…` and appends the source parameter at 16465 under exactly one condition: `if (t.kind === 'external' && t.source)`. For a composed office descriptor the condition can never fire — the link goes out with no `&src=` for either side. Every real share seat feeds the builder a composed descriptor: the row ⋮ menu's Share and the `[data-rowshare]` handler (both resolve from `state.dayDescs` — the v653 card-key read), the Favorites mirror (12470), and `shareTrackSheet` (16484). (The player's own share of an office track escapes the gap: `state.current` is rebuilt by `queueLiveDesc` from the raw slot track, kind standing — named here so the fix does not disturb it.)
4. **The landing is whole — it is starved, not broken.** The landing parse (16658) accepts `src` and validates it against `shareSrcOk643` (the standing labels: 'Divine Office' · 'Sing the Hours' · every EXT_SLOTS source; an invalid src refuses the whole landing). `trackPageDaySelect643(L)` (16764) with `L.src` standing filters the day's candidates by `x.source === L.src` and falls back to the slot's backup record — it selects the named side's own descriptor. With no `src` in the link it returns `pool[0]`, the first-painted side. **No landing change stands in this release.**
5. **Why the gap never showed (Improvement D):** v643's harness office legs and v653's L6c drove the builder with descriptors whose kind stood — v653's L6c literally hand-stamps it (`Object.assign({}, doSide, { kind: 'external' })`, harness-v653.mjs:331). The production shape — the composed descriptor — was never driven. This release's harness drives composed descriptors only (§2.5).

### 2.2 The fix shape — PICKED: key the branch on the descriptor's own source, guarded by the labeled slot

In `shareAppUrlFor`'s day-form branch, the `&src=` appends when the descriptor's own `source` stands AND either of the standing discriminators holds:

- `t.kind === 'external'` — the standing condition, byte-for-byte (raw descriptors, the player's rebuilt current, and every kind-standing shape keep exactly today's behavior), OR
- `opnLabeledSlot650(id)` — the descriptor's id is one of the two labeled office slots (`ext-morning-prayer` · `ext-evening-prayer`, 2209): the only slots where two tracks share one slotId, which is the only case `&src=` exists for (the v643 §3.2 comment at the branch says exactly this).

The appended value is the descriptor's own `source`, verbatim, through the standing `shareEnc640` — the same value the standing branch appends, and a member of the landing's accepted label set for both labeled sources.

**Why not the other shape (carry `kind: 'external'` through `trackDesc`): rejected on grounded side effects.** The composed descriptor's missing kind is load-bearing elsewhere today: `epCardIsEpisode` (10207), consulted with the composed descriptor in the rowmenu handler (17055), returns false for office rows precisely because the kind is absent — so office rows' ⋮ menus carry no **Details** item today. Stamping the kind at the seam would silently add that item (and re-dress every other kind consumer in §2.3) — behavior changes outside this release's ask, taken without John's word. The source-keyed branch changes exactly one thing: the office day-row share link gains its side's `&src=`.

**Byte-identity guard:** for any descriptor that is not (kind-standing external) and not (a labeled-slot id), the branch's condition is unchanged-false, so the URL is built by the identical code path as the base — podcast · own episode · prayer · non-office external day rows (e.g. the readings slot: composed, source standing, id not a labeled slot → no `&src=`, as today) all stand byte-identical. Implement proves this by harness (§2.5 L3), not by assertion.
