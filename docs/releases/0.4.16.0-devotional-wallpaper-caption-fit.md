# Release 0.4.16.0 - devotional-wallpaper-caption-fit

- Status: IMPLEMENTED, REVIEWED, AND VERIFIED
- Created / updated: 2026-10-11
- Base: 0.4.15.0
- Branch: fix/devotional-wallpaper-long-title
- Source: failed scheduled/manual devotional wallpaper runs on 2026-10-10 and 2026-10-11; linked run 38114743285.

## Scope

### Problem
- Recent wallpaper workflow runs fail with `Wallpaper text does not fit its device safe area` during local caption rendering.
- This exception happens before local OCR and vision QA, so the existing third-attempt fallback is never reached and no image is delivered.
- The renderer stops shrinking text at 20 pixels. A valid long caption that is only slightly wider than its safe area at that floor aborts the entire run.

### Audience
- Primary user: the operator relying on daily phone and watch devotional wallpapers.
- Secondary stakeholders: the scheduled GitHub Actions workflow and private run-summary consumers.

### Current Status Quo
- The linked run resolved 14 devotional subjects and then failed in the wallpaper pipeline with the safe-area exception; its private artifact records `status: failed` and no completed-run summary.
- The same exception appears in the October 10 manual/scheduled failures and October 11 scheduled failure.
- Main already accepts the third rendered image when local OCR or vision QA still rejects it, marks `fallback_used: true`, and reports `complete_with_warnings` after delivery. That behavior only applies after caption composition succeeds.
- `_draw_centered_label` shrinks in 2-pixel steps only while the size is greater than 20, then raises if any line still exceeds the allowed width.

### Goal
- Keep all exact title and subtitle text and fit valid captions within phone/watch safe areas by shrinking to a tested minimum and wrapping without dropping words.
- Preserve the existing three-generation attempt policy and third-attempt QA fallback.
- Reserve hard failure for captions that cannot fit at the minimum readable size, invalid images, provider failures, or delivery/integrity errors.

### Constraints
- Preserve phone/watch dimensions, naming, prompts, QA thresholds, staging, checksum verification, rotation, and current QA fallback semantics.
- Do not weaken OCR/vision review or mark a rejected caption as approved.
- Do not change the unrelated infographic workflow.

### Narrow Wedge
- Fix the deterministic label-fitting boundary in `_draw_centered_label` so long valid titles can shrink below 20 pixels and wrap into additional safe lines.
- Add a regression test at a constrained width that fails on the current minimum-size behavior and passes when the smaller safe size is evaluated.

### Non-Goals
- Changing image-generation retry count or adding a new QA fallback path; main already implements and records acceptance on the third QA-rejected render.
- Changing calendar resolution, image models, visual prompts, OneDrive storage, scheduling, or rotation.

### Risks And Unknowns
- Very small text can be hard to read; retain a minimum font size, limit the number of lines, and cover both device layouts with tests.
- If a title truly cannot fit after safe wrapping, the renderer should continue to fail clearly rather than clip or omit text.

### Recommended Next Step
- Update the shared label fitter and add a targeted regression test, then run the wallpaper renderer and pipeline suites.

## Research

- Production evidence: run 38114743285 failed in `Run wallpaper pipeline` with `RuntimeError: Wallpaper text does not fit its device safe area`; its uploaded artifact contains only the resolved calendar report and failed run status, confirming the error occurred before a completed summary.
- The October 10 manual run 38027446291, October 10 scheduled run 38047389364, and October 11 scheduled run 38135329869 show the same exception.
- `origin/main` already contains the requested third-attempt QA behavior from `fix: continue wallpaper run after QA retries` (commit `b89ce7f`): after three local/vision QA rejections, `render_variant` returns the final image marked unapproved with `fallback_used`, QA stage, issues, and attempt count. The pipeline records this as `complete_with_warnings` after successful delivery.
- `jobs/novena/devotional_wallpaper_render.py::_draw_centered_label` currently shrinks only while `base_size > 20`, then performs a final width check that raises. Phone titles use a 53% image-width base size and watch titles use 4.5% or 5.5%; sufficiently long labels can need smaller lettering.
- `tests/test_devotional_wallpaper_render.py` covers output sizes, circular bounds, monthly captions, and the third-attempt fallback; a focused constrained-width test can expose the fitter's lower-size boundary without a provider call.

## Plan

### Summary
- Extend the existing safe label fitter to evaluate smaller fonts and allow up to four wrapped lines, preserving all text and the existing hard-failure boundary.
- Leave QA fallback and delivery code unchanged because main already implements the requested behavior.

### What Already Exists
- Shared phone/watch label rendering, a circular watch-safe chord calculation, three generation attempts, a third-attempt QA fallback, private QA metadata, delivery verification, and `complete_with_warnings` summaries.

### Architecture
```text
valid title -> deterministic wrap/shrink -> exact overlay -> local OCR -> vision QA
                                                        |             |
                                            caption fit fails       QA still fails
                                            only at safe minimum    after attempt 3
                                                        |             |
                                                  hard error      accepted + warning
```

### Concrete Changes
- `jobs/novena/devotional_wallpaper_render.py`: change `_wrap_lines` to split an individual overlong token safely; update `_draw_centered_label` to try down to a 14-pixel minimum and permit up to four lines while checking every line against its safe-area width.
- `tests/test_devotional_wallpaper_render.py`: test a label that needs a size below 20 at a constrained safe width, verify all text is drawn, and exercise long calendar titles for phone/watch output dimensions and circular constraints.
- `docs/releases/VERSION`: advance to 0.4.16.0 for this planned release.
- `docs/releases/0.4.16.0-devotional-wallpaper-caption-fit.md`: track scope, research, implementation, and verification.

### UX And States
- No interactive UI. Captions that previously aborted while slightly oversized are wrapped/shrunk and processed through existing OCR and vision QA. If QA still rejects the third image, existing behavior delivers it as `complete_with_warnings` with exact issues recorded. A caption that cannot fit safely at the minimum size remains a hard failure.

### Implementation Phases
#### Phase 1: Extend safe caption fitting
- Goal: avoid aborting on valid text that needs modestly smaller or additional line layout.
- Files: `jobs/novena/devotional_wallpaper_render.py`, `tests/test_devotional_wallpaper_render.py`.
- Symbols: `_wrap_lines`, `_draw_centered_label`.
- Change: split overlong words without losing characters; shrink from the current size to a 14-pixel floor; allow up to four lines and recheck each line against the available phone/watch safe area.
- Verification: targeted constrained-width regression, long-title phone/watch render tests, existing circle-bound and normal caption tests.
- Rollback: revert renderer and its tests together.
- Dependencies: none.

### Failure Modes
- Caption still exceeds the safe area at the minimum: retain the explicit fit error; never clip or drop text.
- A caption becomes too small or line-heavy: tests cap the minimum at 14 pixels and layout at four lines; QA still evaluates the final image.
- Third render still fails OCR/vision: existing main-branch behavior accepts it marked unapproved and logs a quality fallback; operational/provider and delivery failures remain fatal.

## Progress

- Preserved the existing third-attempt QA fallback from main; the linked production failure occurs earlier during caption layout, before OCR/vision QA.
- Added constrained-width and long calendar title renderer regressions.
