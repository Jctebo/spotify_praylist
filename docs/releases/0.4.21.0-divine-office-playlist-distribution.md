## Scope

### Problem
- The current Spotify playlists group prayers into Morning, Midday, and Night, leaving several Divine Office hours outside their natural time-of-day groupings.
- Office of Readings, Evening Prayer, and Night Prayer should remain available as distinct daily listening points.

### Audience
- Primary user: the owner and listeners of the daily prayer playlists.
- Secondary stakeholder: the repository playlist refresh and prayer-home publishing workflows.

### Current Status Quo
- `config/spotify/playlists/` defines Morning, Midday, Night, and Sunday.
- Midmorning Prayer and Daily Gospel Exegesis currently share Midday; Daily Mass Readings are in Morning.
- Some Office hours already have contracts but are not distributed across matching playlists.

### Goal
- Maintain Morning, Midmorning, Midday, Mid-afternoon, Evening, Night, and Sunday playlists with the approved ordered membership.
- Include all Divine Office hours, remove Mass Readings from the playlists, place Daily Gospel Exegesis in Midmorning, and place Daily Examen in Evening.
- Refresh and verify the resulting production Spotify playlists and daily prayer home.

### Constraints
- Reuse existing playlist contracts and Spotify playlist IDs wherever possible.
- Create any missing Spotify playlists and store their returned IDs in the repository; do not fabricate IDs.
- Preserve Sunday sermon membership and all existing daily prayers not explicitly removed or moved.
- Avoid changing the unrelated, uncommitted Morning Prayer work in the primary checkout.
- Keep playlist ordering deterministic and reflected in the prayer homepage.

### Narrow Wedge
- Updated the playlist definitions and their regression expectations to the approved seven-playlist layout, created missing Spotify playlist identities, and ran the daily Spotify refresh and Pages build.

### Non-Goals
- Changing prayer audio, contract resolver behavior, publishing schedules, or prayer content.
- Removing Mass Readings from the repository or from any non-playlist surface.
- Merging or renaming Evening and Night.

### Risks And Unknowns
- Created three Spotify playlist identities; retained the current Night playlist ID for Night and used the new identity for Evening.
- The two Mid-afternoon contracts (`midafternoon-prayer` and `afternoon-prayer-loh`) both resolve the same Divine Office hour; including both would duplicate None, so retain one canonical Office entry.
- Production refresh uses the GitHub Spotify credentials; the prayer home deploys through the Pages publish workflow.

### Recommended Next Step
- The playlist identities, homepage grouping, exact membership arrays, and regression tests were verified before implementation.

## Research

- Playlist definitions in `config/spotify/playlists/*.json` are the source of truth for ordered refresh membership and prayer-home groups.
- Current Spotify playlist IDs resolve to the existing “Morning Praylist,” “Midday Praylist,” “Night Praylist,” and “Sunday Praylist” entities. Preserve those IDs and add identities for Midmorning, Mid-afternoon, and Evening.
- The canonical contracts already exist for each Office hour: `divine-office-invitatory`, `office-of-readings`, `morning-prayer-loh`, `midmorning-prayer`, `midday-prayer`, `afternoon-prayer-loh`, `evening-prayer-loh`, and `night-prayer-loh`.
- `midafternoon-prayer` and `afternoon-prayer-loh` both use the `MIDAFTERNOON` resolver, so listing both would insert the same daily Office item twice. Use the explicitly labeled LOH contract once.
- The home builder in `scripts/build_pages_artifact.py` currently imposes a four-group display order. It must be updated to the seven approved groups so generated `prayers.json` follows the same order as the UI.
- `.github/workflows/daily.yml` refreshes Spotify from playlist definitions. The Pages artifact is built and deployed by `.github/workflows/publish_audio.yml` on main; that workflow can be manually dispatched after merge for immediate production verification.
- `tests/test_spotify_contracts.py`, `tests/test_build_pages_artifact.py`, `tests/test_publish_site.py`, and `README.md` contain the membership, display order, workflow, and product documentation expectations that need updating.

## Plan

### Summary
- Expand the daily playlist set to Morning, Midmorning, Midday, Mid-afternoon, Evening, and Night while preserving Sunday.
- Reuse existing Spotify IDs, create only the three missing playlist identities, and keep repository definitions as the single source of truth for membership and home display.

### What Already Exists
- Resolver-backed contracts exist for every Divine Office prayer and fixed/episode-lookup contracts exist for all other items in the approved list.
- `load_spotify_playlist_definitions` validates and loads ordered membership; `refresh_playlist.py` replaces each selected playlist with resolved contract items.
- `build_prayer_data` builds the homepage groups from the same playlist definitions.
- Existing authenticated Spotify and GitHub connections can create playlist identities, dispatch the refresh workflow, and verify the committed deployment.

### Architecture
```text
Playlist JSON definitions ──> Spotify refresh ──> six daily playlists + Sunday
              │
              └─────────────> Pages builder ──> ordered prayer-home groups
```

The refresh replaces each playlist with items in its contract order. Dynamic playlist IDs are created in Spotify, captured in the corresponding JSON definitions, and never synthesized locally.

### Concrete Changes
- `config/spotify/playlists/morning.json`: remove `daily-mass-readings`; preserve the remaining approved morning order.
- `config/spotify/playlists/midmorning.json` (new): add Midmorning Prayer and Daily Gospel Exegesis.

- `config/spotify/playlists/mid-afternoon.json` (new): add Afternoon Prayer (LOH), Saint of the Day, and Auxilium Christianorum.
- `config/spotify/playlists/evening.json` (new): add Office of Readings, evening Marian Antiphon, Daily Examen, and Evening Prayer (LOH).
- `config/spotify/playlists/night.json`: keep the existing Night ID and set membership to Night Prayer (LOH) and Night Before Compline.
- Create Spotify playlists “Midmorning Praylist,” “Mid-afternoon Praylist,” and “Evening Praylist”; copy the IDs returned by Spotify into the three new definitions.
- `scripts/build_pages_artifact.py`: set the page group order to Morning, Midmorning, Midday, Mid-afternoon, Evening, Night, Sunday.
- `scripts/setup_spotify.ps1`: prompt for and write IDs for all seven playlists so future setup runs do not omit the new definitions.
- `tests/test_spotify_contracts.py`: assert the complete ordered membership map, including Mass Readings exclusion and Office placement.
- `tests/test_build_pages_artifact.py`: assert all seven ordered groups and prayer counts.
- `tests/test_spotify_setup_script.py` (new): ensure the setup wizard reads and writes IDs for every checked-in playlist definition.

- `docs/releases/0.4.20.3-divine-office-playlist-distribution.md`: record implementation progress, QA, and release notes.

### Failure Modes
- Playlist creation returns no usable ID: stop before editing definitions and retry or report the Spotify connector error.
- Spotify IDs are not editable by the workflow account: the refresh fails before production is complete; verify account ownership and secret identity.
- A contract fails to resolve on refresh: inspect workflow logs and confirm other playlist items; the runtime reports unresolved contracts.
- Pages order differs from playlist membership order: compare generated `prayers.json` and the builder display-order mapping.
- GitHub CI or deployment fails: keep production unchanged until the failed check is fixed and rerun.
