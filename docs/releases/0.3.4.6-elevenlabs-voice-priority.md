# Release 0.3.4.6 - ElevenLabs Voice Priority

Status: Shipped
Date: 2026-06-05
Branch: enhancement/elevenlabs-voice-priority

## Scope

### Problem
- Some active audio surfaces still encode OpenAI TTS voices as the only voice path or as the first voice option.
- The desired voice policy is focused, not global: Amelia from ElevenLabs should replace OpenAI-first/OpenAI-only TTS surfaces, while existing ElevenLabs-first voices such as Morning Prayer and Rosary stay unchanged.
- Auxilium Christianorum's short role-specific call/response fragments currently use OpenAI voices for the distinct speaker effect; those should move to ElevenLabs Brian instead of OpenAI.

### Audience
- Primary user: the maintainer publishing Ora Pro Nobis prayer audio.
- Secondary stakeholders: listeners who hear the daily Morning Prayer, Auxilium Christianorum, Marian Antiphon, Daily Rosary, and novena feeds.

### Current Status Quo
- Publish-audio contracts support ordered provider lists and already fall back from ElevenLabs to OpenAI.
- Morning Prayer, Marian Antiphons, and Rosary already prefer an ElevenLabs voice before OpenAI; those existing ElevenLabs-first voices are not replacement targets.
- Auxilium Christianorum main narration already uses Amelia `pGAwIQNN9UjOkKxjAyGQ`.
- Auxilium Christianorum `versicle` and `response` role overrides are OpenAI-only today, using `alloy` and `echo`.
- Novena audio still uses the older OpenAI-only audio contract shape.

### Goal
- Make Amelia `pGAwIQNN9UjOkKxjAyGQ` the first provider option wherever active prayer audio currently relies on OpenAI TTS voices as the first or only spoken provider.
- Keep OpenAI voices as the second provider option for fallback, not the preferred voice.
- Replace Auxilium Christianorum's role-specific OpenAI voice usage with ElevenLabs Brian `nPczCjzI2devNBz1zQrb` as the first provider, with the corresponding OpenAI role voice retained second.
- Preserve existing non-OpenAI-first ElevenLabs voices, including the current Morning Prayer and Rosary voices.
- Preserve episode ids, titles, feed routing, loudness normalization, text generation, and cache-safe provider identity.

### Constraints
- Do not change OpenAI text generation for daily intros, Rosary reflections, or novena text cleanup; this release is about spoken TTS providers.
- Do not remove OpenAI fallback unless a surface cannot support provider lists yet.
- Avoid changing RSS identity or Spotify playlist lookup terms.
- Voice/provider changes intentionally invalidate affected fragment cache entries.
- ElevenLabs requires `ELEVENLABS_API_KEY`; OpenAI fallback still requires `OPENAI_API_KEY`.

### Narrow Wedge
- Update only OpenAI-first/OpenAI-only active audio surfaces so ElevenLabs Amelia is first and OpenAI remains second.
- Update Auxilium Christianorum role overrides so Brian is first for the distinct short-role voice, with OpenAI second.
- Research whether novena audio can reuse the publish provider fallback machinery before planning implementation.

### Non-Goals
- No new voice-selection UI.
- No live ElevenLabs voice-library search or sample generation in this scope pass.
- No text prompt, liturgical calendar, Spotify resolver, RSS retention, or loudness target changes.
- No replacement of existing Morning Prayer, Rosary, or Marian Antiphon ElevenLabs-first voices just because OpenAI exists as fallback.
- No broad refactor of all historical release artifacts or legacy page-audio archives.

### Risks And Unknowns
- Novena audio currently renders through an OpenAI-only path; adding provider fallback there may require runtime changes, not just contract edits.
- The repo identifies Amelia from the prior Auxilium release as `pGAwIQNN9UjOkKxjAyGQ`; confirm this is still the intended Amelia voice for OpenAI-first/OpenAI-only replacements before implementation.
- Brian `nPczCjzI2devNBz1zQrb` is user-supplied but not yet present in the repo, so implementation should validate only shape and contract behavior unless a real API smoke run is requested.
- Provider changes will alter fragment hashes and cause rerenders for affected episodes.

### Recommended Next Step
- Use `/research-astack` to map every active OpenAI TTS voice surface, confirm which can be changed by contract only, and identify the minimum runtime changes needed for novena provider fallback.

## Research

### Scope Baseline
- Prefer ElevenLabs Amelia over OpenAI TTS only where OpenAI is currently first or only.
- Preserve OpenAI as fallback.
- Use ElevenLabs Brian for Auxilium Christianorum short role-specific fragments where OpenAI currently provides a separate speaker voice.
- Preserve existing ElevenLabs-first voices, especially Morning Prayer, Daily Rosary, and Marian Antiphons.

### Relevant Files
- `config/publish/contracts/morning-prayer.json` - Morning Prayer active publish-audio contract; already has an ElevenLabs voice first and OpenAI second, so its existing ElevenLabs voice should stay unchanged.
- `config/publish/contracts/auxilium-christianorum.json` - Auxilium active contract; main provider is Amelia, while `role_overrides.versicle` and `role_overrides.response` are OpenAI-only.
- `config/publish/contracts/marian-antiphon-angelus.json` - Ordinary-season Marian Antiphon contract; already has ElevenLabs first and OpenAI second, so it is a preservation target.
- `config/publish/contracts/marian-antiphon-regina-caeli.json` - Easter-season Marian Antiphon contract; already has ElevenLabs first and OpenAI second, so it is a preservation target.
- `config/publish/contracts/rosary.json` - Daily Rosary contract; already has an ElevenLabs voice first and OpenAI second, so its existing ElevenLabs voice should stay unchanged.
- `jobs/publish/contracts.py` - Normalizes `audio_config.providers` and `role_overrides`, validates ElevenLabs `voice_id` and `model_id`, and attaches effective fragment audio configs.
- `jobs/publish/audio.py` - Implements ordered provider fallback for publish-audio fragments and supports OpenAI plus ElevenLabs renderers.
- `jobs/publish/fragments.py` - Includes provider settings in fragment and manifest hashes, so voice/provider changes are cache-safe.
- `jobs/novena_contracts/audio.py` - Novena renderer defaults directly to `openai_tts_renderer` and does not currently use provider fallback.
- `jobs/novena_contracts/contracts.py` - Novena default audio config is OpenAI-shaped with `model`, `voice`, `format`, and `speed`.
- `jobs/novena_contracts/validators.py` - Validates novena publishing shape today but does not validate provider lists.
- `contracts/novenas/families/standard-9-day.json` and many `contracts/novenas/feast-days/*.json` files - Novena contracts explicitly set OpenAI TTS model/voice today.
- `scripts/new_novena_contract.py` - Creates new novena contracts with OpenAI-shaped audio settings today.
- `tests/test_publish_contracts.py` - Existing tests assert Auxilium Amelia voice id, Morning Prayer provider ordering, and Auxilium role override OpenAI voices.
- `tests/test_publish_audio_fragments.py` - Existing tests cover provider fallback, ElevenLabs request shape, and role-specific provider fallback.
- `tests/test_novena_*` - Existing novena tests construct and assert OpenAI-shaped audio configs.

### Current System Map
- Active publish audio loads JSON contracts from `config/publish/contracts`.
- Each publish entry has `audio_config`; if `providers` exists, `jobs/publish/audio.py` tries provider objects in order.
- Role-specific fragments can override the base provider list through `audio_config.role_overrides`, and `jobs/publish/contracts.py` copies those effective configs onto fragments before rendering.
- Cache identity includes normalized provider and voice settings, so changing from OpenAI to Amelia/Brian will naturally create new fragment hashes.
- Novena audio is a separate subsystem under `jobs/novena_contracts`; it builds jobs from `contracts/novenas` and calls `render_fragment_audio` with a single renderer rather than publish-audio provider fallback.
- `jobs/novena_contracts/contracts.py` currently copies only keys already present in `DEFAULT_AUDIO_CONFIG`, so a `providers` list in a novena contract would be dropped unless normalization is extended.
- `jobs/novena_contracts/audio.py` currently sets `renderer = renderer or openai_tts_renderer` and then calls `render_fragment_audio(...)`; this prevents automatic ElevenLabs-first provider fallback.

### Reuse Opportunities
- Reuse existing publish-audio provider objects for Amelia and OpenAI fallback only on OpenAI-first/OpenAI-only surfaces.
- Reuse existing ElevenLabs request support in `jobs/publish/audio.py`.
- Reuse role override support for Auxilium Brian without inventing a new fragment-role mechanism.
- Reuse existing provider fallback tests as the pattern for Brian-first Auxilium role coverage.
- For novenas, expose a small public helper around the existing publish provider fallback logic so novena rendering can share it without duplicating provider resolution.
- Keep explicit OpenAI model/voice fields as fallback compatibility fields on novena audio configs while adding a `providers` array.

### External References
- Existing release artifact `docs/releases/0.3.1.10-morning-prayer-elevenlabs-voice.md` documents the provider-list design and ElevenLabs API requirements.
- Existing release artifact `docs/releases/0.3.2.8-auxilium-response-audio-cleanup.md` documents role-specific fragment provider fallback and the ElevenLabs text-to-speech endpoint shape.
- ElevenLabs text-to-speech conversion endpoint is already implemented as `POST /v1/text-to-speech/{voice_id}` in `jobs/publish/audio.py`.

### Constraints
- Publish-audio contract changes are low-risk because the provider fallback path already exists and is covered.
- Novena changes are higher-risk because provider fallback is not currently wired into `jobs/novena_contracts/audio.py`.
- Contract tests currently expect OpenAI role override voices for Auxilium and will need to be updated to Brian-first expectations.
- Existing sidecar/cache metadata will show changed `tts` settings and changed fragment hashes after implementation.
- Existing Morning Prayer, Rosary, and Marian Antiphon first-provider `voice_id` values must remain unchanged.

### Risks
- Treating this as a pure JSON edit would miss novena OpenAI-only audio.
- Replacing Auxilium role overrides with Brian-only would remove fallback; the scoped intent is Brian first, OpenAI second.
- Applying Amelia globally would incorrectly replace established Morning Prayer/Rosary ElevenLabs voices; implementation must target OpenAI-first/OpenAI-only surfaces only.
- Broadly editing every novena JSON by hand could create noisy churn. Prefer a default/provider normalization path plus a focused update to the family/default contract and contract-generation script, unless tests prove explicit feast-day JSON updates are required.

### Assumptions To Validate
- Amelia should be `pGAwIQNN9UjOkKxjAyGQ` for OpenAI-first/OpenAI-only replacements. It should not replace the existing `2NfTQuOn6dRQvgKuC2le` ElevenLabs voice used by Morning Prayer, Rosary, and Marian Antiphon contracts today.
- Brian should use `model_id` `eleven_multilingual_v2`, `format` `mp3`, and the same conservative voice settings style unless the user wants custom Brian tuning.
- Novena audio should be included in "all usage of OpenAI voices" because its active audio config is OpenAI TTS.

### Unknowns
- Whether legacy custom TTS/page-audio archives should remain untouched; research recommendation is to leave them alone unless active runtime still loads them.
- Whether a real ElevenLabs smoke run should be part of QA or whether tests are enough for this iteration.

### Recommended Direction
- Move to `/plan-astack` with two implementation tracks: Auxilium role override updates first, then a focused novena provider-fallback wiring plan.
- Prefer a complete implementation that covers OpenAI-first/OpenAI-only active audio surfaces, Auxilium role overrides, novena defaults/contracts, and regression tests while explicitly preserving existing Morning Prayer/Rosary ElevenLabs voices. This is a boilable lake: human ~1 day / CC+astack ~30-45 minutes.

### What Already Exists

### Architecture
- Publish-audio path stays contract-driven.
- Novena audio should reuse provider fallback instead of keeping a separate OpenAI-only renderer path.
- Fallback order is always explicit in `providers`.

```text
Audio fragment
  |
  v
effective audio_config
  |
  +-- providers[0]: ElevenLabs Amelia or Brian
  |       |
  |       +-- success -> cache/write fragment
  |       |
  |       +-- failure
  |
  +-- providers[1]: OpenAI fallback voice
          |
          +-- success -> cache/write fragment
          +-- failure -> fail audio job clearly
```

### UX And States
- No UI scope.
- Listener-facing success state: newly rendered Auxilium role fragments and novena episodes use the intended ElevenLabs voice first.

### Failure Modes
- `ELEVENLABS_API_KEY` missing:
  - Detection: ElevenLabs provider raises a missing-env error.
  - User experience: OpenAI fallback renders if `OPENAI_API_KEY` is available; otherwise the job fails with both provider errors.
- Brian or Amelia voice id invalid:
  - Detection: ElevenLabs API returns an error; fallback attempts OpenAI.
  - User experience: audio can still publish through OpenAI fallback, with logs showing ElevenLabs failure.
- Provider list dropped by novena normalization:
  - Detection: novena tests show no `providers` in job/sidecar audio config.
  - User experience: novenas would remain OpenAI-first, violating scope.
- Existing Morning Prayer/Rosary voice accidentally replaced:
  - Detection: preservation tests fail on first provider `voice_id`.
  - User experience: published voices change unexpectedly for established episodes.
- Fragment hash churn:
  - Detection: expected cache misses/rerenders after provider changes.
  - User experience: first run after deployment may render more fragments than usual.
