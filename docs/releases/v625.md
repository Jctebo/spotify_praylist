# v625 — Fix: stale warning is by day, not by hours

## §1 Scope

John's correction (voice call, Ora thread, 2026-11-23 08:39 CT): v624 shipped a stale rule keyed to a 3-hour threshold — a slot served from a last-good pointer whose feed had not answered in 3 hours carries the warning. John: that is wrong. **Staleness is by DAY, not by hours.** If the app serves an episode that is not today's — his example, yesterday's episode standing at 6 AM — it is already stale, because it is not today's episode.

This release changes the stale predicate only:

- A slot served from a last-good pointer whose **episode's day is not the presented day** (America/Chicago) carries the stale warning **from the start of the day, at once** — no threshold, no grace.
- A **same-day** last-good (today's episode re-served after a later fetch failure the same day) is **not** stale: no warning.
- The warning text stands verbatim: **"Today's episode has not updated yet — showing the last one that loaded"** — on the Praylist row and the opened view, as v624 placed it.
- Nothing else in v624 moves: the watcher cron, stand-down, the nudge, the pointers, the "still checking" state — all untouched.

Streamlined small-release path: Scope+Plan compressed into this doc, then Implement · light Review · Ship. Base: pin ora-pro-nobis-v624-1 · Worker 59b7d3e7 · main 2cdc219.

## §2 Grounding + decisions

### Where the 3-hour term lives (grounded firsthand)

One seam paints the warning: `externalsLivePayload` (`app/worker/src/index.ts`) computes, for each slot with a resolution row,

```ts
const stale = !fst?.last_success_at || (Date.now() - Date.parse(fst.last_success_at) > EXT_STALE_MS);
```

— the **feed's last successful read** against `EXT_STALE_MS` (3 h, v624 §2 D3). The client (`client.ts`) only paints the flag it is given (the descriptor's `stale`, threaded live payload → settleMeta → slot state → row + opened view); it holds no threshold of its own. The fix therefore lands server-side at this seam; no client change.

Two field consequences of the shipped rule, both wrong under John's correction:

1. **False warning:** a slot serving today's own episode gains the warning once the feed has been silent 3 h — e.g. a feed that breaks at noon makes the (correct) afternoon paint warn, though the episode standing is today's.
2. **Late warning:** a slot serving a not-today episode under a healthy, answering feed carries no warning until the feed itself ages 3 h past its last success — and a stood-down feed's last success can sit hours back before the flag ever fires.

### How an episode is attributed to a day (grounded per matcher)

The resolver writes one row per (date, slot); the row's `date` is the day being resolved. Whether the episode in the row **is** that day's episode depends on the standing matcher (no matcher is edited, v624 D8 stands):

| Slot class | Matcher | Attribution of the picked episode |
|---|---|---|
| Divine Office ×8 | `extMatchDivineOffice` | Title-date == target date (the matcher requires the title to name the target day). The episode is **for the row's date** by construction — including when it was published the evening before. |
| Bible in a Year | `extMatchBible` | "Day N" with N = day-of-year of the target date, current year. For the row's date by construction. |
| Saint of the Day | `extMatchSaint` | Latest-by-release, then the title's MM/DD prefix must equal the target date — a wrong-day saint reads missing, never served. For the row's date by construction. |
| Daily TV Mass | `extMatchTvMass` | The title names the presented day. For the row's date by construction. |
| Sing the Hours fills | `extMatchSth` | Title prefix `M.D.YY` == target date. For the row's date by construction. |
| Daily Gospel Exegesis | `extMatchLatestByDate` | **Latest release not after the presented date — the one matcher that can seat an older episode under a newer date.** Its standing attribution (v611): the episode FOR day D is the one whose **Chicago release date is D−1**. So the picked episode's own day = its Chicago release date **+ 1 day**, which can be earlier than the row's date when the feed lags (nothing released on D−1 yet, or a posting gap). |

So the day an episode is **for** is knowable at write time for every slot class, and exactly one class (exegesis) can diverge from its row's date. The predicate keys on that attributed day — never on the raw publication date alone: the Divine Office episode published yesterday evening **for** today is today's episode and must not warn (the evening-before trap the correction names).

### Decisions

- **D1 — Record the attributed day at write.** Migration **0048** adds `episode_date TEXT` to `ext_resolutions` (appended last in the column list). `extResolutionWrite` stamps it for every **present** row: the row's date for the date-exact classes; for exegesis, `chicagoShiftDate(chicagoDateOf(picked.pubMs), 1)`. Missing rows carry NULL (no episode stands to be judged).
- **D2 — The predicate.** In `externalsLivePayload`: a present row is stale ⇔ `(episode_date ?? date) !== presented date`. No time term, no feed-state read. The flag keeps its name and payload shape (`stale: true` on the slot entry); the client paint is byte-untouched.
- **D3 — Legacy rows.** Rows written before 0048 carry `episode_date = NULL` and read as their row's date (not stale) — no false warnings on the standing store. At ship, one forced agent-door resolver pass re-stamps today + tomorrow with attribution, so the live window is covered from the first hour.
- **D4 — The nudge need-test is not the warning predicate.** `extNudgeFeedKeys` keeps its standing freshness term (`EXT_STALE_MS`) untouched: it decides which feeds a nudge pass force-fetches, it paints nothing. `EXT_STALE_MS` survives for that one use; its comment is amended to say the warning no longer reads it. (The client's nudge trigger reads the slot flags as before — a stale-flagged slot still wakes the resolver, which is the self-healing path when a lagging feed posts.)
- **D5 — Stale is scoped to present rows.** A missing row serves no episode; its own states (missing after a successful read · missing + unresolved) already carry their paint and their nudge paths, unchanged.
- **D6 — Fallback legs unchanged.** Entries the live payload builds in-request (the courier fallback, the Saint / TV Mass matcher legs) carry no stale flag before or after: they are fresh, date-exact matches computed at read time.

### Harness plan

New `app/worker/harness-v625.mjs`, modeled on harness-v624 (real Worker bundle, real routes, fake D1, production-shaped fixtures):

- **S1 ◆** Yesterday-attributed last-good warns from the start of the day: exegesis feed whose newest item was released two days before today (attributed to yesterday) resolves present for today; the live payload carries `stale: true` with the feed's last success **fresh** (fail-on-old: the 3 h rule warns only after 3 h of feed silence, and not at all under an answering feed).
- **S2 ◆** The same entry with the feed's last success aged 6 h still warns (no threshold shapes the flag at any hour).
- **S3 ◆** Same-day last-good does not warn: exegesis item released yesterday (attributed to today) resolves; a later pass fails (feed 500), the row stands; live payload carries **no** stale with the feed's last success aged 6 h (fail-on-old: the 3 h rule warns).
- **S4** A fresh today resolution does not warn (healthy all-feed resolve; no slot carries stale).
- **S5 ◆** The evening-before office episode attributed to today does not warn: Divine Office items carrying today's title dates with yesterday-evening pubDates resolve for today; no stale — including with the feed's last success aged past 3 h (fail-on-old).
- **S6** A pre-0048 row (episode_date NULL) reads as its row date: no stale.
- **S7** A missing row carries no stale flag; the warning copy stands verbatim in the client (row + opened view).

Regressions: harness-v624 · harness-v620 minimum table. **One leg reversed BY NAME:** harness-v624 **L5 check 1** ("feed silent >3h: slot carries stale:true") encodes the struck rule — a same-day episode gaining the warning from feed silence alone. It is amended in place to the day rule's expectation with a v625 comment; its substance (a not-today episode warns; a fresh slot does not) is re-proven by S1–S5. No other leg moves.

## §3 Implement

Seat: chain-v625-implement · contract 909 · branch release/v625 off main 2cdc219.

### Files changed

- `app/worker/harness-v624.mjs` — L5 check 1 reversed BY NAME only (below); no other leg touched.

### The predicate as shipped (D2/D5)

In `externalsLivePayload`, the 3-hour computation and its feed-state fetch are gone. A row-carrying slot now computes:

```ts
const stale = res.state === "present" && (res.episode_date ?? res.date) !== date;
```

Present rows only (D5); legacy NULL `episode_date` reads as the row's date (D3). `EXT_STALE_MS` survives for its one remaining use — the `extNudgeFeedKeys` need-test (D4, untouched) — and its comment now says so; the `externalsLivePayload` header comment carries the day rule with a v625 note.

### Attribution stamping per class (D1)

- `extResolutionWrite` gains `episodeDate` as its last parameter; `episode_date` is appended LAST in the INSERT column list, LAST in the bind args, and added to the ON CONFLICT update (`episode_date = excluded.episode_date`) — harness-v624's FakeDB arg destructure stays compatible.
- `runSlotFeed` gains optional `episodeDateFor?: (date, it) => string | null`: a present item stamps `episodeDateFor ? episodeDateFor(date, it) : date`; a missing write stamps NULL.
- Daily Gospel Exegesis (the only divergent class): `(date, it) => it.pubMs != null ? chicagoShiftDate(chicagoDateOf(new Date(it.pubMs)), 1) : null` — Chicago release date + 1 (v611).
- Divine Office · Bible in a Year · Saint of the Day · Daily TV Mass: default — the row's date (date-exact by construction; no matcher edited).
- Sing the Hours fills (direct write in the Sth block): the row's `date` (extMatchSth is title-date-exact).
