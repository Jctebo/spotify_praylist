# Release 0.3.10.0 - Novena TTS Normalization and Sacred Bell

Status: Shipped
Branch: codex/novena-tts-sacred-bell
Last Updated: 2026-07-24

## Scope

### Problem
- Printed novena contracts still contain text-to-speech artifacts such as abbreviated saint titles and spoken personal-intention directions.
- The existing deterministic `sacred_bell` cue is functional but needs a more reverent, church-bell character before it is used across the novena catalog.

### Audience
- Primary user: listeners praying along with published Ora Pro Nobis novena audio.
- Secondary stakeholders: maintainers authoring novena JSON contracts and future text-to-speech migrations.

### Current Status Quo
- Novena templates use both compact `blocks` and legacy `sections`; some duplicate spoken content still says “Pause here to mention your request” or uses abbreviations such as `St.`.
- The audio pipeline supports a cached synthesized `sacred_bell`, but its timbre is not explicitly designed as a sacred, resonant bell.

### Goal
- Make every repository novena contract pass the prayer-TTS normalizer in strict mode with no unresolved findings.
- Replace clear personal-intention instructions with a non-spoken sacred-bell cue followed by a five-second pause, preserving the prayer's wording around it.
- Expand safe clerical and saint abbreviations in spoken text while retaining ambiguous wording for review rather than altering it.
- Improve the synthesized bell and invalidate its cache through a synthesis-version change; retain deterministic, provider-free rendering.

### Constraints
- Preserve theology, canonical wording, prayer order, and prosodic punctuation.
- Keep legacy `sections` synchronized with structured `blocks` where both exist.
- Do not invent voice-provider identifiers or apply uncertain editorial removals.
- Keep audio generation offline and cacheable; do not add third-party audio assets or network dependencies.

### Narrow Wedge
- Audit all 94 JSON novena contracts, apply only high-confidence normalization findings, and update the shared sacred-bell synthesis and regression tests.

### Non-Goals
- Rewriting prayer prose, changing doctrine, or removing ambiguous rubrics/provenance.
- Adding new TTS providers, voices, or external bell recordings.
- Migrating unrelated publish-audio contracts.

### Risks And Unknowns
- Large legacy `sections` may require careful regeneration from compact `blocks` to avoid divergence.
- “More sacred” is subjective; the implementation will use a low, resonant strike with a slower, natural decay and validate the generated waveform mechanically.

### Recommended Next Step
- Inspect normalizer findings and the current bell synthesis, then plan an auditable contract migration with synchronized structured and legacy representations.

## Research

### Scope Baseline
- Normalize every novena's spoken contract content, preserving the Father McGivney Guild note, converting clear call-and-response, expanding printed repetitions, and improving the shared bell.

### Relevant Files
- `contracts/novenas/**/*.json`: 94 source contracts; 11 contain role-marker or repeat transformations.
- `jobs/novena_contracts/contracts.py` and `validators.py`: schema/validation boundary for `blocks`, text parts, repeats, and fragment libraries.
- `jobs/novena_contracts/engine.py`: expands structured parts into ordered audio fragments; supports `repeat` and now propagates `audio_role`.
- `jobs/novena_contracts/audio.py`: renders novena fragments; now resolves role overrides per fragment.
- `jobs/publish/contracts.py`: contains the reusable `effective_audio_config_for_fragment` role-override policy.
- `jobs/publish/fragments.py`: deterministic cached sacred-bell synthesis; updated locally to version 2 with lower frequencies and a longer decay.
- `tests/test_novena_contracts.py`, `tests/test_novena_engine.py`, `tests/test_novena_artifacts.py`, and `tests/test_publish_audio_fragments.py`: existing contract, rendering, artifact, and bell regression surfaces.

### Current System Map
- JSON contracts load into `TemplateSpec` objects; `blocks` are the audio-canonical structured form and legacy `sections` remain readable/source-compatible.
- The engine expands one `part` with `repeat: 3` into three ordered audio fragments, each with its own cache key.
- The novena audio renderer previously ignored role overrides even though the publish pipeline already implements them; the local renderer change now reuses the publish helper.
- `sacred_bell` is generated offline by FFmpeg and cache-keyed by a synthesis version.

### Reuse Opportunities
- Use existing `repeat` instead of copying prayer prose.
- Use existing `audio_role` plus `role_overrides` instead of provider-specific branching.
- Reuse the normalizer as the audit oracle; it does not write source contracts.

### External References
- None required: all work uses existing OpenAI voice identifiers and local FFmpeg synthesis.

### Constraints
- `sections` cannot express alternating TTS voices safely; affected contracts must gain canonical `blocks`/`parts` for audio.
- The Father McGivney publisher note remains intact by user decision.
- The currently flagged transformations span eleven contracts: six with V/R markers and six with repeat notation (one overlaps).

### Risks
- Editing duplicated `sections` manually can drift from canonical blocks; contract tests must assert rendered audio order rather than raw string equality alone.
- Some V/R markers appear inside long prose and need manual boundaries to avoid accidentally reclassifying litanies as responses.

### Assumptions To Validate
- OpenAI Alloy is accepted by the configured provider fallback for all novena audio jobs; existing OpenAI configuration patterns establish this, but an isolated render test should confirm it.
- The new bell remains within podcast loudness limits after final assembly.

### Unknowns
- No product decisions remain: the user chose to keep the McGivney note, use Alloy for responses, and expand repetitions structurally.

### Recommended Direction
- Migrate only the eleven identified contracts using native structured parts, then validate every source file with a strict normalizer pass and render focused samples.

## Plan

### Summary
- Complete the contract migration using the existing structured novena model: Ash narrates and reads versicles, Alloy reads responses, repetitions become native repeated fragments, and every intention prompt becomes a bell plus pause.

### Architecture
```
contract blocks/parts -> novena engine -> audio fragments -> role override -> provider render
       V./R. split             repeat expansion       Ash / Alloy        cached MP3
```

### Concrete Changes
- Edit `jobs/novena_contracts/engine.py` and `audio.py` only as needed to preserve `audio_role` and apply role overrides.
- Edit `jobs/publish/fragments.py` to ship the versioned sacred-bell synthesis.
- Migrate the eleven flagged contracts under `contracts/novenas/feast-days/`; create or refine `blocks[].parts[]`, remove spoken markers/notation, and retain matching readable sections.
- Add/update tests in `tests/test_novena_contracts.py`, `tests/test_novena_engine.py`, `tests/test_novena_artifacts.py`, and `tests/test_publish_audio_fragments.py`.

### Implementation Phases
#### Phase 1: Runtime support
- Verify role metadata propagation and per-fragment effective audio configuration.
- Test an Alloy response while Ash remains the default.

#### Phase 2: Contract migration
- Convert the six V/R contracts into explicit versicle/response parts.
- Convert repetitions in the six flagged contracts into `repeat` fields and clean the printed marker from speech.
- Replace every clear personal-intention instruction with `sacred_bell` plus a 5,000 ms pause.
- Preserve the McGivney note unchanged.

#### Phase 3: Bell and verification
- Test the version-2 bell cache and generated MP3.
- Run all novena tests and the strict normalizer over all 94 contract files.

### QA And Test Matrix
- Contract loading accepts every migrated file.
- Engine output preserves exact fragment order, repeat count, cues, pauses, and `audio_role`.
- Audio render uses Alloy only for `response` fragments.
- McGivney output retains the Guild note.
- Sacred-bell output is generated once, cached, and regenerated under the changed synthesis key.
- Strict normalizer audit has no unresolved findings; any review-only text explicitly preserved is documented.

### Failure Modes
- A malformed part or invalid repeat fails contract validation before publish.
- A missing/invalid Alloy override falls back through existing provider policy and is caught by focused renderer tests.
- A source/blocks mismatch is caught by contract and engine tests before release.

### Not In Scope
- New voices/providers, external bell audio, or prose/theological rewrites.
