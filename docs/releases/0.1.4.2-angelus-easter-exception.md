# Angelus Easter Exception

- Status: Shipped
- Created Date: 2026-03-29
- Last Updated: 2026-03-29
- Depends On: 0.1.4.1
- Roadmap: `docs/roadmaps/stabilization.md`
- Notes: Shipped record for the season-aware Angelus resolver that stays on the ordinary-time Angelus URI outside Easter and switches to Regina Caeli during Easter season.

## Scope

### Problem
- The remaining Marian Antiphon contracts still carry one `spotify_uri`, so there is nowhere to express an Easter-season exception.
- The active Spotify contract loader and resolver path treat queue contracts as static URIs or static resolvers.
- The repo already has a shared liturgical calendar helper boundary, but the Marian Antiphon path does not use it to choose between normal and Easter URIs.
- We want the season choice to come from configuration, not from hardcoded special cases in the runtime.

### Audience
- Primary user: the maintainer who owns the Spotify prayer playlists.
- Secondary stakeholders: listeners who expect Marian Antiphon to switch to Regina Caeli during Easter season.
- Secondary stakeholders: future maintainers who need the season rule to be obvious in config, not buried in code.

### Current Status Quo
- `config/spotify/contracts/angelus-morning.json`, `angelus-midday.json`, and `angelus-evening.json` are the remaining Marian Antiphon contracts, and each currently defines a single Spotify URI today.
- The deleted `angelus-song.json` and `angelus-podcast.json` files are no longer part of the active contract set.
- `jobs/playlist/spotify_contracts.py` currently validates exactly one of `resolver` or `spotify_uri`.
- `jobs/playlist/refresh_playlist.py` resolves contract URIs through a single-spec path, with optional fallback resolvers.
- `jobs/novena/liturgical_helpers.py` already exposes the liturgical calendar boundary we should reuse for season detection.
- No config field yet distinguishes ordinary time from Easter season for the Marian Antiphon family.

### Goal
- Add `spotify_url_normal` and `spotify_uri_easter` to the Marian Antiphon contracts.
- Use the shared liturgical helper to identify Easter season and choose Regina Caeli during Easter, the normal Marian Antiphon URI otherwise.
- Keep the change config-driven and limited to the Marian Antiphon family unless the contract shape naturally needs a small generalization.

### Constraints
- Use the shared liturgical helper boundary instead of hand-rolled calendar checks.
- Preserve the active Spotify refresh path and playlist definitions for all non-Marian Antiphon contracts.
- Fail closed if the season cannot be determined or if the season-specific URI is missing.
- Keep the contract shape easy to validate and test from JSON alone.

### Narrow Wedge
- Add `spotify_url_normal` and `spotify_uri_easter` URI slots to the Marian Antiphon contracts.
- Teach the resolver to select the correct URI based on the liturgical season.
- Add tests that prove the resolver chooses the normal URI outside Easter and Regina Caeli during Easter.

### Non-Goals
- Reworking every Spotify contract into a season-aware contract.
- Changing playlist definitions, Notion sync, or playlist membership rules.
- Replacing the liturgical helper boundary or the Romcal calendar source.
- Adding new prayer families or expanding the exception beyond Marian Antiphon and Regina Caeli.

### Risks And Unknowns
- The exact contract field names need to be clear enough that future maintainers do not guess wrong.
- If only part of the Marian Antiphon family is updated, the playlist could become inconsistent across surfaces.
- A hidden fallback could mask a missing Easter URI and make the wrong season play quietly.

## Research

### Scope Baseline
- This release is a narrow Angelus/Marian Antiphon seasonal exception: keep the normal Angelus URI outside Easter and use Regina Caeli during Easter season.
- The affected surface is the three active Marian Antiphon contracts (`angelus-morning`, `angelus-midday`, `angelus-evening`) and the three playlist definitions that include them (`morning`, `midday`, `night`).
- The base Spotify refresh path is already contract-first, so the change should stay on the existing loader/resolver path rather than reintroducing Notion into queue assembly.

### Relevant Files
- `config/spotify/contracts/angelus-morning.json`, `config/spotify/contracts/angelus-midday.json`, `config/spotify/contracts/angelus-evening.json` - current Angelus contracts; each still carries a single `spotify_uri`.
- `config/spotify/playlists/morning.json`, `config/spotify/playlists/midday.json`, `config/spotify/playlists/night.json` - playlist membership surfaces that already reference the Angelus contracts.
- `jobs/playlist/spotify_contracts.py` - contract loader/validator; currently enforces the one-of `resolver` / `spotify_uri` shape.
- `jobs/playlist/refresh_playlist.py` - queue builder and runtime entrypoint; currently resolves contracts through `resolve_contract_uri(...)` inside `build_queue_for_playlist_definition(...)`.
- `jobs/novena/liturgical_helpers.py` - shared Romcal helper boundary; already carries the calendar wiring and Easter Octave precedence logic that a season check would need to sit beside.
- `tests/test_spotify_contracts.py` - loader validation coverage.
- `tests/test_refresh_job.py`, `tests/test_refresh_job_contract_path.py` - queue assembly, weekday gating, and selected-playlist execution coverage.
- `docs/roadmaps/stabilization.md`, `docs/roadmaps/novena-audio.md` - roadmap references that already call out the Angelus default/Easter-season Regina Caeli swap.

### Current System Map
- `jobs/playlist/spotify_contracts.py` loads JSON contracts into `SpotifyQueueContract` named tuples and rejects invalid JSON, duplicate keys/names, invalid weekdays, and contracts that do not match the current single-target rule.
- `jobs/playlist/refresh_playlist.py` builds each playlist by iterating ordered contract keys, gating them by weekday, then resolving either a direct Spotify URI or a resolver with optional fallback.
- The active Spotify refresh path is already contract-first and only uses Notion in optional post-write helpers, so the Angelus change should not need to reopen the old Notion queue-assembly path.
- `jobs/novena/liturgical_helpers.py` should own the Easter-season decision so the Spotify path can reuse the shared liturgical helper boundary alongside the special-Sunday normalization it already carries.
- The three Angelus contracts currently share one Spotify URI, so the Easter distinction does not yet exist anywhere in config.

### Reuse Opportunities
- Reuse `build_queue_for_playlist_definition(...)`, `resolve_contract_uri(...)`, and `contract_runs_today(...)` instead of adding a parallel playlist builder.
- Reuse the shared liturgical helper boundary in `jobs/novena/liturgical_helpers.py` instead of hand-rolling Easter-date math.
- Reuse the existing playlist definitions as the fan-out surface so the Angelus change stays confined to the current Morning, Midday, and Night playlists.
- Reuse the current loader and test modules as the validation layer and extend them for the seasonal contract shape.

### External References
- `romcal` is the non-repo liturgical source behind `jobs/novena/liturgical_helpers.py`; it is the likely boundary for deciding whether a date falls in Easter season.
- `docs/roadmaps/stabilization.md` and `docs/roadmaps/novena-audio.md` already frame this as the next Angelus default/Easter-season repair.
- Spotify URI shape remains the contract boundary for queue resolution.

### Constraints
- The loader currently enforces exactly one of `resolver` or `spotify_uri`, so the Angelus family needs a deliberate exception or a small generalized seasonal-contract shape.
- The change should fail closed if Easter season cannot be determined or if the seasonal URI is missing.
- The scope stays limited to the Marian Antiphon family and should not become a repo-wide seasonal URI model.
- The release artifact should stay aligned with the code and tests as the contract shape changes.

### Risks
- If the seasonal decision becomes ad hoc runtime logic, the wrong prayer could play with no visible config trail.
- If only one Angelus contract is updated, Morning, Midday, and Night will diverge across the same season rule.
- If the new contract shape is too broad, it could invite season-aware behavior into unrelated Spotify contracts.
- If Easter detection is implemented in more than one place, the logic can drift.

### Assumptions To Validate
- The loader should accept the Angelus-specific seasonal fields while keeping the existing one-of `resolver` / `spotify_uri` rule for every non-Angelus contract.

### Unknowns
- Whether the loader should add a dedicated seasonal-contract shape for Angelus or generalize the contract schema just enough to support the exception cleanly.

### Recommended Direction
- Keep the scope narrow: add explicit `spotify_url_normal` and `spotify_uri_easter` slots for the three Angelus contracts, route selection through the existing contract-resolution path, and place Easter detection in `jobs/novena/liturgical_helpers.py`.
- This is ready for `/plan-astack` now that the season-detection boundary is locked.

## Plan

### Summary

- Keep the contract-first Spotify refresh path unchanged for every non-Angelus contract and keep Easter detection in the shared liturgical helper boundary.

### What Already Exists
- `jobs/playlist/spotify_contracts.py` already owns contract JSON loading, duplicate detection, and weekday gating.
- `jobs/playlist/refresh_playlist.py` already resolves each playlist through `build_queue_for_playlist_definition(...)` and `resolve_contract_uri(...)`.
- `jobs/novena/liturgical_helpers.py` already wraps Romcal, and `romcal_fetch_day(...)` returns `season` and `season_name` for a specific date.

- The three playlist definitions that fan out Angelus already exist, so this release only needs the contract swap.

### Architecture
- Add `is_easter_season_for_date(calendar: str, locale: str, dt: date) -> bool` to `jobs/novena/liturgical_helpers.py`, implemented from `romcal_fetch_day(...)` and `Season.easter_time`.
- Extend `SpotifyQueueContract` with Angelus seasonal fields `spotify_url_normal` and `spotify_uri_easter`.
- Keep the existing `resolver` / `spotify_uri` shape for every non-seasonal contract.
- Thread the current runtime date from `main()` into `build_queue_for_playlist_definition(...)` and `resolve_contract_uri(...)` so weekday and Easter checks use the same cutoff.
- Normalize the chosen seasonal value to a queue-safe `spotify:` URI before handing it to Spotify writes.
- Flow:

```text
config/spotify/contracts/angelus-*.json
        |
        v
load_spotify_queue_contracts()
        |
        v
main() -> current_date + weekday
        |
        v
build_queue_for_playlist_definition(..., current_date)
        |
        v
resolve_contract_uri(..., current_date)
        |
        +-- Easter season -> spotify_uri_easter (Regina Caeli)
        |
        +-- otherwise     -> spotify_url_normal (normal Angelus)
        |
        v
recreate_playlist_items()
```

### Failure Modes
- Missing or partial Angelus seasonal fields: loader rejects the contract before any Spotify write, and the user sees a clear `RuntimeError`.
- Wrong runtime date or timezone cutoff: the wrong Angelus variant could be selected for a boundary run; the date-threading tests should catch this.
- Bad Spotify link shape in `spotify_url_normal`: normalization fails, the queue never reaches Spotify, and the run exits non-zero instead of publishing bad data.
