# Release 0.3.1.12 - Publish Audio Bootstrap No Cache Hotfix

Date: 2026-05-09

Status: Shipped
Last Updated: 2026-05-09
Branch: enhancement/publish-audio-force-rebuild
Depends On: 0.3.1.11

## Scope

### Problem
- The publish audio job can short-circuit on an already-published episode when the MP3 and sidecar content hash already match.
- That behavior is usually correct, but it makes a rerun on `main` too sticky when we need to force a fresh rebuild after changing runtime wiring or revalidating a day-level publish.

### Goal
- Add a `bootstrap-no-cache` publish mode so the publish audio workflow can deliberately bypass the episode-level cache gate while still behaving like bootstrap for date selection.
- Keep the normal cache path unchanged for `daily`, `bootstrap`, and `reset`.
- Add regression coverage for the new mode and the workflow wiring.

## Research

### Findings
- `jobs/publish/audio.py::render_audio_job()` returns early when the target MP3 and sidecar already exist with the same content hash.
- The publish workflow already exports job-level env vars for audio publishing, so a job-scoped override fits the existing pattern.
- The fragment cache should remain intact; the override only needs to bypass the top-level episode reuse gate.

## Plan

### Implementation
- Add a `PUBLISH_AUDIO_FORCE_REBUILD` env flag in `jobs/publish/audio.py`.
- Skip the current audio-file short-circuit when the flag is truthy.
- Add a `bootstrap-no-cache` workflow input option and map it to `PUBLISH_AUDIO_FORCE_REBUILD: true`.
- Add tests that prove the new mode bypasses the cache gate and that the workflow exports the flag.
