# Release 0.4.29.0: Daily Mass From the Current Date

## Scope

### Problem
- The Mass and Homilies playlist is refreshed daily, but its Mass slot uses a fixed Spotify URI for Daily TV Mass Friday October 23, 2026.
- The successful refresh therefore restores that dated episode instead of selecting the Daily TV Mass for the current local date.

### Audience
- Primary user: listeners expecting the Mass and Homilies Spotify playlist to contain today's Daily TV Mass.
- Secondary stakeholders: maintainers of the scheduled Spotify playlist refresh.

### Current Status Quo
- `.github/workflows/daily.yml` schedules the Spotify playlist refresh daily and recent scheduled runs completed successfully.
- The playlist definition includes `daily-tv-mass-2026-10-23`, a contract containing a fixed episode URI.
- The live playlist currently contains the October 23 Mass even though October 25 and October 26 Daily TV Mass episodes are available.
- The generic contract system already supports exact-date episode lookup; the playlist's homilies use separate latest-release resolvers.

### Goal
- On each refresh, select the Daily TV Mass episode whose title contains today's date in the configured job timezone.
- Never substitute an older Mass when today's episode is unavailable; leave the Mass unresolved while allowing the rest of the playlist to refresh.
- Keep the existing playlist identity, order, daily schedule, and homily behavior.

### Constraints
- Use the date supplied by the existing refresh pipeline (`JOB_UTC_OFFSET`, defaulting to the repository's configured offset).
- Match the Daily TV Mass show and today's explicit title date so Sunday and weekday episode naming both work.
- Do not change the Spotify playlist ID or manually write playlist contents outside the existing refresh job.

### Narrow Wedge
- Replace the dated fixed-URI contract with the existing date-aware Spotify episode lookup contract for the Daily TV Mass show.
- Add regression coverage proving today's weekday and Sunday Mass titles resolve exactly and that an older episode is not used when today's episode is missing.

### Non-Goals
- Change the daily workflow schedule or timezone policy.
- Change Fr. Mike or Bishop Barron's homily selection.
- Add a fallback to the latest available Mass or alter other playlists.

### Risks And Unknowns
- Sunday Mass titles contain an additional “Sunday” prefix, so the lookup must match the shared “Daily TV Mass” name term and exact date substring rather than a rigid full title.
- If Spotify has not published today's episode when the refresh runs, the Mass item will be omitted and the unresolved resolver status should make that visible; an older Mass must not be silently kept.

### Recommended Next Step
- Complete repository research and the implementation plan, then replace the fixed contract and validate the daily refresh path with date-specific regression tests.

### Current System Map
- The daily workflow invokes the playlist refresher; playlist and contract JSON are the source of playlist identity and ordered membership.
- `resolve_contract_uris()` routes `spotify_episode_lookup` contracts through `spotify_episode_lookup_search_uris()`, which scans the configured show's episode pages and requires both configured title terms and one rendered date string.
- The date comes from the refresh pipeline's configured local date (`JOB_UTC_OFFSET`). The current Mass contract bypasses this path because it stores one fixed URI.
- If the exact-date lookup returns no item, queue construction records `Unresolved:<contract name>` and continues with the other contracts. The old episode is not retained by the queue builder.
- Pages item URLs use the resolved episode URI when available. If dynamic resolution is unavailable, the prayer item URL is omitted; the Mass and Homilies playlist URL remains available.

## Plan

### Summary
- Replace the fixed October 23 episode contract with a `spotify_episode_lookup` contract that selects the Daily TV Mass whose title includes the refresh's current local date.
- Reuse the existing resolver so no runtime selection behavior is duplicated or new fallback introduced.

### What Already Exists
- Contract loading, title term matching, date rendering, Spotify show pagination, and unresolved-item reporting are implemented in `jobs/playlist/spotify_contracts.py` and `jobs/playlist/refresh_playlist.py`.
- The Pages builder derives a direct episode URL from a resolved URI and tolerates unresolved dynamic links.
- Playlist identity and ordered membership are stored in `config/spotify/playlists/sunday.json`.

### Architecture
- Daily workflow passes the configured local date to the queue resolver.
- The Mass contract searches the Daily TV Mass show and accepts an episode only when its title contains both `Daily TV Mass` and the rendered date `Month D, YYYY`.
- The resolver returns no URI when no exact-date episode exists; queue construction records an unresolved Mass and writes other resolved playlist entries.

```text
daily refresh (JOB_UTC_OFFSET date)
  -> Mass and Homilies contract list
  -> Daily TV Mass show episodes
  -> title contains "Daily TV Mass" + today's full date?
       yes -> add today's episode URI
       no  -> mark Mass unresolved; add no stale Mass
  -> write the other resolved playlist entries
```

### Concrete Changes

Prefer renaming to `config/spotify/contracts/daily-tv-mass.json` so the filename and key no longer encode a date.

- `tests/test_build_pages_artifact.py` — assert Mass item key/name reflect the generic contract, no fixed episode URL is emitted without a dynamic resolution, and a supplied resolved URI becomes the direct episode URL.

### Failure Modes
- Today's episode is not yet published: exact lookup returns empty, resolver status is unresolved, and no prior episode is added. Detect in workflow logs; subsequent daily refresh retries.
- Spotify API fails: workflow fails under its normal error behavior; no success claim is made without live verification.
- Contract key is stale in any config/test: contract validation or focused tests fail before merge.
- Pages credentials are unavailable: dynamic item link is omitted, but playlist link and daily refresh remain independent.
