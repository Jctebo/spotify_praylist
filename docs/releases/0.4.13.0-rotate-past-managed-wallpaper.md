## Scope

### Problem
- Calendar resolution now correctly skips the unclassified Saturday context and retains the valid Our Lady of the Rosary entry on Oct. 10.
- The generation run then stopped because the existing Sept. 30 watch-current image did not match an old checksum in rotation state.

### Goal
- Allow the queue rotation to archive the current image as it exists and promote the complete new date set without stale prior checksums blocking the change.

### Constraints
- Keep validation of queued images and new current promotions.
- Preserve unknown/unmanaged-file and complete phone/watch set protections.
- Keep the existing image in the archive before replacing current.

## Research

- Run 36846690805 uploaded `resolve-report.json` confirming the Oct. 10 recognized devotion remained eligible and the unclassified Saturday context was recorded as skipped.
- The same run failed later on `Managed current wallpaper checksum mismatch` for the Sept. 30 watch-current image.
- `rotate_current` checked the prior file against its rotation-state checksum during preflight and archive, despite the complete Oct. 1 pair being queued.

## Plan

- Remove stale-manifest checksum gates on previously managed current files.
- Archive the bytes actually present, verifying the archived copy against those bytes.
- Preserve checksums on queued assets and their promotion into current.
- Add regression tests for modified old current data and missing current with an existing archive.
