## Scope

### Problem
- The traditional novena import flow still needed a local July/August batch runner, plus a parser fix for the live Catholic Novena App page layout.
- Marian Antiphons still lacked dedicated seasonal publish-audio contracts, so Angelus and Regina Caeli could not be shipped as season-aware feed items.
- The Spotify refresh cadence was too sparse for the operator workflow we want now.

### Audience
- Primary user: the repo owner running novena imports, publishing audio, and maintaining Spotify refreshes.
- Secondary users: listeners and future maintainers who benefit from stable, date-scoped feed items and repeatable local import flows.

### Current Status Quo
- Traditional novena imports now have a reusable July/August local runner, and the importer can parse the current live page layout.
- The publish audio pipeline already supports date-scoped episodes and archive-backed feed rebuilds.
- The Spotify refresh job still needs the tighter cadence and the Marian Antiphon seasonal contract pair to match the church season.

### Goal
- Ship the completed traditional novena local import workflow and the associated importer fix.
- Ship the seasonal Marian Antiphon publish-audio contracts for Angelus and Regina Caeli.
- Ship the earlier, three-times-daily Spotify refresh cadence.

### Constraints
- Keep the novena importer parser changes fail-closed and localized to the live page shape change.
- Keep the Marian Antiphon output date-scoped so reruns overwrite the same feed item.
- Keep the Spotify refresh cadence change limited to the existing scheduled workflow.
- Do not disturb the existing Morning Prayer, Rosary, or novena publishing runtime paths beyond the intended contract additions.

### Narrow Wedge
- Add the batch runner and keep the importer as the source of truth for novena parsing.
- Add two Marian Antiphon contracts and route them by liturgical season.
- Update the refresh schedule to run about two hours earlier and two more times per day.

### Non-Goals
- Do not redesign the publish pipeline.
- Do not add new devotional families beyond the Marian Antiphons work already in scope.
- Do not build a general-purpose import scheduler for arbitrary month ranges.
- Do not change the Spotify queue contract model beyond the existing seasonal Marian Antiphon exception.

### Risks And Unknowns
- The main risk is accidentally widening the release beyond the intended batch import and schedule changes.
- Another risk is leaving the release metadata split across multiple draft artifacts instead of one clear shipped release.

### Recommended Next Step
- Finalize the combined release metadata, run the focused regression suite, and ship the branch as one mega-release.

### Current System Map
- The novena URL importer parses the Catholic Novena App catalog and writes contract drafts plus reports.
- The local runner batches the importer across July and August and writes month-specific report files.
- The publish pipeline renders date-scoped audio jobs from checked-in contracts and rebuilds the RSS archive.
- The Spotify refresh workflow uses a scheduled GitHub Actions cadence that is now tightened to three runs per day.

### Reuse Opportunities
- Reuse the existing importer and bulk report writer instead of inventing a second parser.
- Reuse the publish audio fragment and RSS archive code instead of adding a second feed builder.
- Reuse the existing Spotify refresh workflow and only adjust its cron schedule.

### Constraints
- The import batch runner must keep month outputs isolated.
- The Marian Antiphon contracts must stay season-gated and date-scoped.
- The refresh schedule should remain easy to understand in the workflow file.

### Risks
- If the release metadata stays split, it becomes hard to tell what was actually shipped together.
- If the mega-release does not own the shipped scope, later maintenance will be harder for the next person.

## Plan

### Summary
- Package the completed novena importer work, the Marian Antiphon seasonal publish contracts, and the Spotify refresh cadence change into one release.

### What Already Exists
- The importer fix, batch runner, and generated traditional novena contracts are in the worktree.
- The Marian Antiphon publish-audio contracts and templates are in place.
- The Spotify refresh workflow has already been updated to the new three-run cadence.

### Architecture
- The release stays split along the same runtime boundaries that already exist: novena import, publish audio, and Spotify refresh.
- The release artifact is the umbrella that describes the combined ship, not a new execution layer.

```text
novena importer -> traditional batch runner -> report files
publish contracts -> seasonal Marian Antiphons -> RSS/audio output
scheduled refresh workflow -> three daily runs
```
