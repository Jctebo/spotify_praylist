## Scope

### Problem
- The traditional Saint Anthony novena audio can verbalize the word `colon`, which makes the prayer sound like markup instead of spoken devotional text.
- The immediate source text needs cleanup, and the TTS path needs a defensive normalization step so imported labels like `Prayer:` do not leak into future audio as spoken punctuation names.
- This matters now because the Saint Anthony feast is June 13, and this contract is active in the traditional novena publishing window.

### Audience
- Primary user: the playlist/podcast maintainer who publishes Ora Pro Nobis novena audio.
- Secondary stakeholders: listeners praying the daily traditional novena through the generated RSS/Spotify audio.

### Current Status Quo
- `contracts/novenas/feast-days/st_anthony.json` is an imported traditional novena contract with embedded `blocks`, day-specific `parts`, and canonical `Our Father`, `Hail Mary`, and `Glory Be` fragments.
- The novena engine passes rendered fragment text directly into the shared publish-audio fragment renderer.
- Existing importer normalization handles many instruction-heavy cases, but the active runtime has no final TTS-input sanitizer for spoken markup artifacts.

### Goal
- Remove the offending verbalized `colon` artifact from the Saint Anthony traditional novena contract.
- Add a shared TTS input cleanup layer that strips or converts label-style `word:` prefixes before audio rendering without changing public episode titles or RSS metadata.
- Preserve cache safety so sanitized TTS input changes fragment hashes and stale audio is not reused.
- Add focused regression tests proving the Saint Anthony rendered audio fragments and generic fragment renderer no longer send label-colon text to TTS.

### Constraints
- Keep this as a narrow audio/text cleanup; no live OpenAI, ElevenLabs, Spotify, Notion, or RSS publishing run is required for the planning pass.
- Do not rewrite the imported Saint Anthony novena wholesale.
- Preserve devotional wording except where needed to remove the artifact.
- Keep text sidecars auditable: either the sidecar stores the sanitized spoken text or clearly prevents mismatch between cached audio and recorded fragment text.

### Narrow Wedge
- Fix Saint Anthony source text and add one shared `sanitize_tts_input` helper used immediately before fragment hashing/rendering.
- Cover common label artifacts such as `Prayer:`, `Memorare:`, `Reflection:`, and the literal word `colon` when it appears as a standalone markup artifact, while avoiding destructive changes to ordinary prose.

### Non-Goals
- Re-importing Saint Anthony from the source website.
- Cleaning every traditional novena contract by hand.
- Changing episode title/description formatting.
- Reworking the full URL importer or OpenAI normalization prompt beyond the guard needed for this bug.
- Publishing regenerated MP3 files in this release plan.

### Risks And Unknowns
- The exact Saint Anthony phrase the listener heard is not visible as a literal `Prayer:` string in the checked-in contract, so implementation should render the active Saint Anthony day and inspect all TTS fragments before editing.
- Over-aggressive colon stripping could damage natural scripture references, abbreviations, or time-like text.
- If the sanitizer changes audio input but the cache hash still uses unsanitized text, stale audio can be reused.

### Recommended Next Step
- `/research-astack` should validate the exact active rendering path, the Saint Anthony fragment text, and where to place sanitizer logic so hashes, renderer input, and sidecars stay consistent.

  - Existing importer cleanup area. `_prepare_tts_source()`, `_local_tts_resolution()`, and `_resolve_tts_text()` normalize imported novena text before contracts are written.

  - Existing contract loader tests; useful for proving Saint Anthony still loads and validates.

### Current System Map
- Traditional novena contracts load through `jobs.novena_contracts.contracts.load_novena_contracts()`.
- `TemplateSection.parts` supports `{"kind": "text"}` and `{"kind": "fragment"}`.
- `render_novena()` selects the active day, adds an intro fragment, expands text and canonical fragment parts, and joins all fragment text into `content.text`.
- `build_novena_audio_job()` carries `audio_fragments` and `audio_config` into a publish-audio job and computes `content_hash` with `audio_manifest_hash()`.
- `render_novena_audio_job()` renders each fragment through `jobs.publish.fragments.render_fragment_audio()`.
- `render_fragment_audio()` currently hashes the raw fragment text and sends `str(fragment.get("text", ""))` directly to the configured TTS renderer.

### Reuse Opportunities
- Reuse the shared publish-audio fragment boundary for sanitation so novenas, Rosary, Auxilium, Marian Antiphons, and Morning Prayer benefit without duplicating cleanup in each contract engine.
- Reuse existing fragment hashing behavior by making sanitized spoken text the text that participates in `fragment_content_hash()`.
- Reuse existing fake-renderer tests to assert exact renderer input without live API calls.
- Reuse existing Saint Anthony contract fixture instead of creating synthetic large fixtures.

### External References
- No external docs are required for implementation; this is internal text normalization and cache correctness.
- Prior release artifact `docs/releases/0.3.2.8-auxilium-response-audio-cleanup.md` documents shared publish-audio fragment roles, TTS provider settings, and cache safety expectations.

### Constraints
- The fix must be deterministic and offline-testable.
- Sanitization must run before hashing and rendering, otherwise cached fragments may not reflect the spoken text.
- The sanitizer should be conservative: remove obvious spoken-markup labels, not all colon punctuation.
- Contract JSON should remain valid and readable.

### Risks
- Sanitizing too broadly can remove meaningful punctuation from legitimate text.
- Sanitizing only in Saint Anthony source text leaves the broader TTS engine vulnerable to the same problem in future imports.
- Sanitizing only at renderer call time without changing fragment hashes can reuse old cached audio.
- Updating the contract manually without a regression test could regress on the next import.

### Assumptions To Validate
- The verbalized artifact is caused by label-style text or a literal `colon` token in a TTS fragment, not by metadata such as episode title.
- It is acceptable for the stored sidecar fragment text to reflect the sanitized spoken text if that is the actual audio input.
- Contract-level cleanup should keep the traditional prayer wording faithful and only remove markup-like artifacts.

### Unknowns
- The exact generated Saint Anthony day/audio fragment that produced the audible `colon` needs confirmation during implementation.
- Whether other checked-in traditional novena contracts have the same issue is likely but outside the immediate hand cleanup.

### Recommended Direction
- Add a small shared `sanitize_tts_input()` helper in `jobs/publish/fragments.py`, apply it before fragment hashing, sidecar writing, and renderer calls, then clean the Saint Anthony contract phrase that triggered the report.

## Plan

### Summary
- Build a two-layer fix: repair the Saint Anthony traditional novena source text and add a conservative shared sanitizer at the TTS fragment boundary.
- This approach fixes the reported contract and prevents the same audible `colon` artifact from recurring in other imported prayers without broad importer churn.

### What Already Exists
- Traditional novena contracts already use compact reusable audio fragments.
- The shared publish-audio fragment renderer already centralizes hashing, caching, sidecars, and renderer calls.
- Tests already cover novena rendering, artifact writing, fragment hash invalidation, and fake TTS renderer calls.

### Architecture
- Add a deterministic normalization function at the fragment boundary:

```text
novena contract
  -> render_novena()
  -> build_novena_audio_job()
  -> render_novena_audio_job()
  -> sanitize_tts_input()
  -> fragment_content_hash()
  -> render_fragment_audio()
  -> OpenAI/ElevenLabs renderer
```

- Sanitized text should be used consistently for:
  - `fragment_content_hash()`
  - renderer input
  - fragment sidecar text
  - episode sidecar fragment text when practical

### Failure Modes
- Sanitizer misses the exact artifact.
  - Detection: Saint Anthony regression still finds standalone `colon` or fake renderer receives it.
  - User experience: listener still hears markup.
- Sanitizer is too broad.
  - Detection: tests with legitimate colon punctuation fail or rendered text loses meaningful prose.
  - User experience: prayers can sound grammatically flattened.
- Cache hash mismatch.
  - Detection: hash tests fail or stale sidecar/audio is reused despite sanitized input changes.
  - User experience: old audio persists after text cleanup.
- Sidecar/rendered-text mismatch.
  - Detection: sidecar assertions fail.
  - User experience: audio audit trail becomes confusing.
