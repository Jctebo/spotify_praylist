# Release 0.3.6.5: Disable Publish Prayer Text

## Scope

### Problem
- `Publish Prayer Text` is repeatedly failing in GitHub Actions because the Notion publish target is not configured correctly.
- The workflow still auto-runs after successful `Daily Spotify Playlist Refresh` runs, creating noisy failures.

### Audience
- Repo maintainer monitoring remote pipeline health.

### Current Status Quo
- `.github/workflows/publish_text.yml` supports both manual dispatch and automatic `workflow_run` dispatch from `Daily Spotify Playlist Refresh`.
- Recent remote logs show `NOTION_PUBLISH_DATABASE_ID` is blank and Notion returns a 400 on the fallback database query.

### Goal
- Disable the `Publish Prayer Text` GitHub Actions workflow completely until the Notion target is corrected.
- Preserve the workflow definition for future re-enable work.

### Constraints
- Do not remove the underlying text publishing code or tests.
- Do not change Notion secrets or database behavior in code.
- Keep publish-audio and website validation workflows unchanged.

### Narrow Wedge
- Move `publish_text.yml` out of `.github/workflows/` into a disabled workflow archive folder.
- Update README workflow documentation.
- Add/adjust tests so the active workflow directory cannot accidentally expose `Publish Prayer Text`.

### Non-Goals
- Fixing `NOTION_PUBLISH_DATABASE_ID` or Notion schema.
- Deleting the text pipeline implementation.

### Risks And Unknowns
- If someone expects manual text publishing from GitHub Actions, they will need to re-enable the archived workflow first.

### Recommended Next Step
- Implement the archive move, doc update, regression test, review, ship, and confirm no active `Publish Prayer Text` workflow remains.

## Research

- `.github/workflows/publish_text.yml` is the only active workflow named `Publish Prayer Text`.
- It has both `workflow_dispatch` and `workflow_run` triggers.
- README currently says `Publish Prayer Text` runs after `Daily Spotify Playlist Refresh`.

## Plan

### Summary
- Disable the workflow by moving it outside `.github/workflows/`, preserving the YAML for later restoration.

### What Already Exists
- Text pipeline implementation remains in `jobs/publish/run_text_pipeline.py`.
- Unit coverage remains in `tests/test_publish_text_pipeline.py`.

### Architecture

```text
GitHub Actions active workflows
  -> .github/workflows/*.yml

Archived disabled workflows
  -> .github/disabled_workflows/*.yml
```

### Concrete Changes
- Move `.github/workflows/publish_text.yml` to `.github/disabled_workflows/publish_text.yml`.
- Update `README.md`.
- Add a test in `tests/test_publish_text_pipeline.py` that verifies no active workflow file defines `Publish Prayer Text`.
- Update release log and version.

### UX And States
- No UI scope.
- Remote Actions list should no longer offer or auto-run the text publish workflow after this lands.

### Implementation Phases
