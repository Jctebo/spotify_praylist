## Scope

### Problem
- The Daily Reflection is spiritually strong, but the spoken structure is still too dense and repetitive for audio.
- The current script includes a spoken `Episode Title` heading and a long middle block that leaves too little room for silence.
- The reflection and examen need to feel more distinctly shaped by each day's liturgical context instead of following a mostly fixed rhythm.

### Audience
- Primary user: listeners of the Daily Reflection episode in the Ora Pro Nobis podcast.
- Secondary stakeholders: the publish-audio pipeline, the Spotify lookup contract, and future podcast narration/music selection surfaces.

### Current Status Quo
- The reflection generator already builds from the shared daily liturgical helper and emits an Ignatian-style prayer.
- The current fallback still formats the spoken script with `Episode Title`, `Opening Welcome`, `Liturgical Context Introduction`, `Ignatian Reflection`, `Guided Examen`, `Closing Prayer`, and `Final Closing`.
- The audio pipeline already applies shared seasonal branding and a common background music bed through the audio-branding layer.

### Goal
- Remove the redundant spoken title header from the prayer script while keeping the metadata episode title unchanged.
- Shorten the main reflection and increase deliberate pauses so the narration breathes naturally.
- Make the main reflection and guided examen clearly vary by feast day, Gospel, season, saint, tone, and imagery from the daily helper.
- Keep the Daily Reflection on the shared seasonal music bed used by the other daily prayer experiences.
- Use several natural pauses throughout the reflection, with at least 15 seconds of music continuing under each pause.

### Constraints
- Do not change the existing prayer families or the Spotify resolver surface.
- Preserve deterministic fallback behavior when OpenAI is unavailable.
- Do not invent new liturgical facts outside the shared helper payload.
- Keep the output audio-friendly; any pause cues must not be spoken literally by TTS.
- The pause rhythm should be implemented as silent gaps between spoken fragments, not as literal pause text.

### Narrow Wedge
- Update only the Daily Reflection generator and its validation so the structure becomes question-led, pause-rich, and day-specific.
- Reuse the existing daily helper and shared music bed rather than adding a new background-music system.

### Non-Goals
- No changes to Morning Prayer, Rosary, Auxilium Christianorum, or Marian Antiphons.
- No new Spotify lookup logic.
- No new liturgical data source or calendar engine.
- No dedicated music scoring or per-day soundtrack selection system.

### Risks And Unknowns
- The main risk is making the script shorter without flattening the spiritual content.
- We need to be sure pause cues survive as natural spoken rhythm instead of being read aloud as markup.
- The exact word-count target for the shorter reflection needs to stay loose enough for varied daily content.

### Recommended Next Step
- Validate the implemented pause rhythm against the Daily Reflection audio path and ship the release artifact.

## Research

### Scope Baseline
- Refine the existing Daily Reflection so it sounds more like a guided Ignatian meditation with questions and pauses, while keeping the same shared liturgical foundation and seasonal music bed.

### Relevant Files
- `jobs/publish/ignatian_reflection.py`: current reflection generator, fallback text, title builder, and validation rules.
- `jobs/publish/daily_liturgical_context.py`: shared helper that supplies theme, tone, imagery, saint, and gospel metadata.
- `jobs/publish/contracts.py`: wires the helper and reflection into text/audio jobs and sidecar metadata.
- `jobs/publish/audio.py`: renders the episode audio and writes sidecar output.
- `jobs/publish/audio_branding.py`: applies the shared seasonal music bed and welcome mix.
- `config/publish/contracts/daily-reflection.json`: Daily Reflection contract metadata and block wiring.
- `config/publish/audio_branding.json`: shared seasonal music configuration.
- `tests/test_publish_ignatian_reflection.py`: current structure and validation expectations for the reflection generator.
- `tests/test_publish_contracts.py`: text-job assembly, section titles, and Daily Reflection sidecar expectations.
- `tests/test_publish_audio_pipeline.py`: audio-job inclusion, branding, and archive/feed regression coverage.
- `README.md`: published description of the Daily Reflection and shared helper.

### Current System Map
- `build_daily_liturgical_context(...)` resolves the day, chooses the primary theme, and normalizes the supporting metadata.
- `build_ignatian_reflection_episode(...)` uses that helper, tries OpenAI first, and falls back to deterministic narration when needed.
- The fallback currently emits a full spoken structure with section headings, including the redundant `Episode Title` heading.
- `build_text_jobs(...)` and `build_audio_jobs(...)` carry the reflection into Notion, MP3 output, sidecars, resume markers, and archive/feed generation.
- `apply_audio_branding(...)` already gives the Daily Reflection the same common seasonal bed pattern as the other audio experiences.

### Reuse Opportunities
- Reuse the shared helper fields already on `DailyLiturgicalContext` instead of adding a second context engine.
- Reuse the existing audio-branding layer for the common background music bed.
- Reuse the existing publish contract and sidecar path so Spotify lookup and archive behavior stay stable.
- Reuse the current fallback path so the shorter structure still works when OpenAI is absent.

### External References
- No new external library or API appears necessary for this iteration.
- The existing OpenAI Responses API usage in `jobs/publish/ignatian_reflection.py` remains the only generation dependency.

### Constraints
- The audio renderer currently speaks plain text, so pause design has to be implemented as natural prose rhythm, not as literal stage directions unless the renderer is taught to strip them.
- The episode title metadata must remain stable so the existing Spotify lookup continues to match `Daily Reflection`.
- The shared music bed comes from `config/publish/audio_branding.json`, so the reflection should stay compatible with the existing seasonal asset set.

### Risks
- If the revised script is too prescriptive, the daily output may become repetitive again.
- If the pause cadence is encoded poorly, TTS may verbalize the markers.
- If validation stays too strict, day-specific output may fail on otherwise good reflections.

### Assumptions To Validate
- The shorter reflection can still stay spiritually complete at roughly 300-450 words for the main reflection block.
- The best pause format is blank-line separation and question-led transitions rather than literal `[pause]` tokens.
- The existing seasonal bed is sufficient as the common music layer; no new bed selection is needed.

### Unknowns
- None blocking for the current implementation; the pause rhythm, structure, and helper-driven variation are now in place.

### Recommended Direction
- Proceed to `/plan-astack` with a generator-first change that keeps the helper and audio-branding layers intact, then tighten tests around the new pause-rich structure.

## Plan

### Summary
- We are reshaping only the Daily Reflection script so it opens immediately with the welcome, then moves into a shorter, question-led, pause-rich Ignatian reflection and examen.
- The chosen approach keeps the shared liturgical helper, shared music bed, and Spotify-facing metadata stable.

### What Already Exists
- `DailyLiturgicalContext` already supplies the daily feast, Gospel, season, tone, imagery, music mood, opening tone, closing tone, saint intercessions, and summary.
- The audio pipeline already applies a shared seasonal background bed through `jobs/publish/audio_branding.py` and `config/publish/audio_branding.json`.
- The Daily Reflection already has a dedicated contract, sidecar metadata, and regression tests.

### Architecture
- Flow:

```text
romcal + Gospel context
        |
        v
DailyLiturgicalContext
        |
        v
Ignatian reflection prompt/fallback
        |
        v
Daily Reflection text + audio fragments
        |
        v
shared audio branding + seasonal background bed
        |
        v
MP3 sidecar + RSS/feed + Spotify lookup
```

- The main change is in how the reflection text is generated, not in how the episode is published or discovered.

### Concrete Changes
- `jobs/publish/ignatian_reflection.py`
  - Remove the spoken `Episode Title` section from both generated and fallback text.
  - Rewrite the OpenAI prompt so the reflection is led by day-specific questions and short pauses.
  - Update the deterministic fallback to mirror the new structure and to vary its prompts from the helper payload.
  - Tighten validation so it checks for the revised spoken structure, question-led pause cadence, and a shorter reflection length band.
- `tests/test_publish_ignatian_reflection.py`
  - Update fallback assertions for the new opening, pause cadence, and shorter length.
  - Add coverage for feast/Gospel/season-driven variation so the reflection is not same-y across days.
- `tests/test_publish_contracts.py`
  - Update contract/job assertions that currently assume the old spoken section layout.
  - Keep the metadata title and Spotify-facing contract behavior unchanged.
- `tests/test_publish_audio_pipeline.py`
  - Confirm the Daily Reflection still enters the audio pipeline with the shared branding metadata and the common seasonal bed.
  - Preserve sidecar expectations for `daily_reflection.helper` and audio branding status.

### UX And States
- The listener should hear the welcome immediately, then move into a short context introduction and a series of reflective questions with natural breathing room.
- Success state: the episode feels quieter, more personal, and more varied from day to day.
- Failure state: the text reads like a script with labels, sounds too repetitive, or causes TTS to speak pause markers.

### Failure Modes
- The script can become too short and lose spiritual substance.
- The pause markers can be spoken literally if they are encoded as raw text tags.
- The daily helper can still produce a good theme, but the reflection can sound generic if the prompt does not actually use it.
- Audio branding can stay present but the spoken cadence can still feel rushed if the text is overpacked.

- Render Daily Reflection for at least one feast day, one ordinary-time Gospel-driven day, and one season-fallback day.

### Rollout Notes

### Not In Scope

- No separate soundtrack editor or music recommendation engine.
