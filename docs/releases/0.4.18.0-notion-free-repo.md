## Scope

### Problem
- The repository still runs or advertises several Notion integrations, so Notion credentials and external databases remain part of prayer generation, calendar publishing, image setup, and disabled legacy workflows.
- The user wants to remove all repository Notion integrations after first removing the Spotify refresh dependency.

### Audience
- Primary user: repository maintainer operating Spotify, prayer, calendar, image, and podcast workflows.
- Secondary stakeholders: listeners using Spotify playlists and the podcast feed.

### Current Status Quo
- Spotify playlist refresh now reads checked-in playlist definitions, but its contract loader still accepts a legacy `notion_name` alias.
- Notion-backed prayer generation, page audio, daily reset, and calendar sync remain in code or workflows. The public site and scheduled devotional imagery are also still active.
- Podcast audio/RSS publishing and contract-driven novena publishing already use local contracts and repository state.

### Goal
- Remove all active Notion API clients, credentials, configuration, workflows, scripts, and runtime compatibility hooks from the repository.
- Remove repository Notion integrations, retire the calendar ICS publisher and devotional infographic publisher, and replace the public prayer directory with a simple “Coming soon” page.
- Preserve Spotify refresh, local episode state, podcast audio/RSS publishing, feed URL, and podcast cover image.
- Success: active repository files have no Notion integration hooks; ICS and infographic publishing are retired; the separate OneDrive wallpaper pipeline remains usable; Pages serves only “Coming soon” and podcast feed assets; focused tests and the local test suite are run and outcomes documented.

### Constraints
- Preserve existing uncommitted Spotify and podcast work. Do not reset, commit, or overwrite unrelated local changes.
- Keep local audio/RSS publishing, Spotify refresh, and episode state intact.
- Remove the ICS exporter, scheduled workflow, generated calendar file, and associated settings/docs/tests.
- Remove devotional infographic generation and Pages publication entrypoints; keep the separate daily wallpaper workflow, its local OneDrive tooling, source assets, and remote data.
- GitHub Pages should serve only a static coming-soon landing page, `podcast.xml`, and the podcast cover image required by the RSS feed.
- Historical release records may retain references to integrations that existed at the time; active docs and current setup instructions must describe the Notion-free system.

### Narrow Wedge
- Remove Notion-backed code paths and automation surfaces; retire calendar and infographic publishing; keep wallpaper, Spotify, and podcast operations available.

### Non-Goals
- Changing Spotify queue behavior, podcast content/audio behavior, R2 audio hosting, or local episode state.
- Deleting image source assets or user-owned OneDrive material.
- Deleting user-owned Notion data or changing the external Notion workspace.

### Risks And Unknowns
- The public Pages deployment must preserve the podcast RSS URL and its cover-art URL while removing all other generated site content.
- The old Notion novena generator and page-audio service are separate from the current contract-based podcast publishing path; ensure no active workflow still invokes them before retirement.
- Full-suite results may include pre-existing failures from the user's uncommitted podcast changes; report these separately from this removal.

### Recommended Next Step
- Remove integrations and obsolete calendar/image jobs, stage the reduced Pages artifact, audit references and deployment contents, then run focused and repository test suites.

## Research

- Spotify refresh uses `config/spotify/playlists/*.json`; `notion_name` compatibility exists only in contract loading and fixtures.
- Notion execution remains in `jobs/notion/`, `jobs/publish/notion.py`, legacy novena generation/calendar sync, and optional devotional-image setup.
- Active Notion automation is present in daily reset, yearly calendar sync, Morning Prayer page-audio workflows, an archived publish-text workflow, and Compose services.
- `jobs/novena/liturgical_helpers.py` contains shared Romcal functions mixed with Notion helpers.
- `publish_audio.yml` currently restores devotional image trees, builds the prayer website, then copies all of `docs/` to Pages. Podcast RSS and cover art are generated separately and must stay available.
- `jobs/novena_contracts` and `jobs/publish` local-state pipeline provide the current local novena/podcast publishing path and must be preserved.
