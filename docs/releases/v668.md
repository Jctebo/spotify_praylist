### §2.1 The root cause — the ladder never gets its scroller

Every sheet in the app scrolls the same way: `.sheet .inner` is a flex column with `overflow:hidden` and a fixed height (ui.ts:558), and the middle content scrolls inside `.sheet .panelbody { overflow-y:auto; flex:1 1 auto; min-height:0 }` (ui.ts:560). The `.panelbody` does not exist in markup — `mountDrawer` (client.ts:1267) CREATES it at mount time, splitting the `.inner`'s standing children into head (the first title row) / body (a new `.panelbody` wrapping the rest) / foot (a trailing `.btn` row re-dressed `.panelfoot`). Every other sheet sets `sheet.innerHTML` (with its `.inner`) BEFORE calling `mountDrawer` — verified at the speed sheet, the confirm sheet, the Mass personal picker, the Configure screen.

The ladder is the one exception. `openAddLadder603` creates the EMPTY sheet, appends it, calls `mountDrawer(sh, true)` — which finds no `.inner` and returns after adding the `drawer-tall` class — and only afterwards calls `paint()`, which sets `sh.innerHTML` with the head row, the search pill, the bare list div `[data-p603list]`, and the Back/Close rows standing as plain flex children of `.inner`. No `.panelbody` is ever created, on any rung. A list taller than the 92dvh `.inner` is clipped by its `overflow:hidden`; nothing on any Add-flow page can scroll.

## §3 The fix

One move, in `openAddLadder603`'s `paint()` (client.ts), emitting the standing sheet structure mountDrawer would have built:

- The head row (title) stands as the `.inner`'s first child, unchanged.
- The search pill, the list div, and the Back row stand wrapped in `<div class="panelbody">…</div>` — the standing scroller (ui.ts:560: `overflow-y:auto; flex:1 1 auto; min-height:0`) takes the space between head and foot and scrolls.
- The Close row stands after the panelbody with the standing foot dress (`class="row panelfoot"` — `.sheet .panelfoot`, ui.ts:562).

Nothing else moves: `paintList()` still repaints only `[data-p603list]` (which now lives inside the panelbody — the search input keeps focus and text, the standing pattern); `wire()`/`wireList()` query within the sheet and are untouched; the `drawer-tall` class mountDrawer already adds keeps the `.inner` at 92dvh; the grab strip / drag / scrim behavior is exactly as today (mountDrawer's early return is unchanged — this release does not re-order the mount, it emits the structure directly). The v666 dress, the ladder tree (Catechesis · Prayers · Videos, the block as frame), the Add-daily cards, the dynamic adds, and every other v666 behavior are unchanged.

Consumers named (gate e): the touched code is the ladder's own `paint()` — its only consumers are the ladder's two hosts (the profile editor's Add act and Edit today's Add act), both through `openAddLadder603`. `mountDrawer`, `.panelbody`, `.panelfoot`, and ui.ts's sheet rules are NOT modified, so no other sheet is a consumer of this change. The pin bumps to ora-pro-nobis-v668-1 at its one seat in ui.ts.
