## Scope

### Problem
- The generated daily prayer episodes currently move too abruptly from the day announcement into the prayer body.
- Auxilium Christianorum announces the date, liturgical celebration, and season, then immediately starts the prayer sequence.
- Marian Antiphon episodes announce the liturgical day through the daily intro, then immediately begin the Angelus or Regina Caeli.
- The listener needs a warmer spoken bridge that names the prayer and connects today's liturgical theme to the devotion without adding a long reflection.

### Audience
- Primary user: the maintainer shaping the Ora Pro Nobis daily podcast listening experience.
- Secondary stakeholders: prayer listeners who expect the episode to feel like guided prayer rather than concatenated fragments.

### Current Status Quo
- `config/publish/contracts/auxilium-christianorum.json` starts with a `liturgical_announcement` block, followed by the Auxilium opening prayers.
- `jobs/publish/liturgical_announcement.py` produces deterministic date, celebration, and optional season sentences; it does not introduce the upcoming prayer.
- `config/publish/contracts/marian-antiphon-angelus.json` and `config/publish/contracts/marian-antiphon-regina-caeli.json` start with a `daily_intro` block, followed by the prayer sequence.
- `jobs/publish/daily_intro.py` prompts for a short liturgical/Gospel opening block; it is not told which prayer will follow.
- Existing block kinds support static `inline` text and generated intro blocks, but there is no explicit prayer-transition block that can use the resolved day context and the target prayer name.

### Goal
- Add one natural transition sentence between the day announcement and the prayer body for Auxilium Christianorum.
- Add one natural transition sentence between the Marian Antiphon daily intro and the Angelus or Regina Caeli prayer.
- Make the transition sound like a spoken guide, for example:
  - `In today's Marian Antiphon, we turn to Our Lady through the Angelus, reflecting on {day theme} as we enter this prayer.`
  - `As we begin today's Auxilium Christianorum prayers, we place {day theme} under Mary's protection and ask for strength in the spiritual battle.`
- Keep the transition concise: one sentence only, no mini-homily, no duplicate date announcement.
- Preserve existing episode titles, Spotify lookup behavior, audio provider settings, and prayer template content.

### Constraints
- Scope-only release artifact for this turn; no implementation yet.
- The transition must be deterministic or tightly validated so audio generation does not become brittle.
- The Marian Antiphon implementation should cover both ordinary-season Angelus and Easter-season Regina Caeli contracts, even if the user-facing example mentions Angelus.
- The Auxilium contract must keep the lay-member prayer sequence and source boundary intact.
- Tests should not depend on live OpenAI, Spotify, Notion, or ElevenLabs calls.

### Narrow Wedge
- Introduce a small generated or templated `prayer_intro`/transition capability for publish contracts.
- Wire it into:
  - Auxilium Christianorum after `liturgical_announcement` and before opening prayers.
  - Marian Antiphon Angelus after `daily_intro` and before the Angelus prayer.
  - Marian Antiphon Regina Caeli after `daily_intro` and before the Regina Caeli prayer.
- Add focused tests proving rendered text/audio fragments include exactly one transition sentence in the expected position.

### Non-Goals
- Do not rewrite the full daily intro prompt into a longer reflection.
- Do not change Rosary reflection prompts or novena intros.
- Do not alter the official Auxilium Christianorum prayer text templates.
- Do not change Marian Antiphon season gating or Spotify lookup contracts.
- Do not introduce a new audio voice or provider for the transition sentence unless implementation research shows the existing voice handling cannot reuse the entry provider.

### Risks And Unknowns
- The strongest implementation shape is still open: a static contract `inline` sentence is simple but cannot reflect the actual day theme; a generated transition can be more natural but needs validation and fallback behavior.
- The current daily intro validation is strict for non-missing Gospel flows but relaxed when `allow_missing_gospel` is true; transition wording should not weaken existing validation.
- "Day theme" needs a precise source: celebration name, Gospel summary, liturgical season, or a compact derived label.
- If transition text becomes dynamic, cache keys and resume markers must remain stable and auditable.

### Recommended Next Step
- Run `/research-astack` to map the existing publish block rendering, audio fragment labeling, resume markers, and daily-intro context reuse, then decide whether the transition should be a new block kind or explicit inline blocks backed by a small helper.

### Current System Map
- Publish contracts define ordered `blocks` per entry.
- `load_publish_contracts()` normalizes every block through `_normalize_block()`.
- `build_text_jobs()` renders each top-level block via `resolve_block_content()` and also creates text `sections` and text-section resume markers.
- `build_audio_jobs()` calls `expand_audio_fragments()`, which walks the same ordered block tree and creates one audio fragment per leaf block.
- Leaf block kinds such as `daily-intro`, `liturgical-announcement`, `rosary-intro`, `file`, and `inline` already get stable labels, fragment keys, effective audio configs, and resume markers.
- Auxilium already uses deterministic Romcal-backed day context through `liturgical_announcement`; Marian Antiphon uses generated `daily_intro` with `allow_missing_gospel=true`.

### Reuse Opportunities
- Add a new leaf block kind in `jobs/publish/contracts.py` instead of special casing individual contracts.
- Reuse Romcal celebration lookup patterns from `jobs/publish/liturgical_announcement.py` for a deterministic `day_theme`.
- Reuse existing top-level block ordering to make the transition appear as its own text section and audio fragment.
- Reuse `_fragment_label_for_block()`, `_fragment_path_segment()`, and existing resume marker construction by registering the new block as a normal leaf.
- Reuse current tests that stub `build_liturgical_announcement_text()` and `build_daily_intro_text()`; new tests can stay offline by using Romcal fixtures already exercised in this suite.

### External References
- No new external services are required.
- Existing Romcal integration through `jobs.novena.liturgical_helpers.romcal_fetch_day()` remains the only calendar dependency.
- Existing OpenAI/ElevenLabs paths should remain untouched.

### Constraints
- The transition should be deterministic to avoid new OpenAI brittleness and cache churn.
- The transition must be exactly one sentence and should not repeat the date announcement.
- The transition must work for both Angelus and Regina Caeli, not only ordinary-season Angelus.
- Auxilium official prayer templates should remain unchanged; the bridge should live in the publish contract layer.
- Audio fragments must preserve stable keys and resume markers so sidecars remain usable.

### Risks
- `day_theme` can become awkward if it blindly includes multiple celebration names; the helper should join existing Romcal names naturally and fall back to a generic liturgical-day phrase if needed.
- Adding a new block kind touches normalization, text rendering, label handling, section/resume naming, and audio fragment expansion; missing one registration point would break either text or audio output.
- Existing tests assert exact section order for Auxilium, Morning Prayer, and Rosary; Auxilium expectations must be intentionally updated.

### Assumptions To Validate
- A deterministic theme based on celebration names is good enough for this release; Gospel-derived or model-generated transitions can wait.
- Making the transition its own top-level section/audio marker is acceptable and useful for resume navigation.
- Existing entry audio provider settings should narrate the transition; no role override is needed.

### Unknowns
- Whether the final wording should mention `today's liturgical theme` explicitly or use a more devotional phrase around the resolved celebration name.
- Whether future contracts will want custom transition templates; this release can support contract-level `prayer_title`, `devotion`, and optional `template` fields without adding a general templating engine.

### Recommended Direction
- Build a deterministic `prayer_intro` leaf block in `jobs/publish/contracts.py`.
- Resolve `{day_theme}` from Romcal celebration names with calendar/locale config inherited from contract metadata or block-level overrides.
- Add `prayer_intro` blocks to Auxilium, Angelus, and Regina Caeli contracts immediately after the existing day-context block.
- Add focused contract tests for text section order, one-sentence content, audio fragment order, labels, fragment keys, and resume markers.

## Plan

### Summary
- Build a deterministic `prayer_intro` publish block that renders exactly one spoken transition sentence from contract-provided prayer metadata and the day's Romcal celebration names.
- Use it for Auxilium Christianorum, Marian Antiphon Angelus, and Marian Antiphon Regina Caeli directly after their existing day-context block.
- This is the chosen approach because it gives natural prayer-specific transitions without adding another model dependency or changing official prayer templates.

### What Already Exists
- Publish contracts already render ordered block trees into both text sections and audio fragments.
- Leaf blocks already receive labels, fragment keys, effective audio configs, and resume markers.
- `liturgical_announcement` and `daily_intro` blocks already know how to use calendar/locale metadata.
- `jobs/publish/liturgical_announcement.py` already has deterministic Romcal celebration-name helpers we can mirror or reuse locally.

### Architecture
- Add a new normalized leaf block kind: `prayer-intro`.
- The block accepts:
  - `title`: section/fragment label.
  - `prayer_title`: spoken prayer name, such as `Auxilium Christianorum prayers`, `Angelus`, or `Regina Caeli`.
  - `devotion`: spoken devotion family, such as `Auxilium Christianorum` or `Marian Antiphon`.
  - `calendar`, `locale`: optional overrides, inherited from relevant contract metadata when omitted.
  - `template`: optional one-sentence format string using `{day_theme}`, `{prayer_title}`, and `{devotion}`.
- Text and audio rendering call one helper to produce the same transition sentence.

```text
publish contract blocks
  -> daily_intro / liturgical_announcement
  -> prayer_intro
       -> Romcal celebration names
       -> one deterministic transition sentence
  -> existing prayer sequence
  -> text sections + audio fragments + resume markers
```

### Failure Modes
- Romcal returns no celebration names:
  - Publish job raises missing-data errors through the existing fail-closed path.
- Template renders more than one sentence:
  - Helper rejects it during rendering and tests cover expected one-sentence output.
- New block is not registered in audio expansion:
  - Text jobs would pass while audio jobs fail; audio fragment tests catch this.
- Transition duplicates date or sounds generic:
  - Contract templates are explicit and one sentence; tests assert devotional phrases and day-theme inclusion.
