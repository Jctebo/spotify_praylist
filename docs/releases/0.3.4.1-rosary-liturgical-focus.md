## Scope

### Problem
- Daily Rosary episodes currently identify the date, but the episode title does not surface which mystery set is being prayed or what the day's liturgical focus is.
- Rosary reflections are Gospel-aware and season-aware, but they do not yet prioritize feast days or explain the day's prayer focus at the start of the rosary.
- Why now: the generated Daily Rosary is already live enough that listeners need clearer daily orientation before the decades begin.

### Audience
- Primary user: the maintainer publishing Ora Pro Nobis Daily Rosary episodes.
- Secondary stakeholders: listeners who choose an episode from Spotify or a podcast client and want to understand the day's liturgical focus quickly.

### Current Status Quo
- The Daily Rosary episode title renders as `Daily Rosary - {date_display}`.
- The rosary body starts with the fixed opening prayers, then moves into the selected weekday mysteries.
- Per-mystery reflections prefer today's Gospel, then the liturgical season, then deterministic fruit-based fallback text.
- This is insufficient because feast days should shape the reflection before ordinary Gospel or season fallback logic, and the listener does not hear a short generated orientation for the day.

### Goal
- Add the selected mystery set and a short day's focus to the prayer title, for example `Daily Rosary - Joyful Mysteries - Saint Example - April 6, 2026` or `Daily Rosary - Joyful Mysteries - Today's Gospel - April 6, 2026`.
- Add a 3-4 sentence generated Rosary intro that announces the calendar day and liturgical season, then states the focus for today's rosary.
- Choose the focus in priority order:
  - Feast day, when any eligible feast, solemnity, memorial, or optional memorial is present. Optional memorials count, including suppressed optional celebrations returned by Romcal for the day.
  - Today's Gospel, when no feast focus is available and Gospel text is available.
  - Liturgical season, when Gospel text is unavailable.
  - Generic fruit-of-the-mystery focus, when no higher context is available.
- Orient each decade reflection around the chosen focus source while preserving the mystery title and fruit requirements.
- Success criteria:
  - Text and audio jobs both render the mystery set and resolved focus label in the Rosary episode title.
  - Multiple feast or memorial names use a short comma-delimited title label rather than long prose.
  - The Rosary content includes exactly one intro block before the opening prayers or before the decades, whichever is cleaner in the current contract model.
  - Tests prove feast focus wins over Gospel focus, Gospel wins over season focus, season wins over generic fruit fallback, and title rendering includes the mystery set.

### Constraints
- Keep the existing publish contract model and Rosary weekday mystery mapping.
- Reuse Romcal and USCCB/Gospel helpers already present in `jobs.publish.daily_intro` and `jobs.novena.liturgical_helpers`.
- Keep generated text suitable for spoken prayer and short enough for TTS pacing.
- Do not make Spotify lookup brittle; existing required title terms should still resolve the Daily Rosary episode after the title includes mystery and focus labels.
- Preserve deterministic fallback behavior when OpenAI, Romcal, or Gospel sources fail.

### Narrow Wedge
- Implement one Rosary-specific focus resolver shared by the title, intro, and decade reflections.
- Add a Rosary pre-render context step before title, description, and episode metadata rendering.
- Add one Rosary intro block to the checked-in Rosary publish contract.
- Expose the selected mystery set and resolved focus label as publish metadata so title templates, text jobs, audio jobs, and Spotify lookup tests can use them.
- Add unit coverage around focus priority, generated prompt content, deterministic fallback, title rendering, and audio fragment ordering.

### Non-Goals
- Do not change the traditional weekday mystery schedule.
- Do not add custom feast-to-mystery overrides.
- Do not rewrite the general Morning Prayer daily intro system.
- Do not redesign the podcast feed or Spotify resolver architecture.
- Do not require live network calls in unit tests.

### Risks And Unknowns
- Optional memorials count as feast-day focus even when Romcal returns them as suppressed optional celebrations.
- Feast-day naming can be broad or duplicated, so prompt text should avoid unsupported saint biography and avoid pronouns when not needed.
- Adding the mystery set and focus label to the episode title may require updating Spotify contract required terms or date matching expectations.
- If the Rosary intro and reflection builder each fetch context independently, the daily run may do duplicate network work unless the implementation shares context carefully.

### Recommended Next Step
- Run `/research-astack` to map the exact title-rendering path, Rosary block expansion path, Spotify lookup expectations, and existing Romcal/Gospel helper behavior before implementation.

## Research

### Scope Baseline
- Add Daily Rosary title context, Rosary intro context, and decade reflection focus from one shared day resolver.
- Title target is `Daily Rosary - {Mystery Set} - {Day Focus} - {Date}`.
- Title focus should stay short; multiple feast or memorial names should be comma-delimited.
- Focus priority is feast or solemnity or memorial or optional memorial first, then Gospel, then liturgical season, then mystery fruit.
- Optional memorials count even when Romcal exposes them as suppressed optional celebrations.

### Relevant Files
- `config/publish/contracts/rosary.json`: checked-in Daily Rosary publish contract, current title template, weekday mystery map, Rosary block order, and audio settings.
- `jobs/publish/contracts.py`: publish contract loader, block normalization, Rosary decade text/audio expansion, title rendering, text job construction, and audio job construction.
- `jobs/publish/rosary_reflections.py`: Rosary mystery parsing, reflection generation, prompt validation, Gospel/season/fallback behavior, and natural home for a Rosary day-focus resolver.
- `jobs/publish/daily_intro.py`: existing Romcal plus USCCB Gospel context fetch, OpenAI settings resolution, and daily intro validation pattern.
- `jobs/publish/liturgical_announcement.py`: deterministic date, celebration, and season announcement pattern using Romcal.
- `jobs/publish/formatting.py`: publish template context and strict placeholder rendering; currently only static entry/date/season fields are available to title templates.
- `jobs/novena/liturgical_helpers.py`: Romcal wrapper, `romcal_fetch_day`, optional celebration expansion, rank inference, and Easter season helper.
- `config/spotify/contracts/daily-rosary.json`: Spotify lookup contract that currently requires `Daily Rosary` and a date format.
- `tests/test_publish_contracts.py`: expected Rosary text/audio job titles, sections, fragments, and contract loading behavior.

- `tests/test_spotify_contracts.py` and `tests/test_refresh_job.py`: Spotify episode lookup contract and date/name matching coverage.

### Current System Map
- Publish jobs load `config/publish/contracts/*.json` through `load_publish_contracts`, normalize each block, then build text/audio jobs from approved entries.
- Rosary content is generated by one `rosary_decades` block. The block selects the mystery template by weekday, parses the template title and five mystery rows, then expands five decades with generated reflections plus reusable prayer files.
- `_render_entry_metadata` renders title, description, and episode id before `_entry_text_body`, `_build_text_sections`, or `expand_audio_fragments` expands Rosary blocks.
- `build_publish_context` does not know dynamic Rosary values. Title templates can use date and entry fields, but not the selected mystery set or focus label.
- Text and audio paths both call the Rosary block expansion independently. Text jobs call `_entry_text_body` and `_build_text_sections`; audio jobs call `expand_audio_fragments` and then `_entry_text_body`.
- The existing Rosary reflection flow fetches Gospel context, tries Gospel-grounded OpenAI, falls back to season-grounded OpenAI, then deterministic fruit/season fallback.
- `romcal_fetch_day` returns the primary mass-calendar event plus `optional_celebrations` as rows marked `suppressed: True`; `infer_celebration_rank` can classify `optional_memorial`.
- Spotify lookup matches required title terms and date strings against episode names. Since the Rosary contract requires only `Daily Rosary` plus the date, adding mystery/focus between those terms should remain compatible.

### Reuse Opportunities
- Reuse `parse_rosary_mysteries` for title metadata instead of adding another mystery parser.
- Reuse `_selected_rosary_mystery_text` and `_rosary_reflection_config` in `contracts.py` so title metadata and block rendering choose the same weekday mystery template and calendar settings.
- Reuse `fetch_daily_gospel_context` for Gospel text, celebration names, and calendar/locale resolution rather than adding a second readings integration.
- Reuse `romcal_fetch_day`, `celebration_name`, and `infer_celebration_rank` to detect feast-day focus, including suppressed optional memorial rows.
- Reuse `render_publish_template` by adding Rosary-specific context keys before rendering, for example `rosary_mystery_set_title` and `rosary_focus_label`.
- Reuse existing `daily-intro` and `liturgical-announcement` block patterns when adding a Rosary-specific intro block kind or resolver.

### External References
- Local dependency: `romcal` via `jobs/novena/liturgical_helpers.py`; this is the source of celebration ranks, optional celebrations, and seasons.
- Local dependency: `catholic_mass_readings.USCCB` plus direct USCCB HTML fallback via `jobs/publish/daily_intro.py`; this is the source of Gospel text.
- OpenAI Responses API is already wrapped locally by `daily_intro.py` and `rosary_reflections.py`; no new API surface is needed.

### Constraints
- Title rendering must happen before job objects are emitted, so Rosary metadata must be available before `_render_entry_metadata` finishes.
- Add a pre-render Rosary context step before `_render_entry_metadata` so title, description, and job metadata can receive the same selected mystery set and focus labels used by Rosary content generation.
- The focus resolver should be shared by title, intro, and reflections; otherwise the title could say one focus while generated reflections use another.
- Unit tests should mock Romcal, Gospel, and OpenAI calls; the repo's current tests avoid live network dependence.
- `render_publish_template` rejects unknown placeholders, so any new title template placeholders must be present for all render paths using the Rosary contract.
- Audio fragment caching depends on fragment text and metadata; adding an intro fragment will intentionally change the audio manifest/content hash.
- Notion upsert uses the rendered title as the page title, so changing title shape creates new Notion pages unless a migration/update strategy is accepted.

### Risks
- Duplicate context fetches are likely if title metadata, intro text, reflections, sections, and audio fragments each resolve independently.
- Existing partial code in `jobs/publish/rosary_reflections.py` already starts a focus-context implementation, but it is not yet integrated with contract title rendering or tests.
- If feast focus labels include many optional memorials, episode titles can become long and noisy.
- If focus labels include punctuation from Gospel citations, title strings may be less readable and Spotify search could be less predictable.
- Changing the Notion title shape will break tests and may change upsert behavior from updating the old Rosary page title to creating the new title.

### Assumptions To Validate
- Feast-title focus should use short display celebration names directly; multiple names should be joined with commas.
- For Gospel fallback title labels, `Today's Gospel` is likely better than including the citation in the episode title, while the intro/reflections can include the citation.
- The Rosary intro should be its own first block before the fixed opening prayers, unless planning prefers it immediately before the decades.
- `Daily Rosary` plus date remains sufficient for Spotify lookup after title expansion; no additional required terms should be added unless tests prove ambiguity.

### Unknowns
- Whether very long feast or memorial names need a maximum title length or abbreviation rule.
- Whether non-saint feasts, solemnities, and memorials ever need title wording beyond the short display celebration name.
- Whether the title should use `Today's Gospel`, `Gospel`, or the Gospel citation when the focus source is Gospel.
- Whether the deterministic generic fallback title should say `Mystery Fruits`, `Fruits of the Mysteries`, or another listener-facing phrase.

### Recommended Direction
- Add a small Rosary day-context resolver that returns mystery set title, focus source, focus label for titles, focus label for prompts, celebration data, Gospel text, and season label.
- Call that resolver in a pre-render step once per text/audio job path before `_render_entry_metadata`, then pass its values into the publish template context and into Rosary intro/reflection builders.
- Add a `rosary_intro` block kind or a Rosary intro resolver that can use the same context and emit one cacheable audio fragment.
- Update `config/publish/contracts/rosary.json` title template to include `{rosary_mystery_set_title}` and `{rosary_focus_title}`.
- Keep `config/spotify/contracts/daily-rosary.json` required terms as `Daily Rosary` and date-only matching unless research in planning finds a collision.
- Build tests around mocked focus contexts first, then add integration tests proving text jobs, audio jobs, Notion text pipeline, RSS/feed output, and Spotify lookup still resolve the new title shape.

## Plan

### Summary
- Build one Rosary day-context path that selects the weekday mystery set, resolves the day's liturgical focus, and feeds title rendering, the Rosary intro, and decade reflections.
- Use short title labels: feast/memorial names as display names joined by commas, `Today's Gospel`, the season label, or `Mystery Fruits`.
- Add a Rosary-specific intro block before the fixed opening prayers so the listener hears the day, season, and focus before beginning the rosary.

### Failure Modes
- Romcal unavailable:
  - Detection: exceptions during context resolution.
  - User experience: title uses `Mystery Fruits`; intro/reflections use deterministic fruit fallback or season if available.
- Gospel unavailable:
  - Detection: empty `gospel_text` from `fetch_daily_gospel_context`.
  - User experience: focus falls to season unless feast focus exists.
- OpenAI unavailable:
  - Detection: intro/reflection generation exceptions.
  - User experience: deterministic intro/reflections render so publish can continue.
- Template context missing:
  - Detection: `render_publish_template` raises unknown placeholder.
  - User experience: publish job fails closed before emitting inconsistent title/content.
- Title too long:
  - Detection: tests should cover multiple names; manual review of generated title.
  - User experience: podcast title may be verbose but still usable; plan keeps labels short and comma-delimited.
- Notion title change:
  - Detection: text pipeline creates/updates by new title.
  - User experience: a new date-scoped Rosary page title appears for the day; old title is not reused.
