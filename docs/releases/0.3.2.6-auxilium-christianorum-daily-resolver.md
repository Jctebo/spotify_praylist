## Scope

### Problem
- Release 0.3.2.5 added a generated Ora Pro Nobis Auxilium Christianorum daily episode, but the Spotify queue contract still points at the legacy `AUXILIUM` resolver.
- The legacy resolver searches an external show by weekday token, so the Spotify playlist can select a weekday-named external episode instead of the repo-generated date-scoped Ora Pro Nobis episode.
- The README still documents this as intentionally deferred; this release should close that gap now that generated Auxilium titles and sidecars are stable.

### Goal
- Migrate `config/spotify/contracts/auxilium-christianorum.json` from `resolver: "AUXILIUM"` to the existing `spotify_episode_lookup` contract model.
- Resolve the generated Ora Pro Nobis episode titled `Auxilium Christianorum - {date_display}` from the Ora Pro Nobis Spotify show.
- Preserve existing Notion membership behavior for the Auxilium row unless the repo owner separately updates the Notion row spelling.
- Leave the generic Spotify episode lookup implementation intact unless research proves a narrow helper change is required.

### Success Criteria
- The checked-in Auxilium Spotify contract owns an Ora Pro Nobis `spotify_episode_lookup` using show id `4PNxb0OazrkcEp3FAggRoD`.
- A playlist refresh for a date such as April 6, 2026 resolves `Auxilium Christianorum - April 6, 2026`.
- The resolver does not depend on the weekday-only legacy `AUXILIUM` path.
- Regression tests prove the checked-in Auxilium contract loads as episode lookup and resolves the generated daily title.
- README no longer says Auxilium Spotify migration is deferred.

### Constraints
- Do not change the Auxilium publish contract or prayer content in this release.
- Do not remove the legacy `AUXILIUM` resolver branch yet unless it is provably unused by all checked-in contracts and removal is covered by tests.
- Do not change playlist definitions or Notion membership/order semantics.
- Do not rename `notion_name` from `Auxillium Christianorum` in the repo contract during this release unless the Notion row is also confirmed updated; the current misspelling appears to be the active membership key.
- Do not add live Spotify integration tests; use mocked Spotify show episodes like the existing Morning Prayer, Daily Novenas, and Marian Antiphon tests.

### Narrow Wedge
- Update only `config/spotify/contracts/auxilium-christianorum.json`, README documentation, and focused Spotify resolver tests.
- Keep the lookup shape simple:
  - `required_name_terms`: `["Auxilium Christianorum"]`
  - `date_formats`: canonical long date format first, with short-month fallbacks if useful for future title drift.
- Keep Notion row matching untouched.

### Non-Goals
- No Spotify playlist definition changes.
- No Notion row migration.
- No publish audio title changes.
- No episode-sidecar or feed changes.
- No removal of old show ids, token config, or legacy resolver code unless a later cleanup release is scoped.

### Risks
- If Spotify has not indexed the generated Ora Pro Nobis Auxilium episode by refresh time, the playlist row will resolve no URI for that run.
- If the Notion row is later corrected from `Auxillium Christianorum` to `Auxilium Christianorum`, this contract will stop matching until the `notion_name` is updated.
- The generated title currently uses long dates such as `April 6, 2026`; changing the publish title template later would require updating the lookup date formats or terms.

## Research

### Current Auxilium State
- `config/spotify/contracts/auxilium-christianorum.json` currently contains:
  - `key`: `auxilium-christianorum`
  - `notion_name`: `Auxillium Christianorum`
  - `resolver`: `AUXILIUM`
- `config/publish/contracts/auxilium-christianorum.json` now emits:
  - title template: `Auxilium Christianorum - {date_display}`
  - episode id template: `auxilium-christianorum-{date_iso}`
  - audio enabled for generated Ora Pro Nobis podcast output.
- Publish tests already assert an example generated title: `Auxilium Christianorum - April 6, 2026`.

### Existing Resolver Architecture
- `jobs/playlist/spotify_contracts.py` already supports a mutually exclusive `spotify_episode_lookup` shape with:
  - `show_id`
  - flat `required_name_terms` and `date_formats`, or ordered `searches`
  - validation that prevents mixing episode lookup with `resolver`, `fallback_resolver`, fixed URI, or seasonal URI fields.
- `jobs/playlist/refresh_playlist.py` already routes `contract.spotify_episode_lookup` through `spotify_episode_lookup_search_uris(...)` and marks `status[contract.notion_name]` based on whether URIs were found.
- `spotify_episode_lookup_search_uris(...)` fetches Spotify show episodes once, tries ordered search profiles, and returns the first successful set of matching URIs.
- `_spotify_episode_search_matches(...)` normalizes episode names, requires every configured name term, and requires one generated date candidate.

### Prior Patterns To Reuse
- `config/spotify/contracts/morning-prayer.json` resolves Ora Pro Nobis Morning Prayer with `required_name_terms: ["Morning Prayer"]` and long/short month date formats.
- `config/spotify/contracts/daily-novenas.json` resolves one or more generated novena episodes by required term `novena` plus long, short, and ordinal date formats.
- `config/spotify/contracts/angelus-morning.json`, `angelus-midday.json`, and `angelus-evening.json` show the recent migration pattern from fixed/legacy Angelus behavior to Ora Pro Nobis episode lookup.
- Tests already cover:
  - loading checked-in lookup contracts in `tests/test_spotify_contracts.py`
  - resolving checked-in lookup contracts against mocked Spotify show episodes in `tests/test_refresh_job_contract_path.py`
  - generic lookup matching, date fallback, pagination, deduping, and ordered searches in `tests/test_refresh_job.py`.

### Implementation Boundary
- Most likely implementation is config-only plus test/doc updates.
- No Python runtime change is needed for the happy path because `resolve_contract_uris(...)` already prioritizes `spotify_episode_lookup`.
- A Python cleanup to remove `get_auxilium_for_weekday(...)` and the `AUXILIUM` branch is deliberately not part of the narrow wedge; keeping it avoids accidental breakage of historical/local configs.

### Open Decisions
- Whether to correct `notion_name` spelling. Recommendation: do not correct it in this release because Notion row title matching is exact and the current checked-in value likely mirrors production data.
- Whether to include short-month date formats. Recommendation: include the same long and short fallbacks as Morning Prayer for resilience even though the current title template emits long dates.

### User-Facing Behavior
- When the Auxilium row is enabled in Notion and assigned to a playlist, the Spotify refresh will search the Ora Pro Nobis show for the current date's generated Auxilium episode.
- If the episode is present on Spotify, the playlist receives that date-specific Auxilium episode.
- If the episode is not yet indexed or the title date does not match, the row contributes no URI for that run, matching existing lookup-contract failure behavior.

### Failure Modes
- Missing Spotify episode for the date: resolver returns no URI and status for `Auxillium Christianorum` is false.
- Title format drift: tests catch drift for the current canonical title shape, and fallback date formats cover short-month variants.
- Accidental mixed contract shape: existing loader validation rejects a contract that combines `spotify_episode_lookup` with `resolver`.
- Notion title mismatch: left unchanged in this release; future spelling correction should be coordinated with the Notion row.
