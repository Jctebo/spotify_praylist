## §2 The defect + grounded cause

v627 §1 recorded the failed-fetch body change as part of its fix: where the reading view's text fetch failed, the view painted a sentence about the failure — first the struck availability phrase, then v627's load-error sentence. John's correction is that the view carries no such sentence at all: a text that does not load is not announced; the reading view is for reading, and either the text stands or nothing stands.

Grounded cause, verified firsthand on the base tree: exactly one seam. In `openRead` (`app/worker/src/client.ts`, line ~16587 on the base tree), the fetch chain's catch painted the body:

```
if (body) body.textContent = "The episode's text could not be loaded.";
```

The sweep for siblings found none in this view: the other `.readtext` in the client (the prayer book, line ~15021) paints server-body HTML through `bookBodyHtml`, not this view's fetch; the remaining "could not be loaded" strings belong to the pool tab, the Mass view, and the pictures tab — three different surfaces, all left standing. The struck line therefore has exactly one home to remove, and this release removes exactly it.
