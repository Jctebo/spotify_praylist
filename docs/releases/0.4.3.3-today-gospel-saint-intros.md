## Scope

### Problem
- Shared introductions can currently look ahead across a ten-day liturgical window and promote a future solemnity or feast when the target day has no qualifying observance.
- That future-looking anchor is consumed by every generated daily prayer introduction, so listeners can hear an introduction about a celebration that is not today.

### Audience
- Primary user: listeners praying the daily Morning Prayer, Daily Rosary, Auxilium Christianorum, Daily Reflection, Marian Antiphon, and generated novena introductions.
- Secondary stakeholders: maintainers of the shared liturgical context and publish-audio pipeline.

### Current Status Quo
- The shared saint-centered theme builder gathers target-day data plus nine future days and selects a future suitable observance when today has no suitable anchor.
- Generated introductions receive the resulting shared anchor and may therefore reference an upcoming solemnity or feast.
- The pipeline already fetches the target day’s Gospel and can use a target-day saint or observance as local context.

### Goal
- Every prayer introduction that has an introduction must speak from today’s Gospel or today’s saint/observance, never from a future solemnity or feast.
- Success criteria:
  - a target day with no qualifying observance never selects a future calendar row as its primary anchor;
  - target-day Gospel context is available as the fallback anchor/source when no target-day saint or observance exists;
  - all affected prayer families receive the corrected shared context;
  - regression tests cover future solemnity exclusion, today’s saint preference, and today’s Gospel fallback;
  - the full pipeline passes and the deployed production artifact proves that introductions are target-day grounded.

### Constraints
- Preserve the liturgical calendar’s precedence within the target day.
- Preserve novena activation windows; those windows determine whether a novena is active and are not introduction lookahead.
- Preserve deterministic fallbacks when Gospel or calendar providers are unavailable.
- Deploy through the repository’s normal GitHub Actions production workflow and verify public artifacts.

### Narrow Wedge
- Change the shared intro-context anchor selection to target-day-only selection, enrich the target-day Gospel fallback, add regression coverage across the shared context and contracts, then regenerate and inspect production prayer artifacts.

### Non-Goals
- Rewriting the Roman calendar or changing the Church’s liturgical precedence rules.
- Removing intentional date arithmetic used to resolve active novena schedules.
- Changing fixed prayer text, audio voices, or unrelated site presentation.

### Risks And Unknowns
- Some target days may have a Gospel but no saint name; the fallback must remain truthful and clearly identify the Gospel rather than inventing a saint.
- Existing cached sidecars/audio can preserve old future-looking introductions until the production pipeline is run with cache bypass or the affected jobs are regenerated.
- The production workflow may require repository secrets or deployment access that are not available locally.

### Recommended Next Step
- None. The target-day-only context is shipped and verified in production.

## Research

### Repository Map
- `jobs/publish/saint_centered_theme.py` builds the shared daily context consumed by Morning Prayer, Daily Rosary, Auxilium Christianorum, Daily Reflection, and Marian Antiphon paths.
- `_select_anchor` previously checked target-day rows, then promoted a suitable row from the following nine days.
- `jobs/publish/daily_intro.py` supplies target-day Gospel and celebration data for the Morning Prayer intro.
- `jobs/publish/contracts.py` passes one canonical daily-theme context into the prayer intro builders and expands the generated intro fragments into text/audio jobs.
- `jobs/novena_contracts/engine.py` uses the shared context for novena intro wording; `jobs/novena_contracts/resolver.py` separately uses feast-date windows to determine active novenas.

### Findings
- Future observances were attached to `window_items` and could become primary through `_select_anchor`; removing future-row collection stops them from reaching shared intro consumers.
- The target-day Gospel is already fetched and attached to target-day rows. When calendar rows are absent, `_normalize_rows` creates a `Weekday Gospel` row, which can be selected as the truthful target-day fallback.
- The canonical runtime currently labels a non-target anchor as `upcoming`; after the fix, shared intro contexts should report `today` or a deterministic target-day fallback only.
- Active novena date windows are scheduling logic, not shared introduction selection, and remain unchanged.

## Plan

### Summary
- Make the shared intro context target-day-only, preserving calendar rank precedence and using the target-day Gospel row when no suitable saint/observance exists.
- Stop fetching future rows for shared introductions, so future solemnities cannot influence anchor metadata, themes, supporting context, or generated copy.
- Add regression tests at the selector, runtime, and contract levels, then run the full pipeline and verify regenerated production sidecars/audio/feed output.

### What Already Exists
- `SaintCenteredThemeBrief` already carries target date, anchor metadata, Gospel provenance, and all window rows.
- `DailyThemeRuntimeCache` already centralizes one context per publish date/config.
- Existing publish contract tests cover all daily prayer families and sidecar metadata.
- The GitHub Actions publish-audio workflow supports cache-bypassed regeneration and deployment.

### Architecture
```text
target date
    |
    v
calendar + Gospel lookup ----> target-day rows ----> target-only anchor
             |                                      |
             +--------------------------------------v
                                  canonical shared intro context
                                                    |
                 +----------------+----------------+----------------+
                 v                v                v                v
             Morning          Rosary          Auxilium        Reflection/
             Prayer           intro            intro            Antiphon
```
- `_select_anchor(rows, target_date)` will rank only target-day suitable rows, then prefer a target-day Gospel row, then a generic target-day row.
- `build_saint_centered_theme_brief` will collect only the target date; `primary_anchor_date`, `primary_anchor_timing`, and `selection_source` will always describe today or the deterministic target-day fallback.
- Existing deterministic fallback behavior remains when both calendar and Gospel data are unavailable.

### Concrete Changes
- Edit `jobs/publish/saint_centered_theme.py`:
  - remove future-candidate promotion from `_select_anchor`;
  - make target-day Gospel fallback selectable and ensure anchor metadata cannot say `upcoming` for shared intros;
  - adjust source/rationale fields to distinguish target-day saint, target-day Gospel, and deterministic fallback.
- Edit `jobs/publish/daily_theme_runtime.py` only if needed to preserve the corrected target-day metadata through runtime fields and sidecars.
- Add or update `tests/test_publish_saint_centered_theme.py` for future solemnity exclusion, target-day saint precedence, target-day Gospel fallback, and metadata assertions.
- Add or update `tests/test_publish_contracts.py` to prove each intro-bearing publish family receives the corrected target-day context and no future solemnity as the primary anchor.
- Update this artifact’s `Progress`, `QA`, and `Release Notes` as work is completed.

### UX And States
- No UI changes.
- Target-day saint/observance: introductions may name that saint or observance.
- No target-day saint/observance but Gospel available: introductions use today’s Gospel/“Weekday Gospel” context.
- Neither available: existing deterministic seasonal fallback keeps the pipeline publishable without claiming a future celebration.

### Implementation Phases
#### Phase 1: Correct shared target-day selection
- Goal: prevent future solemnities/feasts from becoming primary intro context.
- Exact files: `jobs/publish/saint_centered_theme.py`, optionally `jobs/publish/daily_theme_runtime.py`.
- Verification: focused selector/runtime tests with synthetic target and future rows.
- Rollback: revert the shared-context source change; no schema or data migration.

#### Phase 2: Add regression coverage and run pipeline tests
- Goal: prove all intro consumers inherit the corrected context and preserve fallbacks.
- Exact files: `tests/test_publish_saint_centered_theme.py`, `tests/test_publish_contracts.py`, plus any narrowly required tests.
- Verification: targeted publish tests, full repository test suite, `git diff --check`, and a local pipeline dry run with deterministic/offline inputs where supported.
- Rollback: revert source and tests together if the established contract changes unexpectedly.

#### Phase 3: Review, ship, and production verification
- Goal: land the change and prove public artifacts are regenerated with target-day introductions.
- Verification: `/review-astack`, fresh tests after any review fixes, normal release workflow, cache-bypassed production publish workflow, and public sidecar/audio/feed inspection.
- Rollback: stop promotion if artifacts retain future anchors; rerun the last known-good workflow or restore the prior release.

### Failure Modes
- A future solemnity still appears as primary: selector/runtime regression test or sidecar metadata scan fails; do not ship.
- Target-day Gospel lookup fails: deterministic fallback is used and metadata records the fallback reason; no future celebration is substituted.
- Cached audio preserves old copy: cache-bypassed production run and sidecar hash comparison detect it; regenerate affected episodes.
- Contract family is missed: all intro-bearing contracts are enumerated in tests and production sidecar inspection.

### QA And Test Matrix
- Unit: `_select_anchor` with target saint, target Gospel, target weekday, and future solemnity rows.
- Runtime: `build_canonical_daily_theme_runtime_context` reports target date, timing `today`, and no future primary anchor.
- Integration: `build_audio_jobs`/`build_text_jobs` for Morning Prayer, Daily Rosary, Auxilium Christianorum, Daily Reflection, and season-enabled Marian Antiphon paths.
- Regression: active novena resolution still honors its explicit activation windows.
- Static: scan changed/generated JSON for future primary-anchor metadata and run `git diff --check`.
- Production: verify public sidecars’ `target_date`, `primaryAnchorDate`, `primaryAnchorTiming`, intro text/source metadata, non-zero MP3 responses, and RSS links for regenerated episodes.

### Rollout Notes
- No feature flag or migration is required.
- Ship code first, then run the production publish workflow with cache bypass so all affected daily intros regenerate.
- Do not fetch future calendar rows for shared introductions; any future-date scheduling used by novena activation remains separate.

### Not In Scope
- Changing novena activation date arithmetic or liturgical-calendar data.
- Rewriting fixed prayer text or TTS provider behavior.
- Retrofitting unrelated historical audio that is not regenerated by the normal publish workflow.

### Open Questions
