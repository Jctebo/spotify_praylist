## Scope

### Problem
- Ora Pro Nobis episodes are currently assembled from spoken prayer fragments only, with short silence between fragments and final loudness normalization after assembly.
- The show lacks a consistent branded opening, seasonal musical identity, low-volume prayer bed, and closing fade that can apply to every generated Ora Pro Nobis episode.
- Seasonal music has already been generated, but the project needs a maintainable asset/configuration boundary so those files can be added without hard-coded paths spread across show contracts or render code.
- The welcome statement, `Welcome to Ora Pro Nobis, where we pray with the Saints.`, should be spoken in the existing cloned ElevenLabs voice and integrated into the opening.

### Audience
- Primary user: the maintainer producing the Ora Pro Nobis podcast feed and daily prayer audio.
- Secondary stakeholders: listeners who expect a polished podcast-style opening while keeping spoken prayer clear and dominant.

### Current Status Quo
- `jobs/publish/contracts.py` resolves all active publish contracts into text jobs and audio jobs.
- Active Ora Pro Nobis audio jobs include Morning Prayer, Auxilium Christianorum, Daily Rosary, and season-gated Marian Antiphon episodes.
- `jobs/publish/audio.py` renders each TTS fragment, assembles the fragment files, applies final loudness normalization, writes `docs/audio/<episode_id>.mp3`, and writes JSON sidecars.
- `jobs/publish/fragments.py` owns fragment hashing, cached TTS output, ffmpeg concatenation, silence insertion, and normalized TTS settings.
- Existing ElevenLabs provider lists already carry the cloned voice for Morning Prayer, Daily Rosary, and Marian Antiphons, with Auxilium using its configured ElevenLabs voice and role overrides.
- Existing loudness normalization targets `-16 LUFS`, `-1.5 dBTP`, and `11 LRA` by default for publish-audio jobs.
- Existing liturgical season handling is limited: contract gating only distinguishes `ordinary` and `easter`; this feature needs Advent, Christmas, Ordinary Time, Lent, Holy Week, and Easter.

### Goal
- Add centrally configured seasonal music assets for:
  - Advent
  - Christmas
  - Ordinary Time
  - Lent
  - Holy Week
  - Easter
- Automatically select the correct music for each generated episode date using the project's existing Romcal/liturgical helper patterns.
- Add an intro treatment for every Ora Pro Nobis audio job:
  - 3-5 seconds of seasonal intro music before spoken prayer content begins.
  - The spoken welcome statement rendered with the existing cloned ElevenLabs voice.
  - Smooth intro fade-in and natural ducking/fade under the welcome voice.
- Add optional quiet background music underneath spoken prayer/audio:
  - Approximately 15-25 dB below spoken voice.
  - Target practical bed level around `-28 dB` to `-35 dBFS`, tuned so speech remains clearly dominant.
  - Configurable so it can be enabled globally or disabled without changing every show contract.
- Add an outro/fade-out treatment where appropriate:
  - Seasonal music outro fade around 4-8 seconds.
  - Smooth fade-out.
- Preserve the existing episode generation structure:
  - Keep contract expansion, TTS fragment rendering, cache hashing, RSS/feed output, sidecars, and final loudness normalization patterns.
  - Insert music mixing after spoken audio generation/assembly and before final export/mastering.
- Keep final rendered episodes podcast-safe:
  - `-16 LUFS` for stereo output or `-19 LUFS` for mono output.
  - Final true peak at or below `-1 dBTP`.
  - No clipping.

### Constraints
- Scope-only pass for this turn; no implementation yet.
- Do not rewrite unrelated audio logic or show-specific contract structure.
- Do not duplicate music-mixing logic across Morning Prayer, Auxilium Christianorum, Daily Rosary, Marian Antiphons, or future Ora Pro Nobis shows.
- Avoid scattered hard-coded asset paths.
- Missing or unavailable music must not fail episode generation:
  - Continue rendering without music.
  - Log a clear warning with episode id, date, season, and missing path/key.
- No fallback seasonal music is required or desired.
- Attached/generated music files are not yet visible in the repo during scoping, so implementation must include a clear asset placement convention.
- Tests must remain offline and must not require live ElevenLabs, OpenAI, Spotify, Notion, or Romcal network calls.

### Narrow Wedge
- Build a shared seasonal audio-branding layer for all publish-audio jobs.
- Add a centralized seasonal music asset manifest under the existing `config/publish` tree, with seasonal MP3 assets stored under `config/publish/audio`.
- Add a liturgical season resolver that maps a target date to the six required music seasons.
- Add one reusable audio-mixing helper/service that:
  - Resolves the seasonal asset.
  - Renders or reuses the welcome TTS fragment through the existing provider/cache pattern.
  - Mixes intro, welcome, optional bed, spoken episode audio, outro, fades, ducking, and final mastering.
- Wire the helper once in `render_audio_job()` after spoken fragment assembly and before `normalize_episode_loudness()`.
- Add focused tests for season resolution, missing music behavior, timing/fade command construction, bed volume settings, content hash/cache behavior, and sidecar metadata.

### Non-Goals
- Do not change prayer text content, episode titles, Spotify lookup contracts, or RSS naming.
- Do not change the existing prayer fragment cache design except where music/welcome metadata must affect episode-level cache identity.
- Do not make a UI for music management.
- Do not add fallback music from another season.
- Do not introduce new generated prayer intros or reflection text.
- Do not require live audio quality review in CI.
- Do not make background music mandatory if the centralized config disables it.
- Do not overhaul mono/stereo policy beyond honoring the existing output and final mastering constraints.

### Risks And Unknowns
- The exact attached file names, formats, durations, and channel layout are unknown until the assets are present.
- Existing publish contract season gating only knows `ordinary` and `easter`; research must confirm the best way to extract Advent, Christmas, Lent, Holy Week, and Easter from Romcal data in this repo.
- Background music under long prayers, especially the Rosary, may need looping/trimming logic that does not create audible seams.
- Episode content hashes must include the seasonal music config and welcome voice settings so cached full-episode MP3s rebuild when branding changes.
- Welcome voice selection must be clarified: use the existing cloned Ora Pro Nobis voice id where already configured, not Auxilium's alternate narrator unless the implementation finds a central cloned-voice config.
- Final loudness/true peak validation may need ffmpeg loudnorm plus true-peak metadata checks, not just assuming the existing normalization step is sufficient after mixing.
- If a seasonal music file is missing, episode sidecars should make the omission auditable without treating it as a failed render.

### Recommended Next Step

### Current System Map
- Contract loading and expansion:
  - `jobs/publish/contracts.py` loads JSON publish contracts and turns approved entries into audio jobs.
  - `build_audio_jobs()` attaches `published_date`, `audio_fragments`, `audio_config`, `render_context`, and `content_hash`.
- TTS rendering:
  - `render_audio_job()` in `jobs/publish/audio.py` renders each fragment through `render_fragment_audio_with_provider_fallback()`.
  - Provider fallback already supports ElevenLabs-first/OpenAI-second provider lists.
  - `render_fragment_audio()` in `jobs/publish/fragments.py` hashes sanitized text plus normalized TTS settings and caches the generated MP3.
- Spoken assembly:
  - `assemble_audio_fragments()` concatenates rendered fragment files with cached silence fragments.
  - The current output is spoken-only MP3 bytes.
- Mastering/export:
  - `render_audio_job()` calls `normalize_episode_loudness()` after spoken assembly, then writes `docs/audio/<episode_id>.mp3` and sidecar JSON.
  - Existing loudness normalization uses ffmpeg `loudnorm` with `I`, `TP`, and `LRA` settings.
- Season handling:
  - Current publish contract season routing only supports `ordinary` and `easter`.
  - Romcal exposes normalized season values: `advent`, `christmas_time`, `lent`, `paschal_triduum`, `easter_time`, and `ordinary_time`.
  - Holy Week before the Triduum still reports Romcal season `lent`, but rows include ids such as `palm_sunday_of_the_passion_of_the_lord` and `holy_monday`.

### External References

- Apple Podcasts audio requirements: https://podcasters.apple.com/support/893-audio-requirements
  - Relevant because it recommends overall loudness around `-16 dB LKFS` and true peak no higher than `-1 dB FS`; this aligns with the scoped podcast-safe target.

### Constraints
- Keep music behavior centralized and job-level; do not add intro/bed/outro blocks to every publish contract.
- Missing music must warn and return spoken-only audio; this is different from existing missing TTS/template errors, which often fail closed.
- Branding metadata must affect the episode `content_hash`, otherwise existing full-episode cache skip behavior can reuse an unbranded MP3 after assets/config change.
- Welcome rendering should use the cloned Ora Pro Nobis voice, currently visible in Morning Prayer, Rosary, and Marian Antiphon provider lists as ElevenLabs voice id `2NfTQuOn6dRQvgKuC2le`.
- Auxilium’s main narrator uses a different ElevenLabs voice; the welcome should still use the cloned Ora Pro Nobis voice via central branding config.
- Tests should use generated tiny MP3 fixtures and monkeypatched ffmpeg helpers where possible; no live ElevenLabs/OpenAI/Romcal network calls.

### Risks
- Holy Week mapping is the most nuanced calendar case: Palm Sunday through Holy Wednesday report `lent`, while Holy Thursday/Good Friday report `paschal_triduum`, and Holy Saturday reports `easter_time` with Triduum precedence. The helper must intentionally classify the whole Holy Week window as `holy_week`.
- Long background beds need looping/trimming without audible discontinuities; implementation should use ffmpeg stream looping and fades rather than pre-rendering repeated files.
- A complex ffmpeg filter graph can silently produce wrong relative timing if delay/trim labels are wrong; tests should assert command construction and at least one real render smoke path.
- The existing fragment cache skip checks only compare `content_hash`; missing branding metadata in that hash would make reruns stale.
- Final loudness can shift after adding music even when speech is intelligible, so normalization must stay after the branding mix.

### Assumptions To Validate
- The central welcome voice should be ElevenLabs voice id `2NfTQuOn6dRQvgKuC2le`, matching the cloned voice already used by Morning Prayer, Rosary, and Marian Antiphons.
- Background music should be enabled by default for this release, with a single central `enabled` flag to disable it if listening checks show it distracts from prayer.
- The same seasonal MP3 should be reused for intro, background bed, and outro unless future assets split those roles.
- A single-pass `loudnorm` pass is acceptable for this release because the current pipeline already uses it; deeper two-pass analysis can be deferred unless QA shows target misses.

### Unknowns
- Exact subjective bed level still needs listening validation; research supports configuring `-32 dB` as the initial central default within the requested `-28 dB` to `-35 dBFS` range.
- The assets' musical start/end points have not been auditioned, so intro/outro trim offsets may need tuning after a sample render.
- Mono-vs-stereo final target behavior is currently not explicit in the publish pipeline; implementation can keep stereo `-16 LUFS` unless a mono output path is introduced later.

```text
publish contracts
  -> build_audio_jobs()
  -> render_audio_job()

       -> audio_branding.apply_audio_branding()

            -> render/cache welcome TTS fragment
            -> ffmpeg mix intro + welcome + optional bed + spoken + outro
            -> return branded bytes + branding metadata
       -> normalize_episode_loudness()
       -> write MP3 + JSON sidecar + RSS metadata
```

### Failure Modes
- Seasonal asset missing:
  - Detected by asset resolution before ffmpeg mix.
  - User experience: spoken-only episode renders; logs warning; sidecar records skipped music.
- Romcal season missing:
  - Detected by `resolve_liturgical_music_season()`.
  - User experience: branding skips with warning rather than failing the whole audio job, unless research during implementation shows season lookup failures should remain hard errors.
- Welcome TTS provider failure:
  - Detected through existing provider fallback path.
  - User experience: if all welcome providers fail, skip branding and render spoken-only with warning, because the main prayer content must still publish.
- FFmpeg mix failure:
  - Detected by `_run_ffmpeg()` non-zero exit.
  - User experience: skip branding and render spoken-only with warning; final loudness normalization still runs on spoken audio.
- Final loudness normalization failure:
  - Existing behavior remains: rendering fails because final export quality cannot be guaranteed.
- Stale cache:
  - Prevented by including branding config, season, asset identity, and welcome TTS settings in the episode content hash.
