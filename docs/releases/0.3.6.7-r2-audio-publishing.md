# Release 0.3.6.7 - R2 Audio Publishing

## Scope

### Problem
- GitHub Pages is carrying the whole podcast audio archive under `docs/audio/`, producing a Pages artifact larger than 1 GB.
- The podcast must keep old audio reachable while new audio moves to Cloudflare R2 at `audio.orapronobis.media`.
- The publish workflow must preserve RSS episode GUIDs and existing podcast continuity so Spotify and other clients do not see duplicate episodes.

### Audience
- Primary user: the site/podcast maintainer publishing Ora Pro Nobis audio.
- Secondary stakeholders: podcast listeners, Spotify/Apple podcast ingestion, and anyone opening prayer pages from the static site.

### Current Status Quo
- `Publish Prayer Audio` restores and saves `docs/audio` as a GitHub Actions cache.
- The workflow uploads all of `docs/` to GitHub Pages, including every MP3 and sidecar under `docs/audio/`.
- RSS enclosure URLs and prayer-page latest audio links are derived from the GitHub Pages base URL.
- Cloudflare R2 is now provisioned manually:
  - Bucket: `orapronobis-audio`
  - Public custom domain: `https://audio.orapronobis.media`
  - GitHub Actions secrets/variables are configured for R2 access.

### Goal
- Upload generated MP3 and sidecar audio artifacts to R2 during the publish workflow.
- Generate RSS and prayer-page audio URLs using `https://audio.orapronobis.media/...` for audio artifacts.
- Keep the static site and podcast feed on GitHub Pages.
- Stop including the full `docs/audio` archive in the Pages artifact so the artifact warning goes away.
- Preserve episode IDs and RSS GUIDs.

### Constraints
- R2 upload must use GitHub Actions secrets for `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`.
- Non-secret R2 settings are GitHub Actions variables: `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ENDPOINT`, and `AUDIO_PUBLIC_BASE_URL`.
- Existing local publishing should still work without R2 credentials.
- Podcast feed recovery must still preserve older episode history.
- Do not delete the existing local/generated audio archive as part of this code change.

### Narrow Wedge
- Add an R2 upload step to the publish workflow and a small helper script that syncs `docs/audio` to R2.
- Add a separate audio public base URL setting so generated sidecars, RSS enclosures, archive manifests, and prayer pages can point to R2 while the feed/site base remains GitHub Pages.
- Exclude `docs/audio` from the Pages upload artifact after successful R2 upload.

### Non-Goals
- Do not migrate the existing historical MP3 archive in this release unless the publish workflow already has it restored locally.
- Do not change podcast GUIDs, titles, or Spotify resolver behavior.
- Do not move `podcast.xml` off GitHub Pages in this release.
- Do not remove generated local `docs/audio` files from developer machines.
- Do not build a Cloudflare Worker.

### Risks And Unknowns
- R2 endpoint values may be jurisdiction-specific; the workflow must consume `vars.R2_ENDPOINT` instead of constructing one blindly.
- If R2 upload fails but Pages excludes audio, newly generated RSS links could point to missing MP3s.
- Remote archive recovery currently reads RSS and local cache state; excluding `docs/audio` from Pages must not break feed continuity.
- Sidecar JSONs may be useful for prayer pages and archive manifests; they should be uploaded beside MP3s unless proven unnecessary.

### Recommended Next Step
- Plan a workflow-first migration: implement audio URL configuration, R2 sync, Pages artifact staging that excludes `docs/audio`, and focused tests for URL generation/workflow wiring.

## Research

### Existing Code
- `.github/workflows/publish_audio.yml` restores `docs/audio`, runs the audio and novena pipelines, builds the prayer website, saves `docs/audio`, and uploads `${{ github.workspace }}/docs` to Pages.
- `jobs/publish/audio.py` owns `github_pages_base_url()`, `audio_public_url()`, `podcast_cover_art_public_url()`, archive sidecar loading, and archive page generation.
- `jobs/publish/rss.py` builds RSS using each job's `audio_url`; GUIDs come from episode IDs and are independent of URL host.
- `jobs/publish/run_audio_pipeline.py` passes the same site base URL into feed generation and archive loading.
- `jobs/publish/site.py` reads sidecars via `load_published_audio_jobs()` and renders latest audio players/links from job `audio_url`.
- Tests already cover RSS enclosure shape, archive loading, site audio links, and workflow text expectations.

### Constraints Confirmed
- R2 bucket and custom domain are active in Cloudflare.
- GitHub Actions has the needed secrets and variables.
- Local runs must retain GitHub Pages defaults when `AUDIO_PUBLIC_BASE_URL` is unset.

### Implementation Implications
- The site/feed base URL and audio file public base URL need to become separate concepts.
- `docs/audio` should remain the local build/cache/staging directory.
- R2 sync should happen before Pages artifact upload.
- Pages upload should use a staged copy of `docs/` with `audio/` removed, instead of mutating generated output.

## Plan

### Summary
- Add R2-backed audio publishing while keeping GitHub Pages as the static site and RSS feed host.
- Use `AUDIO_PUBLIC_BASE_URL` for MP3/sidecar links and keep `PUBLISH_GITHUB_PAGES_BASE_URL` for site/feed links.
- Upload `docs/audio` to R2, then upload a staged Pages artifact without `docs/audio`.

### What Already Exists
- Contract-driven audio generation into `docs/audio`.
- Archive sidecars that preserve audio metadata and prayer-page latest episode data.
- RSS generation that consumes per-job `audio_url`.
- GitHub Actions cache for `docs/audio`.
- Static site generation from the audio sidecars.

### Architecture

```text
publish workflow
  -> restore docs/audio cache
  -> render/update docs/audio + docs/podcast.xml
  -> build prayer site using sidecars
  -> sync docs/audio/* to R2
  -> copy docs -> artifact staging, remove artifact/audio
  -> upload staged artifact to GitHub Pages

site/feed host:  https://jctebo.github.io/spotify_praylist
audio host:      https://audio.orapronobis.media
```

  - Update `audio_public_url()` to use the audio base by default.
  - Keep cover art URLs on the site/feed base.
  - Ensure archive manifest sidecar links use the site/feed base while MP3 links use the audio base.
- `jobs/publish/run_audio_pipeline.py`
  - Use separate `site_base_url` and `audio_base_url`.
  - Pass the audio base into archive sidecar/job loading and RSS job URLs.

  - Ensure site generation passes the configured audio base into `load_published_audio_jobs()` while retaining the site base for page URLs.
- `scripts/sync_r2_audio.py`
  - New script to upload `docs/audio` recursively to R2 using S3-compatible credentials.
  - Fail fast if required R2 env vars are missing.

  - Run `python scripts/sync_r2_audio.py` after site generation.

  - Upload the staged `docs` artifact instead of raw `docs`.
- `README.md`
  - Document R2 audio hosting variables and the split between site/feed host and audio host.
- Tests
  - Add/adjust tests for `audio_public_url()` and site/RSS audio host split.

### Failure Modes
- Missing R2 credentials: sync script exits nonzero before Pages deploy.
- Wrong R2 endpoint: sync script fails before Pages deploy.
- `AUDIO_PUBLIC_BASE_URL` unset: audio URLs fall back to GitHub Pages and local behavior remains compatible.
- R2 upload succeeds but custom domain has propagation trouble: feed links resolve after Cloudflare finishes activation; domain is already active.
- Historical audio not present in cache: feed can preserve remote RSS items, but old MP3s must be migrated separately if absent from restored `docs/audio`.
