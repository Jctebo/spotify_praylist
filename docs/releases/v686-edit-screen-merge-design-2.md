### §1.1 The six decisions, as approved

- **Q1 — Source-row seats.** Edit-form per-block lists carry the block's daily-source rows **interleaved at their composed seats, fixed**: no reorder acts (no drag — retired by v684 anyway — and no up/down buttons), no Remove. Each carries the tag **"Daily source"**. Contents items sort around them as today.
- **Q2 — Source-row controls.** Each source row carries its **On/Off switch** and its **day pick** (Daily · Sundays · Fridays · Fallback only where it stands today) on the row itself.
- **Q3 — Closing "Mass and Homilies" section.** A closing section in the Edit form homes the rows no block seat holds: the two homily sources (`fr-mike-homily` · `barron-sermon`, day pick Sundays) and the unplaced Stations row (`stations-of-the-cross`, enabled 0, Fridays, tagged **"Not placed"**). - **Q5 — Write target.** The Edit form writes the **same** `player_source_settings` store (enabled · dayRule; block and sortOrder untouched as values the form sends — see C1, §1.3). No resolver change, no store change, no migration.
- **Q6 — Move act.** A contents item's ⋮ menu in the Edit form carries **"Move to block…"** — it opens the block list (every block, disabled blocks named as disabled); the item lands at the **end** of the target block's contents, its settings travelling (an office item keeps its source pick); it works from a disabled block; daily-source rows get **no** Move; a move into a block already holding that office hour is **refused with the reason named**.

### §1.4 Contradictions found at Plan — named, not improvised around

- **C1 — Q5's "sortOrder untouched" vs the standing PUT.** The standing write route **renumbers** `sort_order` gapless per block from the body's array order, and writes `sort_order = NULL` for disabled or unplaced rows (server: index.ts:6199 batch at the PUT, index.ts:6150; local router twin: client.ts:3870). No route exists that writes enabled/dayRule alone. §2.5 prescribes the body-order discipline that makes the renumber order-preserving, and the composition gate (§2.7) proves no composed seat moves. The literal wording of Q5 cannot be met by the standing route; the *effect* (no seat, block, or value changes) can, and is gated.
- **C2 — The USCCB row's switch gates nothing today.** All four Mass and Homilies slots retired from the client slot table at v499 (`EXT_SLOTS`, client.ts:18876 — its comment names the retirement), so no leg resolves `ext-usccb-readings`. So the USCCB source row stands in Morning per Q3 with a working store write (§2.5), but flipping it Off does **not** drop the readings from the composed day under the standing resolver — and Q5 forbids a resolver change in this release. The harness therefore proves the drop/return leg on a gated source (§2.7 L2) and proves paint + write + read-back for the USCCB row (L2b). **If John expects the USCCB switch to gate the readings, that is a resolver change and a new word is needed — flagged to the coordinator with this Plan.**
- **C3 — Move from/into a disabled block vs the contents validators.** Contents entries for a block outside the profile's `coreBlocks` are refused: `opnCheckContents590` (client.ts:3007) throws `contents for a block that does not stand`, its server mirror stands behind the profiles routes, and `opnWrite604` (client.ts:24053) itself deletes non-core contents entries before writing (both scopes). So a Move whose source **or** target block stands disabled cannot persist through the standing write path — the moved item's source list (or target list) is dropped/refused. Q6's "works from a disabled block" therefore needs the narrow write-path step named in §2.6 step 5; it touches the **contents** write path only, never the source-settings store, but it widens the package's "contents mechanics stand as today" OUT line and is **flagged to the coordinator with this Plan** rather than silently absorbed.

(b) The two fallback rows (`sth-lauds` · `sth-vespers`): they share their slot's seat with the primary (§2.1 #4/#18); a separate row would double the seat. Their visible control is the office item's v670 source segtoggle, per the designs report ("the fallback tie stands as data, invisible"). ### §2.5 (e) The write path

- **Route (standing, reused — no new route):** `PUT /api/player/source-settings` — the Settings editor's own write (`saveSettings`, client.ts:12733), served by index.ts:6150 on the Worker and by the local router (client.ts:3870) on device/web shapes.
