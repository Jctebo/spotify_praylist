## Scope

### Problem
- Several novena prayer texts still contain printed `V:` and `R:` abbreviations before call-and-response lines.
- Those labels are editorial directions, not spoken prayer, so narrating them makes the audio unnatural and inconsistent with the agreed call-and-response treatment.

### Audience
- Primary user: listeners praying along with novena audio.
- Secondary stakeholders: maintainers importing, validating, and publishing novena contracts.

### Current Status Quo
- The tracked novena catalog contains standalone `V:`/`R:` and `V.`/`R.` labels across 22 feast-day contracts, often repeated in each day and duplicated between legacy `sections` and canonical `blocks`.
- The call and response wording itself is already correct, but the printed labels remain embedded in spoken text.

### Goal
- Ensure novena audio speaks the call and response naturally without saying the printed abbreviations.
- Success criteria: no spoken novena source text contains standalone `V:`/`R:` or `V.`/`R.` labels; the call and response wording remains unchanged; both `sections` and `blocks` stay synchronized; regression tests cover the full catalog audit.

### Constraints
- Preserve the prayer wording, order, repetition, and theology.
- Do not change unrelated `V`/`R` text, generated audio files, or non-novena content.
- Keep legacy `sections` and canonical `blocks` consistent.

### Narrow Wedge
- Normalize every affected checked-in novena contract at its source and add a repository audit test that fails if standalone call-and-response labels reappear in novena spoken text.

### Non-Goals
- Re-recording or deleting existing audio artifacts.
- Rewriting every editorial notation in the repository.
- Changing voice assignment or call-and-response timing.

### Risks And Unknowns
- Other source systems may contain untracked or externally managed novena text; the repository audit can only guarantee checked-in contract content.
- Removing the labels must not accidentally alter legitimate prayer text or adjacent punctuation.

### Recommended Next Step
- Inspect the novena contract and validation paths, apply a minimal synchronized content edit, add focused regression coverage, then run the relevant and full test suites.

## Research

- The repository’s novena loader reads 398 checked-in contracts from `contracts/novenas`; spoken text is represented in both legacy `sections` and canonical `blocks`.
- A read-only catalog audit found 22 affected feast-day contracts with standalone `V:`/`R:` or `V.`/`R.` labels, including repeated day text. No source edit is needed outside `contracts/novenas/feast-days/*.json`.
- The existing TTS normalizer treats these markers as print-only artifacts. Its preview is diagnostic-only and does not overwrite contracts.

## Plan

### Summary

- Remove only standalone `V:`/`R:` and `V.`/`R.` prefixes from every affected novena spoken-text string.
- Add a catalog-level regression test so future imports cannot reintroduce these labels.

### What Already Exists

- `jobs.novena_contracts.contracts.load_novena_contracts()` parses both `sections` and `blocks` and validates the full catalog.
- `tests/test_novena_contracts.py` already contains repository-fixture regression tests.
- `.agents/skills/normalize-prayer-tts/scripts/normalize_prayer_tts.py` provides preview/strict diagnostics for prayer TTS artifacts.

### Architecture

```text
checked-in novena JSON
        |
        v
load_novena_contracts() --> sections + blocks --> audio renderer
        ^
        |
catalog regression audit rejects standalone V./R. or V:/R. labels
```

- Source contracts remain the single source of truth; no runtime stripping is added.
- The audit traverses loaded contract dictionaries and checks text in both representations, avoiding false positives in metadata or code.

### Concrete Changes

- Edit the 22 affected files under `contracts/novenas/feast-days/`, removing only the marker tokens while preserving following text and punctuation.
- Add a focused test to `tests/test_novena_contracts.py` that loads the repository catalog, traverses each novena template’s `sections` and `blocks` text/parts, and asserts no standalone marker remains.
- Update this release artifact’s progress and QA sections after verification.

### UX And States

- An over-broad replacement could alter legitimate prose; JSON parse checks, exact diff review, and unchanged call/response text checks detect this.
- New imported contracts may reintroduce labels; the catalog test fails before release.
